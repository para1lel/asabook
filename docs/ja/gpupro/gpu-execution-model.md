::: info 概要
- GPU kernel の実行はまずスレッド階層によって決まります。スレッド、warp、warpgroup、CTA、クラスタ、grid はそれぞれ異なるコラボレーションの粒度に対応しています。 Blackwell の多くの操作には独自の自然な範囲があります。例えば、TMA コピーは単一のスレッドで開始され、完全な TMEM accumulator は自身の 32 レーンウィンドウから 4 つの warp で読み取られます。2CTA の協調型 MMA は 2 つの CTA にまたがります。
- データは一箇所に留まることはありません。 GMEM、SMEM、TMEM、レジスタはそれぞれ異なる容量、遅延、アクセス範囲に対応しています。 このクラスタはまた、ある CTA が DSMEM を介して別の CTA の共有メモリにアクセスすることも可能にします。 高性能 kernel の中核的な役割の一つは、これらの空間間で効率的なデータ移動を手配することです。
- 計算とデータ転送は、異なるハードウェアエンジンが連携して処理します。 CUDA Core はアドレス計算、制御フロー、スカラーロジックを担当し、Tensor Core はメイン行列計算、TMA は非同期データ転送を担当します。 最後に、GEMM のデータパイプラインを用いてこれらのコンポーネントを接続し、高性能 kernel が重複を通じて複数のエンジンを同時に忙しく保つ方法を示します。
:::

高性能 GPU kernel を書くには、まずスレッドの構成方法、データの保存場所、kernel 実行中に異なるハードウェアエンジンがどのように連携しているかを理解する必要があります。 本章では、まず GPU のスレッド階層を紹介し、次にデータの保存と転送に使われるメモリ空間、そして計算とデータ転送を担うハードウェアエンジンの 3 点に焦点を当てます。 次に、これらの概念を結びつけるために GEMM パイプラインを用い、データがメモリ空間間でどのように移動し、計算とデータ処理がどのように重なり合うかを説明します。 今後の章では、これらの基本的なメカニクスを基に多くの最適化が進められます。

## 実行レベル

GPU は何千ものスレッドをフラットなコレクションとして管理するのではなく、複数のレイヤーに整理します。 各層は協働粒子のサイズに対応しています。 下の図は Blackwell のスレッド階層を示しています。

<iframe src="/gpupro/demo/thread_hierarchy.html" title="Blackwell thread hierarchy" loading="lazy"
        style="width:100%; height:520px; border:1px solid var(--vp-c-border); border-radius:6px;"></iframe>

*図内のコンポーネントをクリックすると、スレッド、warp、warpgroup、CTA、クラスタ、grid を層ごとにご覧いただけます。*

- **スレッド**: 実行単位の最小。 各スレッドは独自のプログラムカウンタとレジスタを持ち、warp 内のレーン ID で識別されます。
- **warp**: SIMT で実行される 32 スレッドのセット (*単一命令、複数スレッド*)。 warp 内のレーンは同じ命令を同時に発行しますが、各レーンは独自のレジスタを保持し、個別にマスクすることができます。分岐に遭遇した場合、warp は異なるマスクを通じて各パスを個別に実行します。
- **warpgroup**: 4 本連続で 128 糸。 ホッパーアーキテクチャは warpgroup を導入し、warpgroup レベルの MMA(`wgmma`)を開始しました。 ブラックウェルでは、その 4 つの warp は tensor メモリの 4 つの 32 レーンウィンドウを個別に覆うこともできます。
- **CTA** (*協調スレッド配列*、すなわち CUDA のスレッドブロック): ハードウェアスケジューリングの基本ユニットです。 CTA は単一の SM 上で動作し、その SM 内で独自の共有メモリ割り当てを持っています。 複数の CTA は同じ SM 上に同時に存在でき、この時点でその SM の共有メモリ容量がこれらの CTA に割り当てられます。
- **cluster**: 互いに協力できる CTA のグループ。 クラスタ内の CTA は異なる SM に位置することがあり、 これらは相互に同期でき、分散共有メモリ(DSMEM)を通じて互いの共有メモリにもアクセスできます。

Blackwell のキー操作はすべて同じスレッドセットから開始されるわけではありません。 TMA コピーは単一のスレッドから開始され、その後ハードウェアに引き渡されて実行されます。 各 warp は warp レベルの TMEM ロードを通じて独自の 32 レーンのウィンドウを読み込みます。 `tcgen05` MMA は選ばれたスレッドで提出されます。 2-CTA 協同型 MMA は 2 つの CTA にまたがります。

後に、操作に関わるスレッド範囲はその scope と呼ばれます。 kernel を分析する際には、操作の範囲、データ layout、ディスパッションメソッドを考慮する必要があります。


## メモリ空間

スレッド階層は計算の組織化を説明し、次にデータがどこに保存されているかを決定する必要があります。 GPU はさまざまなメモリ空間を提供し、容量、遅延、アクセス範囲の間で異なるトレードオフを行います。 kernel はこれらの空間間でデータを効率的に移動させる必要があります。

| 記憶 | 訴訟範囲 | 目的 | 説明 |
|------|----------|------|------|
|グローバル(GMEM)| 装置全体 | tensor を長期間保存する方法 | 大容量 HBM、すべての SM が共有 |
|共有(SMEM)| 各 CMA(1 つの SM 以内) | tile: 一時的な保管 | 低遅延の一時記憶領域; B200 は最大 228 KB/SM に達します |
|tensor メモリ(TMEM)| 各 CTA は | MMA accumulator ストレージ | ブラックウェルは付け加えた。 `tcgen05` 用途 |
|レジスタファイル(RF)| 各スレッド | スカラーと各スレッドの tile 断片 | もうすぐだ; epilogue/一時的な価値を保存する |

tensor メモリ(TMEM)は、ブラックウェルが追加した追加のオンチップストレージスペースです。 以前のアーキテクチャでは、MMA accumulator は通常レジスタに保存されていました。 MMA tile が増えるにつれて、これらの accumulator は多くのレジスタを占めます。 Blackwell の `tcgen05` は TMEM に accumulator を書き込み、この部分のレジスタ負荷を軽減します。

TMEM は CTA で使用される二次元の一時的な記憶領域と見なすことができます。 この空間は 128 行(128 の TMEM レーンに相当)と最大 512 列(各列の幅 32 ビット)を含みます。 論理的には CTA が使っていますが、物理的には SM 内に残っています。

TMEM はプログラムによって明示的に管理される必要があります。 kernel は TMEM を割り当てて解放しなければなりません。 MMA が完了した後、epilogue では TMEM から accumulator をレジスタに戻す必要があります。 128 レーンの accumulatorー全体を読み取ると、warp 群内の 4 つの warp がそれぞれ 32 レーンの TMEM ウィンドウを読み込みます。

### クラスタ内の分散共有メモリ

クラスタは異なる SM 上に複数の CTA を含むことがあります。 各 CTA は引き続き独自の共有メモリを持ちますが、分散共有メモリ(DSMEM)により、同じクラスタ内の他の CTA がデータにアクセスできるようになります。

この機能は、不要な GMEM 往復の回避に役立ちます。 一方の CTA は、相手側が GMEM を書き戻して再読することなく、別の CTA の SMEM に直接アクセスできます。 これらのデータを非同期操作で扱う場合、完了 barrier は処理完了後に続く計算を継続するよう通知します。

図に示されている 2-CTA GEMM では、各 CTA は自分の A と B スライスを保存しつつ、DSMEM を介して別の CTA の B スライスを読み込みます。 ここでの「シェア」とは、2 つの CTA の SMEM が一つに統合されることを意味しません。 これは、クラスタ内の CTA 同士が SM を越えて互いのデータにアクセスできるという意味に過ぎません。

この基盤により、2 つの CTA は `cta_group=2` を形成し、共同で連携して MMA を行い、より大きな出力 tile を生成できます。

## 計算コア: CUDA コアおよび tensor コア

スレッド階層は計算の組織方法を決定し、メモリ空間はデータの保存場所を決定します。 実際の算術操作は SM 内の計算ユニットによって行われます。 SM は主に 2 種類の計算ユニットを含みます: CUDA コアと tensor コアです。

- **CUDA Core** は、スカラー命令およびベクトル命令の実行を担当する汎用 SIMT 算術分析ユニットです。 kernel 内のアドレス計算、要素ごとの操作、還元、制御フローは主に CUDA Core で処理されます。
- **tensor コア** は行列計算を重視した固定関数単位であり、*tile* 粒度で密集行列の乗算・累積を実行し、1 命令で $D = AB + C$ を計算します。

tensor コアは CUDA コアよりもはるかに高い算術スループットを持ち、通常は FLOP/s の 10 倍以上に達します。GEMM、畳み込み、注意のような高密度線形代数計算は、tensor コアを完全に活用して初めてピーク性能に近づくことができます。 高性能 kernel はまた、tensor コアがデータや依存関係の待ち時間によるアイドル化を防ぐために、タイムリーにデータを準備する必要があります。

異なる GPU アーキテクチャは tensor コアのスループットを変えるだけでなく、プログラミング手法や accumulator の格納場所も変えます。 ホッパーは非同期 warpgroup MMA(`wgmma.mma_async` 年)を導入しました。 ブラックウェルの第 5 世代 tensor コア、すなわち `tcgen05` は、レジスタの代わりに tensor メモリに accumulator を配置しました。 この点については今後の章で議論します。

GEMM における cluster は、2 つの重要な応用ももたらします。 2-CTA 協調型 MMA、2 つの CTA がそれぞれ SMEM 作業の一部を提供し、より大きな tensor コア MMA tile を共同で立ち上げることができます。 TMA マルチキャスト単一の GMEM ロードで同じ tile を複数の CTA に送信できるため、各 CTA が同じデータを個別に読み取ることによる冗長なグローバルメモリトラフィックを回避できます。 どちらも以前に導入された cluster および DSMEM メカニズムに依存しています。


## GEMM データパイプライン

単一の GEMM tile は通常 3 段階を経ます。

1. ロード: TMA コピーは、A または B の操作と tile を GMEM から SMEM へ移動させます。 スレッドがこのコピーを開始し、到着予定のバイト数を記録します。 データが SMEM に書き込まれると、TMA エンジンが進行状況を更新します。 すべての期待バイトが到達した後にのみ完了 barrier が発生します。
2. 計算: `tcgen05` MMA は SMEM から operand tile を読み取り、その積を TMEM tile に追加します。選択されたスレッドがこの MMA をコミットします。 計算が完了すると、ハードウェアは対応する barrier に完了信号を送ります。
3. epilogue: warpgroupTMEM accumulator をレジスタに読み戻し、結果を出力 dtype に変換して GMEM に書き戻します。 このステップは通常 SMEM ステージングから始まりますが、最終的な書き込みには TMA ストアを使って行う場合もあります。

これら 3 段階はデータ依存関係を持ちますが、完全に直列に実行される必要はありません。 単純な kernel は、ロード、待機、計算、待機、保存を順次実行し、各ハードウェアユニットが順番に待機します。

高性能 kernel はそれらを組立ラインに組織します。tensor コアが `k` 番目の tile を計算すると、TMA エンジンは `k+1` 番目の tile を運び、epilogue は `k-1` 番目の tile を処理します。 barrier モデルと位相モデルはこれらの非同期相間の安全なハンドオーバーを担い、その後の GEMM 最適化はこのメカニズムに基づいて構築されています。
