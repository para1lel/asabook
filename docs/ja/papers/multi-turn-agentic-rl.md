## 概要

本研究では、マルチターン強化学習によって大規模言語モデルをエージェントとして訓練する際、実際に何が機能し、何が機能しないのかを検討する。急速な進歩にもかかわらず、既存のフレームワークと定義は断片化しており、どの設計選択がタスクをまたいで重要になるのかについて、体系的な定式化も分析も存在しない。本研究ではこの隔たりを埋めるため、まず設計空間を相互に関連する三つの柱、すなわち環境、報酬、方策に分解し、状況に根差したテキスト領域で LLM エージェントを訓練するためのレシピを実証的に導出する。具体的には、状況に根差した身体性推論を検証する代表的な領域である TextWorld と ALFWorld に加え、よりソフトウェアエンジニアリング寄りのタスクとして SWE-Gym を検証する。（i）環境については、状態空間と行動空間の大きさ、および最適解の長さという観点からタスク複雑度の影響を分析し、同一領域内の単純な環境であっても、エージェントがより複雑なタスクへどの程度汎化できるかを示すシグナルを得られることを明らかにする。（ii）報酬については、報酬の相対的な疎性をアブレーションし、密なターン単位の報酬が訓練を加速する一方で、性能と安定性が RL アルゴリズムの選択に大きく左右されることを観察する。（iii）エージェントの方策については、報酬の疎性と、バイアスのある方策勾配法（PPO、GRPO）および不偏な方策勾配法（RLOO）との相互作用を探るとともに、予算が固定されている場合に教師ありファインチューニング（SFT）と RL の最適な訓練比率を求める方法を示す。

## 1 はじめに

自律エージェントとして LLM を訓練し、オープンエンドな環境を探索させることには、長いホライズンにわたる計画、マルチターンの逐次的な意思決定、マルチターン報酬の最適化という固有の課題がある。静的なシングルターン問題解決から動的な多段階推論への移行は、対話的テキストや身体性シミュレーション（TextWorld [Cot19]、ALFWorld [Shr21] など）、実世界のソフトウェアプログラミング（OSWorld [Xie24a]、SWE-gym [Pan25b] など）、新規状況での抽象推論（ARC-AGI [Cho25d]）といったエージェント型ベンチマークに不可欠である。しかし、既存のマルチターン RL の実装には大きなばらつきがあり、ツールで拡張した単一クエリをマルチターンと呼ぶものもあれば [Zen25c]、モデルベースの仮定に依存するものも多い [Wan25ag]。こうした断片化により、論文間で結果を比較できず、真のマルチターン学習とシングルターン手法の疑似マルチターン適応との違いをめぐる混乱が生じている。

本論文の目的は、「LLM エージェントの学習においてマルチターン RL を機能させるうえで、実際に重要な要因は何か」という未解決の研究課題への取り組みを促進することである。マルチターン RL 手法が標準化されていないことを踏まえ、本研究では設計空間を相互依存する三つの柱、すなわち環境、報酬、方策へ体系的に分解し、状況に根差したテキスト領域で LLM エージェントを訓練するためのレシピを実証的に導出する（[図 1](#figure-01)）。身体性推論には TextWorld と ALFWorld、実世界のプログラミングには SWE-gym を用いて本手法を評価し、各柱について重要な知見を得る。**環境**については、環境の複雑度とタスクの多様性に応じて性能がどうスケールするか、また異なる環境やタスクをまたいでエージェントがどう汎化するかを調べる。**方策**については、モデルの事前知識が継続的なマルチターン RL 訓練に与える影響を調べ、マルチターン模倣学習（SFT）とマルチターン RL の相互作用を分析する。さらに、バイアスのある方策勾配 RL アルゴリズム（PPO、GRPO）と不偏なアルゴリズム（RLOO）を比較し、アルゴリズム上のヒューリスティクスによる利点を切り分ける。**報酬**については、ターン単位の報酬密度を変え、訓練への影響を把握する。

実験により、本研究のレシピがテキスト推論、状況に根差した身体性推論、ソフトウェアエンジニアリングの各タスクで機能することが示された。分析から得られた主要な知見は次のとおりである。（1）マルチターン RL の性能は、空間、オブジェクト、解という各次元の環境複雑度に応じてスケールする。（2）より単純な環境で訓練したエージェントは、複雑な環境への有望な汎化を示す。（3）マルチタスク訓練はマルチターン RL の性能を高める。（4）少量のデモンストレーションから得たモデルの事前知識は収束を加速するが、汎化には依然として RL が不可欠である。（5）予算が固定されている場合、タスク精度と汎化のバランスを取る最適な SFT:RL 比が存在する。（6）バイアスのあるアルゴリズムと不偏なアルゴリズムの双方が安定した学習を実現し、性能向上がアルゴリズム上のヒューリスティクスではなく、本研究のマルチターン定式化に由来することを裏付ける。（7）密なターン単位の報酬は疎な報酬よりもマルチターン RL 訓練を加速するが、アルゴリズムごとの調整が必要である。

これらの知見から、三つの柱すべての協調設計を導く具体的なマルチターン RL のレシピが得られる。LLM を用いたマルチターン RL は、シングルターン最適化を単に拡張したものではなく、環境、方策、報酬のすべてを根本から再考する必要があることを示す。今後の研究を促進するため、veRL [She25c] を基盤としたマルチターン・エージェント RL フレームワークを、本論文の実験に用いた訓練スクリプトおよびモデル重みとともに公開する予定である。本研究は、実世界の対話環境で効果的に動作できるエージェント型 AI システムの開発に向けて、理論的知見と実践的指針の両方を提供する。

## 2 関連研究

PPO [Sch17a]、RLOO [Ahm24]、GRPO [Sha24d]、DAPO [Yu25g] など、LLM 向けのシングルターン RL 手法は即時応答の品質を高めるために広く最適化されてきたが、それらをマルチターンのエージェント型シナリオへ適応するのは容易ではない。これらの手法は、個々の行動の直後に報酬が得られると仮定するが、マルチターン環境では長い対話系列の後にしか結果が明らかにならず、シングルターン手法が依拠する行動と報酬の結び付きが崩れる。マルチターン RL に関する既存研究は、こうした課題について限定的な進展しか遂げていない。シングルターンの QA ペアにツール使用または推論ステップを交互に挿入し、マルチターンのシナリオを構築する手法がある [Zen25c, Don25g]。一方、真の対話環境を扱う研究は、ターン単位の学習シグナルを持たない疎な終端報酬に依存するか [Wan25ag]、細粒度の信用割当を行わず系列内のトークンへターン単位のアドバンテージを一様に割り当てている [Zho25g]。さらに重要なことに、RL の三つの基本的な柱、すなわち環境、方策、報酬が、マルチターン対話環境での性能を共同でどう決めるのかについて、包括的な理解が不足している。本論文では、RL の基本的な柱がそれぞれマルチターン RL 訓練にどう影響するかを体系的に分析し、異なる対話型エージェント環境でマルチターン RL を実際に訓練する方法について知見をまとめる。本論文全体を通じて、関連研究は各節で個別に扱う。

## 3 マルチターン・エージェント強化学習

マルチターンのエージェント型タスクを、タプル $(\mathcal{S},\mathcal{A},\mathcal{T},\mathcal{R},\Omega,\mathcal{O},\gamma)$ で定義される部分観測マルコフ決定過程（POMDP）として定式化する。TextWorld タスク [Cot19] を例にすると、エージェントは行動空間 $\mathcal{A}$ からサンプリングした行動 $a_{t}$（`go south`）を取り、観測空間 $\Omega$ からテキスト観測 $o_{t}$（`You are in front of a garden`）を受け取る。$o_{t}$ は、完全な状態世界モデルを含む隠れ状態空間 $\mathcal{S}$ における真の状態 $s_{t}$ の部分的な記述である。状態遷移関数 $\mathcal{T}:\mathcal{S}\times\mathcal{A}\rightarrow\mathcal{S}$ は決定論的であると仮定する。エージェントは行動を取ると、スカラー報酬 $r_{t}=\mathcal{R}(s_{t},a_{t})$ も受け取る。エージェントの目的は、期待割引報酬和 $\mathbb{E}[\sum_{t}\gamma^{t}\cdot r_{t}]$ を最大化する方策を学習することである。

タスクプロンプト $u$、行動系列、状態系列からなる軌跡履歴を $h_{t}=(u,s_{0},a_{0},s_{1},a_{1},\cdots,s_{t})$ と表す [+1]。方策 $\pi_{\theta}$ を持つ LLM エージェントは、軌跡履歴に基づいて行動系列 $a_{t}\sim\pi_{\theta}(\cdot|h_{t})$ をサンプリングする。$a_{t}$ は自然言語のトークン系列 $(a_{t}^{1},a_{t}^{2},...,a_{t}^{n_{t}},a_{t}^{\mathrm{eos}})$ であり、各トークン $a_{t}^{i}$ は $\pi_{\theta}(\cdot|h_{t},a_{t}^{<i})$ として生成される。エージェント環境は言語コマンドが完成して初めて実行するため、`<eos>` トークンで示されるコマンド境界に報酬構造が自然に定義される。したがって、$a_{t}^{\mathrm{eos}}$ にスカラー報酬 $r_{t}$ を割り当て、各行動トークンの報酬を $r_{t}^{i}=\begin{cases}r_{t}&\mathrm{if}\ a_{t}^{i}=\texttt{<eos>}\\ 0&\mathrm{otherwise}\end{cases}$ と定式化する。すべての状態トークンをマスクし、行動トークンだけが損失に寄与するようにする。

具体例として、ロールアウト段階でチャットテンプレートを用いる場合、LLM への入力は次のとおりである。

```text
<|im_start|>user
Your task is: {task prompt}. state: {state 0} your action:<|im_end|>
<|im_start|>assistant
{action 0}<|im_end|>
...
<|im_start|>user
state: {state t} your action:<|im_end|>
<|im_start|>assistant
```

方策 $\pi_{\theta}$ の LLM は、出力 `{action t}<|im_end|>` を生成する。環境は状態遷移と報酬計算を処理する：`next_state, reward, done = env.step(state, action)`。各ターンの報酬は `<|im_end|>` トークンに割り当てられる。その後、行動と次の状態をテンプレートに従ってチャット履歴へ追加する。

## 4 背景と実験設定

本実験では、RL の三つの基本的な柱がマルチターン・エージェント RL の性能にどう影響するかを体系的に調べる。**環境**（[第 5 節](#section-5)）については、環境複雑度のスケーリングが空間、オブジェクト、解の各次元で学習にどう影響するかを調べ（[第 5.1 節](#section-5-1)）、単純な環境で訓練したエージェントが複雑な環境へ汎化するかを評価し（[第 5.2 節](#section-5-2)）、タスクの多様性が訓練と汎化にどう影響するかを分析する（[第 5.3 節](#section-5-3)）。**方策**（[第 6 節](#section-6)）については、デモンストレーションデータから得られるモデルの事前知識が RL の収束へどう影響するかを分析し、予算制約下での SFT 対 RL データの最適比率を特定する（[第 6.1 節](#section-6-1)）。バイアスのあるアルゴリズム（PPO、GRPO）と不偏なアルゴリズム（RLOO）を比較し、アルゴリズム設計の利点と本研究のマルチターン定式化の利点を切り分ける（[第 6.2 節](#section-6-2)）。**報酬**（[第 7 節](#section-7)）については、軌跡中のフィードバックシグナルの頻度である報酬密度が、訓練と最終性能にどう影響するかを調べる（[第 7.1 節](#section-7-1)）。これらの実験は、マルチターン RL ではシングルターン手法を素朴に拡張するのではなく、すべての構成要素を慎重に協調設計する必要があることを示す。

**タスクと環境。** 状況に根差したテキストベンチマークを三つ用いて評価する。状況に根差した身体性推論における言語グラウンディングには TextWorld [Cot19] と ALFWorld [Shr21]、実世界のソフトウェアエンジニアリングには SWE-Gym [Pan25b] を用いる。veRL [She25c] の効率的な RL 訓練基盤を拡張し、標準的な `step` および `reset` インターフェースを介して、これらのベンチマーク環境を統合する。重要なのは、観測と許容される行動の一覧をともに与える従来の RL 設定（問題を行動選択へ単純化する）とは異なり、本研究のエージェントは行動のヒントなしに、環境観測だけから実行可能な自然言語コマンドを生成しなければならない点であり、これは探索によって有効な行動を発見する能力を検証する。タスクと環境の詳細は [付録 B](#appendix-b) に示す。

- **TextWorld**：エージェントが部屋を移動し、オブジェクトを操作し、自然言語によってクエストを解くテキストアドベンチャーゲーム環境である。world size（w）、オブジェクト数（o）、クエスト長（q）という三つの次元で複雑度を制御し、タスクを手続き的に生成する。たとえば「w2-o3-q4」は、2 部屋、3 オブジェクト、4 ステップのクエストを表す。多様性を確保するため、各タスクには一意のシードを用いる。
- **ALFWorld**：テキスト対話を通じて多段階タスクを完了する必要がある、身体性を備えた家庭内環境である。六つのタスクカテゴリにわたるテキストのみの変種を用い、「train」split で訓練し、「valid_unseen」split で評価する。
- **SWE-Gym**：バグ修正や機能実装を含む実世界のプログラミングタスクである。代表的な 5 種類のタスク、getmoto、pydantic、mypy、pandas、iterative_dvc に着目し、訓練用 90 インスタンスと評価用 25 インスタンスをランダムにサンプリングする。

**訓練と評価。** ベースモデルには Qwen2.5-1.5B-Instruct、Qwen2.5-7B-Instruct、Qwen3-8B（略称は Qwen-1.5B、Qwen-7B、Qwen-8B）を用い、PPO [Sch17a]、GRPO [Sha24d]、RLOO [Ahm24] アルゴリズムで訓練する。最大反復ステップ数とトークン上限はタスク複雑度に応じてスケールさせる。ロールアウト生成中は、探索と活用のバランスを取るため温度 0.7 を用いる。保留したテストセットでエージェントを評価し、タスク成功率、すなわち探索予算内でエージェントが目的を達成したエピソードの割合を主要指標として報告する。SWE-Gym については、テストスイート通過率を報告する。訓練の全詳細とハイパーパラメータ調整の分析は付録 [C](#appendix-c) および [A](#appendix-a) に示す。

## 5 環境

環境は、エージェントが克服すべき課題を根本的に決定する。シングルターンのタスクが主に推論の難しさを測るのに対し、マルチターン環境には空間移動、オブジェクト操作、長い計画ホライズンといった次元が加わる。マルチターンを実用展開するうえで中心となる三つの研究課題を調べる。（1）*環境複雑度はマルチターン RL の訓練効率にどう影響するか。* これは、複雑度の異なる環境タスクに必要な探索予算とモデルサイズを決める。（2）*単純な環境で訓練したエージェントは、複雑な環境へ汎化できるか。* これは、エージェントシステムをスケールアップする際の主要な考慮事項を扱う。（3）*タスクの多様性は訓練と汎化にどう影響するか。* TextWorld で機能する本研究のマルチターン RL レシピが ALFWorld と SWE-Gym にも汎化することを示すだけでなく、エージェントが汎化可能なスキルを学ぶのか、それともタスク固有の挙動を記憶するのかも明らかにする。本実験は、マルチターン RL によって、環境や多様なタスクをまたぐ効果的な知識転移が可能になることを示す。

**設定。** 環境複雑度とタスク多様性を変化させるため、二つの実験条件を設計する。**環境複雑度**については、基本設定 w2-o3-q4 から、w8-o3-q4（空間複雑度を増加）、w2-o12-q4（オブジェクト複雑度を増加）、w8-o12-q4（両次元を増加）、w4-o6-q8（全次元を比例してスケーリング）という制御された変種を作る。SWE-Gym では複雑度の要因を切り分けるため、getmoto タスクのサブセットに着目し、（1）*解の複雑度*（正解パッチのコード行数）と（2）*検証の複雑度*（テストスイートのサイズ）という二つの異なる指標に基づいてタスクを Easy、Medium、Hard に分類する。**タスク多様性**については、訓練用に異質性を段階的に高めた混合データを構築する。ALFWorld では、単一タイプ（pick & place のみ）、4 タイプ（heat、cool、cook、examine）、全 6 タイプ（pick two & place を追加）を検証する。SWE-Gym では、単一タイプ（getmoto のみ）と全 5 タイプ（getmoto、pydantic、mypy、pandas、iterative_dvc）を比較する。公平に比較できるよう、すべての混合データのサイズを同じにし、単一タイプと混合タイプの両方の保留テストセットで評価する。Qwen-1.5B、Qwen-7B、Qwen-8B の各モデルを、一貫したハイパーパラメータの下で PPO と GRPO を用いて訓練する。タスク仕様と訓練の全詳細は付録 [B.1](#appendix-b-1) および [C.1](#appendix-c-1) に示す。

### 5.1 マルチターン RL の性能は環境複雑度に応じてどうスケールするか

[表 1](#table-01) は、空間とオブジェクトの両次元をスケールさせると性能が 17% からわずか 3% に低下し、環境複雑度の増加に伴ってベースモデルが著しく苦戦することを示している。重要なことに、**マルチターン RL による性能向上は、複雑度が増すほど小さくなる**。PPO は基本環境で 88% の向上を達成するが、最も複雑な設定では 51% に低下する。とりわけ、**オブジェクト複雑度は空間複雑度よりも難しいことが分かった**。これは、状況に根差したテキスト領域では、ターンをまたいで複数のオブジェクトを操作し追跡することが、空間探索よりも根本的に難しい課題であることを示唆する。コーディング領域でも同様の傾向が見られる（[表 2](#table-02)）。より長いコード解が必要になるか、より厳格なテストスイートを通過する必要が生じるにつれて、ベースモデルの性能は低下する。しかし、Multi-turn GRPO はすべての難易度で一貫して性能を回復しており、本研究の指標が真の複雑度を捉えていることを裏付ける。

**性能はモデルサイズに応じてもスケールする**。[表 3](#table-03) に示すように、7B モデルは w4-o6-q8 で成功率 72% に達し、より大きなモデルほど複雑な環境で拡大した状態空間をうまく扱えることが分かる。注目すべきことに、1.5B モデルでさえ強い学習可能性を示し、w2-o3-q4 と w4-o6-q8 でそれぞれ 65% と 58% の向上を達成する。

### 5.2 マルチターン RL は複雑度の異なる環境へどう汎化するか

マルチターン RL が転移可能なスキルを学習するかを調べるため、環境間汎化を評価する。w2-o3-q4、w8-o3-q4、w2-o12-q4 でそれぞれ単一タスクモデルを訓練するとともに、w2-o12-q4 と w8-o3-q4 を同じ比率で含む複雑度混合モデルを訓練し、すべての条件で RL データ総量を一定に保つ。[表 5](#table-05) は、**単純な環境で訓練したエージェントが、より複雑な環境へ大幅に汎化する**ことを示しており、w2-o3-q4 で訓練したモデルは、より複雑なすべての環境で性能を向上させる。w8-o3-q4（空間複雑度を増加）からの転移はとりわけ強く、転移先全体で平均向上幅が最大になり、特に w8-o12-q4 では 48% 向上して、w8-o12-q4 だけで訓練した場合の 48% の向上と並ぶ。これらの結果は、マルチターン RL が空間探索やオブジェクト操作といった再利用可能なスキルを獲得し、複雑度の段階をまたいで転移できることを示す。

### 5.3 マルチターン RL は同一領域内の異なる種類のタスクへどう汎化するか

[第 5.1 節](#section-5-1) と [第 5.2 節](#section-5-2) では、単一のタスクタイプ内で環境複雑度を変化させたとき、エージェントがどう対処するかを検討した。ここでは、より広い問い、すなわち「本研究のマルチターン RL レシピは、ALFWorld のような複雑で状況に根差した環境や、SWE-Gym のような実世界のシナリオで機能するか」を扱う。さらに、「タスクのサブセットで訓練したエージェントは、タスク分布全体へ汎化できるか」を問う。多様なタスクタイプでの訓練が、二つの領域における汎化へどう影響するかを調べる。ALFWorld では、タスクごとに異なる物理的スキルが必要であり、cleaning ではオブジェクトを見つけて配置する一方、heating では所定の順序で機器を操作する必要がある。SWE-gym のタスクは、pydantic の問題修正から pandas の問題解決まで、多様なソフトウェアエンジニアリング上の課題にまたがる。

[表 7](#table-07) と [表 8](#table-08) は、**マルチターン RL が、難度の高い ALFworld および SWE-Gym 環境へうまく適用できる**ことを示している。注目すべきことに、**単一のタスクタイプで訓練したエージェントは、未見のタスクタイプへ十分な汎化を達成する**。単一タイプだけの訓練でも、全タスクタイプにわたって 12%（ALFWorld）と 7%（SWE-Gym）の向上が得られる。これは、限られたタスクしか経験しなくても、マルチターン RL が転移可能なスキルを学習することを示している。意外にも、マルチタスク訓練は一見無関係なタスクにも有益であり、clean、heat、cool、cook の混合データで訓練したエージェントは、単一の pick & place に特化したモデルを、その単一タスク自体で 19%、全タイプ評価で 21% 上回る。この結果は、**マルチターン RL が多様な目的をまたいで転移する汎化可能なスキルを獲得する**ことを示す。

## 6 方策

RL 最適化アルゴリズムとモデル初期化の選択は、マルチターン RL の性能を決定的に左右する。まず、デモンストレーションデータの役割を検討する。実際には、教師ありファインチューニング（SFT）に用いる人間のデモンストレーションデータへのアクセスは限られている可能性がある。そこで、（1）*どのようなモデルの事前方策が、効果的なマルチターン RL を可能にするか。* これは、エージェントがスクラッチから効果的に学習できるなら、高価な人間のデモンストレーションが必要かどうかを扱う。（2）*データ予算が固定されている場合、SFT データと RL データの最適比率はどれだけか。* これは、デモンストレーションの収集とオンライン学習の間で、限られたリソースを最適に配分する方法を決める。次に、*RL 最適化の選択がマルチターン RL 訓練へ大きく影響するか*を調べる。ヒューリスティックな方策勾配法（PPO [Sch17a]、GRPO [Sha24d]、Reinforce++ [Hu25d]）と不偏な手法（RLOO [Ahm24]）を比較し、特定の最適化ヒューリスティクスによる寄与と本研究のマルチターン定式化による寄与を切り分ける。これは、ヒューリスティクスに依存する結果の落とし穴を示した最近の研究 [Oer25] のように、アルゴリズム上の向上を厳密に主張するうえで不可欠である。

**設定。** TextWorld は手続き的に生成した各ゲームの正解を提供するため、それを人間によるマルチターン軌跡に相当する SFT のデモンストレーションデータとして用いる。SFT データは、ほとんどの命令追従シナリオで使われるデフォルトテンプレートである、ターンベースのチャット形式に従う。データ漏洩を防ぐため、SFT データは RL データとは異なるランダムシードで生成する。Qwen-1.5B、Qwen-7B、Qwen-8B の各モデルを、実験間で一貫したハイパーパラメータの下、PPO、GRPO、Reinforce++、RLOO を用いて訓練する。タスク仕様と訓練の全詳細は付録 [B.2](#appendix-b-2) および [C.2](#appendix-c-2) に示す。

**Multi-turn PPO の定式化。** Proximal Policy Optimization（PPO）[Sch17a] など、アドバンテージ推定を伴う最適化アルゴリズムには、トークン単位の信用割当を採用する。トークン単位の価値を計算し、TD 誤差に適用して $\delta_{t}^{i}=r_{t}^{i}+\gamma V(h_{t}^{i+1})-V(h_{t}^{i})$ とする。ここで、$h_{t}^{i}$ はトークン $a_{t}^{i}$ までを含む履歴である。続いて GAE を用い、各トークンのアドバンテージを $\hat{A}_{t}^{i}=\sum_{l=0}^{L-i}(\gamma\lambda)^{l}\delta_{t}^{i+l}$ と推定する。ここで、$L$ はホライズン（エピソードが終了するまでのトークン数）である。報酬を受け取るのは `<eos>` トークンだけだが、価値ブートストラップにより、それ以前のすべてのトークンはゼロでないアドバンテージを得る。したがって、軌跡内の全トークンに対する Clipped Surrogate Objective は次のように書ける。

$$
L^{\mathrm{CLIP}}(\theta)=\mathbb{E}_{\tau\sim\pi_{\theta}}\left[\sum_{t=0}^{T}\sum_{i=1}^{n_{t}+1}\min\left(r_{t}^{i}(\theta)\hat{A}_{t}^{i},\mathrm{clip}(r_{t}^{i}(\theta),1-\epsilon,1+\epsilon)\hat{A}_{t}^{i}\right)\right]
$$

ここで、各トークンの確率比は $r_{t}^{i}(\theta)=\dfrac{\pi_{\theta}(a_{t}^{i}|h_{t},a_{t}^{<i})}{\pi_{\theta_{old}}(a_{t}^{i}|h_{t},a_{t}^{<i})}$ である。

### 6.1 モデルの事前方策はマルチターン RL 訓練へどう影響するか

事前方策の確立（SFT による）と、継続学習を通じたその洗練（マルチターン・オンライン RL による）を区別する。この二段階手法は、エージェントがオンライン学習の前にデモンストレーションから学ぶ実世界での展開を反映している。**強力な SFT 事前方策は、RL の効率を劇的に高めることが分かった。** TextWorld の w2-o3-q4 タスクの正解で訓練すると、大規模な RL 訓練の性能を、わずかなデータで達成できる。[表 9](#table-09) に示すように、わずか 60 件のデモンストレーションで初期化し、400 件の RL episode で洗練したモデルは成功率 85% を達成し、5000 episode を要する純粋な RL 訓練の 88% にほぼ匹敵する。

最適なリソース配分を決めるため、SFT データには RL episode の 10$\times$ のコストがかかると仮定し、人間によるアノテーションの労力がより大きいことを反映して、1000 コスト単位に固定した予算の下で性能を分析する。**純粋な SFT は既知のタスクで優れる一方、堅牢性には RL が不可欠であることが分かった。** 予算の全額を SFT（100 件のデモンストレーション）に用いると、ドメイン内性能は非常に高い（w2-o3-q4 タスクで 95%）が、より難しいタスクへの汎化は低い（w4-o6-q8 タスクで 55%）。最良点は、60 件のデモンストレーションに続いて 400 件の RL episode を用いるハイブリッド構成と考えられる。この構成は、SFT による挙動の基礎付けと RL の適応性を両立し、ドメイン内で 85% の成功率を維持しながら、複雑な w4-o6-q8 タスクへの汎化を 59% まで高める。

### 6.2 RL アルゴリズムはマルチターン RL 訓練へどう影響するか

性能向上が本研究のマルチターン定式化に由来するのか、特定のアルゴリズム選択に由来するのかを把握することは、本手法の汎化可能性を確立するうえで重要である。PPO（価値関数ブートストラップを用いるヒューリスティックな方策勾配法）と RLOO（不偏な方策勾配推定量）、さらに Reinforce++ や GRPO のような最近の変種を比較し、本研究のトークン単位の信用割当による寄与と、アルゴリズム設計上の判断による寄与を切り分ける [Oer25]。

**PPO と RLOO はどちらもベースモデルを上回り、性能向上が PPO 固有のヒューリスティクスではなく、マルチターン定式化に由来することを示す。** [表 10](#table-10) は、w2-o3-q4 で PPO が成功率 88%、RLOO が 51% を達成することを示している。対照的に、Reinforce++ と GRPO がベースモデルにもたらす向上は無視できるほど小さい。より難しい w4-o6-q8 タスクではこの差が広がり、PPO は成功率 59% を維持する一方、1.5B モデルでは RLOO、Reinforce++、GRPO のすべてが崩壊する。

**モデルをスケールすると単純なタスクでの差は縮まり**、複雑な推論では PPO が依然として最良のアルゴリズムとなる。7B パラメータでは、PPO と RLOO はいずれも単純な w2-o3-q4 タスクで収束する（$\approx$ 98%）が、Reinforce++ と GRPO は依然として遅れを取る（それぞれ 72% と 79%）。より難しい w4-o6-q8 タスクでは、PPO が成功率 72% で優位に立ち、RLOO の 47%、GRPO の 36% を上回る。これらの結果は、タスクをまたいで RLOO が一貫して向上していることから、性能向上が PPO のヒューリスティクスによるものではないと確認する一方、**この領域では PPO が Reinforce++ および GRPO よりもはるかにサンプル効率が高く、堅牢である**ことも明らかにしている。

## 7 報酬

マルチターン環境では通常、タスク完了時に疎なフィードバックが与えられるため、長い系列にわたって課題が生じ、収束の遅延や訓練の不安定化につながり得る。しかし環境によっては、解に至る途中のマイルストーンで部分報酬を与える、密な報酬シグナルを利用できる。軌跡中のフィードバックシグナルの頻度である報酬密度が、マルチターン RL の性能と学習効率へどう影響するかを調べる。

**設定。** テキストベースのゲームである TextWorld とソフトウェアエンジニアリング環境である SWE-Gym という二つの異なる領域で、報酬設計の影響を調べる。**TextWorld** については、組み込み関数を用いて報酬密度を操作し、**疎な報酬**（タスク完了時のみ）と**密な報酬**（中間ステップ）を比較する。*tw-simple* タスク [+2] で、PPO と RLOO を用い、3,000 episode にわたって評価する。**SWE-Gym** については、報酬の*情報源*と*粒度*をさらに複雑に評価する。正解に基づく実行から得られる**検証済み報酬**（二値のタスク完了と細粒度の単体テスト比率の両方）と、judge が合成する**モデルベース報酬**（CodeRM-8B [Ma25e] と GPT-4.1）を比較する。コーディングタスクはホライズンが長いため、安定性を確保するために GRPO を用いる。両環境と報酬設定の全仕様は付録 [B.3](#appendix-b-3) および [C.3](#appendix-c-3) に詳述する。

### 7.1 マルチターン RL 訓練にはどのような報酬シグナルが必要か

**密な報酬はマルチターン RL の性能を大きく高めるが、最適な密度はアルゴリズムによって異なる。** [表 11](#table-11) に示すように、PPO はより頻繁なフィードバックから恩恵を受け、成功率は疎な報酬での 41% から、最も密なシグナル（Dense 2）での 58% へ上昇する。対照的に RLOO は、二つの密な設定で安定した性能（55%）を維持しており、<strong>不偏な勾配推定は報酬密度に左右されにくいことを示唆する。</strong>

ここで重要なのは、報酬密度を最適化戦略に合わせて調整すべきだという点である。密なシグナルは収束を加速できるが、その有用性はシグナルの品質に左右される。中間報酬の設計が不適切であれば、エージェントを誤った方向へ導くノイズが混入するおそれがある。

<span id="section-7-2"></span>

### 7.2 複雑なタスクにおける検証済み報酬とモデルベース報酬

TextWorld は報酬密度を分析するための制御された設定を提供するが、ソフトウェアエンジニアリングのような実世界の応用では、複雑で長いホライズンの推論を伴うことが多く、報酬密度の定義はさらに難しい。これに対処するため、SWE-Gym を用いて分析をコーディング領域へ拡張する。二つの重要な問い、すなわち（1）*検証済みフィードバックの粒度は重要か。*（2）*モデルベースの judge は検証器の代わりになり得るか。*を調べる。

**細粒度の検証器報酬の必要性。** まず、実行ベースのフィードバックについて二つの実装を比較する。疎な*二値の検証済み報酬*（テストスイート全体を通過した場合にのみエージェントが +1 を受け取る）と、密な*比率ベースの検証済み報酬*（通過した単体テストの割合に比例する）である。[表 12](#table-12) に示すように、**より複雑なタスクには、細粒度の検証器報酬が不可欠である。** 疎な二値報酬では、エージェントの成功率はわずか 4.2% であり、ベースモデルの 4% からほとんど向上しない。しかし、密な比率ベースのフィードバックを与えると、性能は 22% まで上昇する。これは、ソフトウェアエンジニアリングのような複雑な領域では、最終テストスイートによる「すべてか無か」のシグナルは疎すぎて方策を導けない一方、個々の単体テストの通過に対する細粒度の報酬が、学習に必要な勾配を与えることを裏付ける。

**検証器とモデルベースの judge。** モデルベース報酬が検証器の有効な代替となり得るかも検討する。コード生成が可能な二つのモデルベース judge、CodeRM-8B [Ma25e] と GPT-4.1 を用い、合成テストスイートを生成してエージェントのコード生成の進捗を評価する。モデルベース報酬はベースモデルよりいくらか改善するものの、検証済み報酬を大きく下回る。[表 12](#table-12) に示すように、CodeRM-8B と GPT-4.1 によって形成した報酬で得られる成功率は、それぞれ 7.2% と 9.3% である。これらのモデルベース judge はある程度有用なシグナルを与えるものの、検証済み比率報酬（22%）には大差で及ばない。したがって実務家にとって、**最も堅牢なレシピは、モデルベースの代理指標ではなく、実行ベースの単体テストに依拠することである。**

![表 12。異なる報酬シグナルを用いた SWE-Gym タスクにおける GRPO の性能。ベースモデルに対して、検証済み報酬（二値と比率）およびモデルベース報酬（CodeRM-8B と GPT-4.1）を比較する。](../../papers/multi-turn-agentic-rl/table-12.png)

## 8 レシピと結論

環境、方策、報酬という柱を体系的に調査した結果、TextWorld、ALFWorld、SWE-Gym で検証された、マルチターン・エージェント RL の実践的なレシピが得られた。

**環境：** *カリキュラムが重要である。* より単純な環境、または検証複雑度の低いタスクから訓練を始める。エージェントは、より容易な設定で再利用可能なスキル（状態追跡など）を身に付け、それが複雑でオブジェクト数の多いタスクや長いホライズンのタスクへ効果的に汎化することが分かった。

**方策：** *安定性と事前方策を優先する。* バイアスがあり安定化されたアルゴリズム（PPO、GRPO）は、マルチターン設定において、不偏推定量（RLOO）と素朴な勾配法（Reinforce++）を大幅に上回る。さらに、強力な SFT 事前方策で初期化すると RL のサンプル複雑度が劇的に低下し、純粋な RL よりも効率よく収束できる。

**報酬：** *近似よりも粒度が重要である。* 複雑な推論には密な報酬が不可欠である。しかし本研究の結果は、**検証済みの実行フィードバック**（単体テスト通過率など）がモデルベースの代替物よりはるかに優れていることを示す。実務家は報酬モデルの訓練よりも、細粒度で実行ベースのシグナルを設計することを優先すべきである。

**カリキュラム + 安定化された方策 + 検証済みの密な報酬**というレシピを体系的に特定することで、長期にわたって実世界と対話できる真に自律的なエージェントを開発するための実証的基盤と実践的指針を提供する。

## 付録 C 訓練と評価の詳細

Qwen-1.5B、Qwen-7B、Qwen-8B を 8 基の NVIDIA H100 GPU で訓練する。

PPO ではデフォルトで、actor learning rate 5e-7、critic learning rate 5e-6、clip ratio 0.2、discount factor $\gamma$ 1.0、KL penalty coefficient 0.001、batch size 256 を用い、Qwen-1.5B と Qwen-7B の両モデルで entropy regularization を 0 とする。

GRPO ではデフォルトで、Qwen3-8B モデルに actor learning rate 1e-6、KL loss coefficient 0.001、GRPO sampling number 4、batch size 16 を用いる。

RLOO ではデフォルトで、Qwen-1.5B と Qwen-7B の両モデルに actor learning rate 1e-6、KL penalty coefficient 0.001、batch size 256 を用いる。

SFT ではデフォルトで、learning rate 1e-6 を用いる。

### C.1 [第 5 節](#section-5)の訓練に関する追加詳細

TextWorld の実験では 150 epoch 訓練し、epoch 150 の時点で保留した 100 件のテストセット（seed 1 から 100）を用いて評価する。

ALFWorld の実験では、ベースモデルのタスク精度が 0 であるため、RL データとは異なる seed を持つ 300 件のデータで SFT を 1 epoch 行う。SFT による初期化後、90 epoch 訓練し、epoch 90 の時点で保留した 100 件のテストセットを用いて評価する。

SWE-Gym の実験では 15 epoch 訓練し、epoch 15 の時点で保留した 25 件のテストセットを用いて評価する。

<span id="appendix-c-2"></span>

### C.2 [第 6 節](#section-6)の訓練に関する追加詳細

SFT はちょうど 1 epoch だけ実行し、過学習を避けるためデモンストレーションデータを 1 回だけ通過するようにする。その SFT に重ねて、さらに 100 epoch の RL 訓練を行う。

RLOO と PPO の比較では、付録 C.1 と同様に、それぞれ 150 epoch 訓練する。

<span id="appendix-c-3"></span>

### C.3 [第 7 節](#section-7)の訓練に関する追加詳細

密な報酬を用いる PPO と RLOO の訓練では、それぞれ 150 epoch 訓練し、epoch 150 の時点で保留した 100 件のデータを用いてテストする。

## 付録 E LLM の使用

本原稿の作成では、文章の推敲と文法確認だけに大規模言語モデル（具体的には Claude）を使用した。LLM は、明瞭さの改善、文法誤りの修正、文章の簡潔さの向上に使用した。実験設計、分析、解釈、科学的結論はすべて、著者自身による独自の成果である。実験結果の生成、図表の作成、技術的内容の生成には LLM を一切使用していない。本論文で提示する中核的な研究上の着想、方法論、知見は、人間の著者による成果である。
