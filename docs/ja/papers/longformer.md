## 概要

Transformer ベースのモデルは、系列長に対して二次でスケールする自己注意演算のため、長い系列を処理できない。この制約に対処するため、系列長に対して線形にスケールする注意機構を備え、数千トークン以上の文書を容易に処理できる Longformer を導入する。Longformer の注意機構は標準的な自己注意をそのまま置き換えられ、局所的なウィンドウ注意と、タスクに基づくグローバル注意を組み合わせる。長系列 Transformer に関する先行研究にならい、Longformer を文字レベル言語モデリングで評価し、`text8` と `enwik8` で最先端の結果を達成する。大半の先行研究とは異なり、Longformer を事前学習し、さまざまな下流タスクでファインチューニングする。事前学習済み Longformer は、長文書タスクで一貫して RoBERTa を上回り、WikiHop と TriviaQA で新たな最先端の結果を達成する。最後に、長文書を対象とする生成型 sequence-to-sequence タスクに対応した Longformer の変種、Longformer-Encoder-Decoder（LED）を導入し、arXiv 要約データセットでその有効性を示す。 [+1]

## 1 はじめに

Transformer [Vas17] は、生成言語モデリング [Dai19, Rad19] や識別的言語理解 [Dev18] を含む、幅広い自然言語タスクで最先端の結果を達成している。この成功の一因は、ネットワークが系列全体から文脈情報を捉えられるようにする自己注意コンポーネントにある。自己注意は強力だが、そのメモリ要件と計算要件は系列長に対して二次で増加するため、長い系列の処理は不可能、または非常に高コストになる。

<span id="figure-01"></span>

![Longformer の注意機構実装における実行時間とメモリの比較](../../papers/longformer/figure-01.png)

**図 1。** 完全自己注意と、Longformer の自己注意に対する各種実装の実行時間およびメモリ。`Longformer-loop` は非ベクトル化実装、`Longformer-chunk` はベクトル化実装、`Longformer-cuda` はカスタム CUDA カーネル実装である。長い系列では現在の GPU 上で完全自己注意機構がメモリ不足になるのに対し、Longformer のメモリ使用量は系列長に対して線形にスケールする。実装によって速度は異なり、ベクトル化された `Longformer-chunk` が最速である。詳細は [第 3.2 節](#section-3-2)を参照されたい。

この制約に対処するため、系列長に対して線形にスケールする自己注意演算を備え、長文書の処理に広く利用できる改変 Transformer アーキテクチャ、Longformer を提示する（[図 1](#figure-01)）。これは、長文書分類、質問応答（QA）、共参照解析などの自然言語タスクに有利である。従来の手法では、BERT 系事前学習済みモデルの典型的な 512 トークン制限に収まるよう、長い文脈を小さな系列に分割または短縮している。このような分割では、分割間の重要な情報が失われる可能性があり、既存手法はこの問題を緩和するため、そうした相互作用を扱う複雑なアーキテクチャに依存することが多い。一方、提案する Longformer は複数層の注意を用いて文脈全体の文脈表現を構築できるため、タスク固有アーキテクチャの必要性が低下する。

近年の研究では、長い系列に対する Transformer の計算効率の低さが扱われている（[表 1](#table-01)を参照）。しかし、それらは主に自己回帰言語モデリング（LM）に焦点を当てており、転移学習の設定 [Dai15, Pet18, How18, Dev18] で長文書 Transformer を文書レベル NLP タスクへ適用する試みは、ほとんど検討されていない。本研究はこの空白を埋め、Longformer の注意機構が事前学習済み Transformer の自己注意機構をそのまま置き換えられ、一連の文書 NLP タスクで性能向上をもたらすことを示す。

Longformer の注意機構は、ウィンドウ化された局所文脈の自己注意と、タスクに関する帰納バイアスを符号化する最終タスクに基づくグローバル注意を組み合わせたものである。アブレーションと対照実験を通じて、両方の注意が不可欠であることを示す。局所注意は主として文脈表現の構築に用いられ、グローバル注意は Longformer が予測用の系列全体の表現を構築できるようにする。

まず、ウィンドウ注意と新たな拡張注意パターンを組み合わせた自己回帰文字レベル言語モデリングで Longformer を評価し、現代の GPU 上で最大 32K 文字の系列を処理できるようにする。`text8` と `enwik8` のベンチマークデータセットで最先端の結果を達成し、長文書モデリングにおける Longformer の有効性を示す。

次に、既存の事前学習済みモデルの完全自己注意演算を Longformer が置き換えられるか評価するため、公開された RoBERTa [Liu19a] チェックポイントから継続し、マスク言語モデリング（MLM）目的で事前学習する。事前学習後、ファインチューニングを通じて下流の言語タスクに適用し、Longformer がテキスト分類、QA、共参照解析を含む幅広い文書レベル自然言語タスクで一貫して RoBERTa を上回り、そのうち 2 つのデータセットで最先端の結果を達成することを示す。

最後に、エンコーダのみの Transformer アーキテクチャではなく、元の Transformer モデル [Vas17] と同様のエンコーダ・デコーダアーキテクチャに従い、sequence-to-sequence（seq2seq）学習 [Sut14] を目的とする Longformer の変種を導入する。このモデルを Longformer-Encoder-Decoder（LED）と呼ぶ。LED はエンコーダネットワークに Longformer の効率的な注意パターンを用いるため、要約などの長文書 seq2seq タスクを扱える。arXiv 要約データセット [Coh18] で LED の有効性を示す。

## 2 関連研究

**長文書 Transformer。** [表 1](#table-01)に長文書に関する近年の先行研究をまとめる。自己注意については 2 種類の手法が検討されている。第 1 は、文書をチャンク単位で左から右へ処理する left-to-right（ltr）手法である。この種のモデルは自己回帰言語モデリングで成功しているが、双方向の文脈が有益なタスクを対象とする転移学習手法には適さない。

本研究は、何らかの疎な注意パターンを定義し、完全な二次の注意行列積の計算を避ける、もう一方の一般的な手法に属する。本研究に最も近い注意パターンを持つモデルは Sparse Transformer [Chi19] であり、BlockSparse [Gra17] が提供するサイズ 8x8 のブロックに対し、拡張スライディングウィンドウの一種を用いる。本研究の実装（[第 3 節](#section-3)）にもカスタム CUDA カーネルが含まれるが、C++ で実装され特定バージョンの TensorFlow 向けに設計された BlockSparse より、柔軟で保守しやすい。また、一般的な NLP タスクに適した、タスクに基づく追加のグローバル注意パターン（[第 3 節](#section-3)）を導入し、転移学習の設定で良好な性能を得るために不可欠であることを示す。

いくつかのモデルは自己回帰言語モデリング以外のタスクを試している。言語モデリングを主要な評価対象に据えることが、適用範囲の限られたモデルの開発につながってきたとも考えられるため、これは前進である。BP-Transformer [Ye19] は機械翻訳（MT）で評価されたが、事前学習・ファインチューニング設定を検討していない。Blockwise attention [Qiu19] はモデルを事前学習し、質問応答（QA）で評価した。しかし、評価に言語モデリングが含まれず、QA データセットの文書も比較的短いため、 [+2] 長文書タスクにおけるこのモデルの有効性は未検討のままである。

**長文書向けタスク固有モデル。** BERT のような事前学習済み Transformer モデルの 512 トークン制限を回避するため、多くのタスク固有手法が開発されてきた。最も単純な手法は文書を切り捨てるだけで、分類で広く用いられる [Xie19]。別の手法では、文書を長さ 512 のチャンク（重複してもよい）に分け、各チャンクを個別に処理してから、タスク固有モデルで活性化を統合する [Jos19]。マルチホップ QA やオープンドメイン QA で一般的な第 3 の手法は 2 段階モデルであり、第 1 段階で関連文書を検索し、それを第 2 段階に渡して回答を抽出する [Cla17, Che17]。これらの手法はいずれも、切り捨てによる情報損失、または 2 段階手法の連鎖的な誤りという問題を抱える。これに対し、Longformer は切り捨てやチャンク分割を行わずに長い系列を処理できるため、利用可能な文脈を連結し、1 回のパスで処理する、はるかに単純な手法を採用できる。

同時期のいくつかの研究 [+3] は、Transformer で局所注意とグローバル注意を用い、長文書自然言語タスク向けに事前学習するという、Longformer に似た考え方を検討している。特に ETC [Ain20] は、完全自己注意の代わりに同様の局所・グローバル注意を用い、Transformer を長文書にスケールさせる。Longformer とは異なり、ETC は相対位置埋め込み（本研究では自己回帰 LM の設定でのみ使用）を用い、事前学習に追加の学習目的（CPC loss）を導入し、グローバル注意をわずかに異なる方法で構成する。読解や分類を含む複数のタスクで高い性能を示している。GMAT [Gup20] は、入力内の少数のグローバル位置をグローバルメモリとして機能させる、同様の考え方を用いる。BigBird [Zah20] は ETC を拡張し、要約を含む追加タスクで評価したものである。重要な点として、BigBird は理論解析を通じ、疎な Transformer が系列関数の万能近似器であり、完全自己注意のこれらの性質を保持することを示している。

## 3 Longformer

元の Transformer モデルは、入力系列長を $n$ とすると、時間計算量とメモリ計算量が $O(n^{2})$ の自己注意コンポーネントを持つ。この課題に対処するため、互いに注意を向ける入力位置の組を指定する「注意パターン」に従って、完全自己注意行列を疎化する。完全自己注意とは異なり、提案する注意パターンは入力系列に対して線形にスケールするため、長い系列を効率よく処理できる。本節では、この注意パターンの設計と実装について論じる。

<span id="section-3-1"></span>

### 3.1 注意パターン

**スライディングウィンドウ。** 局所文脈の重要性 [Kov19] を踏まえ、本研究の注意パターンは各トークンの周囲に固定サイズのウィンドウ注意を適用する。このようなウィンドウ注意を複数層積み重ねると、大きな受容野が得られる。CNN [Wu19] と同様に、上位層はすべての入力位置にアクセスでき、入力全体の情報を組み込んだ表現を構築する能力を持つ。固定ウィンドウサイズを $w$ とすると、各トークンは両側の $\frac{1}{2}w$ 個のトークンに注意を向ける（[図 2(b)](#figure-02)）。このパターンの計算量は $O(n\times w)$ であり、入力系列長 $n$ に対して線形にスケールする。$\ell$ 層の Transformer では、最上位層の受容野サイズは $\ell\times w$ である（すべての層で $w$ が固定と仮定）。用途によっては、効率とモデルの表現能力のバランスを取るため、層ごとに異なる $w$ の値を用いるとよい（[第 4.1 節](#section-4-1)）。

**拡張スライディングウィンドウ。** 計算量を増やさずに受容野をさらに広げるため、スライディングウィンドウを「拡張」できる。これは拡張 CNN [Oor16] に似ており、ウィンドウ内に dilation $d$ の大きさの間隔を設ける（[図 2(c)](#figure-02)）。すべての層で $d$ と $w$ が固定されると仮定すると、受容野は $\ell\times d\times w$ となり、$d$ が小さくても数万トークンに達し得る。

マルチヘッド注意では、各注意ヘッドが異なる注意スコアを計算する。ヘッドごとに異なる dilation 構成を用いる設定では、dilation のないヘッドが局所文脈に集中し、dilation のあるヘッドがより長い文脈に集中できるため、性能が向上することが分かった。

**グローバル注意。** 自然言語タスク向けの最先端 BERT 系モデルでは、最適な入力表現は言語モデリングとは異なり、タスクによっても変化する。マスク言語モデリング（MLM）では、モデルは局所文脈を用いてマスクされた単語を予測する一方、分類では、系列全体の表現を特殊トークン（BERT では `[CLS]`）に集約する。QA では質問と文書を連結し、自己注意を通じてモデルが質問と文書を比較できるようにする。

本研究の場合、ウィンドウ注意と拡張注意だけでは、タスク固有表現を学習するのに十分な柔軟性がない。そこで、事前に選択した少数の入力位置に「グローバル注意」を追加する。重要なのは、この注意演算を対称にすることである。すなわち、グローバル注意を持つトークンは系列全体のすべてのトークンに注意を向け、系列内のすべてのトークンもそのトークンに注意を向ける。[図 2(d)](#figure-02)は、任意の位置にある少数のトークンにグローバル注意を付与したスライディングウィンドウ注意の例を示す。たとえば分類では `[CLS]` トークンにグローバル注意を用い、QA ではすべての質問トークンにグローバル注意を付与する。このようなトークンの数は系列長に比べて少なく、$n$ に依存しないため、局所注意とグローバル注意を組み合わせた計算量も $O(n)$ のままである。グローバル注意の指定はタスク固有だが、モデルの注意に帰納バイアスを加える容易な方法であり、小さな入力チャンク間の情報を複雑なアーキテクチャで統合する既存のタスク固有手法よりもはるかに単純である。

**グローバル注意の線形射影。** 線形射影 $Q$、$K$、$V$ が与えられると、Transformer モデル [Vas17] は次のように注意スコアを計算する。

<span id="equation-01"></span>

$$
\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\left(\frac{Q{}K^\top}{\sqrt{d_{k}}}\right)V
$$

スライディングウィンドウ注意の注意スコアを計算する射影 $Q_{s}$、$K_{s}$、$V_{s}$ と、グローバル注意の注意スコアを計算する射影 $Q_{g}$、$K_{g}$、$V_{g}$ の 2 組を用いる。追加の射影によって、異なる種類の注意をモデル化する柔軟性が得られ、下流タスクで最高性能を得るうえで不可欠であることを示す。$Q_{g}$、$K_{g}$、$V_{g}$ はいずれも、$Q_{s}$、$K_{s}$、$V_{s}$ と一致する値で初期化される。

<span id="section-3-2"></span>

### 3.2 実装

通常の Transformer では、注意スコアは [式 1](#equation-01)のように計算される。$Q$ と $K$ はともに $n$ 個（系列長）の射影を持つため、行列積 $Q{}K^\top$ の計算が高コストである。Longformer の拡張スライディングウィンドウ注意は、$Q{}K^\top$ の対角線のうち固定数だけを計算する。[図 1](#figure-01)に示すように、完全自己注意のメモリ使用量が二次で増加するのに対し、この方法では線形に増加する。ただし、その実装には、PyTorch や TensorFlow など既存の深層学習ライブラリがサポートしていない帯行列積の一種が必要になる。[図 1](#figure-01)では 3 種類の実装方法の性能を比較している。`loop` は dilation に対応するメモリ効率のよい PyTorch 実装だが、実用にならないほど遅く、テストにのみ用いる。`chunks` は非拡張の場合にのみ対応し、事前学習・ファインチューニングの設定で用いる。`cuda` は TVM [Che18d] を用いて実装した、すべての機能を備える高度に最適化されたカスタム CUDA カーネルであり、言語モデリング実験に用いる（詳細は [第 9 節](#section-9)を参照）。

## 4 自己回帰言語モデリング

自己回帰または左から右への言語モデリングは、大まかには、入力系列内の先行トークン・文字が与えられたときに、既存のトークン・文字の確率分布を推定することと定義される。このタスクは自然言語における基礎的なタスクの一つと考えられており、Transformer で長い系列をモデル化する近年の先行研究では、主要な評価としてこのタスクが用いられてきた [Dai19, Rae20, Suk19]。同様に、本研究でも自己回帰言語モデリングでモデルを開発、評価する。

<span id="section-4-1"></span>

### 4.1 注意パターン

自己回帰言語モデリングには、本研究の拡張スライディングウィンドウ注意を用いる。[Suk19] にならい、層ごとに異なるウィンドウサイズを用いる。具体的には、下位層では小さいウィンドウサイズを用い、上位層に進むにつれてウィンドウサイズを大きくする。これにより、下位層が局所情報を捉える一方で、上位層は系列全体の高水準な表現を学習できる。さらに、効率（ウィンドウサイズが小さいほど非ゼロ値が少なく計算コストが低い）と性能（ウィンドウサイズが大きいほど表現力が高く、多くの場合は性能が向上する）のバランスが得られる。

下位層が直近の局所文脈を学習して利用する能力を最大化するため、下位層では拡張スライディングウィンドウを用いない。上位層では、2 つのヘッドにのみ、少量ずつ増加する dilation を用いる。これにより、局所文脈を犠牲にせず、離れたトークンへ直接注意を向けられる。

<span id="section-4-2"></span>

### 4.2 実験設定

先行研究と比較するため、文字レベル LM [Mah06] に焦点を当てる。

**学習。** 理想的には、現代の GPU メモリに収まる最大のウィンドウサイズと系列長でモデルを学習したい。しかし、モデルが長い文脈を利用する方法を学ぶ前に、まず局所文脈を学習するには多数の勾配更新が必要であることが分かった。これに対応するため、複数の学習フェーズを通じて注意ウィンドウサイズと系列長を増加させる段階的な学習手順を採用する。具体的には、第 1 フェーズを短い系列長とウィンドウサイズで開始し、以降の各フェーズでウィンドウサイズと系列長を 2 倍にし、学習率を半分にする。これにより学習が高速になり、遅い部分（最長の系列とウィンドウサイズ）を最後に回せる。合計 5 フェーズでモデルを学習し、開始時の系列長は 2,048、最終フェーズの系列長は 23,040 とする（各フェーズの詳細な構成とその他すべてのハイパーパラメータは [第 10 節](#section-10)を参照）。

**評価。** 長さ 32,256 の系列で評価する。[Dai19] にならい、データセットをサイズ 32,256、ステップサイズ 512 の重複系列に分割し、系列の最後の 512 トークンに対する性能を報告する。

## 5 事前学習とファインチューニング

多くの NLP タスクにおける現在の最先端システムは、タスクの教師信号を用いて事前学習済みモデル（BERT など）をファインチューニングする。本研究の主な動機の一つは、長文書タスクに適した同種のモデルを開発することにある。このため、文書コーパスで Longformer を事前学習し、分類、QA、共参照解析を含む 6 つのタスクでファインチューニングする。得られたモデルは、最大 4,096 トークン（BERT の 8 倍）の系列を処理できる [+5]。

Longformer の事前学習にはマスク言語モデリング（MLM）を用い、その目的は系列内でランダムにマスクされたトークンを復元することである。MLM の事前学習は高コストであるため、Longformer の注意機構に対応するために必要な最小限の変更だけを加え、公開済みの RoBERTa [Liu19a] チェックポイントから事前学習を継続する。本研究の注意パターンは、モデルアーキテクチャを変更せずに任意の事前学習済み Transformer モデルへ組み込めることに注意されたい。

**注意パターン。** ウィンドウサイズ 512 のスライディングウィンドウ注意を用いるため、計算量は RoBERTa と同じである。 [+6]

**位置埋め込み。** RoBERTa は、最大位置が 512 の学習済み絶対位置埋め込みを用いる。より長い文書に対応するため、位置 4,096 までを扱える位置埋め込みを追加する。BERT の注意ヘッドの解析では、直前または直後のトークンを含む局所文脈に注意を向ける、強く学習されたバイアスが示されているため [Cla19a]、RoBERTa の事前学習済み重みを活用すべく、新しい位置埋め込みをランダムに初期化する代わりに、RoBERTa の 512 個の位置埋め込みを複数回コピーして初期化する。コピーによる初期化は、分割境界を除くすべての位置でこの局所構造を保持する。単純な方法だが、非常に有効であることが分かった（[表 5](#table-05)を参照）。少数の勾配更新で Longformer の事前学習を急速に収束させられる。

## 6 タスク

Longformer を QA、共参照解析、分類を含む複数の長文書タスクに適用する。[表 6](#table-06)が示すように、評価データセットの文脈は 512 wordpiece より大幅に長い。主な目的は、本研究の注意機構が BERT 系モデルの標準的な自己注意機構を置き換えられるか、また強力なベースラインとの対照実験で検証することである。また、BERT の文脈長制限のために必要となる複雑なタスク固有モデルを、利用可能なすべての文脈を 1 つの系列に連結するだけの単純なモデルで置き換えられるかにも関心がある。

ベースラインは RoBERTa ベースのモデルであり、文脈を可能な限り長いセグメントに分割し、それぞれを個別に RoBERTa へ通した後、活性化を連結して後続処理を行う。QA タスクでは、RoBERTa が質問に基づいて文脈の文脈表現を条件付けできるよう、各セグメントに質問も連結する。Longformer の変種では、RoBERTa の自己注意機構を、事前学習中に使用したウィンドウ注意と、タスクに基づくグローバル注意に置き換える。グローバル注意には追加の線形射影を用いる（[第 3.1 節](#section-3-1)）。

<span id="section-6-1"></span>

### 6.1 質問応答

WikiHop [Wel18]、TriviaQA [Jos17]、HotpotQA [Yan18a] の 3 つのデータセットを用いた。 [+7]

WikiHop と TriviaQA では BERT [Dev18] の単純な QA モデルにならい、質問と文書を 1 つの長い系列に連結して Longformer に通し、その後にデータセット固有の予測層を置く。WikiHop は候補用の分類層を用い、TriviaQA は回答スパンの予測に [Cla17] の損失関数を用いる。WikiHop では質問トークンと回答候補に、TriviaQA では質問トークンにグローバル注意を付与する。

HotpotQA は、10 個の Wikipedia 段落から回答スパンと根拠文を抽出するマルチホップ QA データセットであり、そのうち 2 段落が関連し、残りは distractor である。まず最も関連性の高い段落を選択し、第 2 段階に渡して回答を抽出する 2 段階モデルを用いる。両段階とも質問と文脈を 1 つの系列に連結して Longformer に通し、タスク固有の予測層を用いる。関連段落、根拠文、回答スパン、質問タイプ（yes/no/span）を同時に予測するよう、マルチタスク方式でモデルを学習する。このモデルは、複雑なタスク固有アーキテクチャを含む近年の SOTA モデル（[Tu19, Che19d, Tu20, Gro20] など）より単純であることに注意されたい。モデルとハイパーパラメータの詳細は [第 12 節](#section-12)を参照されたい。

<span id="section-6-2"></span>

### 6.2 共参照解析

OntoNotes [Pra12] と [Jos19] のモデルを用いる。後者は [Lee18c] のシステムを改変し、ELMo を BERT に置き換えたものである。Longformer システムは、ベースラインモデルの RoBERTa を Longformer に置き換え、系列長を拡張するという直接的な適応である。このタスクではグローバル注意を用いなかった。

### 6.3 文書分類

IMDB [Maa11] と Hyperpartisan news detection [Kie19] のデータセットで評価する。 [+8] IMDB は映画レビューからなる標準的な感情分類データセットである。このデータセットの大半の文書は短いが、約 13.6% は 512 wordpiece を超える（[表 6](#table-06)）。Hyperpartisan の文書は比較的長く、文書数はわずか 645 と小規模であるため、限られたデータに適応する Longformer の能力を検証するのに適している。`[CLS]` トークンにグローバル注意を用いる。

### 6.4 結果

**主結果。** [表 7](#table-07)に、すべてのファインチューニング実験の結果をまとめる。Longformer は一貫して RoBERTa ベースラインを上回る。性能向上は、WikiHop や Hyperpartisan のように長い文脈を必要とするタスクで特に明確である。TriviaQA では、多くの場合に局所文脈だけで質問に答えられるため、改善はより小さい。HotpotQA では、supporting fact の補助教師信号により、モデルが関連文脈を容易に発見し、その後は局所文脈に集中できるため、改善幅が小さくなる。これは、中間推論チェーンに対する distant supervision しか含まない WikiHop とは対照的であり、WikiHop では文脈全体を対象に推論する本手法が優れている。IMDB と OntoNotes のデータセットでは、性能向上は小さい。IMDB ではデータセットの大半が短い文書で構成されるため、改善が小さいのは予想どおりである。OntoNotes では、任意の 2 つの mention 間の距離が通常かなり短いため、小さなチャンクを別々に処理するベースラインでも、チャンク間の相互作用を考慮せずに mention をつないで共参照チェーンを形成できることが分かった。

## 7 Longformer-Encoder-Decoder（LED）

元の Transformer [Vas17] はエンコーダ・デコーダアーキテクチャで構成され、要約や翻訳などの sequence-to-sequence タスク [Sut14] を目的としていた。エンコーダのみの Transformer はさまざまな NLP タスクで有効だが、事前学習済みエンコーダ・デコーダ Transformer モデル（BART [Lew19] や T5 [Raf19] など）は、要約のようなタスクで高い性能を達成している。しかし、このようなモデルは、入力が長い seq2seq タスクへ効率よくスケールできない。

seq2seq 学習で長い系列をモデル化できるようにするため、エンコーダとデコーダの両方の Transformer スタックを持ちつつ、エンコーダの完全自己注意の代わりに Longformer の効率的な局所・グローバル注意パターンを用いる Longformer の変種を提案する。デコーダは、符号化されたすべてのトークンと、それまでに復号された位置に対して完全自己注意を用いる。このモデルを Longformer-Encoder-Decoder（LED）と呼び、入力に対して線形にスケールする。LED の事前学習は高コストであるため、LED のパラメータを BART から初期化し、層数と隠れサイズについて BART とまったく同じアーキテクチャに従う。唯一の違いは、より長い入力を処理するため、位置埋め込みを 16K トークン（BART の 1K トークンから増加）まで拡張し、RoBERTa に対する [第 5 節](#section-5)と同様、BART の 1K 個の位置埋め込みを 16 回繰り返しコピーして新しい位置埋め込み行列を初期化する点である。BART にならい、LED-base と LED-large の 2 つのモデルサイズを公開する。エンコーダとデコーダの各スタックは、それぞれ 6 層と 12 層である。

科学分野の長文書要約に焦点を当てた arXiv 要約データセット [Coh18] を用い、要約タスクで LED を評価する。文書長の 90 パーセンタイルは 14.5K トークンであり、LED の評価に適したテストベッドである。LED のエンコーダは文書を読み取り、デコーダは出力要約を生成する。エンコーダはウィンドウサイズ 1,024 トークンの局所注意と、先頭の `<s>` トークンに対するグローバル注意を用いる。デコーダはエンコーダ全体と、それまでに復号された位置に対して完全注意を用いる。seq2seq モデルで標準的な方法として、LED は正解学習要約に対する teacher forcing で学習し、推論時にはビームサーチを用いる。

## 8 結論と今後の課題

長い入力をチャンク分割・短縮せず、またそれらのチャンク間の情報を統合する複雑なアーキテクチャも用いずに、幅広い文書レベル NLP タスクを容易に実行できる、長文書処理にスケール可能な Transformer ベースのモデル Longformer を提示した。Longformer は局所情報とグローバル情報を組み合わせ、系列長に対して線形にもスケールする注意パターンを用いる。Longformer は文字レベル言語モデリングタスク `text8` と `enwik8` で最先端の結果を達成する。事前学習した Longformer は、長文書タスクで一貫して RoBERTa を上回り、WikiHop と TriviaQA で新たな最先端結果を達成する。さらに、sequence-to-sequence タスクをモデル化する Longformer のエンコーダ・デコーダ変種 LED を提示し、arXiv の長文書要約タスクで最先端の結果を達成する。今後は、特に LED を対象に別の事前学習目的を研究し、系列長を増やし、本モデルから恩恵を受け得る他のタスクを検討したい。

## 9 実装の詳細

Longformer の拡張スライディングウィンドウ注意を実装するには、PyTorch や TensorFlow など既存の深層学習ライブラリでは直接サポートされない帯行列積の一種（特定の対角線を除き出力がすべてゼロになる行列積）が必要である。[図 1](#figure-01)では、3 種類の実装方法について実行時間とメモリを比較している。<br>`Longformer-loop` は、各対角線をループ内で個別に計算する素朴な実装である。非ゼロ値だけを計算するためメモリ効率はよいが、実用にならないほど遅い。実装が容易なのでテストにのみ用い、実験の実行には用いない。<br>`Longformer-chunks` は非拡張の場合にのみ対応する。$Q$ と $K$ をサイズ $w$、重複サイズ $\frac{1}{2}w$ の重複ブロックに分割し、ブロックを乗算した後、対角線をマスクする。PyTorch の単一の行列積演算を用いるため計算効率は非常に高いが、一部のゼロ値も計算するため、完全に最適化された実装が消費すべき量の 2 倍のメモリを消費する。計算効率が高いため、この実装は事前学習・ファインチューニングの場合に最も適している。この設定では、メモリ使用量の増加が問題になるとは分からなかった。<br>`Longformer-cuda` は、TVM [Che18d] を用いて実装したカスタム CUDA カーネルである。本研究の注意を完全に機能させる実装であり（`Longformer-chunks` のような制限はない）、メモリ効率が最も高く、高度に最適化された完全自己注意と同程度に高速である。 [+10] メモリ効率が高く（最長の系列を扱える）、dilation に対応する（文字 LM 実験に必要）ため、主に自己回帰言語モデリング実験でこの実装を用いる。

**Tensor Virtual Machine（TVM）。** 深層学習用コンパイラスタックである TVM [Che18d] を用い、カスタム CUDA カーネルを構築する。TVM は、関数の高水準な記述を最適化されたデバイス固有コードへコンパイルする。TVM を用いて帯行列積を高水準な Python 構文で記述すると、TVM が対応する CUDA コードを生成し、GPU 向けにコンパイルする。

## 10 文字 LM のハイパーパラメータ

`text8` と `enwik8` で評価する。どちらも Wikipedia から得た 100M 文字を、学習、開発、テスト用に 90M、5M、5M へ分割したものである。本モデルは自己注意コンポーネントの動作だけを規定し、Transformer モデルに関するその他の設計上の選択には依存しない。本研究の実装は、メモリ機構を無効にした Transformer-XL [Dai19] のコード [+11] に基づく。[Dai19] と同様に、正弦波の重みを持つ相対位置埋め込みを用いる。[Dai19] と同様の小規模モデル（12 層、隠れサイズ 512）と、[Chi19] と同様の大規模モデル（30 層、隠れサイズ 512）の 2 種類のモデルサイズを用いる。メモリ使用量を削減し、学習を高速化するため、apex [+12] を用いた混合精度学習（16 ビットと 32 ビットの浮動小数点数）を採用した。ただし、数値的不安定性の問題を避けるため、注意の計算は fp32 のままにした。 [+13] メモリ使用量を削減するため勾配チェックポイント [Che16] を用い、48GB の RTX8000 GPU 上で実験を行った。すべてのハイパーパラメータとフェーズ構成を [表 12](#table-12)に示す。本研究の CUDA カーネルは、各トークンが先行トークンのウィンドウだけに注意を向ける自己回帰モードに対応する。実装には、本研究の拡張スライディングウィンドウ注意と互換性のある相対位置埋め込みの一版も含まれる。

## 12 タスク固有モデルの詳細

すべての QA モデルと分類モデルは PyTorch-Lightning [+14] で実装する。Hyperpartisan news を除くすべてのデータセットでは公式の train/dev/test 分割を用い、Hyperpartisan news は train/dev/test 用に 80/10/10 の比率でランダムに分割する。

**WikiHop。** WikiHop の各インスタンスは、質問、回答候補（2 候補から 79 候補）、補助文脈（3 段落から 63 段落）、正解で構成される。データセットにはマルチホップ推論チェーンの中間アノテーションがないため、モデルは間接的な回答教師信号からそれらを推定する必要がある。

Longformer と RoBERTa への入力データを準備するため、まず RoBERTa の wordpiece tokenizer を用いて質問、回答候補、補助文脈をトークン化する。次に、質問と回答候補を特殊トークンとともに `[q] question [/q] [ent] candidate1 [/ent]... [ent] candidateN [/ent]` の形式で連結する。文脈も RoBERTa の文書区切りトークンをセパレータとして、`</s> context1 </s>... </s> contextM </s>` の形式で連結する。特殊トークン `[q], [/q], [ent], [/ent]` は RoBERTa の語彙に追加し、タスクのファインチューニング前にランダム初期化した。

入力データの準備後、次のように各モデルの最上位層から活性化を計算する。質問と回答候補に、モデルの系列長（RoBERTa は 512、Longformer は 4,096）まで可能な限り多くの文脈を連結し、その系列をモデルに通して出力活性化を収集し、すべての文脈を使い切るまで繰り返す（Longformer-large を除くすべてのモデル。Longformer-large ではメモリ要件のため、最初の長さ 4,096 の系列だけを含める）。その後、すべてのチャンクのすべての活性化を、1 つの長い系列に連結する。Longformer の場合、質問と回答候補の系列全体にグローバル注意を用いる。

予測では、単一の logit を出力する線形層を各 `[ent]` に接続し、チャンク全体で各候補のすべての logit を平均し、softmax を適用して、正解の回答候補に対する交差エントロピー損失を用いる。

学習には Adam optimizer を用い、200 回の勾配更新にわたる線形 warmup で最大学習率に達した後、残りの学習では線形に減衰させた。勾配累積を用いて実効バッチサイズを 32 インスタンスとし、250 回の勾配更新ごとに開発正解率を確認し、最大の開発正解率を報告した。その他のハイパーパラメータ（dropout、weight decay）は RoBERTa の事前学習と同一である。

一般に、ハイパーパラメータの試行は最小限にしたが、Longformer と RoBERTa を公平に比較するため、Longformer-base と RoBERTa-base で同一のハイパーパラメータ探索を実施した。これは LR [2e-5, 3e-5, 5e-5] とエポック数 [5, 10, 15] のグリッドサーチである。Longformer-base の最良構成は lr=3e-5、15 エポックであった。Longformer-large については、lr=3e-5、エポック数 [5, 15] の 2 つのハイパーパラメータを試行した（5 エポックのモデルの開発正解率 77.6 がより高く、この単一モデルをテストセット評価のため公開リーダーボードへ投稿した）。すべてのモデルを 1 基の RTX8000 GPU で学習し、Longformer-base の 5 エポックには約 1 日を要した。

**TriviaQA。** TriviaQA には、学習用に 100K を超える質問、回答、文書の三つ組がある。文書は Wikipedia の記事であり、回答は記事内で言及される固有表現である。質問に答えるスパンは注釈されていないが、単純なテキスト照合で見つけられる。

WikiHop と同様に、RoBERTa の tokenizer を用いて質問と文書をトークン化し、`[s] question [/s] document [/s]` の形式で入力を構成する。処理が極端に遅くなるのを避けるため、文書を 4,096 wordpiece で切り捨てる。その後、前述の WikiHop と同様に、RoBERTa と Longformer から活性化を得る。すべての質問トークンにグローバル注意を用いる。

予測では、回答スパンの開始と終了を予測する層を 1 つ追加する。学習データが distant supervision である（正解の回答スパンがない）ため、モデルがすべてではなく 1 つの回答スパンだけを正しく予測すればよい OR のように動作する、[Cla17] の損失関数を用いる。

最良構成のハイパーパラメータを [表 14](#table-14)に示す。その他すべてのハイパーパラメータは RoBERTa と同様である。ハイパーパラメータ探索では RoBERTa ベースラインの LR だけを調整し、[3e-5, 5e-5, 1e-4] を試した後、その最良値 3e-5 を追加調整なしですべての後続実験に用いた。Longformer-large は最良構成で 1 回学習し、その出力をリーダーボードへ投稿した。実験には 32GB の V100 GPU を用いた。小規模モデルは 4 基の GPU で学習に 1 日、大規模モデルは 8 基の GPU で 1 日を要する。

**HotpotQA。** HotpotQA データセットでは、10 件の異なる Wikipedia 記事から得た 10 段落に基づいて質問に答える。2 段落は質問に関連し、残りは distractor である。回答スパン抽出と根拠文特定の 2 つのタスクが含まれる。本研究の HotpotQA モデルは、回答スパン抽出と根拠抽出を 1 つの結合モデルにまとめる。まず関連段落を特定し、その後に最終的な回答スパンと根拠を見つける、同様の設定の 2 段階 Longformer モデルを用いると、性能が高くなることが分かった。 [+15] これは主に、最初に distractor 段落を除去すると最終的な根拠とスパン検出のノイズが減るためであり、このデータセットにおける近年の最先端手法 [Fan20c] でも重要であることが判明している。WikiHop や TriviaQA と同様、Longformer への入力データを準備するため、質問に続いて 10 個すべての段落を 1 つの長い文脈に連結する。具体的には、特殊トークンを用いた次の入力形式を使用する。「`[CLS] [q] question [/q] $\langle$t$\rangle$ $\texttt{title}_{\texttt{1}}$ $\langle$/t$\rangle$` $\texttt{sent}_{\texttt{1,1}}$ `[s]` $\texttt{sent}_{\texttt{1,2}}$ `[s]` `...` $\langle$`t$\rangle$ $\texttt{title}_{\texttt{2}}$ $\langle$/t$\rangle$ ` $\texttt{sent}_{\texttt{2,1}}$ `[s]` $\texttt{sent}_{\texttt{2,2}}$ `[s]` `...`」。ここで `[q]`、`[/q]`、$\langle$`t$\rangle$`、$\langle$`/t$\rangle$`、`[s]`、`[p]` は、それぞれ質問の開始と終了、段落タイトルの開始と終了、文を表す特殊トークンである。これらの特殊トークンは Longformer の語彙に追加し、タスクのファインチューニング前にランダム初期化した。Longformer では、質問トークン、段落タイトル開始トークン、文トークンにグローバル注意を用いる。モデルは、関連段落の予測用として段落タイトル開始トークンの上に、また根拠文の予測用として文トークンの上に、追加の feedforward 層を持つ。第 1 段階モデルの学習後、学習セットと開発セットの両方について関連段落スコアを予測する。次に、生スコアが所定の閾値（-3.0）を上回る段落を最大 5 個保持し、その他の段落を文脈から除去する。得られた短い文脈で第 2 段階モデルを学習する。回答スパン抽出には、先頭の特殊トークン（`[CLS]`）上に質問タイプ（yes/no/span）分類ヘッドを追加した BERT の QA モデル [Dev18] を用いる。根拠抽出では、文トークンと段落トークンに対応する表現の上に 2 層 feedforward network を適用して、対応する根拠予測スコアを得て、二値交差エントロピー損失でモデルを学習する。根拠抽出の推論時には、このデータセットの設定に従い、根拠文が厳密に 2 段落から得られることを保証する [Gro20] と同様の制約付き復号戦略を用いる。スパン、質問分類、文、段落の損失を統合し、損失の線形結合を用いたマルチタスク方式でモデルを学習する。実験は RTX8000 GPU 上で行い、各エポックの学習には 4 基の GPU で約半日を要する。線形 warmup（1000 ステップ）と線形減衰を備えた Adam optimizer でモデルを学習した。LR 3e-5 と 5e-5、エポック数 3 から 7 について最小限のハイパーパラメータ調整を行い、LR 3e-5、5 エポックのモデルが最良であることが分かった。RoBERTa ベースラインにも同じハイパーパラメータ探索を行う。その他のハイパーパラメータは [表 14](#table-14)に報告する。

**共参照モデルの詳細。** 共参照モデルは、[Jos19] の coarse-to-fine BERT ベースモデルを直接適応したものである。RoBERTa の wordpiece tokenizer で各文書を前処理した後、各文書を最大系列長までの重複しないセグメントに分割し、共参照クラスタを形成する coarse-to-fine clustering 段階に向けて活性化を連結する。RoBERTa-base の最大系列長は 384 であり、元の実装の既定ハイパーパラメータを用いて [256, 384, 512] から 3 回の試行後に選択した。 [+16] Longformer-base の系列長は 4,096 である。元の実装と同様に、事前学習済み RoBERTa パラメータとランダム初期化されたタスクパラメータには異なる学習率を用いた。タスクパラメータに大きな学習率を用いると、事前学習済み RoBERTa パラメータ内の情報を壊さずに、optimizer がタスクパラメータをランダム初期値からより大きく調整できる。

ハイパーパラメータ探索は最小限であり、公平な比較のため、RoBERTa と Longformer の両方について、RoBERTa の LR [1e-5, 2e-5, 3e-5] とタスク LR [1e-4, 2e-4, 3e-4] のグリッドサーチを行った。Longformer-base の最良構成は RoBERTa lr=1e-5、task lr=1e-4 であった。その他すべてのハイパーパラメータは元の実装と同一である。学習には 1 基の GPU で約 10 時間を要する。

本研究の実装は、PyTorch と TensorFlow が単一のプロセスと GPU を共有する superhack である。[Lee18c] が最初に公開した高度に最適化されたカスタム GPU カーネルを伴う、TensorFlow の複雑な coarse-to-fine ロジックを PyTorch で再実装するのを避けるため、モデル下部の Transformer 部分が PyTorch と TensorFlow の間で活性化と勾配をやり取りするシステムを考案した。入力テンソルをまず PyTorch の Transformer に通し、最上位層から活性化を収集して GPU から CPU へ転送した後、CPU から TensorFlow へ、さらに GPU へ戻し、coarse-to-fine clustering を実行して損失を計算する。次に、TensorFlow で Transformer の最上部まで勾配を逆伝播し、逆の手順で PyTorch へ転送して、モデルの残りの部分を逆伝播する。パラメータ更新用に、同一の LR スケジュールを持つ別個の optimizer を維持する。この手法のオーバーヘッドは、モデル実行の総コストと比べると小さい。

**テキスト分類。** 分類では BERT にならい、先頭の `[CLS]` トークン上で単純な二値交差エントロピー損失を用い、`[CLS]` にグローバル注意を追加した。バッチサイズ 32 の Adam optimizer を用い、総学習ステップの 0.1 に等しい warmup ステップを用いて線形に warmup、減衰させた。IMDB と Hyperpartisan news の両方について LR [3e-5, 5e-5] とエポック数 [10, 15, 20] をグリッドサーチし、[3e-5]、15 エポックのモデルが最良であることが分かった。実験は 1 基の RTX8000 GPU 上で行った。
