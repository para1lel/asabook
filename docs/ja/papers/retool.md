## 概要

強化学習（RL）で学習した推論モデル（DeepSeek R1 など）はテキスト推論に優れる一方、幾何推論、簡潔な計算、複雑な方程式の求解といった、構造化された問題解決を要する場面では苦戦する。このような場面では、コードインタプリタ（CI）などの計算ツールが明確な利点を示す。この隔たりを埋めるため、ツール統合学習によって長文推論を強化する **ReTool** を提案する。ReTool には 2 つの主要な特徴がある。（1）自然言語による推論過程の途中で、リアルタイムのコード実行を動的に挟み込む。（2）複数ターンのリアルタイムコード実行を伴うポリシー rollout を可能にし、結果フィードバックに基づいて、いつ、どのようにツールを呼び出すかをモデルに学習させる自動 RL パラダイムである。ReTool は体系的な学習フレームワークを採用し、まず合成コールドスタートデータを生成して、ベースモデルの微調整に用いるコード拡張型の長い推論軌跡を作成する。その後の RL 学習では、タスク結果を報酬として利用し、モデルのツール利用戦略を反復的に改善することで、人手の事前知識を用いずに最適なツール呼び出しパターンを自律的に発見できるようにする。難度の高い数学オリンピックベンチマーク AIME での実験は、ReTool の優位性を示している。32B モデルは 400 学習ステップで正解率 67% を達成し、テキストベースの RL ベースライン（正解率 40%、1080 ステップ）を学習効率と性能の両面で上回った。拡張設定では、ReTool-32B の正解率は 72.5% に達し、OpenAI の o1-preview を 27.9% 上回った。さらに分析すると、コードの自己修正などの創発的挙動が見られた。これは、モデルが適応的なツール利用を自律的に習得する「aha moment」を示している。これらの結果は、結果駆動型のツール統合が複雑な数学推論を前進させる可能性を示すとともに、ニューラル・シンボリック混成システムに新たな知見を与える。

## 1 はじめに

強化学習（RL）は近年、大規模言語モデル（LLM）の推論能力を高め、長い思考連鎖（CoT）を探索・改善させる一般的なパラダイムとなっている [Wei22a, Yao23a, Luo24a, Zha24v]。OpenAI o1 [Ope24h] や DeepSeek R1 [Dee25c] などの推論モデルは、自己修正と、より慎重で分析的な思考を学ぶことにより、純粋なテキストベースの推論タスクで高い性能を示す [Ant25b, Qwq25, Tea25h]。こうした進歩は、モデルが推論するだけでなく、自らの推論過程を監視して修正するという、メタ認知的制御の初期兆候を示している。

こうした進歩にもかかわらず、長いテキスト推論過程を備えた推論 LLM [Ouy22a] は、幾何推論、精密な計算、複雑な方程式の求解など、正確な数値計算や記号操作を要するタスクで依然として明確な限界を示す。これに対して、コードインタプリタ（CI）などの計算ツールは、純粋なテキスト推論をはるかに超える記号計算能力をモデルに与えられる。内部の言語パターンだけに依存するテキスト CoT [Wei22a] とは異なり、コードインタプリタは、列挙、検証、精密な計算のための形式的かつ実行可能なインターフェースを提供する。これにより、中間ステップの数値を厳密に検証し、テキスト推論でよく見られる曖昧さと誤差の累積を大幅に減らせる [Che22, Wan23i] だけでなく、プログラム可能な探索によって解の探索空間を広げることもできる。

近年の研究では、プロンプトや教師あり微調整 [Che25y, Pan23] を用いて、LLM にツール利用能力を与える方法が検討されている。しかし、これらの手法は、特定の方法で選別されたデータ分布を模倣するものに限られ、未見のパターンへ汎化したり、いつ、どのように外部ツールを呼び出すかを適応的に判断したりできないことが多い。その結果、モデルはツールを誤用するか、多様な問題設定に対して頑健でない脆弱なヒューリスティクスへ戻る可能性がある。こうした制約を克服する原理的な解決策が RL である。RL により、モデルは柔軟な推論軌跡を探索し、結果ベースのフィードバックに導かれたツール利用戦略を学習できる。このパラダイムは、正しい解を促すだけでなく、ツール実行の失敗から自己修正によって回復する方法や、長い思考連鎖の途中でツールを効果的に実行する時機の判断といった、細かな行動パターンを発見することも可能にする。

本研究では RL パラダイムを採用し、推論時に外部計算ツールを活用する最適戦略へ LLM を明示的に導く、**ツール（Tool）**拡張型の**強化（Reinforcement）**学習フレームワーク **ReTool** を提案する。ReTool は 2 つの主要な構成要素からなる。まず、コードインタプリタをいつ、どのように呼び出すかを明示的に示す、高品質なコールドスタートデータセットを選別するデータ構築パイプラインを開発する。これにより、モデルはツール利用と実行結果分析の初歩的な能力を学ぶ。次に、ツール拡張強化学習を適用し、最適なツール操作推論戦略を発見し、結果ベースの報酬を通じて行動を調整するようモデルを学習する。これは教師あり学習だけで捉えられる範囲を超える。長い思考連鎖による推論中、ポリシーモデルはコードブロックを柔軟に記述し、サンドボックス型コードインタプリタからリアルタイムの実行結果を取得して、その後の思考を補助する rollout を行う。

難度の高い数学オリンピックベンチマーク AIME2024 と AIME2025 で ReTool を評価する。Qwen2.5-32B-Instruct [Yang24] を基盤とした本モデルは、わずか 400 学習ステップで AIME2024 の正解率 67.0% を達成し、1080 ステップで正解率 40.0% のテキストベース RL ベースラインを大幅に上回る。この大きな向上は、意思決定過程の一部としてツール利用を明示的にモデル化することが、モデル推論の限界を押し上げると同時に、学習効率も改善することを示す。DeepSeek-R1-Distill-Qwen-32B [Dee25c] で学習した場合、本モデルはさらに改善し、QwQ-32B-Preview [Qwq25]、s1-32B [Has25]、OpenAI o1-preview [Ope24] といった競争力のあるベースラインを上回る。これは、RL 学習過程がより効率的な問題解決戦略を引き出すことを示唆する。さらに、Qwen2.5-32B-Instruct を基盤とするコールドスタートモデルは、AIME2024 で正解率 40.9% を達成し、同じバックボーンを用いるテキストベース RL ベースライン（40.0%）と同等であり、未学習の Qwen2.5-32B-Instruct（26.7%）を大幅に上回る。これらの結果は、選別したデータセットが実行可能な推論軌跡に含まれるツール利用パターンを効果的に捉え、CI 統合学習が推論性能へ良い影響を与えることを示す。

さらに、RL 学習を通じた CI の認知的挙動を包括的に分析し、いくつかの主要な知見を得た。本モデルはコード利用能力を高め、より正確で複雑なコード断片を使用できる。また、ツールを適切に呼び出し、適応的に選択し、ツール呼び出しを効果的に構成し、創発的なコード自己修正能力によって推論を反復的に改善することも学習する。

**主な貢献は次のとおりである。**

1. コードインタプリタの実行を LLM の推論ループへ統合する、新しい強化学習フレームワーク **ReTool** を提案する。コードインタプリタを呼び出す基礎能力をモデルに与えるため、開発したパイプラインを用いて高品質なコールドスタートデータセットを選別する。さらに、rollout 中のコード実行を交互に挟める強化学習フレームワークを設計し、サンドボックス化されたコードインタプリタからのフィードバックに導かれたツール拡張対話を通じて、モデルが推論戦略を反復的に探索、改善、最適化できるようにする。

2. [3.3 節](#section-3-3)に示すように、包括的な実証分析と行動分析を行い、いくつかの主要な知見を得た。（1）RL 学習後の応答長は学習前より約 40% 短くなり、CI 駆動推論が推論 token の効率を改善する可能性を示す。（2）RL 学習中、コード比率、コード行数、正しいコード数は増加傾向を示し、コード呼び出しの時機は早まる。これは、コード利用能力の向上と戦略的なツール利用の発達を示す。（3）RL フェーズでは、コードの自己修正や適応的なツール選択などの創発的挙動が観察され、より高度なツール拡張推論パターンが生じる。

## 2 手法

本節では、数学問題の解決を目的とした CI 駆動 RL フレームワーク ReTool を説明する。まず ReTool の概要を示す。次に、データ構築パイプラインと教師あり微調整を含むコールドスタート学習を説明する（[2.2 節](#section-2-2)）。その後、戦略的なツール利用能力をさらに発達させるため、コードインタプリタのサンドボックスで強化した強化学習パイプラインを示す（[2.3 節](#section-2-3)）。

<span id="section-2-1"></span>

### 2.1 概要

本手法は、コールドスタート教師あり微調整と、それに続くコード実行を交互に挟む rollout を用いた強化学習という 2 つの主要段階からなる。最初に、設計したパイプラインを用いてコールドスタート教師あり微調整（SFT）用データを収集し、強化学習フェーズに頑健な初期状態を与える。モデルのツール利用能力を高めるため、推論中にツールを適切に選択・適用する能力を強化する、ツール利用専用の強化学習パイプラインを導入する。

<span id="section-2-2"></span>

### 2.2 ツール統合推論の基盤となるコールドスタート

高品質なデータを収集・選別するパイプラインを設計した。具体的には、Open-Thoughts [Ope25h] などのオープンソースデータセットを含む多様な情報源から、既存の数学推論データを収集する。続いて、人間の専門家による選別と Deepseek-R1 [Dee25c] による評価を組み合わせた二重検証で、無効なデータを除外する。これらの手順により、高品質なテキストベース推論データセット $\mathcal{D}_{\mathrm{init}}$ を得る。

$\mathcal{D}_{\mathrm{init}}$ に基づき、コード統合推論データをさらに自動構築する。まず、構造化プロンプトテンプレート（[図 8](#figure-08)に詳述）を用いて変換し、コード実行が有効な手計算のステップを、対応するコード断片とインタプリタの実行結果に置き換えることで、元の思考過程を修正する。この最初の変換後、2 段階の検証手順を適用する。第 1 段階は形式検証であり、可読性を改善して構文を統一し、その後の強化学習フェーズで計算ツール呼び出しのトリガーを効率よく検出できるようにする。第 2 段階は解答検証であり、最終出力が数学問題の正解と一致しないデータサンプルを除外する。最終的に、コードで拡張された長い推論軌跡からなるデータセット $\mathcal{D}_{\mathrm{CI}}$ を収集する。

ReTool は教師あり微調整を用い、前述のデータセット $\mathcal{D}_{\mathrm{CI}}$ からコードインタプリタをいつ、どのように呼び出すかを学習し、計算ツールを適切に利用する能力を高める。

### 2.3 ReTool: 戦略的ツール利用のための強化学習

<span id="section-2-3-1"></span>

#### 2.3.1 学習アルゴリズム

PPO アルゴリズム [Sch17a] に基づいて ReTool を学習し、次の目的でポリシーを更新する。

<span id="equation-01"></span>

$$
\begin{aligned}
\mathcal{J}_{\mathrm{PPO}}(\theta) = \mathbb{E}_{(q,a)\sim \mathcal{D},o_{\le t}\sim\pi_{\theta_{\mathrm{old}}}(\cdot\mid q)}
\Bigg[
\min \Bigg(&\frac{\pi_{\theta}(o_t\mid q,o_{<t};\mathrm{CI})}{\pi_{\theta_{\mathrm{old}}}(o_t\mid q,o_{<t};\mathrm{CI})} \hat{A}_t,\\
&\mathrm{clip} \Bigg( \frac{\pi_{\theta}(o_t\mid q,o_{<t};\mathrm{CI})}{\pi_{\theta_{\mathrm{old}}}(o_t\mid q,o_{<t};\mathrm{CI})}, 1 - \varepsilon, 1 + \varepsilon \Bigg) \hat{A}_t \Bigg) \Bigg],
\end{aligned}
$$

ここで、$\pi_{\theta}$ はポリシーモデル、$\pi_{\theta_{\mathrm{old}}}$ は参照モデル、$\pi_{\theta}(o_t\mid q,o_{<t};\mathrm{CI})$ はコード実行とコードインタプリタからのフィードバックが交互に挿入された rollout を表す。

ツール統合推論に適するよう PPO を変更する。学習中、ポリシー LLM はコードサンドボックスと連携し、複数ターンのリアルタイムコード実行によって与えられた問題を解く rollout を生成する。ルールベースの結果報酬を実装し、コード利用の認識、コード選択、コード呼び出しの時機、その他の多様な挙動について、モデルが柔軟に戦略を自律探索・発達させられるようにする。

**報酬設計** ツールをいつ、どのように呼び出すかをモデルに学習させるため、ルールベースの正解報酬を実装してモデルを最適化する。正解報酬は応答の正しさを評価する。最終解答を所定の形式（たとえば `\boxed{}` 内）で提示するようモデルに求め、信頼できるルールベース検証を可能にする。報酬は次式で表される。

<span id="equation-02"></span>

$$
R(a, \hat{a}) =
\begin{cases}
1, & \texttt{is\_equivalent}(a, \hat{a}) \\
-1, & \mathrm{otherwise}
\end{cases}
$$

ここで、$a$ と $\hat{a}$ は、それぞれ正解と予測解答を表す。報酬ハッキングを緩和し、コード実行可能性の報酬を考慮せず、結果フィードバックだけに基づく多様な問題解決行動を促すため、報酬設計を単純化する。

**コード実行を交互に挟む Rollout** 推論と実行可能コードをモデル内で統合するため、自然言語による推論過程の途中でリアルタイムコード実行を動的に挟める rollout 手法を提案する。[図 2b](#figure-02)に示すように、本手法の rollout 過程は、通常テキストベースの推論だけを生成する従来手法（[図 2a](#figure-02)）とは異なる。これに対して本手法では、ポリシー LLM と外部コードサンドボックスを連携させ、テキスト、コード断片、リアルタイムのインタプリタフィードバックからなる混成コンテンツを生成できる。具体的には、プロンプトテンプレート（[図 7](#figure-07)）を用いてモデルとコードサンドボックスの対話を誘導し、`<code></code>` タグで生成コードの境界を明示する。Rollout 中、ポリシーモデルはテキストベース推論 $t_1$ を生成し、コード終了トリガー（`</code>`）を検出すると生成を一時停止して、生成済みコード $c_1$ を解析し、コードサンドボックス環境へ送信して実行する。実行が完了すると、サンドボックスの出力 $f_1$（成功結果またはエラーメッセージ）を `<interpreter></interpreter>` タグ内に挿入してモデルへ返す。モデルは、最終解答 $o$ を提示するか、新しいコード断片を生成するまで rollout を続け、最終的に混成推論軌跡 $[t_1 \oplus c_1 \oplus f_1 \oplus ... \oplus o]$ を生成する。

特に、本手法はコード実行に成功した結果とインタプリタのエラーメッセージの両方をモデルへ返す。この動的フィードバック機構により、モデルは推論戦略とツール利用戦略を反復的に探索、改善、最適化できる。

<span id="section-2-3-2"></span>

#### 2.3.2 学習の詳細

**コールドスタートと RL** 学習には VeRL フレームワーク [+1] を用いる。RL 手法には PPO を採用する。選別したコールドスタートデータを用いて、モデルを 2 epoch 学習する。ハイパーパラメータについては、初期学習率 1e-6 の AdamW オプティマイザを用いる。想定最大系列長は 16384 token とする。学習時の mini-batch サイズは 512、KL 係数は 0.0 とする。主要バックボーンには Qwen2.5-32B-Instruct [Qwe25] を用いる。

**インタプリタフィードバックのマスク。** `<interpreter></interpreter>` 内のフィードバック出力を損失計算から除外する。このサンドボックス出力のマスキングにより、外部 token が損失計算へ干渉するのを防ぎ、学習を安定させるとともに、モデル自身が生成する一貫した推論系列が乱されるのを防ぐ。

**KV-Cache の再利用。** Rollout 中のメモリコストを削減するため、コード終了トリガー（`</code>`）を検出するたびに、コード実行前の全 KV-cache をキャッシュし、インタプリタフィードバック（`<interpreter></interpreter>`）に対応する KV-cache だけを計算して追加する。これにより、各 rollout の KV-cache を大幅に削減できる。

**サンドボックスの構築。** RL 学習を高速化するため、非同期コードサンドボックス環境を設計する。サンドボックス pod はプール内の worker として機能し、現在の処理能力に応じてそれぞれ独立にタスクを取得することで、効率的な負荷分散機構を形成する。この分散非同期方式は、複数 thread で環境との対話を並列化して RL 学習を高速化する。遅い thread がボトルネックになるのを防ぎ、リソース利用を最適化して、学習中のスループットを継続的に維持する。

[+1]: [https://github.com/volcengine/verl](https://github.com/volcengine/verl)

## 3 実験

本節では ReTool の性能を評価し、モデル出力の挙動を包括的に分析する。

<span id="section-3-1"></span>

### 3.1 評価設定

安定した評価を行うため、AIME2024・2025 の評価セットを 32 回繰り返し、全体の平均正解率を報告して pass@1 を推定する。評価時の推論ハイパーパラメータは、temperature 1.0、top-p 0.7 とする。ReTool を、Qwen2.5-Math-72B-Instruct [Yan24j]、Qwen2.5-Math-72B-Instruct-TIR [Yan24j]、Sky-T1 [Sky25]、DeepSeek-R1-Zero-Qwen-32B [Dee25c]、QwQ-32B-Preview [Qwq25]、s1-32B [Has25]、OpenAI o1-preview [Ope24] などの競争力のあるベースラインと比較する。ReTool の有効性を検証するため、ツールを利用しない RL、すなわちテキストベース RL（Qwen2.5-32B-Instruct）との性能比較も行う。ベースラインの結果については、対応する文献の avg@k を転記し、pass@1 として報告する。

### 3.2 主要結果

[表 1](#table-01)に示すように、ReTool により LLM は RL フェーズでコードインタプリタを柔軟に活用でき、性能が大幅に向上する。具体的には、ReTool（Qwen2.5-32B-Instruct）はわずか 400 学習ステップで、AIME2024 と AIME2025 において、それぞれ 67.0% と 49.3% の正解率を達成する。テキストベース RL ベースライン（Qwen2.5-32B-Instruct）は 1000 ステップを超えて学習しても、それぞれのベンチマークで 40.0% と 36.7% にとどまり、ReTool が明確に上回る。これらの結果は、ReTool が採用するツール統合学習パラダイムが、モデルの推論能力だけでなく学習効率も改善することを示す。さらに AIME2024 では、ReTool（Qwen2.5-32B-Instruct）が競争力のあるベースライン s1-32B を 10.3% 上回る。同様に AIME2025 では、OpenAI の o1-preview を 11.4% 上回る。より高度なバックボーンと組み合わせると、ReTool（DeepSeek-R1-Distill-Qwen-32B）の性能はさらに向上し、AIME2024 で 72.5%、AIME2025 で 54.3% を達成する。これらの結果は、RL 学習過程でより有効な問題解決戦略が発見されることを示唆する。

また、Qwen2.5-32B-Instruct を基盤とするコールドスタートモデルは、AIME2024 で正解率 40.9% を達成し、テキストベース RL ベースライン（40.0%）に近い一方、ベースモデル（26.7%）を大幅に上回る。これらの結果は、選別したデータセットが実行可能な推論軌跡に含まれるツール利用パターンを効果的に捉え、CI 統合学習が推論性能へ良い影響を与えることを示す。

### 3.3 認知分析

探索から得られたいくつかの主要な知見を包括的に分析する。（1）RL 過程を通じたコードインタプリタ（CI）関連挙動の変化、（2）自己修正能力の創発、（3）RL 前後のコード用途の違い、（4）CI 駆動推論とテキストベース推論の相違である。

<span id="figure-03"></span>

![図 3。RL 学習中に変化する 6 つの CI 関連挙動指標。](../../papers/retool/figure-03.png)

**図 3。** RL 学習中における CI 関連挙動の変化。

**CI 関連挙動の変化。** ReTool の RL 過程をより深く理解するため、CI 関連指標を体系的に評価した。具体的には、RL 学習中に保存した各 checkpoint について、AIME2024 と AIME2025 データセット上でモデルが生成した出力を分析し、各指標を計算した。結果を[図 3](#figure-03)に示す。分析内容は次のとおりである。

- **応答長**（[図 3a](#figure-03)）：平均応答長を計算すると、生成応答の長さが最初に急減し、その後は比較的緩やかに増加する明確な傾向が見られた。初期の減少は、複雑な計算過程がより簡潔なコードに置き換わったためであり、その後の増加は、RL 学習中に、より多様で複雑なコード挙動が現れたためと考えられる。最終的な平均応答長は、RL 学習前より依然として 40% 短い（10k から 6k）。これは、複雑な計算過程をコードで置き換える CI 駆動推論が、推論 token の利用効率を改善する可能性を示す。

- **コード比率**（[図 3b](#figure-03)）：コードを含む応答の比率も計算した。分析の結果、RL 学習過程を通じて平均コード比率は全体として上昇し、最終的に全問題の約 98% を占めた。これは、RL 過程でモデルのコード利用能力が徐々に向上し、戦略的なツール利用能力の発達を促したことを示す。

- **コード行数**（[図 3c](#figure-03)）：生成コードの行数は、その複雑さをある程度反映する。応答中の平均コード行数は、学習全体を通じて一貫して増加した。RL 学習の終了時には、最終的な平均コード行数は学習前の約 5 倍となった。この傾向は、モデルが RL フェーズで、より複雑なコード戦略を学んだことを示す。

- **テストセットで正しかったコードの総数**（[図 3d](#figure-03)）：テストセットにおける正しいコードの総数は、RL 学習中に全体として増加し、1k から 5k となった。この改善は、コードツールを活用する熟練度が高まったことを示す。

- **コード通過率**（[図 3e](#figure-03)）：CI 駆動推論では、最初に誤った中間コードを生成した後、インタプリタのフィードバックに基づいて反復的に改善し、実行可能なコードを生成する場合がある。このため、誤答中の最後のコードについて平均通過率を報告する。正答のコード通過率は一貫して高く、100% に近い一方、誤答のコード通過率は低下傾向を示す。このパターンは、コードの実行可能性が推論過程と最終結果に影響することを示す。

- **コード呼び出しの時機**（[図 3f](#figure-03)）：コードの開始位置を応答全体の長さで割って求める、コード呼び出しの時機も計算する。この指標は、応答内でコードを呼び出す時機を反映する。結果は、RL 学習過程でコード呼び出しの時機が早まることを示しており、モデルがツール利用の時機を判断するよう学習したことが分かる。

![図 4。未定義関数のエラー後にコードを自己修正する例。](../../papers/retool/figure-04.png)

**図 4。** コード自己修正に関する「aha moment」の事例。

**コード自己修正の「Aha Moment」。** 興味深いことに、コード自己修正の明示的な学習データがないにもかかわらず、本モデルは実行不能なコードを自己修正する創発的能力を示す。[図 4](#figure-04)に示すように、モデルが最初に生成したコードは、関数「greedy()」が未定義だったため実行に失敗した。インタプリタからフィードバックを受け取ると、モデルはエラーを認識し、「**Oops, the functions need to be defined in the same scope. Let's correct that**」と振り返った。その後、必要な関数定義をすべて含む、実行可能な修正版コードを生成した。この創発的挙動は、強化学習がメタ認知能力を育み、モデルが生成コードを反復的に改善して、より複雑な問題に対処できるようにする可能性を示す。

**CI 駆動推論とテキストベース推論。** [図 6](#figure-06)に示す事例を用いて、強化学習（RL）後の CI 駆動推論と、RL 学習前の従来型テキストベース推論の違いを説明する。同じ質問に対して、テキストベース推論は「骨の折れる」テキストだけの計算過程に依存し、数値誤差が生じやすく、しばしば誤った推論結果となる。これに対して、CI 駆動推論は、この複雑な計算過程を簡潔なコードで置き換える。この方法は、外部コードインタプリタの支援によって計算精度を保証するだけでなく、モデルが全体的な推論戦略へより効果的に集中できるようにする。

<span id="section-4"></span>

## 4 背景と関連研究

<span id="section-4-1"></span>

### 4.1 LLM 推論

大規模言語モデル（LLM）の近年の進歩 [Wei22a, Yao23a, Luo24a, Ope24h, Tea25h, Dee25c, Xai23, Ant25b, Tea23, Yang24] は、思考連鎖（CoT）プロンプティングを通じて、人間のメタ認知に似た認知能力へ大きく近づいていることを示す。[Wei22a] が最初に導入した CoT プロンプティングは、段階的な自然言語記述を利用して LLM の推論能力を高め、さまざまな推論タスクの性能を大幅に改善する。この基盤の上で、近年の研究は学習時スケーリングからテスト時スケーリングへ重点を移している [Sne24]。テスト時スケーリングでは、推論時に追加の計算資源を割り当て、中間推論ステップを生成できるようにする。段階的選好最適化 [Lai24]、モンテカルロ木探索（MCTS）[Xie24]、強化学習 [Luo24a] などの手法が、多段階で長い数学推論の改善に用いられている。OpenAI-o1 [Ope24h] や DeepSeek-R1 [Dee25c] などの高度なモデルは、CoT ベース推論の有効性を示している。CoT を補完するものとして、[Che22] と [Gao23] が導入した Program-of-Thought（PoT）推論は、Python インタプリタなどの外部計算ツールを統合し、複雑な推論ステップの単純化と検証を行うことで、正解率を高める。

<span id="section-4-2"></span>

### 4.2 ツール統合推論

ツール統合推論は、プログラミング戦略を統合し、計算量の多い数学問題を LLM が解けるようにするために最初に導入された [Che22, Yue23, Jin25b, Son25a, Wan24aa]。この基盤の上で、[Wan23i] はテキスト推論とコード実行を組み合わせ、相互に検証して推論精度を高める反復的手法を提案した。より最近では、[Che25y] が、自ら選別したコード統合 CoT データで教師あり微調整を行い、コード実行を推論過程へ統合した。しかし、この方法は特定のデータ分布に依存するという本質的な制約があり、いつ、どのようにツールを呼び出すかといった適応的なツール利用戦略を、強化学習によって学ぶことができない。同時期の研究 [Li25o] は、1.5B と 7B 規模の Qwen2.5-Math モデル [Yan24j] に強化学習を適用してツール利用戦略を学習したが、性能は依然として最適とはいえなかった。この研究方向をさらに大規模化し、コードインタプリタをいつ、どのように呼び出すかを強化学習によって戦略的に判断するフレームワーク ReTool を提案する。本手法は AIME2024 と AIME2025 において、Qwen-Math-72B-TIR [Yan24j] と o1-preview [Ope24] を大幅に上回る。また、学習されたツール利用挙動を包括的に分析し、ReTool 学習後のコード呼び出しに関するモデルの認知パターンについて、いくつかの主要な知見を示す。

<span id="section-5"></span>

## 5 結論

本論文では、コードインタプリタを効果的に利用することで、大規模言語モデルが数学推論能力を自己強化できる新しい強化学習フレームワーク ReTool を提案した。AIME2024 と AIME2025 での包括的な実験から、ReTool は従来のテキストベース RL 手法より高い正解率を達成するだけでなく、大幅に少ない学習ステップで収束することを示した。慎重なデータ選別と専用のツール利用パイプラインにより、ReTool は高度な計算介入戦略をモデルに発達させ、LLM における、より効率的で強力なツール拡張推論への道を開く。
