## 概要

大規模言語モデル（LLM）の登場により、自由形式の自然言語対話を通じた情報アクセスと推論は一変しました。しかし、LLM には依然として、知識が静的であること、事実に反するハルシネーション、リアルタイムまたはドメイン固有の情報を取得できないことという制約があります。検索拡張生成（RAG）は、モデルの出力を外部の証拠に基づかせることでこれらの問題を緩和しますが、従来の RAG パイプラインは多くの場合、単一ターンでヒューリスティックに依存しており、検索と推論を適応的に制御できません。近年の *agentic search* の進展は、LLM が検索環境と複数ステップで対話しながら計画、検索、内省できるようにすることで、これらの制約に対処しています。このパラダイムにおいて、強化学習（RL）は、適応的かつ自己改善的な検索行動を実現する強力な仕組みとなります。本サーベイでは、*RL-based agentic search* を初めて包括的に概観し、この新興分野を相補的な 3 つの次元、すなわち（i）*RL は何のために使われるか*（機能的役割）、（ii）*RL はどのように使われるか*（最適化戦略）、（iii）*RL はどこに適用されるか*（最適化の範囲）に沿って整理します。代表的な手法、評価プロトコル、応用をまとめ、信頼性とスケーラビリティを備えた RL 駆動型 agentic search システムの構築に向けた未解決の課題と今後の方向性を論じます。本サーベイが、RL と agentic search の統合に関する今後の研究を促すことを願っています。リポジトリは [https://github.com/ventr1c/Awesome-RL-based-Agentic-Search-Papers](https://github.com/ventr1c/Awesome-RL-based-Agentic-Search-Papers) で公開しています。

## 1 はじめに

大規模言語モデル（LLM）[Ouy22a, Tou23a, Zha25ak] は、自然言語の理解、推論、生成において前例のない能力を示し、ユーザーが情報にアクセスし、情報と関わる方法を根本から変えてきました。こうした利点がある一方で、LLM には依然として複数の制約があります。静的な知識のカットオフに縛られ [Che24r]、事実に反するハルシネーションを起こしやすく [Sah24]、リアルタイムまたはドメイン固有の情報にアクセスできません。これらの課題に対処するため、*検索拡張生成（Retrieval-Augmented Generation：RAG）* [Lew20, Gao24e] というパラダイムが広く使われる解決策として登場しました。RAG は、LLM の推論能力と、TF–IDF [Spa72, Aiz03]、BM25 [Rob95, Rob09]、PageRank [Bri98, Pag99, Bia05] のようなリンク解析モデルなど、古典的な情報検索（IR）技術の精度を組み合わせます。外部の知識ベースから証拠を取得し、そのコンテキストを条件として応答を生成することで、RAG は LLM に、より正確で事実に根ざした出力を生成させます。これは特に知識集約型タスクで有効です [Asa24, Bor22, Fan24c]。

しかし、従来の RAG システム [Che17] は通常、単一ターンでヒューリスティックに駆動されます。すなわち、検索を一度行い、生成も一度行うだけで、中間フィードバックに基づいてクエリを反復的に改良したり、検索戦略を適応させたりする能力がありません。検索された文書は無関係であったりノイズを含んでいたりする場合があり、後続の推論を妨げます [Jia23c, Cha25b, Jin25e, Jin25b]。さらに、LLM は検索された証拠を十分に活用できないことが多く、パイプライン全体の有効性を制限しています。これらの制約が、LLM が複数のステップにわたって動的に計画、検索、推論、内省を行う自律的な意思決定主体として機能する、より *agentic な検索システム* の開発を促しています。

この目的に向けて、研究者は *検索エージェント*、すなわち検索環境と複数ステップで対話できる LLM ベースのシステムを提案してきました [Jia24c, Zhe25f]。従来の RAG とは異なり、検索エージェントはクエリの発行と改良を反復し、検索結果の品質を評価し、複雑なマルチホップタスクを解くために戦略を動的に適応させられます。受動的な検索から能動的なエージェンシーへのこの移行は、情報探索におけるパラダイム転換を表しています。しかし、初期の検索エージェントは、人手で作られたプロンプティング [Li25k] や教師ありファインチューニング [Qin23b, Asa24a] に大きく依存することが多く、最適な戦略を自律的に発見する能力が制限されていました。

近年、強化学習（RL）[Sut98] は、適応的で自律的な検索エージェントを開発するための有望なパラダイムとして台頭しています [Jin25b, Wan25ah]。本稿では、*RL-based agentic search* を、検索環境と対話して外部フィードバックを受け取り、報酬を最大化するために戦略を反復的に改善する意思決定エージェントとして LLM を学習させることと定義します。この定式化は 3 つの重要な側面を強調します。すなわち、（i）エージェントが自身の検索行動を決める *自律性*、（ii）手作業による設計ではなく強化を通じて戦略を獲得する *学習*、（iii）推論と検索を改良するためにエージェントが検索環境と複数ターンにわたってやり取りする *対話* です。

急速な進展にもかかわらず、RL-based agentic search に対する体系的な理解はまだ十分ではありません。[表 1](#table-01) にまとめたように、近年のサーベイ [Xi25a, Li25q, Gao25e] はさまざまな観点から agentic search を検討しています。しかし、それらは RL にあまり注意を払っていない [Xi25a] か、Deep Research [Li25q] や RAG [Gao25e] など特定のサブドメインに焦点を絞っています。適応的で自律的な検索行動を可能にする RL の役割は、十分に探究されていません。これに対して本稿は、RL-based agentic search に特化した*初の*包括的サーベイを提示し、相補的な 3 つの次元に沿って RL が agentic search にどのような利点をもたらすかを明らかにすることを目指します。すなわち、（i）検索、推論、意思決定を導く機能的役割を説明する *RL は何のために使われるか*、（ii）報酬設計、方策学習、高度な学習手法などの最適化戦略を扱う *RL はどのように使われるか*、（iii）エージェントレベルからステップおよびモジュールレベルまで、RL が介入する範囲を検討する *RL はどこに適用されるか* です。各次元について、代表的な手法を概観し、新たに現れている傾向をまとめます。本稿の全体構成を [図 1](#figure-01) に示します。

本稿の構成は次のとおりです。[第 2 節](#section-2) では、agentic search と RL の基礎を紹介します。[第 3 節](#section-3) から [第 5 節](#section-5) では、上記の 3 つの観点から agentic search のための RL を検討します。[第 6 節](#section-6) では評価指標と代表的な応用を概観し、[第 7 節](#section-7) では未解決の課題と今後の方向性をもって締めくくります。

## 2 背景と予備知識

<span id="section-2-1"></span>

### 2.1 エージェントとしての大規模言語モデル

LLM [Ouy22a, Tou23a, Yan25g, Wan25n, Lin25f, Zha24t] は、テキストの理解、推論、生成において顕著な能力を示し、人間が情報にアクセスし、情報と関わる方法を根本から変えてきました。その成功により、多様な知識資源に対する自然言語インターフェースが実現しました。しかし、これらのモデルには、静的な学習コーパス、ハルシネーション、リアルタイムまたはドメイン固有の知識に直接アクセスできないことという制約が残っています [Ji23a]。これらを克服するため、研究者は LLM に外部情報源と意思決定能力を付加する取り組みを強めています。顕著な方向性の 1 つが *検索拡張生成（RAG）* [Lew20, Gao24e, Liu25r] であり、LLM が外部の知識ベースに問い合わせ、検索された証拠に応答を根拠づけます。このパラダイムを基礎として、近年の進展 [Qin23b, Zhe25f] ではさらに LLM を *agentic システム* と位置づけ、*検索エンジン、コードインタープリター、知識ベース照会 API、Web ブラウザー*などの外部ツールを呼び出して動的な環境と対話し、複数ステップの推論を行えるようにしています。

<span id="section-2-2"></span>

### 2.2 従来の IR から Agentic Search へ

<span id="section-2-2-1"></span>

#### 2.2.1 従来の IR

古典的な情報検索（IR）の主な目的は、TF–IDF [Spa72] や BM25 [Rob95] などの統計モデル、および純粋なテキスト以外のメタデータも取り込む PageRank [Bri98, Pag99] のようなリンク解析手法を利用し、ユーザーのクエリに最も適合する文書のランキングを返すことです。検索そのものがプロセスの終点であり、結果の解釈と統合はユーザーに委ねられます。また、従来の IR 手法は多くのタスクに有効である一方、複雑なユーザー意図を捉えたり、複数ステップの推論を行ったりする能力に根本的な制約があります [Sha25c]。

<span id="section-2-2-2"></span>

#### 2.2.2 RAG

検索拡張生成（RAG）[Lew20] は、検索された文書を条件として LLM の応答を生成することにより、検索を生成プロセスへ統合します。標準的なパイプラインでは、モデルがクエリを発行し、関連する証拠を検索し、その入力に基づいて回答を生成します。この retrieve-then-read アーキテクチャは事実的な根拠を改善しますが、依然として制約があります。RAG は通常単一ターンであり、クエリを適応的に改良する仕組みを欠き、無関係またはノイズの多い検索結果に弱いという問題があります [Jia23c, Jin25e]。反復的な拡張 [Tri22a, Asa24a] は複数回の検索を可能にしますが、こうした手法もなお、LLM を能動的な検索エージェントではなく、おおむね受動的に証拠を受け取る存在として位置づけています。

<span id="section-2-2-3"></span>

#### 2.2.3 Agentic Search

Agentic search は、LLM を自律的な意思決定エージェントとして捉えることで RAG を超えていきます。モデルは検索文書を受動的に利用するのではなく、*いつ*、*どこで*、*どのように*検索するかを決定し、取得した証拠を進行中の推論と行動に統合します。しばしば *deep research エージェント* [Xu25f] として実装されるこのパラダイムは、静的な証拠注入としての検索から、問題解決のための動的なツール利用としての検索への転換を表します。形式的には、deep research エージェントとは、複雑な情報調査タスクを支援するため、動的な推論、適応的な計画、複数ターンのデータ検索、ツール利用、証拠の統合を一体化した LLM 駆動型システムです。

<span id="section-2-3"></span>

### 2.3 強化学習の基礎

<span id="figure-02"></span>

![図 2。RL の構成要素の概観](../../papers/rl-based-agentic-search/figure-02.png)

**図 2。** RL の構成要素の概観

強化学習（RL）は、試行錯誤を通じて累積報酬を最大化するために、エージェントが環境とどのように対話するかを研究する、機械学習の基本的なパラダイムです [Sut98]。[図 2](#figure-02) に示すように、エージェントは環境から状態 $s_{t}$ を各時刻 $t$ に観測し、行動 $a_{t}$ を方策 $\pi(a_{t}|s_{t})$ に従って選択した後、報酬 $r_{t}$ を受け取り、環境は新たな状態 $s_{t+1}$ へ遷移します。エージェントは、時間にわたる累積報酬を最大化するため、方策 $\pi$ を継続的に更新します。形式的には、このような最適化問題はマルコフ決定過程（MDP）としてモデル化され、タプル $(\mathcal{S},\mathcal{A},\mathcal{T},\mathcal{R})$ で表されます。ここで $\mathcal{S}$ は取り得る状態の集合、$\mathcal{A}$ は行動空間、$\mathcal{T}:\mathcal{S}\times\mathcal{A}\times\mathcal{S}\rightarrow[0,1]$ は状態遷移確率関数、$\mathcal{R}:\mathcal{S}\times\mathcal{A}\times\mathcal{S}\rightarrow\mathbb{R}$ は報酬関数を表します。最適化の目的は、方策 $\pi$ を学習して期待割引累積報酬 $\sum_{k=0}^{\infty}\gamma^{k}r_{t+k+1}$ を最大化することであり、$\gamma\in(0,1]$ は割引率です。

方策勾配法 [Sch17a, Liu25u, Fen25b] は、大規模な離散行動空間上の確率的方策を直接最適化するため、RL-based agentic search で広く用いられています。一般に、（i）新しいロールアウトから方策を更新する *オンポリシー最適化*（例：PPO [Sch17a]、GRPO [Sha24d]）と、（ii）オンラインサンプリングを必要とせず、オフラインの軌跡または選好データを活用する *オフポリシーまたは選好ベースの最適化*（例：DPO [Raf23]、ReMix [Lia25g]）に分類できます。

<span id="section-2-3-1"></span>

#### 2.3.1 オンポリシー最適化

オンポリシーアルゴリズムは、現在の方策で環境と対話してロールアウトを収集し、アドバンテージを推定し、それらのサンプルを生成した同じ方策を更新します。正確な報酬信号のもとで行動方策を直接最適化できるため、大規模な LLM および agentic search の学習で好まれています。この系統は、さらに 2 つの下位群に分けられます。

- **critic ベースのアルゴリズム。** これらの手法は、各状態またはトークンの期待リターンを推定するため、明示的な*価値関数*または *critic* モデルに依存します。critic は、方策勾配の分散を抑えて学習を安定させるトークンレベルのフィードバックを提供しますが、計算コストとメモリのオーバーヘッドも追加します。PPO [Sch17a] は、このパラダイムで最も広く使われている例です。
- **critic を用いないアルゴリズム。** これに対し、critic を用いない手法は価値ネットワークを完全に取り除き、相対的な報酬統計からアドバンテージを直接推定します。学習された価値予測に依存する代わりに、これらのアルゴリズムは各入力について複数の応答をサンプリングし、グループ内で報酬を正規化することで*グループベースのアドバンテージ*を計算します。この戦略は、安定した最適化を維持しながら、学習の複雑さと GPU メモリ消費量を大幅に削減します。代表例として、GRPO [Sha24d]、Dr.GRPO [Liu25u]、DAPO [Yu25g]、GiGPO [Fen25b] があります。

**Proximal Policy Optimization（PPO）。** PPO [Sch17a] は、RL エージェントの学習に最も広く使われている手法の 1 つです。次の目的関数を最大化することを目指します。

<span id="equation-01"></span>

$$
\mathcal{J}_{\mathrm{PPO}}(\theta)=\mathbb{E}_{x\sim\mathcal{D},y\sim\pi_{\mathrm{old}}(\cdot|x)}\left[\min\left(\frac{\pi_{\theta}(y|x)}{\pi_{\mathrm{old}}(y|x)}A,\right.\right.\left.\left.\mathrm{clip}_{\epsilon}\left(\frac{\pi_{\theta}(y|x)}{\pi_{\mathrm{old}}(y|x)}\right)A\right)-\beta\mathbb{D}_{\mathrm{KL}}(\pi_{\theta}\mid\mid\pi_{\mathrm{ref}})\right],
$$

ここで、$\pi_{\theta}$ と $\pi_{\mathrm{old}}$ は、それぞれ現在と直前の方策モデルを表します。$\pi_{\mathrm{ref}}$ は、KL ダイバージェンスのペナルティによって方策更新を正則化する参照モデルであり、その大きさと重みはそれぞれ $\mathbb{D}_{\mathrm{KL}}$ と $\beta$ で表されます。$x$ は分布 $D$ から抽出された入力サンプルを表します。$\mathrm{clip}_{\epsilon}$ は、学習を安定させるハイパーパラメータ $\epsilon$ を持つクリッピング関数です。アドバンテージ推定値 $A$ は、報酬 $r$ と学習済み価値関数 $V_{\psi}$ に基づき、一般化アドバンテージ推定（GAE）[Sch15] を用いて計算されます。

**Group Relative Policy Optimization（GRPO）。** GRPO [Sha24d] は、多くの場合メモリ使用量を倍増させる個別の価値関数モデルを不要にすることで PPO を拡張します。代わりに、同じ入力からサンプリングした応答のグループ内で相対アドバンテージを推定し、学習効率を改善します。具体的には、各入力 $x\in D$ について、GRPO は出力のグループ $\{y_{1},y_{2},\cdots,y_{G}\}$ を旧方策 $\pi_{\mathrm{old}}$ からサンプリングし、次を最大化することで新しい方策 $\pi_{\theta}$ を最適化します。

<span id="equation-02"></span>

$$
\mathcal{J}_{\mathrm{GRPO}}(\theta)=\mathbb{E}_{x\sim\mathcal{D},\{y_{i}\}_{i=1}^{G}\sim\pi_{\mathrm{old}}(\cdot|x)}\frac{1}{G}\sum_{i=1}^{G}\left[\min\left(\frac{\pi_{\theta}(y|x)}{\pi_{\mathrm{old}}(y|x)}A_{i},\mathrm{clip}_{\epsilon}\left(\frac{\pi_{\theta}(y|x)}{\pi_{\mathrm{old}}(y|x)}\right)A_{i}\right)-\beta\mathbb{D}_{\mathrm{KL}}(\pi_{\theta}\mid\mid\pi_{\mathrm{ref}})\right],
$$

ここで、$A_{i}$ は各グループ内の出力に対応する報酬 $\{r_{1},r_{2},\ldots,r_{G}\}$ を用いて計算されるアドバンテージです。

<span id="equation-03"></span>

$$
A_{i}=\frac{r_{i}-\mathrm{mean}(\{r_{1},r_{2},\ldots,r_{G}\})}{\mathrm{std}(\{r_{1},r_{2},\ldots,r_{G}\})}.
$$

**Decoupled Clip and Dynamic Sampling Policy Optimization（DAPO）。** DAPO [Yu25g] は、長い思考連鎖（CoT）推論モデルを学習するための新しい RL 手法です。具体的には、DAPO はエントロピー崩壊、報酬ノイズ、学習の不安定性など、GRPO の複数の制約に対処します。長い CoT の状況で RL の性能を改善するため、clip-higher、動的サンプリング、トークンレベルの方策勾配損失、長すぎる出力に対する報酬シェーピングという 4 つの主要技術を導入します。形式的には、DAPO の目的関数は次を最大化することを目指します。

<span id="equation-04"></span>

$$
\begin{aligned}
\mathcal{J}_{\mathrm{DAPO}}(\theta)= & \mathbb{E}_{x\sim\mathcal{D},\{y_{i}\}_{i=1}^{G}\sim\pi_{\mathrm{old}}(\cdot|x)}\frac{1}{G}\sum_{i=1}^{G}\left[\min\left(\frac{\pi_{\theta}(y|x)}{\pi_{\mathrm{old}}(y|x)}A_{i},\mathrm{clip}\left(\frac{\pi_{\theta}(y|x)}{\pi_{\mathrm{old}}(y|x)},1-\epsilon_{\mathrm{low}},1+\epsilon_{\mathrm{high}}\right)A_{i}\right)\right] \\
& \mathrm{s.t.},~0<|\{y_{i}\mid\mathit{it\_equivalent}(x,y_{i})\}|<G,
\end{aligned}
$$

ここで、$A_{i}$ は [式 3](#equation-03) で定義したアドバンテージ推定値です。$\epsilon_{\mathrm{high}}$ は通常、低確率トークンの確率を高める余地を広くするため $\epsilon_{\mathrm{low}}$ より大きく設定され、$\mathit{it\_equivalent}$ は、正解率が 1 または 0 のプロンプトを過剰サンプリングして除外する動的サンプリング関数です。長い CoT モデルの学習中にはモデルの分布が初期モデルから大きく乖離し得るため、DAPO では KL 項が除外されている点に注意してください。

<span id="section-2-3-2"></span>

#### 2.3.2 オフポリシー最適化

これに対し、オフポリシーおよび選好ベースのアルゴリズムは、現在の方策から新たなロールアウトを必要としません。代わりに、以前に収集した軌跡や明示的な選好アノテーションから学習するため、データ効率と安定性が大きく向上します。これらの手法は、オンラインフィードバックの収集が高コストまたは非現実的な、大規模 LLM アライメントと agentic search のシナリオで特に有用です。

**Direct Preference Optimization（DPO）。** DPO [Raf23] は、LLM を人間の選好に合わせるための代表的な *RL を用いない*手法です。個別の報酬モデルを学習し、反復的な方策最適化（例：PPO）を行う従来の人間のフィードバックからの強化学習（RLHF）[Chr17, Sti20, Ouy22a, Zha25v] とは異なり、DPO はアライメントを直接的な確率分類問題として定式化します。選好ラベル付きの応答対から直接学習することで、明示的な報酬モデリングと RL ループを回避します。形式的には、データセット $\mathcal{D}$ が三つ組 $(x,y_{w},y_{l})$ を含むとします。ここで $x$ はプロンプト、$y_{w}$ と $y_{l}$ はそれぞれ*選好される（勝者）*応答と*選好されない（敗者）*応答を表し、選好は潜在的な報酬関数 $r^{*}(y,x)$ によって、$r^{*}(y_{w},x)>r^{*}(y_{l},x)$ となるよう生成されると仮定します。DPO は方策 $\pi_{\theta}$ を最適化し、$y_{w}$ の $y_{l}$ に対する相対尤度を参照モデル $\pi_{\text{ref}}$ に関して高めます。その式は次のとおりです。

<span id="equation-05"></span>

$$
\mathcal{J}_{\mathrm{DPO}}(\theta)=\mathbb{E}_{(x,y_{w},y_{l})\sim\mathcal{D}}\left[\log{\sigma}\left(\beta\frac{\pi_{\theta}(y_{w}|x)}{\pi_{\mathrm{ref}}(y_{w}|x)}-\beta\frac{\pi_{\theta}(y_{l}|x)}{\pi_{\mathrm{ref}}(y_{l}|x)}\right)\right],
$$

ここで、$\pi_{\mathrm{ref}}$ は参照モデル、$\beta$ はこの正則化の強さを制御するハイパーパラメータです。$\sigma$ 関数はシグモイドであり、2 つの応答の相対確率の最適化に役立ちます。この目的関数により、DPO は中間的な報酬モデルを必要とせず、人間の選好を反映するよう方策を直接最適化します。

### 2.4 RL-based Agentic Search

Agentic search では、検索と推論は固定された 1 回限りのステップとして実行されるのではなく、*逐次的な意思決定過程*に組み込まれます。エージェントは、*いつ*検索するか、クエリを*どのように*組み立てたり改良したりするか、検索した証拠を複数ステップの推論へ*どのように*取り込むかを決めなければなりません。[図 3](#figure-03) はこのパイプラインを概略的に示し、RL が介入できる意思決定点を強調しています。すなわち、（i）**検索制御**（検索するか／いつ検索するか）、（ii）**クエリ最適化**（どのように検索するか）、（iii）**推論への統合**（検索した情報をどのように使うか）です。

<span id="section-2-4-1"></span>

#### 2.4.1 RL 導入前の Agentic Search との比較

agentic search に RL が導入される以前、ほとんどのシステムは、検索と推論の行動を導くために、*構造化プロンプティング* [Zho24h, Xu24e, Wan23h, Lee24e, Che24s] または*教師ありファインチューニング（SFT）* [Sch23, Asa23, Aks23, Zha25ac] のいずれかに依存していました。

**プロンプティングベースの手法。** これらの手法は主として、人間が設計したヒューリスティクスと事前定義された推論ワークフローに依存します。たとえば、PlanRAG [Lee24e] と MetaRAG [Zho24h] は、エージェントが検索、回答生成、品質の内省を交互に行い、さらに検索するかを決める反復ループを採用しています。この処理は、満足できる応答が得られるまで繰り返されます。同様に、Knowledge-driven CoT [Wan23h] は、モデルに中間推論を再評価させ、検索された証拠に基づいて戦略を動的に調整させる内省の連鎖に従います。これらのプロンプティングベースのシステムは有効ですが、固定された記号テンプレートまたは人手で設計されたプロンプト構造に依存しており、未知のタスク分布や動的な検索環境には適応できません。

**SFT ベースの手法。** これらの手法は、検索、内省、生成の行動を含む高品質な軌跡のデータセットでモデルを学習し、こうした行動をパラメータへ内在化させます。たとえば Toolformer [Sch23] は、API 呼び出しをテキスト生成へ自動的に挿入した自己ラベル付きデータで LM をファインチューニングします。計算機や Wikipedia 検索エンジンなどの外部ツールをいつ、どのように使うかを学習し、追加の人間による監督なしに事実性を改善します。同様に SelfRAG [Asa23] は*自己内省型の検索拡張生成*を導入し、通常のトークンと、いつ新しい証拠を検索すべきか、各生成内容が検索文書にどの程度裏づけられているかを示す特別な*内省トークン*（例：`<Retrieve>`、`<Relevant>`、`<Supported>`）の両方を生成するようモデルを教師あり学習します。こうした進展にもかかわらず、SFT ベースの手法は根本的に模倣駆動のままです。コンテキストと行動の相関は捉えられますが、長期的な信用割当や結果駆動型の最適化を行う仕組みがありません。

**制約と RL が必要な理由。** 進展がある一方、プロンプティングベースと SFT ベースのエージェントはいずれも、次の本質的な制約に直面しています。

- *適応性の低さ*：行動の大部分が事前定義されているか、静的なデータセットから模倣されています。未知のタスクや API の挙動に直面した際、検索頻度を動的に調整したり、クエリを再構成したりできません。
- *教師信号のボトルネック*：高品質な推論と検索の軌跡は収集に費用がかかり、タスクをまたいだスケーリングも難しいため、汎化が制約され、実演を超える改善が困難になります。

RL は、環境と対話してフィードバックを受け取り、試行錯誤によって適応する方策 $\pi_{\theta}$ としてエージェントを最適化することで、これらの問題を克服する原理的な方法を提供します。SFT ベースの模倣とは異なり、RL は正確性、コスト、レイテンシを統合したタスクレベルの報酬を直接最適化し、*適応的で効率的な*検索方策の発見を可能にします。このパラダイムにより、エージェントは各検索判断の*長期的な帰結*を考慮でき、静的な模倣から結果駆動型の学習へ進めます。

<span id="section-2-4-2"></span>

#### 2.4.2 定式化

形式的には、RL-based agentic search は MDP としてモデル化できます。目標は、環境内で一連の行動を取り、累積報酬を最大化する方策 $\pi_{\theta}$ を学習することです。主要な構成要素は次のとおりです。（i）**エージェント**：LLM 方策 $\pi_{\theta}$ であり、$\theta$ でパラメータ化され、現在の状態を条件として行動を生成する、（ii）**環境**：検索エンジン API、retriever、知識グラフ、ツールインターフェースなど、エージェントが対話できる外部リソース、（iii）**状態（$s_{t}$）**：元のクエリ、中間推論の軌跡、検索された証拠、行動履歴を含む現在のコンテキスト、（iv）**行動（$a_{t}$）**：クエリの発行、既存クエリの再構成、文書の選択、ツール（例：検索 API、retriever）の呼び出し、最終回答による終了などの離散的な判断、（v）**行動（$a_{t}$）**：クエリの発行、既存クエリの再構成、文書の選択、ツール（例：検索 API、retriever）の呼び出し、最終回答による終了などの離散的な判断、（vi）**報酬（$r_{t}$）**：タスクの成功（例：回答の正確性、事実的一貫性）、プロセスの品質（例：クエリの効率、推論の一貫性）、リソースコスト（例：API 呼び出し、レイテンシ）を捉えるスカラーのフィードバック信号、（vii）**遷移（$\mathcal{T}$）**：環境（例：検索エンジンが文書を返すこと）とエージェントの内部更新の双方によって生じるダイナミクスです。

## 3 RL は何のために使われるか：Agentic Search における機能的役割

RL は、基本的な検索をはるかに超え、agentic search の中で幅広い機能的役割を担います。本節では、RL によってエージェントが*いつ*検索するかだけでなく、クエリを*どのように*組み立てるか、推論と証拠を*どのように*交互に進めるか、複数のエージェントやツールの間で*どのように*連携するかを決定できる仕組みを示すため、これらの役割を 5 つの主要な次元に分類します。[表 2](#table-02) は、RL の各役割における代表的な研究をまとめたものです。

<span id="section-3-1"></span>

### 3.1 検索制御

agentic search における RL の中心的な役割は、エージェントが外部情報を*検索するか、いつ検索するか、どのように検索するか*を制御することです。この観点は固定された設計原理ではなく、RL ベースの検索システムに関する近年の傾向 [Hua25e, Jin25b, Wu25q, Wan25ah] を統合したものであり、検索制御が中心的な最適化対象として浮上しています。過剰または不要なクエリはコストとレイテンシを増大させる一方、検索が不十分であれば重要な証拠を見落とすおそれがあるため、効果的な検索制御は不可欠です。RL により、エージェントはタスクのコンテキストと不確実性に応じる適応的な検索方策を学習し、このトレードオフの均衡を取れます。このカテゴリの手法は 3 つの主要な側面、すなわち（i）検索するかパラメトリック知識に頼るかを決める*適応的な検索判断*、（ii）検索の頻度と深さを決める*検索の強度と持続性*、（iii）タスク性能を保ちながら冗長性、コスト、レイテンシを最小化する*検索効率*に取り組みます。

<span id="section-3-1-1"></span>

#### 3.1.1 適応的な検索判断

RL により、エージェントは質問に内部のパラメトリック知識で回答できるか、外部検索が必要かを判断できます。Search-R1 [Jin25b]、ReSearch [Che25i]、R1-Searcher [Son25a] は、必要な場合にのみ検索エンジンを呼び出すよう LLM に学習させた初期の例です。具体的には [表 3](#table-03) に示すように、内部知識だけでは正確な回答を生成するのに不十分な場合、これらの手法は LLM に検索エンジンを呼び出して外部情報へアクセスするよう促します。この考え方に基づき、DeepRAG [Gua25c] は RAG を MDP として定式化します。そこでは複雑なクエリが、焦点を絞った情報要求をそれぞれ表す原子的なサブクエリへ*反復的に分解*されます。各推論ステップでエージェントは、回答の正確性と検索コストを共同で最適化する報酬に導かれ、パラメトリック知識を用いてサブクエリに答えるか、外部の証拠を検索するかを判断します。

<span id="section-3-1-2"></span>

#### 3.1.2 検索強度

複雑または曖昧なクエリでは、1 回の検索では不十分な場合があります。RL は、検索プロセスの深さと持続性を最適化するために用いられています。Pangu DeepDiver [Shi25d] は *Search Intensity Scaling* を導入し、曖昧性を検出したときに検索を強化したエージェントへ報酬を与えます。ReZero [Dao25] は検索失敗後の再試行に報酬を与え、持続性と頑健性を促します。StepSearch [Wan25ah] は、情報利得と冗長性ペナルティに基づくステップ単位の報酬を導入し、検索を一歩ずつ導きます。

<span id="section-3-1-3"></span>

#### 3.1.3 検索効率

効率は、検索の*コスト*（例：API 呼び出し回数、学習ロールアウト数）と、検索を完了するのに必要な*時間*の双方に関係します。R1-Searcher++ [Son25b] は、応答間の検索回数の分散によって検索の節約度を測る*グループ報酬*を導入して R1-Searcher を拡張し、冗長な検索を罰する一方、最少の検索呼び出しで得られた正解に報酬を与えます。IKEA [Hua25e] は、外部検索が必要でない限り内部推論を優先する、知識境界を考慮した報酬を導入します。Search Wisely [Wu25q] は、質の低い結果になりそうな低信頼度クエリを除外し、コスト効率を改善します。StepSearch [Wan25ah] はステップ単位の報酬で冗長なクエリにペナルティを与え、より簡潔な検索戦略を促します。ZeroSearch [Sun25b] は潜在空間で検索をシミュレーションすることで API のオーバーヘッドを削減し、実際の検索エンジンに依存しないカリキュラム形式の学習を可能にします。検索呼び出しの削減にとどまらず、ParallelSearch [Zha25af] は複雑な質問を並列サブクエリへ分解し、網羅性を維持しながら応答時間を大幅に短縮します。RAG-R1 [Tan25c] も同様に、複数クエリの並列化を促して推論効率を高めます。さらに WebThinker [Li25l] は、効率の概念を検索コストから推論行動へ拡張し、選好最適化を適用してクエリ戦略を、正確性、ツール効率、思考の簡潔さといった長期的な推論目標に整合させます。これにより、検索精度だけでなく、推論駆動のフィードバックを通じて検索判断を改良します。

<span id="section-3-2"></span>

### 3.2 クエリ最適化

検索を実行する場合でも、クエリの品質は結果に強く影響します。不適切に構成されたクエリからは、無関係またはノイズの多い結果が得られます。そこで RL は、静的なヒューリスティクスを超え、フィードバックに基づいてクエリ生成を改良するために使われます。既存研究は、（i）*対話的な再構成*と（ii）*retriever を考慮した最適化*に分類できます。

<span id="section-3-2-1"></span>

#### 3.2.1 対話的な再構成

対話的な環境では、ユーザーのクエリは曖昧またはコンテキスト依存であることが多く、直接検索は信頼できません。RL は、再構成を逐次的な意思決定過程として捉えることで、こうした入力を自己完結したクエリへ再構成できるようにします。ConvSearch-R1 [Zhu25i] は検索ベースの報酬で rewriter 方策を最適化し、再構成したクエリが正解文書を上位に検索した場合に高い報酬を割り当てます。その rewriter はまず、検索に導かれた自己蒸留で生成したデータを用いる SFT によってファインチューニングされ、続いて、正解文書をより上位に配置するよう促しながら報酬の疎性を緩和する *Rank-Incentive Reward Shaping* 関数を用い、RL によって改良されます。この 2 段階設計は、クエリ rewriter を retriever の選好に整合させ、複数ターン検索の精度を改善します。MaskSearch [Wu25r] は、より包括的に検索できるよう検索クエリを改良する *Rewriter Agent* を組み込み、このパラダイムを拡張します。その出力はさらに、LLM の SFT に用いる推論軌跡にも利用されます。個別の rewriter 方策を最適化する代わりに、RAG-R1 [Tan25c] は、推論効率と検索の多様性を高めるため、単一のプロンプト内で複数の並列クエリを生成するよう LLM 自体に促します。同様に ParallelSearch [Zha25af] は、1 回の推論ターン内で複雑またはマルチホップな質問を並列サブクエリへ分解するよう LLM を学習させます。RL ファインチューニング中には、*分解報酬*が有効なクエリ分解を促し、*検索回数報酬*が過剰な検索行動を罰することで、再構成の粒度と検索効率の均衡を取ります。

<span id="section-3-2-2"></span>

#### 3.2.2 Retriever を考慮した最適化

対話的な再構成がユーザー側の曖昧性の解消に焦点を当てる一方、retriever を考慮した最適化は、クエリ生成のシステム側を対象とします。特定の retriever の特性、バイアス、フィードバック信号にクエリを適応させるようエージェントを学習します。目的は、LLM が生成するクエリと retriever の実際のランキング挙動との意味的な隔たりを埋め、異なる検索基盤にわたって検索精度と頑健性を改善することです。DeepRetrieval [Jia25c] は、ブラックボックス検索エンジンのバイアスに合致するクエリを生成するよう LLM を学習し、retriever の挙動を効果的に利用して再現率を最大化することで、この考え方を例示します。WebThinker [Li25l] は選好最適化を適用し、クエリ戦略を、正確性、ツール効率、思考の簡潔さといった長期的な推論目標に整合させます。これによりエージェントは、検索精度だけでなく推論駆動のフィードバックを用いて検索行動を改良できます。ZeroSearch [Sun25b] はさらに検索環境をシミュレーションすることでこの手法を拡張し、実際の API 呼び出しに伴うコストと不安定性を避けながら、異なる retriever に汎化する頑健なクエリ行動を学習できるようにします。同様に s3 [Jia25d] は、LLM 生成器から分離した軽量な RL ベースの検索モジュールを導入し、スケーラブルでモデル非依存のクエリ最適化を可能にします。これらの手法は合わせて、異種の検索環境にわたって有効性を保つ、retriever を考慮したクエリ方策を設計するという、より広い目標を示しています。

<span id="section-3-3"></span>

### 3.3 推論と検索の統合

効果的に検索する*時点*と*方法*を決めるだけでなく、知識集約型タスクでは推論と検索を密接に結合する必要がしばしばあります。証拠は推論を改善する場合にのみ価値があり、推論は次に何を検索するかを導くべきです。RL は、LLM がこれらのプロセスをどのように交互に進め、コンテキストを管理し、フィードバックに基づいて推論を改良するかを最適化します。

<span id="section-3-3-1"></span>

#### 3.3.1 推論と検索の交互実行

推論中に検索を単に許可する [Jin25b, Che25i] だけでなく、RL は推論の品質を高めるよう検索を最適化します。R-Search [Zha25at] は、より有益な証拠を得られる高品質なクエリ生成を促す*証拠報酬*を導入します。AutoRefine [Shi25e] は、標準的な「search-and-think」パラダイムを「search-and-refine-during-think」へ拡張し、中間の改良ステップに報酬を与えて、忠実で的を絞った知識抽出を強化します。EvolveSearch [Zha25au] はさらに、SFT と RL の反復サイクルを通じて推論と検索の相互作用を強化し、学習時のデータ効率を高めることで、エージェントが推論経路と検索戦略の双方を段階的に改良できるようにします。これに対し MaskSearch [Wu25r] は、RL 最適化の*前に*、検索を考慮したモデルの推論能力を高めることに焦点を当てます。*Retrieval-Augmented Mask Prediction（RAMP）事前学習タスク*を導入し、SFT 段階で、外部検索ツールを活用してマスクされた範囲を検索知識で埋めるようモデルに学習させます。この RL 前の目的は、推論と検索の行動を整合させる、検索を考慮した事前分布を確立し、さまざまな下流タスクにわたる汎用的な検索能力を高めます。

<span id="section-3-3-2"></span>

#### 3.3.2 コンテキストとメモリの管理

既存の agentic search システム [Zha25at, Jin25b, Wan25ah] は、単一ターンの検索やステップレベルの推論など短期的なタスクには有効ですが、長期的または複数セッションの状況では問題を抱えることがよくあります。そこでは、限られたコンテキストウィンドウ内で長い対話履歴を管理しなければなりません。このような制約のもとで効率的に動作するには、エージェントは検索エピソードの進行に伴い、どの情報を保持、要約、破棄するかを判断して、*メモリを能動的に管理*する必要があります。近年の研究 [Gao25d, Xu25g, Wu25l, Che25u, Li25h, Li25y] は、このプロセスの最適化に RL を適用し、メモリ制御を*情報の忠実度*と*コンテキスト効率*の均衡を取る逐次意思決定問題として捉えています。具体的には、相補的な 2 つの戦略が登場しています。

- **内部管理：** エージェント自身が RL の指導のもと、作業コンテキストの要約、更新、枝刈りなどのメモリ操作を行います。たとえば ReSum [Wu25l] は RL によってエージェントを学習し、過去の推論と対話の簡潔な要約を生成させ、トークン上限を超えずに長いコンテキストで推論できるようにします。SFR-DeepResearch [Ngu25a] はさらに、明示的なメモリ行動（例：`clean_memory`、`store_snippet`）を導入し、RL 信号を用いて過去の情報を保持するか破棄するかを判断することで、メモリのあふれと冗長性を防ぎます。
- **外部管理：** 別の枠組みでは、補助的な要約モジュールを使い、エージェントの推論ストリームへ履歴コンテキストを再注入する前に圧縮します。この場合、RL または方策学習を用いて、いつ、どのように要約器を呼び出すかを決定します。たとえば **WebSailor** [Li25h] は外部要約器を用いて、複数ページの検索における閲覧軌跡を圧縮します。**ASearcher** [Gao25d] は、重要な発見を保持するため、複数ターンの調査セッションを動的に要約します。**RECON** [Xu25g] は、固定された事前学習済み要約器を RL ベースの検索エージェント（例：Search-R1）へ統合します。教師あり関連性事前学習と多面的蒸留によって学習された要約器により、エージェントは簡潔で事実に即した証拠について推論でき、コンテキスト長とコストを大幅に削減できます。

<span id="section-3-4"></span>

### 3.4 マルチエージェント協調

単一の LLM に推論と検索の双方を担わせるだけでなく、高度な agentic search システム [Che25t, Wan25t] は、クエリ書き換え [Ma23]、文書選択 [Ke24]、推論制御など、複数の専門モジュールへプロセスを分解します。続いて RL を用いて個別エージェントの目的を整合させ、いつ再構成するか、どの証拠を保持するか、検索ステップをどう配置するかといった局所的な判断が、全体として一貫性があり効率的な検索に寄与するようにします。既存手法は、大きく（i）*planner-executor アーキテクチャ*と（ii）*協調型マルチエージェントシステム*に分類できます。

<span id="figure-04"></span>

![図 4。マルチエージェント協調のための RL の概観。（a）*Planner-executor アーキテクチャ*：中央の planner が、タスク分解と動的なサブタスク割当てを行う専用 executor エージェントを調整する。（b）*協調型マルチエージェントシステム*：複数のエージェントが、通信、調整、報酬共有を通じて共有目的を共同で最適化する。](../../papers/rl-based-agentic-search/figure-04.png)

**図 4。** マルチエージェント協調のための RL の概観。（a）*Planner-executor アーキテクチャ*：中央の planner が、タスク分解と動的なサブタスク割当てを行う専用 executor エージェントを調整します。（b）*協調型マルチエージェントシステム*：複数のエージェントが、通信、調整、報酬共有を通じて共有目的を共同で最適化します。

<span id="section-3-4-1"></span>

#### 3.4.1 Planner-Executor アーキテクチャ

代表的なパラダイムは *planner-executor アーキテクチャ*であり、高レベルの planner が、個別の検索または推論操作を担う専用 executor を統率します。[図 4](#figure-04)（a）に示すように、planner はメタ方策として機能し、どの executor を呼び出すか、いつサブタスクを切り替えるか、検索または計算の予算をどのように割り当てるかを決め、異種の RAG モジュールにまたがる*適応的な統率*を実現します。

**MAO-ARAG** [Che25t] はこの設計の一例です。マルチエージェント RAG を*マルチエージェント半マルコフ決定過程（MSMDP）*としてモデル化し、planner がクエリ rewriter、文書 selector、retriever、generator などの executor を調整します。具体的には、planner エージェントは、妥当なコストを維持しながら高品質な回答を目指し、これらの executor から適切なエージェントを知的に選択して統合し、各クエリに合わせた適切なワークフローを構築します。各ターンで planner エージェントは PPO によって学習され、次の報酬で最適化されます。

<span id="equation-06"></span>

$$
r_{t}=r_{\mathrm{F1}}-\alpha\cdot r_{\mathrm{CP}}-r_{\mathrm{FP}},
$$

ここで、$r_{\mathrm{F1}}$ は F1 スコアに基づく結果報酬、$r_{\mathrm{CP}}$ と $r_{\mathrm{FP}}$ はそれぞれコストペナルティと形式ペナルティです。これらの報酬は、コストを妥当な範囲に保ちながら、回答品質をともに改善します。

OPERA [Liu25x] は、この考え方をマルチホップ検索と推論へ拡張します。高レベルの計画モジュールと低レベルの実行エージェントからなる階層型 RL フレームワークを採用しています。*Plan*、*Analysis-Answer*、*Rewrite* という 3 つの役割固有エージェントを、細粒度で役割固有の信用割当を行う GRPO ベースのアルゴリズム、Multi-Agents Progressive GRPO（MAPGRPO）で最適化します。各エージェントは、それぞれに合わせた報酬信号で学習されます。Plan Agent には分解の妥当性、Analysis-Answer Agent には推論と事実の正確性、Rewrite Agent には検索の関連性と形式に対する報酬を与えます。この階層的な最適化は、安定した収束と解釈可能な推論軌跡をもたらし、OPERA がコスト効率に優れ、検証可能な検索と推論のワークフローを学習できるようにします。

<span id="section-3-4-2"></span>

#### 3.4.2 協調型マルチエージェントシステム

別のワークフローでは agentic search を協調型マルチエージェントゲームとしてモデル化し、各モジュールを、その行動が検索結果に影響を与える RL エージェントとして扱い、共有された大域報酬によって、より高い性能を目指して行動を整合させます。全体のフレームワークを [図 3](#figure-03)（b）に示します。たとえば SIRAG [Wan25t] は、いつ検索するかを決める Decision-Maker と、どの文書を後続処理へ渡すかを絞り込む Knowledge-Selector を学習し、RL 報酬によってそれらの判断を高品質な証拠統合へ整合させます。MMOA-RAG [Che25q] は、この設定をより大きなエージェントプールへ一般化し、クエリ再構成、証拠選択、検証の責任をエージェントがどのように分担するかを RL で最適化します。さらに AgentGym-RL [Xi25b] や Chain-of-Agents [Li25j] などの研究は、マルチエージェントシステムを学習するための汎用基盤を提供しており、agentic search が中核的な評価設定となっています。

<span id="section-3-5"></span>

### 3.5 ツールと知識の統合

最後に、agentic search では、エージェントが解決できるタスクの範囲を拡張するため、テキスト検索だけに依存せず、API [Jia25a]、マルチモーダルツール [Wan25ai, Gen25a]、構造化知識ベース [Cha25c, Hao25b] など、異種の外部リソースとの統合がますます必要になっており、RL はそれを可能にする自然な解決策です。このカテゴリの研究は 2 つの方向に分けられます。すなわち、エージェントが検索エンジン、コードインタープリター、視覚モデルなどの多様なツール群を連携して使うことを学習する（i）*複数ツール・複数モダリティ推論*と、知識グラフや表などの記号的環境を目標指向的に探索するよう RL がエージェントを学習する（ii）*構造化知識の探索*です。

<span id="section-3-5-1"></span>

#### 3.5.1 複数ツール・複数モダリティ推論

多くのタスクはテキストベースの検索だけでは足りず、計算、Web 検索、マルチモーダル理解を組み合わせることがエージェントに求められます。ツール呼び出しが正確な推論またはタスク完了につながったかについてフィードバックを与えることで、RL はツールの選択と実行順序を最適化するために使われています。Tool-Star [Don25e] は検索エンジンやコード生成器を含む 6 つのツールを統合し、正しい中間出力に報酬を与える自己 critic 型の RL 設定を用います。VerlTool [Jia25a] は、異種 API とマルチモーダル LLM（MLLM）を管理する統一的な RL フレームワークによって、これを一般化します。マルチモーダルな状況では、MMSearch-R1 [Wu25s]、Visual-ARFT [Liu25z]、VRAG-RL [Wan25ai] が、検索したテキストと視覚的な証拠を整合させる方策に報酬を与えることで、Search-R1 のパラダイムを視覚質問応答へ拡張します。WebWatcher [Gen25a] はさらに、テキスト入力と視覚入力の双方を処理しながら、複数のツールを同時に連携させるよう RL でエージェントを学習します。

<span id="section-3-5-2"></span>

#### 3.5.2 構造化知識のナビゲーション

多くの領域では、重要な情報が知識グラフ（KG）やデータベースなどの構造化リソースに格納されています [Bol08, Zho17b, Lin24f, Lin25g]。探索を逐次的な意思決定過程として定義することで RL を適用します。各ステップでは、どのエンティティまたは関係をたどるかを選び、正確性、網羅性、効率性を反映した報酬を与えます。たとえば GRAIL [Cha25c] は、正解へ効率的に到達する KG 探索方策を学ぶために RL を適用します。DynaSearcher [Hao25b] はこれを複数報酬 RL で拡張し、正確性、効率性、KG の均衡の取れた探索を共同で最適化します。

## 4 RL はどのように使われるか：最適化戦略

本節では、学習パイプライン、アルゴリズム設計、報酬メカニズムを含め、agentic search システムに RL がどのように適用されるかを検討します。[表 7](#table-07) は、代表的な研究とそれぞれの最適化戦略をまとめたものです。

<span id="section-4-1"></span>

### 4.1 学習方式

学習方式は、初期化戦略、環境設計、最適化ワークフローを含め、RL を agentic search へどのように統合するかを定めます。対話ベースの学習を通じて、エージェントが意思決定方策をどのように獲得し、改良し、安定させるかを決定します。

<span id="section-4-1-1"></span>

#### 4.1.1 標準的な Agentic Search パイプライン

Search-R1 [Jin25b] に代表される agentic search の典型的な RL 学習パイプラインは、*コールドスタート*による初期化と、それに続く RL ファインチューニングという 2 つの段階で構成されます。コールドスタート段階では、インターフェースへの準拠（例：API 呼び出し、ツールスキーマ）を確保し、初期のロールアウトを安定させます。RL 学習中、方策 LLM は複雑なクエリを受け取り、シミュレーションまたは実際の検索環境内で、推論とツール利用の行動を交互に生成します。学習パイプライン全体とプロンプトテンプレートを [表 3](#table-03) にまとめます。

#### 4.1.2 コールドスタート

主流のパラダイムでは、RL 最適化の前に教師ありファインチューニング（SFT）によってエージェントを初期化します [Li25h, Wu25d, Don25e, Son25b]。この段階は、モデルに基礎的なタスク能力を与え、長期的な環境における疎な報酬が原因となる初期の不安定性を緩和します。たとえば Webagent-R1 [Wei25f] は、SFT が後続の RL に不可欠な Web 対話の知識を提供することを示し、WebSailor [Li25h] は SFT が収束を速め、複数ステップのツール利用を安定させることを明らかにしています。EvolveSearch [Zha25au] はさらに、自己改善型の SFT-RL ループを導入し、RL で改良された方策が、SFT を反復的に再学習するための新しい実演を生成します。一方で、複数の研究 [Sun25b, Xi25b] は SFT の必要性に疑問を呈しています。ZeroSearch [Sun25b] は SFT を潜在空間の検索シミュレーションに置き換え、外部の教師信号を用いない純粋な RL 学習を可能にします。AgentGym-RL [Xi25b] はカリキュラムベースでホライズンを拡張し、RL のみの学習を安定させます。

<span id="section-4-1-3"></span>

#### 4.1.3 シミュレーションベースの学習

実世界の検索環境で RL エージェントを学習することは、極めて高コストで時間がかかり、再現性に欠ける場合があります。シミュレーション環境は、制御可能で高速かつ費用効率に優れた代替手段となります。たとえば ZeroSearch [Sun25b] は、LLM を検索モジュールへ変換することで検索を*シミュレーション*する新しい RL フレームワークを提案し、学習中の実際の検索エンジンに伴うコストとノイズを避けます。シミュレーション文書の品質を段階的に低下させるカリキュラムを採用し、エージェントをより頑健にします。O<sup>2</sup>-Searcher [Mei25a] も、オープンドメインの自由回答型質問応答シナリオに焦点を当て、効率的なローカルシミュレーション検索環境を学習に活用します。WebSailor-V2 [Li25y] は二重環境の RL フレームワークを提案し、アルゴリズムを迅速に反復するための忠実度の高いシミュレーターと、最終方策を安定して学習するための頑健で管理された実世界環境を利用します。このハイブリッド手法は、スケーラビリティと現実性の双方の課題に対処します。

<span id="section-4-1-4"></span>

#### 4.1.4 RL アルゴリズム

RL ベースの検索エージェントの多くは方策勾配アルゴリズム、特に PPO [Sch17a]、GRPO [Sha24d]、Reinforce++ [Hu25d] を採用しています。近年の変種は、これらの手法を検索のコンテキストへ適応させています。Search Wisely [Wu25q] は不確実性を考慮した較正のために $\beta$-GRPO を導入し、StepSearch [Wan25ah] は情報利得に整合するステップ単位の PPO を実装し、ReinforceRAG [Zen25c] は疎な報酬のもとで分散を緩和するため、検索を考慮したベースラインで方策勾配を拡張します。RL ベースの検索エージェントに適用される RL アルゴリズムの詳細は [表 7](#table-07) に示します。

#### 4.1.5 カリキュラム学習とホライズンの拡張

長期的な検索タスクの RL 学習は、報酬の疎性と不安定な信用割当のため、依然として困難です。カリキュラム学習は、タスクの複雑さまたは対話の長さを徐々に拡大することで、これらの問題を緩和します。AgentGym-RL [Xi25b] は *ScalingInter-RL* を提案します。短く焦点を絞ったタスクから始め、複数ステップの推論へ徐々に拡張して対話ホライズンを段階的に延ばし、探索と活用の均衡を取ります。ZeroSearch [Sun25b] は、検索ノイズを体系的に増やすカリキュラムを採用し、エージェントにより回復力のある戦略の開発を促します。InfoSeek [Xia25d] も同様に、構造的な能力成長を促すため、次第に難しくなる調査タスクを生成します。これらの戦略は合わせて、収束の安定性を改善し、能力の継続的な拡張を支えます。

#### 4.1.6 反復型・自己進化型フレームワーク

静的なカリキュラムを超えて、一部のフレームワークはデータ生成と方策学習のループを閉じています。EvolveSearch [Zha25au] は、この手法の典型です。RL で学習したモデルがより高品質な検索軌跡を生成し、それが SFT データへ蒸留されて、改善の自己強化サイクルを作ります。このような反復型フレームワークは、RL が学習目的としてだけでなくデータ生成器としても機能し、モデルの行動と教師信号の品質の双方を継続的に改良できることを示しています。

### 4.2 報酬設計

報酬設計は、どの行動を強化し、複雑な軌跡にわたって信用をどのように割り当てるかを決定するため、agentic search の RL 学習において極めて重要です。現代の agentic search は、最終結果の正確性と中間推論だけでなく、明瞭性、真実性、簡潔性、効率性、ハルシネーション傾向の低減といった多様な要件も最適化する、*多面的で複数ターンの報酬メカニズム*を採用しています。こうした高度な報酬構造は、時間的な範囲（結果レベルかプロセスレベルか）と、目的の多様性（単一か多面的な最適化か）という 2 つの相補的な次元に沿って分類できます。[表 4](#table-04) は、近年の RL-based agentic search フレームワーク [Jin25b, Che25i, Dao25, Shi25d, Shi25e, Zha25at, Zha25ae, Liu25z] で採用された代表的な報酬関数をまとめ、最終回答の正確性、中間推論の品質、リソース効率に優れた検索の間で、設計ごとにどのように均衡を取るかを示しています。

<span id="section-4-2-1"></span>

#### 4.2.1 結果レベルの報酬

結果レベルの報酬は最終的なタスク完了を評価しますが、単純な正確性を超える複数の品質次元をますます取り込んでいます。Search-R1 [Jin25b] や ReSearch [Che25i] などの初期手法は、正確性と形式の一貫性に対する基本的な完全一致（EM）報酬と形式報酬に依存しています。その後の**多面的な**拡張は、これらの指標を強化します。R-Search [Zha25at] は*モデル間の証拠有用性*を導入し、正確性に加えて証拠の品質と解釈可能性に報酬を与えます。IKEA [Hua25e] は*知識境界シェーピング*を設計し、冗長な検索を抑制することで正確性と効率性の双方を最適化します。R1-Searcher++ [Son25b] は retriever の呼び出し回数の分散を通じて*グループ相対効率*を測定し、タスクの成功とリソース節約の均衡を取ります。O<sup>2</sup>-Searcher [Mei25a] は、予算制約のもとで重複を緩和するよう*クエリの多様性*を促す*多様性報酬*を導入します。

<span id="section-4-2-2"></span>

#### 4.2.2 プロセスレベルの報酬

結果信号は一般的なタスクには単純で有効ですが、長期的で複数ステップの検索環境では、学習を導くには疎すぎることがしばしばあります [Den25b]。プロセスレベルの報酬は、推論と検索の軌跡全体を通じて密で細粒度なフィードバックを与えることでこの制約に対処し、忠実性 [Shi25e] や効率性 [Wan25ah] などの中間行動に対する*複数ターンで多面的な*最適化を可能にします。ReasonRAG [Zha25ae] は*最短経路報酬推定*（SPRE）を導入し、起こり得る結果をシミュレーションして不必要に長い軌跡にペナルティを与えることで、推論の品質と簡潔性を同時に最適化します。StepSearch [Wan25ah] は、情報利得や冗長性ペナルティを含む複数の次元で各検索ステップの有用性を評価します。AutoRefine [Shi25e] は、ステップレベルの反復的な報酬を通じて、忠実で的を絞った知識抽出を強化します。こうした検証可能なルールベース報酬に加え、一部の研究 [Wan25t, Den25b] は、疎な報酬と学習の安定性に対処するため、または忠実な検索を可能にするため [Xu25h]、ステップレベルの報酬を与える LLM から報酬をサンプリングしています。

### 5.1 エージェントレベルの範囲

エージェントレベルでは、RL は、単一の自律検索エージェントまたは連携するマルチエージェント検索システムのいずれかについて、エンドツーエンドの検索方策を最適化します。この範囲は、効果的な情報探索行動を定義する中核的な検索意思決定過程を RL がどのように形作るかを捉えます。

<span id="section-5-1-1"></span>

#### 5.1.1 単一エージェントの最適化

これは最も一般的なパラダイムであり、エージェントの検索ワークフロー全体を支配する統一方策を RL が直接最適化します。エージェントは、いつ検索するか、クエリをどう組み立てるか、証拠をどう解釈するか、いつ検索を終了するかを学習します。Search-R1 [Jin25b] はこの手法の一例であり、推論中に外部検索エンジンをいつ、どのように呼び出すかを自律的に判断するよう LLM を学習します。R1-Searcher++ [Son25b] は、内部知識の利用と外部検索への依存の均衡を取ることで、この手法を拡張します。WebSailor [Li25h] や WebDancer [Wu25d] などの Web ベースのエージェントは、複雑な Web 環境向けの頑健で長期的な検索方策を学習する RL の可能性を示しています。

<span id="section-5-1-2"></span>

#### 5.1.2 マルチエージェント協調

より複雑な検索パイプラインでは、個別のエージェントが、クエリの再構成、文書選択、証拠統合など、検索に関係する機能を専門に担います。RL は、これらの専用検索エージェントを調整し、一貫した情報探索行動を実現します。SIRAG [Wan25t] は、検索のタイミングを制御する *Decision Maker* と、共有報酬関数のもとで検索文書を絞り込む *Knowledge Selector* を共同で学習します。MAO-ARAG [Che25t] は、複数の検索専門エージェント（例：クエリ再構成器、文書 selector、回答 generator）を統率し、RL によって協調的な検索性能を最適化します。

<span id="section-5-2"></span>

### 5.2 モジュールレベルおよびステップレベルの範囲

この範囲は、より広い agentic search ワークフロー内の特定の検索コンポーネントまたは意思決定ステップの最適化に焦点を当てます。エージェント方策全体をエンドツーエンドで学習する代わりに、RL は局所的な行動を改良するため、検索パイプラインの特定の側面を改善するのに有用です。

<span id="section-5-2-1"></span>

#### 5.2.1 モジュールレベルの最適化

RL は、固定された LLM と並行して動作する専用モジュールを強化できます。このモジュール型の手法は、モデル全体を再学習せず、検索固有の能力を分離して重点的に改善します。s3 [Jia25d] は、generator を固定したまま軽量な検索モジュールを学習し、効率性とモデル非依存の適応性を確保することで、この戦略を例示します。AI-SearchPlanner [Mei25b] も同様の設計に従い、最終回答の生成には固定された QA モデルを活用しながら、いつ、どのように問い合わせるかを決める検索計画モジュールを学習します。

<span id="section-5-2-2"></span>

#### 5.2.2 ステップレベルの最適化

RL は、クエリ生成、文書選択、改良など、個々の検索行動に対して細粒度なフィードバックを与えることもできます。StepSearch [Wan25ah] は、情報利得と冗長性ペナルティに基づくステップ単位の報酬を与え、簡潔で効果的な検索を促します。AutoRefine [Shi25e] は反復的な「search-and-refine」行動を強化し、情報収集を反復的に改善するようエージェントに促します。Search Wisely [Wu25q] は検索の信頼度を制御するために RL を適用し、リソースを浪費する低信頼度の検索を抑制します。

<span id="section-5-3"></span>

### 5.3 システムレベルの範囲

システムレベルでは、RL は包括的な検索基盤とマルチエージェント検索エコシステムを統率します。この範囲は個々の検索エージェントを最適化するのではなく、複雑な情報探索プラットフォーム全体にわたって、検索システムのアーキテクチャ、リソース割当て、検索ワークフロー管理を RL がどのように改善できるかを扱います。

<span id="section-5-3-1"></span>

#### 5.3.1 検索のための統一的な RL ベースフレームワーク

近年の複数の研究は、RL ベースの検索エージェントを開発、学習、評価するための汎用プラットフォームを構築しています。AgentGym-RL [Xi25b] は、複数の情報環境にわたって多様な RL アルゴリズムを支えるモジュール型ベンチマークスイートを提供します。RAG-Gym [Xio25a] は、検索拡張エージェントを最適化し、報酬設計と方策設計を体系的に比較するための構造化された環境を提供します。VerlTool [Jia25a] はこの傾向をツール拡張システムへ広げ、異種の情報源とモダリティを扱うエージェントを学習するための統一 API と環境を提供します。

### 6.1 データセット

RL-based agentic search は、オープンドメイン、Web ベース、ドメイン固有の環境で検索の有効性と推論能力を試す、多様なベンチマークで評価されます。[表 6](#table-06) は、これらの代表的なデータセットと、それを採用した研究をまとめたものです。以下で詳細を説明します。

<span id="section-6-1-1"></span>

#### 6.1.1 知識集約型 QA ベンチマーク

Agentic search の主要な評価設定は、モデルのパラメトリック知識を超える外部の証拠を検索しなければ質問に答えられない、*知識集約型質問応答（QA）*です。これらのベンチマークは、（i）関連情報を検索する能力と（ii）証拠を正しく検証可能な回答へ統合する能力を合わせて評価します。Natural Questions（NQ）[Kwi19a] と TriviaQA [Jos17] は、基礎的なシングルホップ QA データセットとして、Search-R1 [Jin25b] や R-Search [Zha25at] などの研究で広く用いられ、エージェントがいつ、どのように検索を呼び出すかを検証します。マルチホップ推論では、HotpotQA [Man18] が ReSearch [Che25i] と AutoRefine [Shi25e] で使用され、複数の証拠連鎖にわたる反復的な検索と推論を要求します。FEVER [Tho18] などのファクトチェックタスクは、検索の忠実性と証拠の検証をさらに試します。たとえば HARIS [Hu25e] は、RL 信号のもとで検索された主張の信頼性を評価するようエージェントを学習するために FEVER を使用します。

<span id="section-6-1-2"></span>

#### 6.1.2 Web ベースの検索ベンチマーク

Web 環境は、より現実的で動的な評価設定を提供します。WebQA [Cha22b] は、WebThinker [Li25l] で用いられる大規模な Web ベースの QA タスクを提供します。GAIA（General AI Assistant）は、推論とツールの連携が必要な複数ステップの対話型 Web タスクを定義し、AgentGym-RL [Xi25b] と WebSailor-V2 [Li25y] の主要なベンチマークとなっています。Mind2Web [Gou25] と関連する Web ナビゲーションデータセットは、WebDancer [Wu25d] などの Web エージェントが、マルチホップの Web 閲覧と行動計画を処理する能力を評価します。

<span id="section-6-1-3"></span>

#### 6.1.3 知識源

ほとんどのオープンドメインおよび Web ベースのエージェントは、大規模なテキストコーパスを検索バックエンドとして利用します。一般的な選択肢には、NQ、TriviaQA、HotpotQA などのベンチマークで広く用いられる英語版 Wikipedia ダンプ [Wik25]、Common Crawl [Com25] や KILT [Pet20] などの Web 規模のリソース、調査志向のエージェント [Zhe25f, Yu25i] を支える PubMed [Nat25] や arXiv [Arx25] などのドメイン固有知識ベースがあります。DeepResearcher [Zhe25f] や WebThinker [Li25l] など一部のシステムはさらに、最新情報または対象ドメインの情報へアクセスするため、これらの静的コーパスを動的な Web 検索 API で拡張します。

<span id="section-6-1-4"></span>

#### 6.1.4 マルチモーダル検索

agentic search の近年の進展 [Wu25s, Liu25z] はテキストのみの検索を超え、視覚的および構造化されたモダリティを取り込み、*マルチモーダル検索*のための新しいベンチマークを生み出しています。初期のデータセット、たとえば **InfoSeek** [Che23e] と **SlideVQA** [Tan23] は、スライドと図に対する視覚言語質問応答を確立し、知覚と推論を結びつけました。この基礎の上で [Liu25z] は、検証可能な報酬信号のもとで agentic な検索能力とツール利用能力を評価する *MAT-Search* と *MAT-Coding* を導入します。**MFC-Bench** [Wan24x] は、操作、文脈外、真偽判定という下位タスクにわたる $35k$ 件の画像・テキストサンプルを用いてマルチモーダルなファクトチェックをベンチマークし、事実的な根拠づけのための大規模なテストベッドを提供します。一方、**MMLongBench-Doc** [Ma24c] は長いコンテキストのマルチモーダル文書理解に焦点を当て、テキスト、レイアウト、表、グラフを組み合わせた $135$ 件の長文書を収録しています。これらのベンチマークは合わせて、RL-based agentic search を、知覚に根ざした統一的なマルチモーダル検索と推論へ前進させます。

<span id="section-6-1-5"></span>

#### 6.1.5 対話型・複数ターン検索

CoQA [Red19] と QuAC [Cho18] は、ConvSearch-R1 [Zhu25i] で検討されるような、複数ターンの対話にわたってコンテキストを維持するエージェントの能力を評価します。MSMarco [Baj16] は大規模な文書検索とランキングを評価し、DeepRetrieval [Jia25c] と RAG-Gym [Xio25a] で適用されているように、関連情報を効率的に見つけるエージェントの能力を測ります。

<span id="section-6-1-6"></span>

#### 6.1.6 ドメイン固有の検索タスク

一部の専用データセット [Wel17, Cla18, Tal19, Hen20] は、特定の推論領域を対象とします。たとえば SciQ [Wel17] と ARC [Cla18] は科学的推論に焦点を当て、DeepResearcher [Zhe25f] などのエージェントに関係します。CommonsenseQA [Tal19] は事実検索と常識推論の統合を試すもので、IKEA [Hua25e] で用いられています。MMLU [Hen20] は一般知識の広さを評価し、Tool-Star [Don25e] などのツール拡張システムに対するマルチドメインベンチマークとなります。

<span id="section-6-2"></span>

### 6.2 指標

RL-based agentic search の評価には、回答品質、検索の有効性、効率性、プロセスレベルの行動など、性能の複数の次元を捉える指標が必要です。

<span id="section-6-2-1"></span>

#### 6.2.1 回答品質

完全一致（EM）と F1 スコアは最も一般的に用いられる 2 つの指標であり、タスクの成功を直接測るものとして、多くの研究 [Jin25b, Dao25] で主要な評価指標となっています。生成された回答の品質を参照応答と比較して評価するため、ROUGE と BLEU スコアが生成回答の品質を参照応答と比較して評価します。回答が正しくても正解とは異なる表現になり得る場合に対処するため、RAG-Gym [Xio25a] では BERTScore [Zha19i] が適用されています。

<span id="section-6-2-2"></span>

#### 6.2.2 検索の有効性

検索された情報の品質を測るうえで、従来の複数の情報検索指標は今なお基礎的です。具体的には、*適合率*、*再現率*、*F1* が検索情報の品質を測ります。システムが複数の検索結果に優先順位を付ける必要がある場合、平均逆順位（MRR）と正規化割引累積利得（NDCG）がランキング品質を評価します。たとえば DeepRetrieval [Jia25c] は、再現率や NDCG などの検索指標でブラックボックス検索エンジンの検索性能を最大化するクエリを生成するよう LLM を学習します。

<span id="section-6-2-3"></span>

#### 6.2.3 検索効率

これは、リソースコストとレイテンシコストの両面から検索エージェントの効率を測ることを目的とします。*検索クエリ数* [Shi25d] はエージェントが発行したクエリ数を測り、*API 呼び出しコスト* [Che25t] は外部サービスを呼び出す費用を数量化します。*応答時間*はエンドツーエンドのレイテンシを評価するもので、対話的な環境で重要です。*検索の冗長性* [Son25b] は、リソースを浪費する反復的または意味的に類似したクエリを捉えます。

<span id="section-6-2-4"></span>

#### 6.2.4 プロセス指標

最終タスクの正確性だけでなく、複数の研究は中間行動を評価しています。StepSearch [Wan25ah] は、各検索行動の有用性を数量化するため、検索ステップごとの*情報利得*を定義します。SIRAG [Wan25t] は、生成されたクエリが関連する証拠を得られそうか評価するため、LLM-as-Judge を用いて*クエリ品質スコア*を測ります。R-Search [Zha25at] は、最終推論で検索情報をエージェントがどの程度有効に活用するかを測る*証拠利用率*を導入します。

<span id="section-6-3"></span>

### 6.3 応用

RL-based agentic search の進展により、科学研究、ソフトウェア開発、マルチモーダル推論、対話型 AI にまたがる幅広い実用的な応用が生まれています。

<span id="section-6-3-1"></span>

#### 6.3.1 Deep Research

科学・学術研究は、RL ベースの検索エージェントの主要な応用領域です。DeepResearcher [Zhe25f] は、学術データベースにわたる RL 最適化済み検索戦略を通じて、文献レビューと仮説生成の自動化を実現します。MedResearcher-R1 [Yu25i] は医学研究に特化し、RL を用いて複雑な生物医学知識ベースを探索し、臨床的な証拠を統合します。WebResearcher [Qia25c] は、制限のない推論ホライズンによって、一般的な Web ベース調査へ調査能力を拡張します。SFR-DeepResearch [Ngu25a] は調査タスクの自律的な推論に焦点を当て、Atom-Searcher [Den25b] は細粒度な原子的思考報酬を通じて deep research を強化します。WebThinker [Li25l] は、反復的なオンライン DPO によって多様な領域で包括的な調査能力を備えた deep research エージェントです。

<span id="section-6-3-2"></span>

#### 6.3.2 マルチモーダル検索

テキストのみの検索に加え、テキスト情報と視覚情報の双方を組み合わせるマルチモーダル検索エージェントを探究する近年の取り組みが複数あります [Wu25s, Wan25ai]。VRAG-RL [Wan25ai] は、視覚的に豊かな情報の理解に向け、視覚知覚ベースの RAG を可能にし、RL を用いてテキストと視覚コンテンツの双方について反復的に推論します。Visual-ARFT [Liu25z] は、視覚検索とテキスト検索を統合する必要があるタスクに対し、視覚的な agentic reinforcement fine-tuning を実証します。WebWatcher [Gen25a] は、Web 検索と視覚分析能力を組み合わせ、視覚言語 deep research エージェントの新境地を開きます。これらの応用は、商品検索で説明文と画像の双方を理解する必要がある e-commerce や、視覚データ分析を伴う科学研究などの領域で特に有用です。

<span id="section-6-3-3"></span>

#### 6.3.3 コードエージェント

典型的な検索関連の応用を超えて、RL 駆動型の検索エージェントはプログラミングとソフトウェア開発のワークフローへ統合されつつあります。Tool-Star [Don25e] は、コード実行とデバッグを含む複数ツール推論能力を実証し、RL を用いて検索エンジン、コードインタープリター、その他の開発ツールを連携させます。VerlTool [Jia25a] は、他の API とともにコードインタープリターを明示的に支援する、ツール利用を伴う agentic RL の統一フレームワークを提供します。これによりエージェントは、コードの解決策を検索して実行し、実装を反復的に改良できます。これらのシステムは、コーディングの解決策を探す Web 検索と直接的なコード実験の均衡を学習し、情報収集と実装効率の双方を最適化します。

<span id="section-6-3-4"></span>

#### 6.3.4 AI アシスタント

対話型 AI は RL ベースの検索エージェントの展開領域として成長しており、素朴なチャットボットをはるかに超えて、さまざまな現実的タスクを処理できるパーソナルアシスタントのようなものです。たとえば ConvSearch-R1 [Zhu25i] は対話型検索のシナリオに特に取り組み、RL を用いてクエリの再構成を強化し、複数ターンの対話にわたってコンテキストを維持します。Lucy [Dao25a] は、機械生成されたタスクベクトルを用いてモバイル端末上で動作する agentic Web 検索を実証し、リソース制約のある環境への実用的な展開を示します。MAO-ARAG [Che25t] はマルチエージェント統率を通じて適応的な検索拡張生成を実現し、応答品質と計算効率の均衡を取る必要がある知的アシスタントの応用に適しています。これらのシステムは RL を用いてユーザーの意図を理解し、関連情報を検索し、会話の流れを維持しながらコンテキストに適した応答を提供することを学習します。

<span id="section-6-3-5"></span>

#### 6.3.5 ドメイン固有の応用

前述の一般的な応用に加え、RL ベースの検索エージェントは、特定の知識領域とユーザーの需要に合わせた専門領域にも適用されています。たとえば HierSearch [Tan25d] は、ローカル知識ベースと Web 検索を統合して企業の情報管理需要に対処する、企業検索フレームワークを提示します。KunLunBaizeRAG [Li25ab] は、ドメイン固有の RAG シナリオにおける大規模言語モデルの推論性能の最適化に焦点を当てます。DynaSearcher [Hao25b] は、構造化された情報検索のために動的な知識グラフ（KG）で拡張した検索を実証し、関係データが豊富な領域で特に有用です。GRAIL [Cha25c] は、RL を通じて検索拡張推論のための対話的な KG 探索を可能にします。

<span id="section-6-3-6"></span>

#### 6.3.6 要点

応用の多様性は、RL-based agentic search システムの幅広い適用可能性と実用的な価値を示しています。コード開発 [Don25e] から科学研究 [Zhe25f]、マルチモーダル理解 [Wu25s]、対話型 AI [Zhu25i]、専門領域 [Tan25d] まで、これらのシステムは複数の分野における実世界の情報探索課題に取り組みます。これらの応用の成功は、実運用におけるドメイン固有の適応、マルチモーダル能力、効率的なリソース管理の重要性を浮き彫りにしています。今後の応用では、モダリティとドメインの間の統合がさらに進み、RL によってエージェントがタスク要件とユーザーコンテキストに基づき、検索戦略を動的に適応させるようになると考えられます。

<span id="section-7"></span>

## 7 課題と今後の方向性

RL-based agentic search は著しい進展を遂げましたが、多くの根本的な課題と機会が残されています。本節では、技術的な制約と実世界への展開で新たに生じる要件の双方を扱い、知的検索エージェントの進化を形作る主要な今後の方向性を論じます。

**マルチモーダル Agentic Search。** 実世界の情報は、テキスト、画像、動画、音声、構造化データを含む複数のモダリティにまたがって存在します。現在の RL ベース検索エージェントは主にテキスト情報に焦点を当てており、多様なコンテンツ種別にわたる理解と推論を必要とする複雑なマルチモーダル情報探索タスクへの適用が制限されています。初期の取り組み [Wu25s, Wan25ai, Gen25a] により、検索エンジンを通じて視覚言語モデル [Bor24, Gao25f, Wu25t] の推論を支援できるようになりましたが、根本的な制約が複数残されています。すなわち、（i）検索を統合した推論中に、テキスト記述と視覚コンテンツの一貫性をどう確保するか、（ii）マルチモーダル検索タスクの成功にどのモダリティが最も寄与するかをどう判断するか、（iii）関連性、一貫性、クロスモーダルな整合性を共同で捉える報酬関数をどう設計するかです。エージェントが異種の情報源を適応的に選択、統合、推論して、自由形式の実世界クエリを解決できる、頑健なマルチモーダル agentic search へ進むには、これらの課題への対処が不可欠です。

**メモリ拡張型・長期的検索。** 実世界の情報探索は複数のセッションにまたがることが多く、エージェントは過去のクエリ、検索した証拠、ユーザーのフィードバックを記憶しなければなりません。現在の RL ベース検索エージェント [Jin25b, Zha25at] は通常、限られたコンテキストウィンドウ内で動作し、情報を長期的に保持して検索するための高度なメモリ機構を欠いています。いくつかの初期の取り組み [Ngu25a, Wu25l] は要約やクリーンアップ操作など単純なメモリ管理技術を検討していますが、長期的な対話とセッションをまたぐ連続性が必要な、より複雑なタスクには依然として対応が困難です。長期的なシナリオで agentic search を進歩させるため、今後の研究では、検索に関係する知識を時間にわたって選択的に保存、整理、検索できる高度なメモリアーキテクチャの開発を検討すべきです。有望な方向性には、（i）短期作業記憶、セッションをまたぐエピソード記憶、長期意味記憶を区別する*階層型メモリシステム*、（ii）長期的な有用性に基づき、検索情報のどれを保持、圧縮、破棄するかを RL 信号で決める*選択的メモリ*機構、（iii）エージェントが情報の減衰、関連性の変化、進化するユーザー意図をモデル化できる*時間推論の統合*があります。

**信頼できる Agentic Search。** オープンな環境で動作する検索エージェントは、ユーザーの信頼に直接影響する、差し迫ったセキュリティ、倫理、信頼性の課題に直面します。これらのエージェントは、敵対的なコンテンツ、誤情報、または有害な目的で行動を操作しようとする悪意ある主体に遭遇する可能性があります。既存研究は、検索拡張システムの重大な脆弱性を明らかにしています。たとえば PoisonedRAG [Zou25a] は、悪意ある知識を注入することで RAG を誤誘導し、不正確または安全でない出力を生じさせられることを示しています。Search Wisely [Wu25q] は過信を緩和するために不確実性を考慮した検索を探究していますが、敵対的な条件のもとで検索エージェントがどのように機能するか、実世界への展開で頑健性をどう保証するかは不明です。さらに、これらのエージェントは機密情報と頻繁にやり取りするため、プライバシー保護、倫理的な情報利用、データガバナンス規制への準拠が懸念されます。今後の研究は、信頼でき、プライバシーを保護し、倫理的に整合した検索エージェントをどのように開発するかを検討すべきです。有望な方向性には、（i）汚染またはノイズを含む検索環境にエージェントをさらして回復力のある方策を学習させる*敵対的に頑健な RL 学習*、（ii）機密性の高いユーザー情報を保護するための、連合型または暗号化された検索エージェントなどの*プライバシー保護型 agentic search*、（iv）最適化目的に公平性、透明性、安全性の制約を組み込む*価値に整合した報酬設計*、（v）開発者とエンドユーザーの双方がエージェントの行動を解釈、監視、評価できる*監査・検証ツール*があります。結論として、これらの手法は RL-based agentic search を、有効であるだけでなく、実世界の応用に対して安全、倫理的、信頼できるシステムへ近づけます。

**クロスドメイン汎化。** 現在の RL ベース検索エージェントは、特定のドメインまたはタスク向けに学習されることが多く、汎化可能性が制限されています。実世界への展開には、多様なドメインとコンテキストにわたって検索戦略を適応できるエージェントが必要です。この課題を解決し、agentic search をより広い応用へ拡張するため、今後の研究は、多様なコンテキストへ適用できる汎化可能な検索原理の学習に焦点を当てられます。たとえば、考えられる解決策の 1 つは、異なる情報空間の間で転移できる汎用的な検索戦略を作るためにメタ学習手法を開発するか、ドメイン固有の検索要件を自動的に特定して適応できるエージェントを構築することです。

**人間と AI の協調検索。** 従来の IR システムは、人間を主なエンドユーザーとして設計されていました [Mar06, Whi09]。大規模 AI システムへの検索の統合は、特に LLM の台頭に伴い、このパラダイムを変えました。検索はもはや人間の利用だけを目的として実行されるのではなく、モデルの推論能力と生成能力を高めるためにも利用されることが増えています [Xu25f]。この変化は、*人間と AI エージェントが探索的検索にどのように協調して関わるか*という根本的な問いを提起します。RL-based agentic search システムは、この転換に向けた自然な基盤を提供します。RL は対話とフィードバックを通じて、進化するユーザー意図とコンテキスト上の手がかりに整合した適応的な検索方策をエージェントが学習できるようにし、エージェントが情報の発見、解釈、統合を支援するコパイロットとして働く*人間と AI の協調検索*を促します。今後の研究では、（i）RL エージェントがユーザーの選好と検索行動を学習して、戦略と結果表示を個別化する*適応的な対話モデリング*、（ii）エージェントが検索の選択理由を説明し、透明性を高める*説明可能な検索推論*、（iii）自然言語対話を通じて検索目標を反復的に再構成できる*協調的なクエリ改良*を検討できるでしょう。

## 8 結論

RL を agentic search へ統合することは、LLM が外部知識と対話する方法の根本的な転換を示します。素朴な RAG とは異なり、RL によってエージェントは*いつ*、*何を*、*どのように*検索するかを動的に決められるようになり、検索を適応的で対話的なプロセスへ変えます。本サーベイは、RL-based agentic search を初めて体系的に概観し、（i）*RL は何のために使われるか*、（ii）*RL はどのように使われるか*、（iii）*RL はどこに適用されるか*という 3 つの観点に沿って研究を統合しました。さらに、評価指標、システムベンチマーク、代表的な応用を検討し、現在の進展を比較できる視点を提示しました。将来に目を向けると、RL-based agentic search には情報検索と推論を再定義する可能性があります。本サーベイが、この新興分野の研究を進める基盤となり、実用的で頑健かつ知的な agentic search システムに向けた新たな方向性を促すことを願っています。
