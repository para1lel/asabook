## 概要

本稿では、20 億パラメータ規模で初のオープンソースかつネイティブな 1-bit 大規模言語モデル（LLM）である BitNet b1.58 2B4T を提示する。4 兆トークンのコーパスで訓練した本モデルを、言語理解、数学的推論、コーディング能力、対話能力を対象とするベンチマークで厳密に評価した。その結果、BitNet b1.58 2B4T は、同規模の主要なオープンウェイト・全精度 LLM と同等の性能を達成しながら、メモリ使用量、エネルギー消費、デコード遅延を大幅に削減するなど、計算効率に顕著な利点を持つことが分かった。今後の研究と利用を促すため、モデルの重みを Hugging Face で公開し、GPU および CPU アーキテクチャ向けのオープンソース推論実装も併せて提供する。

## 1 はじめに

オープンソースの大規模言語モデル（LLM）は、高度な AI 能力へのアクセスを広く開放し、自然言語処理、コード生成、ビジョンコンピューティングなど多様な分野で技術革新と研究を可能にするうえで中心的な役割を担うようになった [Dub24, Qwe25, Bai25a]。一般公開されているため、幅広い実験と適応が可能である。しかし、より広く普及するうえでは、大量の計算資源をデプロイと推論に要することが大きな障壁となっている。最先端のオープン LLM は通常、大量のメモリを必要とし、多くのエネルギーを消費し、推論遅延も無視できないため、多くのエッジデバイス、資源制約のある環境、リアルタイムアプリケーションには実用的でない。

1-bit LLM は、重みと、場合によっては活性化値を二値 $\{-1,+1\}$ または三値 $\{-1,0,+1\}$ に制約する、極端ながら有望なモデル量子化の形態であり、効率上の課題に対する有力な解決策となる。重みの格納に必要なメモリを大幅に削減し、高効率なビット演算を可能にすることで、デプロイコストとエネルギー消費を著しく抑え、推論を高速化できる可能性がある。先行研究でも 1-bit モデルは検討されてきたが、既存のオープンな取り組みは、1）事前学習済み全精度モデルに適用する学習後量子化（PTQ）手法で、大幅な性能低下を招く可能性があるもの [Xu24h, Tea24b]、または 2）比較的小規模で開発され（たとえば OLMo-Bitnet-1B [+1]）、より大規模な全精度モデルにまだ及ばない可能性があるネイティブ 1-bit モデル（1-bit 重みでスクラッチから訓練したモデル）の 2 種類に大別される。この性能差により、これまで 1-bit LLM の実用上の影響は限られていた。

効率と性能の隔たりを埋めるため、本稿では、大規模に訓練した初のオープンソースかつネイティブな 1-bit LLM、BitNet b1.58 2B4T を提示する。20 億のパラメータからなる本モデルは、1-bit パラダイムに特化したアーキテクチャと訓練上の工夫を利用し、4 兆トークンの大規模データセットでスクラッチから訓練した。**本研究の中心的な貢献は、ネイティブ 1-bit LLM を大規模かつ効果的に訓練すれば、幅広いタスクにおいて、同規模の主要なオープンウェイト・全精度モデルに匹敵する性能を達成できることを示した点にある。**

本技術報告では、BitNet b1.58 2B4T の開発と評価を詳述する。アーキテクチャと訓練手法を説明した後、言語理解、数学的推論、コーディング能力、複数ターンの対話能力を測る標準ベンチマークでの包括的な評価結果を示す。評価から、既存の全精度ベースラインに比べて高い性能を持ち、同時に効率面でも大きく優れることが確認された。最後に、BitNet b1.58 2B4T のモデル重みを Hugging Face で公開し、GPU と CPU の双方に最適化したオープンソース推論コードを提供することを発表し、これによって研究の進展と高効率 LLM の実用的なデプロイを促すことを目指す。

## 2 アーキテクチャ

BitNet b1.58 2B4T のアーキテクチャは標準の Transformer モデル [Vas17] から派生しており、BitNet フレームワーク [Wan23, Ma24] に基づく大幅な変更を取り入れている。モデル全体をスクラッチから訓練する。

アーキテクチャ上の中心的な工夫は、標準の全精度線形層（*torch.nn.Linear*）を独自の *BitLinear* 層に置き換えたことである。これは BitNet の手法の基礎をなす。これらの *BitLinear* 層では、次の処理を行う。

- **重み量子化：** 順伝播時にモデルの重みを 1.58 bit へ量子化する。重みを三値 $\{-1,0,+1\}$ に写像する絶対平均（absmean）量子化方式を用いる。これによりモデルサイズが大幅に縮小し、効率的な数値演算が可能になる。
- **活性化量子化：** 線形射影を通る活性化値を 8-bit 整数に量子化する。トークン単位で絶対最大値（absmax）量子化を適用する。
- **正規化：** 量子化訓練で特に有効となり得る訓練安定性の向上を目的として、`subln` 正規化 [Wan22l] を取り入れる。

*BitLinear* 層に加え、性能と安定性を高めるため、確立された複数の LLM 技術を統合している。

- **活性化関数（FFN）：** フィードフォワードネットワーク（FFN）のサブレイヤでは、一般的な SwiGLU 活性化 [Sha20] の代わりに、BitNet b1.58 2B4T は二乗 ReLU（$\mathrm{ReLU}^{2}$）を用いる。この選択は、1-bit の文脈でモデルのスパース性と計算特性を改善できる可能性に基づく [Wan24af, Wan24ag]。
- **位置埋め込み：** 位置情報を付与するために、現代の高性能 LLM で標準的に用いられる Rotary Position Embeddings（RoPE）[Su24] を採用する。
- **バイアスの除去：** LLaMA などのアーキテクチャと同様に、ネットワーク全体の線形層と正規化層からすべてのバイアス項を除き、パラメータ数を減らすとともに量子化を単純化し得る構成とする。

トークン化には、LLaMA 3 [Dub24] 向けに開発されたトークナイザを採用する。このトークナイザは、語彙サイズ 128,256 トークンのバイトレベル Byte-Pair Encoding（BPE）方式を実装している。この選択により、多様なテキストとコードを堅牢に処理できるうえ、このトークナイザが広く採用されているため、既存のオープンソースツールやエコシステムと容易に統合できる。

## 3 訓練

BitNet b1.58 2B4T の訓練は、大規模事前学習、教師あり微調整（SFT）、直接選好最適化（DPO）の 3 段階で行った。Proximal Policy Optimization（PPO）や Group Relative Policy Optimization（GRPO）などの高度な手法により、数学や思考連鎖推論などの能力をさらに高められるが [Sch17a, Sha24d]、現行版の BitNet b1.58 2B4T が使用するのは事前学習、SFT、DPO のみである。強化学習手法の検討は今後の課題とする。

<span id="section-3-1"></span>

### 3.1 事前学習

事前学習段階では、モデルに幅広い世界知識と基礎的な言語能力を付与することを目指した。確立された LLM の手法 [Dub24] から一般的な訓練戦略を取り入れ、1-bit アーキテクチャに合わせて調整した。

<span id="section-3-1-1"></span>

#### 3.1.1 学習率スケジュール

2 段階の学習率スケジュールを用いた。

- **第 1 段階（高学習率）：** 初期段階では標準的なコサイン減衰スケジュールを用いるが、比較的高いピーク学習率から開始した。この判断は、1-bit モデルが全精度モデルより高い訓練安定性を示す場合が多く、初期により積極的な学習ステップを取れるという観察に基づく。
- **第 2 段階（クールダウン）：** 計画した訓練トークン数のおよそ中間地点で学習率を急激に下げ、その後は著しく低いピーク値を持つコサインスケジュールで維持した。この「クールダウン」段階により、モデルはより高品質なデータ上で表現を洗練できる（[第 3.1.3 節](#section-3-1-3) を参照）。

<span id="section-3-1-2"></span>

#### 3.1.2 重み減衰スケジュール

学習率の調整を補完するため、2 段階の重み減衰戦略を実装した。

- **第 1 段階：** 最初の訓練段階では、重み減衰をコサインスケジュールに従って変化させ、ピーク値 $0.1$ に到達させた。この正則化は、初期の高学習率段階における過学習を防ぐのに役立つ。
- **第 2 段階：** 第 2 段階では、重み減衰を実質的に無効化した（0 に設定）。これにより、低い学習率と選別したデータに導かれ、モデルのパラメータはより細粒度の最適解に収束できる。

<span id="section-3-1-3"></span>

#### 3.1.3 事前学習データ

事前学習コーパスは、大規模なウェブクロールである DCLM [Li25a]、教育用ウェブページの FineWeb-EDU [Pen24] など、一般公開されたテキストとコードのデータセットを混合したものである。数学的推論能力を高めるため、合成した数学データも取り入れた。データ提示戦略は 2 段階の訓練に合わせ、一般的なウェブデータの大部分を第 1 段階で処理し、学習率を下げた第 2 段階のクールダウンでは、より高品質に選別したデータセットを重視した。

<span id="section-3-2"></span>

### 3.2 教師あり微調整（SFT）

事前学習後、指示追従能力を高め、対話形式での性能を改善するため、モデルに教師あり微調整（SFT）を施した。

<span id="section-3-2-1"></span>

#### 3.2.1 SFT データ

SFT 段階では、一般公開された多様な指示追従・対話データセットを使用した。これらには WildChat [Zha24ac]、LMSYS-Chat-1M [Zhe23c]、WizardLM Evol-Instruct [Xu24i]、SlimOrca [Lia23] などが含まれるが、これらに限らない。特に推論と複雑な指示への忠実な追従といった特定の能力をさらに強化するため、GLAN [Li24u] や MathScale [Tan24c] などの手法で生成した合成データセットを追加した。

<span id="section-3-2-2"></span>

#### 3.2.2 チャットテンプレート

SFT および推論時の対話タスクでは、次の構造のチャットテンプレートを用いた。

```text
<|begin_of_text|>System: {system_message}<|eot_id|>
User: {user_message_1}<|eot_id|>
Assistant: {assistant_message_1}<|eot_id|>
User: {user_message_2}<|eot_id|>
Assistant: {assistant_message_2}<|eot_id|>...
```

<span id="section-3-2-3"></span>

#### 3.2.3 最適化の詳細

SFT では、複数の最適化上の選択が重要だった。

- **損失の集約：** バッチ内のトークン間で交差エントロピー損失を平均する（mean reduction）のではなく、総和を用いた。実験上、損失を合計することで、本モデルの収束と最終性能が改善することが分かった。
- **ハイパーパラメータ調整：** 学習率と訓練エポック数を慎重に調整した。事前学習での知見と同様に、1-bit モデルでは、一般的な全精度モデルの微調整より比較的大きな学習率が SFT でも有効だった。さらに、最適な収束を達成するには、同規模の全精度モデルより多いエポック数へ微調整期間を延長する必要があった。

<span id="section-3-3"></span>

### 3.3 直接選好最適化（DPO）

有用性と安全性に関する人間の選好へモデルの振る舞いをさらに整合させるため、SFT 段階の後に Direct Preference Optimization（DPO）[Raf23] を適用した。DPO は、選好データを用いて言語モデルを直接最適化し、別個の報酬モデルを訓練する必要をなくすことで、従来の RLHF に代わる効率的な手法となる。この DPO 段階では、実用的な利用場面で望まれる対話パターンに合うよう、モデルの対話能力と全体的なアラインメントを洗練した。

<span id="section-3-3-1"></span>

#### 3.3.1 訓練データ

DPO 訓練に用いた選好データセットは、モデル出力に対する多様な人間の判断を捉えることで知られる公開リソースを組み合わせて構築した。具体的には UltraFeedback [Cui24a] と MagPie [Xu24j] を使用した。これらのデータセットを統合することで、堅牢で多面的な選好信号を得て、人間の期待により沿った応答を生成するようモデルを導いた。

<span id="section-3-3-2"></span>

#### 3.3.2 訓練の詳細

DPO の訓練段階は 2 エポック実施した。学習率には $2\times 10^{-7}$ を用い、参照方策からの乖離を制御する DPO のベータパラメータは 0.1 に設定した。この段階の訓練効率を高めるため、*Liger Kernel* ライブラリ [Hsu24a] の最適化済みカーネルを統合した。定性的な観察では、DPO の過程により、事前学習と SFT で確立した中核能力を大きく損なうことなく、モデルを望ましい応答スタイルへ効果的に導けた。

### 4.1 主な結果

[表 1](#table-01) に示すとおり、BitNet b1.58 2B4T は際立った資源効率を示す。デコード時の埋め込みを除くメモリ使用量と推定エネルギー消費 [Hor14, Zha22g] は、評価対象のすべての全精度モデルより大幅に少なく、運用コストと資源制約のあるデバイスへのデプロイ可能性における大きな利点を示している。

タスク性能の面でも、BitNet b1.58 2B4T は高い競争力を持つ。推論、知識、数学能力にまたがる複数のベンチマークで、比較モデル中最高の結果を達成している。ほかのベンチマークでも、性能は上位の全精度モデルに近い。一部の全精度モデルは、特定のタスクまたは全体平均でわずかに優れるものの、BitNet b1.58 2B4T は全般に高い性能を示す。この結果は、効率を劇的に改善しながら、BitNet b1.58 2B4T が同じ規模区分の主要モデルとほぼ同等の能力を達成することを示している。

<span id="section-4-2"></span>

### 4.2 学習後量子化モデルとの比較

さらに、標準的な INT4 手法（GPTQ と AWQ）で学習後量子化（PTQ）した主要な競合モデル Qwen2.5 1.5B と BitNet b1.58 2B4T を比較し、効率と性能のトレードオフを調べる。結果を [表 2](#table-02) にまとめる。

INT4 量子化は全精度モデルのメモリ使用量を削減できるが、BitNet b1.58 2B4T はネイティブ 1-bit アーキテクチャにより、さらに少ないメモリで動作する。より重要なのは、この優れたメモリ効率が量子化モデルに対する性能を犠牲にしていない点である。標準的な PTQ 手法は、元の全精度モデルと比べて明らかな性能低下を引き起こす。これに対し、評価したベンチマークにおいて、BitNet b1.58 2B4T の全体性能は Qwen2.5-1.5B の INT4 量子化版を上回る。この比較から、BitNet b1.58 2B4T は、既存アーキテクチャに従来の INT4 PTQ を適用するよりも効率と性能の曲線上で望ましい位置にあり、少ない資源使用量で高い性能を提供することが分かる。

### 4.3 オープンウェイト 1-bit モデルとの比較

最後に、1-bit に近い精度向けに設計または量子化したほかのモデルの中に BitNet b1.58 2B4T を位置づける。小規模なネイティブ訓練の 1-bit モデル、および学習後に 1.58-bit 精度へ量子化した大幅に大規模なモデルと比較する。比較結果を [表 3](#table-03) に示す。

評価結果は、BitNet b1.58 2B4T がこの区分を代表するモデルであることを明確に示している。比較対象のほかのすべての 1-bit モデルを全体性能で大幅に上回り、大半のベンチマークで最高スコアを達成する。とりわけ BitNet b1.58 2B4T は、小規模なネイティブ訓練の 1-bit モデルだけでなく、1-bit へ量子化したパラメータ数のはるかに多いモデルも大幅に上回る。この結果は、BitNet b1.58 2B4T が採用したネイティブ訓練手法の有効性を示し、この手法により、極端な量子化水準で動作するモデルの性能を新たな最先端へ引き上げ、学習後量子化を施した大規模モデルさえ上回ることができる。

## 5 推論実装

大規模言語モデルのデプロイ、特に資源制約のある環境へのデプロイには、効率的な推論が不可欠である。1.58-bit 重みと 8-bit 活性化値（W1.58A8）を用いる BitNet b1.58 2B4T 独自の量子化方式には、特化した実装が必要となるが、これは標準的な深層学習ライブラリには、このような混合精度・低ビット形式向けに最適化されたカーネルがない場合が多いためである。この問題に対処するため、GPU と CPU の両プラットフォームに向けた専用推論ライブラリを開発し、オープンソースで公開した。コードは [https://aka.ms/bitnet](https://aka.ms/bitnet) で公開している。

<span id="section-5-1"></span>

### 5.1 GPU 推論

現在の GPU アーキテクチャと関連ソフトウェアライブラリ（たとえば cuBLAS、PyTorch カーネル）は、主に FP16、BF16、INT8/INT4 などの標準データ型を用いる演算向けに最適化されている。BitNet b1.58 2B4T が必要とする W1.58A8 行列乗算をネイティブかつ高性能にサポートする仕組みは、一般に利用できない。この制約により、既存ハードウェア上では、1-bit モデルが理論上もたらす効率向上を実現できない場合がある。

GPU 上で効率的に推論するため、W1.58A8 行列乗算専用の CUDA カーネルを開発した。三値重み（$\{-1,0,+1\}$、1.58 bit を表す）は標準データ型で効率よく格納できないため、複数の重み値を単一の 8-bit 整数（「int8」）へパックして High Bandwidth Memory（HBM）に格納する。具体的には、4 つの三値を 1 つの「int8」値へ符号化する。計算時には、CUDA カーネルがパック済みの「int8」重みを HBM から GPU 上の高速なオンチップ Shared Memory（SRAM）へ読み込む。続いて、8-bit 活性化値との行列乗算を行う直前に、これらの値を効率的な三値計算に適した表現へ展開する（たとえば -1、0、+1 の値を復元する）。この「pack-store-load-unpack-compute」戦略は、独自の計算命令を活用しながらメモリ帯域幅の使用量を抑える。実装の詳細と最適化戦略については、Ladder フレームワーク [Wan24e] で詳述している。

独自カーネルは単純な実装に比べて性能を大幅に改善するが、現在の汎用 GPU アーキテクチャは 1-bit モデル向けに最適には設計されていない。BitNet b1.58 のようなモデルの性能とエネルギー効率の可能性を完全に引き出すには、低ビット演算専用のロジックを取り入れる可能性のある、将来のハードウェア革新が不可欠になると考える。

<span id="section-5-2"></span>

### 5.2 CPU 推論

広く利用できるようにし、高性能 GPU のないデバイス（たとえばエッジデバイス、ノート PC、標準サーバー）へのデプロイを可能にするため、*bitnet.cpp* を開発した。この C++ ライブラリは、BitNet b1.58 を含む 1-bit LLM の CPU 推論向け公式参照実装である。

*bitnet.cpp* は、標準的な CPU アーキテクチャ上で効率よく実行できるよう調整した最適化済みカーネルを提供する。これらのカーネルは、モデル固有の量子化方式で効率よく動作するよう設計され、可能な限り汎用量子化ライブラリのオーバーヘッドや複雑な低レベルのビット操作を避ける。BitNet b1.58 の訓練手法と整合する形で重み要素を処理し、数値的な正確性（訓練手順に対して損失のない推論）を確保する。

この手法により、CPU 上で 1.58-bit モデルを高速かつ正確に推論できる。技術的な詳細と使用手順については、*bitnet.cpp* のリポジトリと関連技術報告 [Wan25ao] を参照されたい。

<span id="section-6"></span>

## 6 結論

本技術報告では、高効率かつ高性能な大規模言語モデルへ向けた大きな一歩となる BitNet b1.58 2B4T を提示した。4 兆トークンを用いて 20 億パラメータ規模で訓練した、初のオープンソースかつネイティブな 1-bit LLM として、本研究は訓練過程に極端な量子化を直接取り入れることの実現可能性を示した。

言語理解、推論、数学、コーディング、対話を評価するベンチマークでの包括的な検証から、BitNet b1.58 2B4T は同規模の最先端オープンウェイト・全精度モデルに匹敵する性能を達成することが分かった。重要なのは、計算要件を劇的に削減しながらこの性能同等性を実現し、メモリ使用量、エネルギー消費、推論遅延を大幅に抑えていることである。実用と今後の研究を促すため、Hugging Face で利用できるモデル重みと併せて、GPU（独自 CUDA カーネルを使用）および CPU（「bitnet.cpp」ライブラリを使用）向けに最適化した推論実装を開発、公開した。

BitNet b1.58 2B4T は、大規模 LLM で高性能を達成するために全精度の重みが必須であるという前提を覆す、有力な概念実証である。従来のモデルを使用できなかった資源制約のある環境へ高性能な言語モデルをデプロイする道を開き、高度な AI 能力へのアクセスを広げる可能性がある。

<span id="section-7"></span>

## 7 今後の方向性

BitNet b1.58 2B4T は有望な結果を示したが、検討すべき研究の方向性がいくつか残されている。

- **スケーリング則と大規模モデル：** ネイティブ 1-bit LLM のスケーリング特性を調べることが重要である。今後は、より大規模なモデル（たとえば 7B、13B パラメータ以上）をさらに大規模なデータセットで訓練し、全精度モデルとの性能同等性が維持されるかを調べる。
- **ハードウェア協調設計と最適化：** 1-bit モデルの潜在能力を完全に引き出すうえで、現在のハードウェア制約が障害となっている可能性が高い。既存ハードウェア（GPU、CPU、NPU）向けに高度に最適化したカーネルを引き続き開発する必要がある。さらに、1-bit 演算とデータ移動に特化して最適化した将来のハードウェアアクセラレータを協調設計すれば、速度とエネルギー効率を桁違いに改善できる可能性がある。
- **系列長の拡張：** BitNet b1.58 2B4T が処理できる最大系列長を伸ばすことが重要である。この改善は、長文書の要約や複雑な問題解決など、長いコンテキストの理解を要するタスクに不可欠であり、特に **長い思考連鎖推論** タスクの性能を高めるうえで重要となる。長い系列長で低ビットモデルに適した効率的な注意機構を検討することが鍵となる。
- **多言語能力：** 現在のモデルは主に英語中心のデータで訓練している。より幅広く適用するには、事前学習コーパスを拡張し、**複数言語**を効果的にサポートできるよう、必要に応じてアーキテクチャを適応させることが重要となる。
- **マルチモーダル統合：** 1-bit の原則を**マルチモーダルアーキテクチャ**へ統合することも、有望な研究領域である。低ビットの枠組みで異なるモダリティ（たとえばテキストと画像）の情報を処理、融合する効率的な方法を開発すれば、新たな応用が可能になる。
- **理論的理解：** 大規模な 1-bit 訓練が有効となる理論的根拠をさらに深く探ることは、依然として未解決の課題である。これらのモデルの学習ダイナミクス、損失ランドスケープ、表現特性を分析すれば、今後の開発に有用な知見が得られる可能性がある。

これらの方向性を追究することで、1-bit LLM の能力と効率をさらに高め、より持続可能で利用しやすい人工知能への道を開くことを目指す。BitNet b1.58 2B4T と関連ツールのオープンソース公開は、コミュニティがこれらの取り組みを発展させるための基盤となる。
