## 摘要

强化学习 (RL) 在增强大语言模型 (LLM) 方面已经取得显著成效, 但相关研究主要集中于数学解题等单轮任务. 由于动态 Web 界面上的长程决策十分复杂, 训练能够进行多轮交互的有效 Web 智能体仍然困难. 本文提出 WebAgent-R1, 一个简单而有效的端到端多轮 RL Web 智能体训练框架. 它直接从与 Web 环境的在线交互中学习, 并行生成多样的轨迹, 完全由取决于任务是否成功的二元奖励引导. WebArena-Lite 基准上的实验表明 WebAgent-R1 行之有效: Qwen-2.5-3B 的任务成功率从 6.1% 提高到 33.9%, Llama-3.1-8B 则从 8.5% 提高到 44.8%; 这些结果大幅超过现有先进方法以及 OpenAI o3 等强大的专有模型. 深入分析表明, 基于思考的提示策略和通过增加 Web 任务交互次数实现的测试时扩展均有效. 我们还引入 WebAgent-R1-Zero 和 WebAgent-R1-CoT 两个变体, 研究不同的 RL 初始化策略; 结果说明预热训练阶段 (即行为克隆) 很重要, 也为 Web 智能体纳入长思维链 (CoT) 推理提供了参考. ## 1 引言

强化学习 (RL) 已成为训练大语言模型 (LLM) 的一种有前景的方法, DeepSeek-R1 等近期进展就是例证 [Dee25c, Tea25h, Yan25g]. 不过, 现有工作主要关注数学推理等单轮、非交互式任务 [Sha24d, Zen25b]. 对于多轮交互环境, 尤其是需要长程决策和领域特定技能的复杂场景 (例如 Web 浏览 [Zho24f, He24e, Cha25d]), 其效果仍缺少充分研究.

与静态环境不同, Web 任务具有动态性, 解法空间也很多样, 这给 LLM 智能体带来了特有的困难. 早期 Web 智能体工作主要采用基于提示的方法 [Wan24ab, Sod24, Fu24b, Zha25aw, Yan25o] 或行为克隆 (BC); 后者通过监督微调模仿示范轨迹 [Yin24, Hon24b, Lai24a, He24f, Put24]. 这些方法初步取得了成效, 但无法探索不同策略或从试错中学习, 因而限制了 Web 智能体的泛化能力. 为解决这一问题, 近期工作开始研究如何用 RL 训练更好的策略. 但这条研究路线大多严重依赖离线或迭代式离策略 RL 方案 [Pen19a, Pan24f, Qi25a]; 这些方案割裂了 Web 智能体与环境之间的端到端交互, 还引入了轨迹筛选 [Bai24a]、结果奖励模型训练 [Qi25a] 或迭代优化流程 [Zho24i] 等额外复杂性. 这些约束降低了它们在现实部署中的实用性.

与此同时, 一些同期工作已经尝试采用带同策略更新的端到端 RL, 在模拟游戏和编程环境等多轮交互场景中训练 LLM 智能体 [Wan25ag, Cao25b]. 离策略 RL 使用旧版智能体生成的数据训练, 而同策略 RL 直接从智能体当前的行为中收集训练数据. 这样一来, 学习过程更贴近智能体最近采取的动作, 往往能得到更稳定、更有效的学习效果 [Sch15, Sch17a]. 它也省去了离策略 RL 的额外开销 (例如维护回放缓冲区和筛除过时轨迹), 并让智能体根据自身过去的决策调整行为. 在早期决策会显著影响后续步骤的交互环境中, 这是一个重要优势.

在线 Web 环境中的任务常因环境动态变化而相互影响, 因此上述优势尤其有用. 例如, 设想智能体先接到退出用户账户的任务, 随后又要编辑该用户的个人资料. 这两个任务本身相互依赖: 智能体一旦退出, 就无法再访问个人资料页面. 如果它使用一个从未退出过账户的旧版本所采集的离策略数据训练, 就没有机会学会登录行为, 还可能错误地认为访问权限仍然存在, 从而生成无效动作, 最终导致任务失败. 端到端 RL 允许智能体根据环境状态的即时变化学到正确行为, 有助于避免这类问题.

基于这一考虑, 我们提出 WebAgent-R1, 一个用于训练 Web 智能体的端到端多轮 RL 框架. 具体而言, 我们的设计处理了这一场景中的几个主要难题. 首先, 每一步的环境观测 (例如 HTML 内容) 可能长达数千个 token, 长程任务中不断累积的上下文会产生很大的内存开销. 为缓解这一问题, 我们引入动态上下文压缩机制, 自适应调整各轮上下文, 从而支持规模扩展并避免内存不足. 其次, 现有面向 LLM 智能体的 RL 方案并不适合多轮场景. 受组相对策略优化 (GRPO) [Sha24d] 启发, 我们将其扩展到多轮场景 (M-GRPO), 并采用并行轨迹 rollout 策略, 通过并行生成多条轨迹进一步提高训练效率. 这些设计让 RL 训练更高效, 并在 WebArena-Lite 基准上取得了先进性能, 如[图 1](#figure-01) 所示. 大量消融实验进一步验证了主要设计选择, 揭示了一种适用于 Web 任务的有效测试时扩展策略, 并分析了行为克隆和长 CoT 推理在基于 RL 的 Web 智能体训练中各自扮演的角色.

本文的贡献如下:

- 我们实现了一个端到端多轮 RL Web 智能体训练框架, 其中的动态上下文压缩和并行轨迹 rollout 机制提高了训练效率.
- 基于所提出的 M-GRPO 算法, 我们的方法显著提高了 Web 智能体的任务成功率: Qwen-2.5-3B 从 6.1% 提高到 33.9%, Llama-3.1-8B 从 8.5% 提高到 44.8%, 超过了 WebArena-Lite 基准此前的先进结果.
- 大量分析和消融实验说明了行为克隆的作用, 验证了基于思考的提示与测试时扩展策略的效果, 并就如何在 Web 智能体中纳入长 CoT 推理给出了可操作的认识.

<span id="section-2-1"></span>

### 2.1 问题形式化

我们将 Web 任务形式化为部分可观测马尔可夫决策过程 (POMDP), 由四元组 $(\mathcal{S}, \mathcal{A}, \mathcal{T}, \mathcal{R})$ 定义. 在每个时间步 $t$, 智能体首先从环境 $\mathcal{E}$ 中观测状态 $s_t \in \mathcal{S}$, 该状态表示为当前 Web 页面的纯文本 HTML 内容. 随后, 它从预定义动作空间 $\mathcal{A}$ 中生成动作 $a_t$; 该空间包含常用的 Web 操作. 环境动态 $\mathcal{T}(s_{t+1}\mid s_t,a_t)$ 表示 Web 页面如何响应动作而变化. 智能体与环境交互, 直到任务成功完成或达到最大步数. 最后, 智能体从奖励函数 $\mathcal{R}$ 获得二元结果奖励 $r_t \in \{0, 1\}$.

沿用先前工作 [Qi25a], 我们选择 WebArena [Zho24f] 作为 Web 环境, 而不是 WebShop [Yao22c] 或 Mind2Web [Den23] 等模拟或静态环境, 以提高实用性. 它为 Web 智能体提供了真实且可以自行托管的环境, 还带有基于规则的评估准则, 能自动检查最终状态中的成功标志 (例如确认消息或页面上的预期内容). 一些先前工作 [Liu25ab, He24e] 还将 Web 页面截图作为额外的视觉输入, 而本文只研究基于 HTML 的纯文本决策. 另一些工作 (例如 [Yan25o]) 在不微调模型的情况下优化动作空间或提示设计. 这些方向与本文研究的问题相互独立, 将来可以在概念上与我们的方法结合.

<span id="section-2-2"></span>

### 2.2 行为克隆

为了初始化 Web 智能体, 我们首先使用固定的专家示范数据集 $\mathcal{D} = \{(h_t, a_t)\}$ 进行行为克隆 (BC), 其中 $h_t$ 表示截至时间步 $t$ 的完整交互历史, 定义为 $h_t = (s_1, a_1, s_2, a_2, \ldots, s_t)$. 策略 $\pi_\theta$ 通过监督微调 (SFT) 训练, 以模仿以该历史为条件的专家动作:

$$
\mathcal{L}_{\mathrm{BC}} = - \mathbb{E}_{(h_t, a_t) \sim \mathcal{D}} \left[ \log \pi_\theta(a_t \mid h_t) \right]
$$

这一预热阶段让智能体获得动作空间中定义的基本 Web 交互技能. 正如消融研究 ([第 3.4 节](#section-3-4)) 所示, 经过 BC 训练的策略为后续强化学习优化奠定了必要基础.

**表 1.** 不同 Web 智能体训练方法的比较. *Trial-and-Error* 表示方法是否支持通过与环境交互来学习 (即强化学习). *On-Policy* 表示训练数据是否由当前策略采集. *Replay Buffer Free* 表示方法是否不需要从回放缓冲区中选择性采样轨迹, 这是离策略 RL 中常见的一项复杂机制. *Self-Sufficient* 表示不需要外部训练信号 (例如 WebRL 会额外训练结果奖励模型, 为 GPT-4 生成的新数据打标签). 如表所示, 我们的方法是唯一一种既能采用同策略更新执行端到端 RL, 又无需维护回放缓冲区等额外机制、也不依赖外部监督的方法.

### 2.3 端到端多轮强化学习

如[图 2](#figure-02) 所示, 我们的端到端多轮 RL 框架通过在线交互训练 Web 智能体, 并由基于规则的结果奖励提供引导. 为了高效、可扩展地训练, 我们实现了两项主要机制: 用于减少内存开销的*动态上下文压缩*, 以及用于提高采样效率的*并行轨迹 rollout*. 在 BC 训练后的策略上, 我们进一步使用 GRPO [Qi25a] 的多轮扩展来微调智能体, 并将其称为 *M-GRPO*. 这一实现可以看作一种简约方案: 它在保持通用性的同时支持高效多轮 RL 训练, 未来还可以继续扩展 (例如为中间步骤加入细粒度奖励塑形).

**动态上下文压缩.** 在 Web 任务中, 每个观测 $s_t$ 往往包含数千个 token. 经过多轮交互后, 累积的上下文会迅速增长, 导致内存占用过高并可能触发内存不足, 使训练难以开展. 为此, 我们提出动态上下文压缩策略. 新观测到达时, 较早的观测会被简化, 从而在保留完整动作历史的同时缩短上下文. 设第 $t$ 步的交互历史为 $h_t = (s'_1, a_1, s'_2, a_2, \ldots, s_t)$, 其中每个 $s'_i$ 都是一个只有少量 token 的模板 (例如 $s'_i=\texttt{"Simplified HTML"}$), 用来表示先前的观测. 当智能体执行动作 $a_t$ 并收到新观测 $s_{t+1}$ 时, 更新后的历史变为 $h_{t+1} = (s'_1, a_1, s'_2, a_2, \ldots, s'_t, a_t, s_{t+1})$, 其中 $s_t$ 被其简化版本 $s'_t$ 取代. 这样, 智能体可以保留紧凑但信息充分的过往交互上下文. 由于上下文会动态变化, 我们也相应更新损失掩码, 确保 M-GRPO 优化期间只在动作 token 上正确计算损失.

**多轮 GRPO.** 受 GRPO 启发, 我们将其标准形式扩展到多轮 RL, 提出多轮组相对策略优化 (M-GRPO). 具体来说, 对每个任务 $q$, 我们先采样一组轨迹 $\{\tau_1, \tau_2, \cdots, \tau_G\}$, 再通过最小化以下损失来优化策略模型 $\pi_\theta$:

$$
\mathcal{L}_{\text{M-GRPO}}(\theta) =
- \frac{1}{G} \sum_{i=1}^G
\frac{1}{|\tau_i|} \sum_{j=1}^{|\tau_i|} \left(
\frac{1}{|a_{i,j}|} \sum_{t=1}^{|a_{i,j}|} \left[
\tilde{A}_{i,j,t} - \beta\, \mathbb{D}_{\mathrm{KL}}(\theta)
\right] \right)
$$

其中, $\tau_i=\{a_{i,1}, a_{i, 2}, \cdots, a_{i,|\tau_i|}\}$ 是第 $i$ 条轨迹中生成的动作序列, $\tilde{A}_{i,j,t} = \min\{ r_{i,j,t}(\theta) A_{i,j}, \operatorname{clip}(r_{i,j,t}(\theta), 1-\epsilon, 1+\epsilon) A_{i,j}\}$ 是轨迹 $\tau_i$ 的动作 $a_{i,j}$ 中第 $t$ 个 token 的优势, $r_{i,j,t}(\theta) = \frac{\pi_\theta(a_{i,j,t} \mid q, a_{i,j,<t})}{\pi_{\mathrm{old}}(a_{i,j,t} \mid q, a_{i,j,<t})}$ 表示重要性采样项, $\epsilon$ 和 $\beta$ 是超参数, $A_{i,j} = \frac{r_i - \mathrm{mean}(\bm{r})}{\mathrm{std}(\bm{r})}$ 是组相对优势, 它由基于规则的奖励函数产生的一组奖励 $\bm{r}=\{r_1, r_2, \ldots, r_G\}$ 计算得到.

![表 2. WebArena-Lite 上的任务成功率比较.](./webagent-r1/table-02.png)

**表 2.** WebArena-Lite 中不同网站上各方法的任务成功率 (SR) 比较 [Liu25ab, Qi25a, Zho24f]. 基线性能取我们的复现结果与文献 [Qi25a] 报告结果中的较高值. 最佳分数以粗体标出.

**并行轨迹 Rollout.** 生成一组轨迹需要与环境反复交互, 可能十分耗时. 为此, 我们引入并行轨迹 rollout 策略, 实例化多个相互独立的浏览器环境 $\{\mathcal{E}_1, \mathcal{E}_2, \cdots, \mathcal{E}_G\}$, 每个实例都维护自己的上下文 (例如 cookie). 对于每个任务, 所有实例从同一个起始页面初始化, 但智能体会分别与它们独立交互, 从而产生多样的历史和轨迹. 这种并行设计能够在 M-GRPO 中高效生成轨迹.

**奖励设计.** 我们使用 Web 环境默认的基于规则的奖励函数; 它按照任务特定标准 (例如到达目标页面) 分配二元奖励 (成功时 $r=1$, 否则 $r=0$). 这样就不再需要结果奖励模型 [Qi25a], 训练设置也更简单、更容易泛化.

## 3 实验

<span id="section-3-1"></span>

### 3.1 实验设置

**Web 环境.** 与先前工作 [Liu25ab, Qi25a] 一样, 我们关注现实场景中的 Web 智能体, 具体使用 WebArena [Zho24f]. 这是一个能够自行托管的真实 Web 环境, 支持多个领域的实际任务: 社交论坛 (Reddit)、协作编程 (GitLab)、电子商务内容管理系统 (CMS)、开放街道地图 (Map) 和在线购物 (Shopping).

**数据集和评估指标.** 沿用 [Qi25a] 的设置, 我们使用公开的 9,460 条轨迹进行行为克隆, 并采用 WebArena 的人工验证版本 WebArena-Lite, 以获得更可靠的评估. 具体而言, 我们使用 165 个已验证任务进行评估, 其余 647 个任务用于 RL 训练. 任务成功率通过内置的规则化评估准则计算.

**基线.** 对于提示基线, 我们全面比较了开源模型和专有模型, 其中既有通用模型 (例如 Qwen2.5、Llama3.1、GPT-4), 也有专门用于推理的模型 (例如 QwQ、OpenAI o3 [Ope25]), 并覆盖多种模型规模. 对于微调方法, 我们采用 Qwen2.5-3B 和 Llama3.1-8B 作为骨干模型. 更多 WebArena-Lite 基线结果见 [Liu25ab].

### 3.2 主要结果

<span id="figure-03"></span>

![图 3. 强化学习期间的训练动态.](./webagent-r1/figure-03.png)

**图 3.** RL 期间的训练动态, 包括奖励、轨迹长度和交互次数. 如图中的竖直虚线所示, 整个过程大致可以分为三个阶段: (1) 初步习得技能, (2) 探索并改进策略, (3) 最终稳定策略.

**大多数 LLM 仍难以只通过提示完成 Web 任务, 说明 Web 智能体需要微调.** 如[表 2](#table-02) 所示, 实验揭示了现成模型在 Web 任务上的局限. 即便拥有很强的通用能力, OpenAI o3 等先进模型的成功率 (SR) 也只有 39.4%. 相比之下, 一个经过简单行为克隆训练的 3B 微调模型成功率达到 20%, 超过了 GPT-4o 等专有模型. 我们推测, 现成模型表现不佳并非因为基础模型的规模或能力不足, 而是因为它们对 HTML 结构和 Web 特有行为理解不够; 行为克隆后, 3B 和 8B 模型性能相近这一现象也支持这一判断. 这些结果说明, 要开发有效的 LLM Web 智能体, 就需要使用 Web 数据进行领域特定训练.

**推理模型是更好的 Web 智能体.** 与通用 LLM 相比, 具备显式思考能力的模型在 Web 任务上表现明显更好, 可能是因为它们能够分解高层目标, 并明确梳理 Web 界面的动态变化. 这种差距表明, Web 环境通常需要多轮决策和动态上下文理解, 因而思考能力很重要. 受这一观察启发, 我们进一步通过提示设计 ([第 3.5 节](#section-3-5)) 和训练策略 ([第 3.4 节](#section-3-4)) 研究如何将思考机制引入 Web 智能体; 结果进一步确认了思考能力对 Web 智能体的好处.

**强化学习让 Web 智能体的性能更强.** 通过 SFT 进行行为克隆可以显著改善 LLM 作为 Web 智能体的性能 (例如将 Qwen2.5-3B 从 6.1% 提高到 20%), 而在 SFT 训练后的策略上继续应用 RL 还能带来可观的额外收益 (例如进一步将 Qwen2.5-3B 从 20% 提高到 33.9%). 我们认为, 这些提升来自 RL 优化长程决策的能力: 它可以在动态 Web 交互中反复试错, 探索 SFT 数据未曾出现的新策略. DigiRL 和 WebRL 等先前的 Web 智能体 RL 方案也取得了性能提升, 但我们的方法结果更好, 表明端到端多轮 RL 框架确实有效.

### 3.3 训练动态

<span id="figure-04"></span>

![图 4. 强化学习初始化策略的消融研究.](./webagent-r1/figure-04.png)

**图 4.** RL 初始化策略的消融研究, 比较 WebAgent-R1 (R1) 和两个变体: WebAgent-R1-Zero (R1-Zero) 直接从未经 SFT 的现成模型初始化; WebAgent-R1-CoT (R1-CoT) 则从行为克隆期间使用长思维链 (CoT) 数据训练的 SFT 模型初始化. 比较涵盖任务成功率、单轮响应长度和交互次数, 并分别评估应用 RL 前后的结果.

为了理解所提出的端到端强化学习如何优化 Web 智能体行为, 我们从三个指标分析训练动态: 奖励、轨迹长度 (即所有多轮交互中模型响应的 token 数量) 和交互次数. 如[图 3](#figure-03) 所示, 学习过程大致可以分为三个不同阶段, 各阶段由竖直虚线隔开.

**奖励.** 阶段 1 的奖励迅速上升, 表明智能体很快学会基本技能, 并开始成功完成较简单的任务. 阶段 2 中, 奖励增长进入平台期并小幅波动, 说明智能体正在探索不同策略并改进策略. 阶段 3 中, 奖励再次逐渐提高, 表明利用增多且稳定性提升.

**轨迹长度.** 轨迹长度在阶段 1 迅速增长, 随后于阶段 2 趋于稳定. 到阶段 3, 又能观察到一定程度的增长. 这一趋势说明, 智能体起初学会生成更详细的输出, 随后经历巩固期, 最后进一步调整, 在详尽程度和任务效果之间取得平衡.

**交互次数.** 阶段 1 中, 随着智能体变得更主动, 交互轮数增加; 阶段 2 中, 智能体学会更高效地交互, 轮数随之减少. 阶段 3 中, 交互次数趋于稳定, 表明策略正收敛到更加一致、有效的交互方式.

这些趋势反映出 RL 中常见的三阶段学习动态: (1) 初步习得技能, (2) 探索并改进策略, (3) 最终稳定策略. 有意思的是, Qwen2.5-3B 和 Llama3.1-8B 呈现出相似的学习模式, 说明我们的端到端多轮 RL 框架可以有效扩展到不同模型规模, 并带来稳定的策略改进.

<span id="section-3-4"></span>

### 3.4 消融研究

为了验证框架中的主要设计选择, 我们以 Qwen2.5-3B 为骨干模型进行了一组消融研究. 具体来说, 我们引入 WebAgent-R1-Zero 和 WebAgent-R1-CoT 两个变体, 研究行为克隆和长 CoT 对 Web 智能体的影响. 结果见[图 4](#figure-04).

**行为克隆对于使用 RL 训练 Web 智能体不可或缺.** WebAgent-R1-Zero 跳过行为克隆阶段, 直接从现成模型开始 RL, 初始成功率仅为 6.1%. 出人意料的是, RL 后模型性能甚至略有下降. 我们推测, 原因在于模型缺少 Web 任务知识, 容易生成不完整或格式错误的动作 (例如缺少必要参数), 并且在 RL 期间很少得到正奖励. 这会严重阻碍有效探索和学习, 说明行为克隆对于初始化 Web 智能体并保证后续 RL 成功十分必要.

**在行为克隆中加入长 CoT 数据可以得到性能更好的 Web 智能体.** 我们首先使用强推理模型生成长 CoT 轨迹, 扩充行为克隆 (BC) 数据 (详见[附录 C](#appendix-c)); 随后应用 SFT, 得到 *long-CoT SFT* 模型 (即 RL 之前的 WebAgent-R1-CoT 变体). 与使用标准 BC 数据训练的 SFT 模型相比, long-CoT SFT 模型的任务成功率高得多 (24.5% 对 20%), 说明长 CoT 推理对 Web 智能体有效.

**RL 对 long-CoT SFT 模型的提升有限.** RL 对普通 SFT 和 long-CoT SFT 模型都能带来提升, 但后者的增益明显更小, 这一现象颇有意思. 具体来说, WebAgent-R1 从 20% 提高到 33.9%, 而 WebAgent-R1-CoT 从 24.5% 只提高到 30.3%. 我们推测, long-CoT BC 学到的确定性推理模式可能会限制模型在 RL 期间的探索空间; 与探索行为更灵活的标准 SFT 模型相比, 它发现新策略的能力因而受到限制.

## 4 相关工作

<span id="section-4-1"></span>

### 4.1 基于 LLM 的智能体

LLM 已经展现出很有潜力的智能体能力, 例如将复杂任务分解为可处理的子目标, 以及进行长程推理 [Zho22b, Hua22c, Mad22, Li23t, Li23w, Wu23c, Liu25ac, Chu25d]. 基于这些能力, LLM 智能体已被用于多种现实交互任务, 包括 Web 导航 [Nak21, Yao22c, Ma23a, Gur24, Abu24, Lut24, Pat24a, Put24]、通用计算机操作 [Li20d, Den23, Yan24l] 和具身环境 [Pui18, Shr20, Toy21, Fan22, Hua22c]. 具体而言, 本文关注纯粹根据 HTML 内容在浏览器环境中操作的文本 Web 智能体, 这需要工具使用、记忆和部分可观测条件下的决策等智能体能力 [Zho24f, Qi25a]. 与这条研究路线互为补充的是, GUI 智能体还会使用截图等多模态输入, 从而在视觉信息引导下与环境交互 [Lee23a, Sha23d, Zhe24b, He24e, He24f, Koh24, Kil24, Lei25, Liu25ab]. 更全面的介绍可参阅近期综述 [Wan24k, Tse24b, Hu25h, Nin25].

<span id="section-4-2"></span>

### 4.2 面向 LLM 的强化学习

DeepSeek-R1 [Dee25c] 等近期进展表明, RL 在增强 LLM 方面潜力很大. 不过, 以往大多数工作关注数学问题等单轮任务 [Sha24d, Zhu25j, Sha25d, Ouy25c, Wei25h], 对多轮场景的研究仍然有限 [Zho24i, Zho25g]. 近期工作已经在这一方向取得一些进展, 例如训练 LLM 智能体反复使用搜索引擎 [Jin25b, Sun25b, Che25z, Son25a, Wan25am], 但通常将动作限制为简单的 API 调用, 不涉及真实环境交互. RAGEN [Wan25ag] 和 SkyRL [Cao25b] 等少数同期工作已将 RL 用于模拟游戏、编程环境 [Jim24] 等更动态的场景. 然而, 现实 Web 环境仍然缺少充分研究. 本文提供了一个实用框架, 并给出了通过端到端 RL 训练 Web 智能体的可操作经验, 从而填补这一空白.

## 5 结论

本文提出 WebAgent-R1, 一个用于训练 Web 智能体的端到端多轮 RL 框架. 我们将标准 GRPO 扩展到多轮场景并称为 M-GRPO, 还实现了动态上下文压缩和并行轨迹 rollout 机制, 以提高训练效率. 实验表明, WebAgent-R1 在 WebArena-Lite 基准上取得了新的先进结果. 研究结果说明, 行为克隆对于初始化 Web 智能体十分重要, 能为有效的 RL 提供坚实基础. 我们还分析了训练动态, 并研究基于思考的提示和测试时扩展策略的影响; 结果表明, 增加交互深度可以持续增强 Web 智能体. 未来工作包括探索多模态输入, 并将我们的方法扩展到 Web 环境以外、更广泛的 GUI 任务, 例如通用计算机操作.

## 局限与潜在风险

WebAgent-R1 虽然有效, 但当前方法仍有几项局限, 也由此产生了未来的研究方向. 第一, 我们只考虑 Web 任务的文本输入. 加入额外的视觉输入 (例如截图) 可能改善性能, 因为布局和颜色等视觉信息有助于有效导航和决策. 第二, 我们的方法依赖基于规则的结果奖励来引导 RL 训练. 这类奖励函数在本文场景中有效, 但在其他交互场景中未必容易获得, 例如开放式旅行规划智能体; 这类任务的目标模糊, 没有明确的参考答案或可验证结果. 最后, 与现有 Web 智能体一样, 我们的模型使用一组固定的预定义动作 (例如点击、输入) 训练, 遇到需要未知操作的交互元素时, 灵活性可能受到限制. 如何动态适应新操作, 仍是 Web 智能体尚未解决的问题.

就潜在风险而言, 将这类智能体部署到现实环境时应谨慎使用, 涉及管理权限的环境尤其如此. 例如, 智能体在生产环境中与内容管理系统 (CMS) 交互时, 可能无意间执行破坏性操作, 如修改或删除敏感数据. 为了安全部署, 未来工作应加入权限控制、确认提示和防护措施, 防止产生影响严重或不可逆的操作.

## A Web 环境

**WebArena-Lite.** WebArena [Zho24f] 是一个面向 LLM 智能体开发、真实且能够自行托管的 Web 环境. 它包含 812 个现实 Web 任务, 覆盖多个领域, 包括社交论坛 (Reddit)、协作编程 (GitLab)、电子商务内容管理系统 (CMS)、开放街道地图 (Map) 和在线购物 (OneStopShop). WebArena-Lite [Liu25ab] 是 WebArena 的精选版本, 旨在提供更可靠的评估. 它选取 165 个代表性任务进行人工验证并作为评估集, 其余 647 个任务则用于训练. 它还提供了由程序化求解器自动标注的 9,460 条轨迹, 用于行为克隆. 对于每个网站, 作者 [Liu25ab] 总结其核心功能和有效项目, 构建一组任务原型, 并使用 Playwright 脚本为每种原型手动实现基于规则的求解器. 随后在网站上执行相应的求解器, 收集真实轨迹. 最终得到 1,186 个有效训练样本, 共包含 9,460 条轨迹, 并以 Apache License 2.0 发布.

**动作空间.** 智能体通过一组预定义动作与环境交互, 包括:

- **点击:** 模拟在网页元素上单击鼠标左键.
- **右键单击:** 在指定元素上单击鼠标右键.
- **输入:** 将文本字符串输入到输入框中.
- **搜索:** 输入搜索查询并触发搜索操作.
- **悬停:** 将光标移到指定元素上, 以显示工具提示或隐藏菜单.
- **向上滚动 / 向下滚动:** 垂直滚动页面.
- **按 Enter 键:** 模拟按下 Enter 键, 通常用于输入文本之后.
- **切换标签页:** 更改当前浏览器标签页.
- **选择下拉选项:** 从下拉菜单中选择一个选项.
- **等待:** 暂停智能体交互一小段时间.
- **退出:** 以最终消息结束当前会话.
- **后退 / 前进:** 在浏览器历史记录中后退或前进.

**基于规则的指标.** 在现实 Web 任务中, 通常不存在闭式解, 多条轨迹也可能都能成功完成任务. 因此, 我们只根据最终目标是否达成来评估智能体, 并计算成功率 (SR); 以下基于规则的评估指标用于判断任务是否成功完成:

- **字符串匹配:** 智能体必须给出与预期输出匹配的答案字符串.
- **URL 匹配:** 智能体必须导航到指定网页. 是否成功通过比较最终 URL 与参考 URL 来判断.
- **程序执行:** 智能体必须修改网页内容或配置. 评估时会执行基于规则的脚本, 提取并验证页面的最终状态.

WebArena 中的每个任务都对应其中一种评估指标; 如适用, 还会提供相应的参考答案、目标 URL 或验证脚本. 这种多样的规则化指标设计既能适应不同的任务目标和输出格式, 又能保证各种 Web 任务的评估一致.

## B 实现细节

我们使用 Qwen2.5-3B 和 Llama3.1-8B 作为骨干模型来实现本文方法. 默认情况下, 提示方法和微调方法都使用经过指令微调的版本. 强化学习 (RL) 的初始化策略来自通过行为克隆得到的监督微调 (SFT) 检查点. 由于 WebRL 使用额外的 GPT-4 生成数据训练 Llama3.1-8B, 为保证公平比较, 我们用其公开发布的检查点初始化 RL 策略, 并且只使用原始的 647 个训练任务执行端到端 RL, 不引入任何额外数据.

我们的模型在单个节点的 8 块 NVIDIA A100 80GB GPU 上通过全参数微调训练. 为优化 GPU 利用率, 我们使用 DeepSpeed [Raj20b] 执行带 ZeRO-3 offload 的分布式训练, 同时启用梯度检查点、FlashAttention-2 [Dao24a] 和 bf16 混合精度训练, 以提高计算效率. SFT 的学习率为 5e-5, 批大小为 128, 并采用余弦学习率调度器, 预热步数占 5%. RL 训练采用 1e-6 的恒定学习率, 批大小为 16. KL 散度正则化系数 $\beta$ 和裁剪比率 $\epsilon$ 分别设为 0.001 和 0.2. 最大上下文长度和新 token 数量分别设为 16,384 和 1024. 为了在 M-GRPO 期间高效执行 LLM rollout, 我们使用 vLLM [Kwo23], 张量并行大小为 1, GPU 内存利用率设为 0.7. rollout 采样的温度和 top-p 均设为 1.0.
