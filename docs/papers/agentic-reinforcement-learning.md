## 摘要

智能体强化学习 (Agentic RL) 的兴起意味着, 应用于大语言模型的传统强化学习 (LLM RL) 正在发生范式转变: LLM 不再只是被动的序列生成器, 而是置于复杂动态世界中的自主决策智能体. 本文通过对比 LLM RL 的退化单步马尔可夫决策过程 (MDP) 与定义 Agentic RL 的时间扩展部分可观察马尔可夫决策过程 (POMDP), 对这一概念转变作出形式化描述. 在此基础上, 我们提出两套完整的分类体系: 一套围绕规划、工具使用、记忆、推理、自我改进和感知等核心智能体能力组织, 另一套按这些能力在不同任务领域中的应用组织. 本文的核心论点是, 强化学习能够把这些能力从静态的启发式模块转化为自适应且鲁棒的智能体行为. 为支持后续研究, 我们还将开源环境、基准和框架汇总成一份实用索引. 本文综合了 500 余项近期工作, 梳理这一快速发展领域的全貌, 以及可扩展通用 AI 智能体面临的机遇与挑战.

## 1 简介

大语言模型 (LLM) 与强化学习 (RL) 的快速融合, 从根本上改变了语言模型的构想、训练和部署方式. 早期的 LLM RL 范式大多把模型视为静态条件生成器, 优化目标是生成符合人类偏好或取得较高基准分数的单轮输出. 这类方法虽然成功改善了对齐和指令遵循能力, 却忽略了现实交互环境所依赖的更广泛的序列决策过程. 这些局限推动了视角的转变: LLM 不再只是被动输出文本, 而是逐渐被视为*智能体*, *即*能够在部分可观察的动态环境中感知、推理、规划、调用工具、维持记忆, 并在长时程交互中调整策略的自主决策者. 我们将这一新兴范式定义为**智能体强化学习 (Agentic RL)**. 为了更清楚地区分本文讨论的 Agentic RL 与传统 RL 方法, 我们给出如下定义:

**智能体强化学习 (Agentic RL)** 是一种将 LLM 视为嵌入序列决策循环的*可学习策略*的范式, 而不是把它当作针对单轮输出对齐或基准性能进行优化的*静态条件生成器*. RL 由此赋予 LLM 自主智能体能力, 包括规划、推理、工具使用、记忆维持和自我反思, 使其能够在*部分可观察的动态环境*中形成长时程的认知与交互行为.

在[第 2 节](#section-2) 中, 我们从符号层面对 Agentic RL 和传统 RL 作出更严格的区分. 与 Agentic RL 相关的既有研究大致分为两个互补方向: **RL 与 LLM 的协同**和**LLM 智能体**, 具体如下:

**RL 与 LLM 的协同.** 第二条研究路线考察如何用强化学习算法改进或对齐 LLM. 其中一个主要分支是用 RL 训练 LLM: 通过同策略方法 (*例如*, 近端策略优化 (PPO) [Sch17a] 和组相对策略优化 (GRPO) [Sha24d]) 与离策略方法 (*例如*, actor-Critic 和 Q-learning [Mni13]), 增强指令遵循、伦理对齐和代码生成等能力 [Agg25, Wan25x, Wan24o]. 与之互补的方向是将 LLM 用于 RL, 即让 LLM 充当规划器、奖励设计器、目标生成器或信息处理器, 以提高控制环境中的样本效率、泛化能力和多任务规划能力; [Cao25c] 给出了系统分类. RL 也已融入 LLM 的整个生命周期, 从数据生成 [Guo25c, Wan25j] 和预训练 [Don25a], 一直延伸到后训练与推理 [Cho25a], 相关工作由 [Wan25h] 综述. 其中最主要的分支是后训练对齐, 尤其是人类反馈强化学习 (RLHF) [Chr17], 以及人工智能反馈强化学习 (RLAIF) [Bai22a]、直接偏好优化 (DPO) [Raf23, Wan24v, Xia24f, Liu25k, Agg25] 等扩展.

**LLM 智能体.** 在这一新范式中, LLM 充当自主或半自主的决策实体 [Wan25o, Li25u], 能够为复杂目标进行推理、规划和行动. 近期综述从多个互补角度梳理了这一领域. [Luo25c] 提出以方法为中心的分类体系, 连接架构基础、协作机制与演化路径; [Pla25] 则把推理、行动和交互视为*智能体式* LLM 的核心特征. 工具使用涵盖检索增强生成 (RAG) 和 API 调用, 是这一范式的核心组成部分, [Li25n] 对此作了详细讨论, [Wan24w] 又进一步给出概念化描述. 规划与推理策略是另一支柱: [Mas24] 和 [Kum25] 等综述总结了计划-执行-反思循环等常见模式, [Tao24] 则把这一思路扩展到自我演化, 让智能体在很少依赖人工干预的情况下迭代改进知识和策略. 其他研究还涉及协作、跨模态和具身场景, 包括多智能体系统 [Ilm25]、多模态集成 [Dur24], 以及具备记忆和感知能力的类脑架构 [Liu25a].

**研究空白与本文贡献.** 近期 LLM 智能体和 RL 增强 LLM 研究的快速增长, 体现了两种互补视角: 一种探讨大语言模型作为自主智能体核心能够完成什么, 另一种关注强化学习如何优化其行为. 然而, 现有工作虽然覆盖广泛, 仍缺少对*智能体强化学习*的统一论述, 也就是把 LLM 视为嵌入序列决策过程、通过策略优化学习的智能体. 当前研究往往分别考察单项能力、特定领域或定制环境, 使用的术语和评估协议也不一致, 因而难以开展系统比较和跨领域泛化. 为填补这一空白, 我们将理论基础、算法方法和实际系统组织成一套连贯的综述框架. 我们使用马尔可夫决策过程 (MDP) 与部分可观察马尔可夫决策过程 (POMDP) 对 Agentic RL 进行形式化, 以区别于传统的 LLM RL 范式; 同时提出以能力为中心的分类体系, 将规划、工具使用、记忆、推理、反思 (自我改进) 和交互视为可由 RL 优化的组成部分. 此外, 我们汇总了支持智能体 LLM 训练与评估的代表性任务、环境、框架和基准, 最后讨论开放问题, 并梳理可扩展通用智能体智能的潜在研究方向. 总体而言, 本综述的研究范围如下:

**重点讨论:**

- ✔ RL 如何在*动态环境*中为基于 LLM 的智能体 (或具有智能体特征的 LLM) 提供支持

**不在讨论范围内 (但偶有提及):**

- ✗ 人类价值对齐的强化学习 (*例如*, 有害查询拒绝的强化学习)
- ✗ 不基于 LLM 的传统 RL 算法 (*例如*, MARL [Moh24])
- ✗ RL 用于提高静态基准上的纯 LLM 性能.

**综述结构.** 本文从概念基础逐步推进到实际实现, 建立对 Agentic RL 的统一认识. [第 2 节](#section-2) 从 MDP/POMDP 视角形式化向 Agentic RL 的范式转变. [第 3 节](#section-3) 从能力角度考察 Agentic RL, 对规划、推理、工具使用、记忆、自我改进和感知等关键模块进行分类. [第 4 节](#section-4) 讨论搜索、GUI 导航、代码生成、数学推理和多智能体系统等领域的应用. [第 5 节](#section-5) 汇总支撑实验与基准评测的开源环境和 RL 框架. [第 6 节](#section-6) 讨论通向可扩展、自适应且可靠的智能体智能所面临的开放问题与未来方向, [第 7 节](#section-7) 总结全文. 整体结构见[图 1](#figure-01).

## 2 预备知识: 从 LLM RL 到 Agentic RL

LLM 最初通过行为克隆进行预训练, 即在网页抓取文本等静态数据集上应用最大似然估计 (MLE). 随后的后训练方法进一步增强模型能力, 并使输出符合人类偏好, 从而让模型不再只是通用的网络数据复现器. 一种常见技术是监督微调 (SFT), 即用人工编写的 (提示, 响应) 示例改进模型. 但要获得足量的高质量 SFT 数据仍很困难 [Mao25a, Sze25, Han25]. 强化微调 (RFT) 提供了另一条路径: 通过奖励函数优化模型, 不再依赖行为示范.

早期 RFT 研究的核心目标是利用人类反馈 [Chr17, Ouy22a] 或数据偏好 [Raf23] 优化 LLM, 使模型符合人类偏好 (RLHF), 或像 DPO 那样直接符合数据偏好. [+1] 这种**基于偏好的 RFT (PBRFT)** 主要是在固定偏好数据集上学习 LLM 的奖励模型并据此优化, 或直接使用数据偏好进行优化. OpenAI o1 [Ope24h] 和 DeepSeek-R1 [Dee25c] 等推理型 LLM 发布后, 它们带来的性能提升与跨领域泛化能力引起广泛关注. OpenAI o3 [Tea25c] 等兼具自我演化推理和工具使用能力的模型随后问世, 研究者开始思考如何用强化学习把 LLM 与下游任务更紧密地结合起来. 研究重点也随之从面向固定偏好数据集的 PBRFT, 转向针对具体任务和动态环境设计的智能体强化学习.

本节形式化描述从 PBRFT 到新兴的**智能体强化学习 (Agentic RL)** 的范式转变. 两者虽然都用强化学习改善 LLM 的表现, 但在基本假设、任务结构和决策粒度上存在根本差异. [图 2](#figure-02) 展示了从 LLM RL 到 Agentic RL 的转变.

### 2.1 马尔可夫决策过程

RL 微调过程的马尔可夫决策过程 (MDP) 可以形式化为七元素元组 $\langle\mathcal{S},\mathcal{O},\mathcal{A},\mathcal{P},\mathcal{R},T,\gamma\rangle$, 其中 $\mathcal{S}$ 表示状态空间, $\mathcal{O}$ 是智能体的观察空间. $\mathcal{A}$ 表示动作空间. $\mathcal{R}$ 被定义为奖励函数, $\mathcal{P}$ 封装了状态转换概率, $T$ 表示任务范围, $\gamma$ 是折扣因子. 通过将基于偏好的 RFT 和 Agentic RL 转换为 MDP 或 POMDP, 我们阐明了将 LLM 视为静态序列生成器或嵌入动态环境中的交互式决策智能体的理论含义.

**PBRFT.** PBRFT 的 RL 训练过程被形式化为由元组定义的简并 MDP:

<span id="equation-01"></span>

$$
\langle\mathcal{S}_{\mathrm{trad}},\mathcal{A}_{\mathrm{trad}},\mathcal{P}_{\mathrm{trad}},\mathcal{R}_{\mathrm{trad}},T=1,\gamma=1\rangle.
$$

**Agentic RL.** Agentic RL 的 RL 训练过程被建模为 POMDP:

<span id="equation-02"></span>

$$
\langle\mathcal{S}_{\mathrm{agent}},\mathcal{A}_{\mathrm{agent}},\mathcal{P}_{\mathrm{agent}},\mathcal{R}_{\mathrm{agent}},\gamma,\mathcal{O}\rangle.
$$

其中智能体接收基于状态 $s_{t}\in\mathcal{S}_{\mathrm{agent}}$ 的观测结果 $o_{t}=O(s_{t})$. PBRFT 和 Agentic RL 之间的主要区别在[表 1](#table-01) 中描述. 总之, PBRFT 在完整观察下优化固定数据集中的输出句子序列, 而 Agentic RL 优化以部分观察为特征的可变环境中的语义级行为.

### 2.2 环境状态

**PBRFT.** 在训练过程中, 每个 episode 都从单个提示状态 $s_{0}$ 开始; 该事件在模型发出一个响应后立即终止. 形式上, 底层 MDP 退化为水平 $T=1$ 的“单步”决策问题. 状态空间简化为单个静态提示输入:

<span id="equation-03"></span>

$$
\mathcal{S}_{\mathrm{trad}}=\{\mathrm{prompt}\}.
$$

**智能体 RL.** LLM 智能体在 POMDP 中的多个时间步上起作用. 令 $s_{t}\in\mathcal{S}_{\mathrm{agent}}$ 表示完整的世界状态, LLM 智能体根据当前状态 $o_{t}=\mathcal{O}(s_{t})$ 获得观测值 $O_{t}$. LLM 智能体根据当前观察 $o_{t}$ 选择一个动作 $a_{t}$, 并且状态随着时间的推移而演变:

<span id="equation-04"></span>

$$
s_{t+1}\sim P(s_{t+1}\mid s_{t},a_{t}).
$$

当智能体积累中间信号时, 例如检索到的工具结果、用户消息或环境反馈. 因此, 这种相互作用本质上是动态的并且在时间上是延长的.

<span id="section-2-3"></span>

### 2.3 动作空间

在 Agentic RL 设置中, LLM 的动作空间包含两个不同的子空间:

<span id="equation-05"></span>

$$
\mathcal{A}_{\mathrm{agent}}=\mathcal{A}_{\mathrm{text}}\cup\mathcal{A}_{\mathrm{action}}.
$$

这里, $\mathcal{A}_{\mathrm{text}}$ 表示通过自回归解码发出的自由形式自然语言标记的空间, 而 $\mathcal{A}_{\mathrm{action}}$ 表示抽象的非语言动作的空间, 通常在输出流中由特殊标记 `<action_start>` 和 `<action_end>` 分隔. 这些操作可能会调用外部工具 (例如, `call("search", "Einstein")`) 或与环境交互 (例如, `move("north")`), 具体取决于任务要求.

值得注意的是, $\mathcal{A}_{\mathrm{action}}$ 是递归构造的, 使得元素 $a\in\mathcal{A}_{\mathrm{action}}$ 本身可以表示原始动作的序列 $(a_{1},\dots,a_{k})$, 从而在同一空间内统一原始动作和复合动作.

形式上, 这两个子空间在语义和功能角色上有所不同: $\mathcal{A}_{\mathrm{text}}$ 定义了用于人类或机器解释的输出空间, 而不直接改变外部状态, 而 $\mathcal{A}_{\mathrm{action}}$ 定义了环境交互行为的空间, 这些行为要么 (i) 通过工具调用获取新信息, 要么 (ii) 修改物理或模拟环境的状态. 这种区别使得统一的策略能够在同一 RL 公式中联合建模语言生成和环境交互.

<span id="section-2-4"></span>

### 2.4 过渡动态

**PBRFT.** 在传统的 PBRFT 中, 过渡动态是确定性的: 一旦采取行动, 就确定下一个状态, 如下所示:

<span id="equation-06"></span>

$$
\mathcal{P}(s_{1}\mid s_{0},a)=1,\quad\mathrm{where\ there\ is\ no\ uncertainty.}
$$

**智能体强化学习.** 在智能体强化学习中, 环境根据以下公式在不确定性下演化

<span id="equation-07"></span>

$$
s_{t+1}\sim\mathcal{P}(s_{t+1}\mid s_{t},a_{t}),\quad a_{t}\in\mathcal{A}_{\mathrm{text}}\cup\mathcal{A}_{\mathrm{action}}.
$$

文本操作 $(\mathcal{A}_{\mathrm{text}})$ 生成自然语言输出, 而不改变环境状态. 结构化操作 $(\mathcal{A}_{\mathrm{action}})$, 由`<action_start>`和`<action_end>`分隔, 可以查询外部工具或直接修改环境. 这种顺序表述与 PBRFT 的一次性映射形成对比, 从而实现迭代地结合通信、信息获取和环境操纵的策略.

<span id="section-2-5"></span>

### 2.5 奖励函数

**PBRFT.** PBRFT 通常具有可验证响应正确性的奖励函数, 可以使用基于规则的验证器 [Dee25c] 或神经网络参数化奖励模型 [Zho25b] 来实现. 无论采用何种实现方法, 其核心都遵循以下等式:

<span id="equation-08"></span>

$$
\mathcal{R}_{\mathrm{trad}}(s_{0},a)=r(a).
$$

其中 $r:\mathcal{A}\!\to\!\mathbb{R}$ 是由人类或人工智能偏好模型提供的标量分数, 没有中间反馈.

**智能体 RL.** LLM 智能体的奖励函数基于下游任务.

<span id="equation-09"></span>

$$
\mathcal{R}_{\mathrm{agent}}(s_{t},a_{t})=\begin{cases}r_{\mathrm{task}}&\mathrm{on\ task\ completion},\\[2.0pt]
r_{\mathrm{sub}}(s_{t},a_{t})&\mathrm{for\ step\!-\!level\ progress},\\[2.0pt]
0&\mathrm{otherwise}.\end{cases}
$$

允许密集、稀疏或学习奖励 (*例如*, 单元测试通过, 符号验证者成功).

<span id="section-2-6"></span>

### 2.6 学习目标

**PBRFT.** PBRFT 的优化目标是基于策略 $\pi_{\theta}$ 最大化响应奖励:

<span id="equation-10"></span>

$$
J_{\mathrm{trad}}(\theta)=\mathbb{E}_{a\sim\pi_{\theta}}\bigl[r(a)\bigr].
$$

不需要折扣系数; 优化类似于最大预期奖励序列建模.

**Agentic RL.** Agentic RL 的优化目标是最大化折扣奖励:

<span id="equation-11"></span>

$$
J_{\mathrm{agent}}(\theta)=\mathbb{E}_{\tau\sim\pi_{\theta}}\left[\,\sum_{t=0}^{T-1}\gamma^{t}R_{\mathrm{agent}}(s_{t},a_{t})\right],\qquad 0\lt\gamma\lt1.
$$

这一目标通过策略梯度法或基于价值的方法优化, 同时涉及探索和长期信用分配.

PBRFT 关注单轮文本质量对齐, 不显式涉及规划、工具使用或环境反馈; Agentic RL 则包含多轮规划、自适应工具调用、有状态记忆和长时程信用分配, 使 LLM 能够成为自主决策智能体.

<span id="section-2-7"></span>

### 2.7 强化学习算法

在当代研究中, 强化学习算法构成了 PBRFT 和 Agentic RL 框架的关键组成部分. 不同的强化学习算法表现出不同的样本效率和性能特征, 每种算法都提供了一种独特的方法来应对将模型输出与复杂的、通常是主观的人类目标保持一致的核心挑战. REINFORCE、PPO [Sch17a]、GRPO [Dee25c] 和 DPO [Raf23] 等经典方法形成了从一般策略梯度到专门偏好学习的范围. 接下来我们介绍这四种经典算法, 并在[表 2](#table-02) 中提供每个系列的流行变体的比较.

**REINFORCE: 基础策略梯度** 作为最早的策略梯度算法之一, REINFORCE [Wil92] 为训练随机策略提供了基础理论. 它通过增加导致高累积奖励的行动的概率并减少导致低奖励的行动的概率来运作. 其目标函数由下式给出:

<span id="equation-12"></span>

$$
\nabla_{\theta}J(\theta)=\mathbb{E}_{s_{0}}\left[\frac{1}{N}\sum_{i=1}^{N}\left(\mathcal{R}(s_{0},a^{(i)})-b(s_{0})\right)\nabla_{\theta}\log\pi_{\theta}(a^{(i)}|s_{0})\right].
$$

其中, $a^{(i)}\sim\pi_{\theta}(a|s_{0})$ 是第 $i$ 个采样响应, $\mathcal{R}(s_{0},a)$ 表示任务完成时收到的最终奖励, $b(s)$ 是用于减小策略梯度估计方差的基线函数. 一般而言, $b(s)$ 可以是包括随机变量在内的任意函数. 实践中, $b(s)$ 通常取值函数 $V(s)$. REINFORCE 的优点是公式简洁且易于实现, 缺点则包括梯度估计方差大、样本效率低、对学习率敏感, 以及缺少 Critic (价值估计器).

**近端策略优化 (PPO)** PPO [Sch17a] 因其稳定性和可靠性而成为 LLM 对齐的主要 RL 算法. 它通过限制更新步骤来改进普通策略梯度, 以防止破坏性的大策略变化. 其主要的裁剪目标函数是:

<span id="equation-13"></span>

$$
L_{\mathrm{PPO}}(\theta)=\frac{1}{N}\sum_{i=1}^{N}\min\left(\frac{\pi_{\theta}(a_{t}^{(i)}|s_{t})}{\pi_{\theta_{old}}(a_{t}^{(i)}|s_{t})}A(s_{t},a_{t}^{(i)}),\;\;\mathrm{clip}\left(\frac{\pi_{\theta}(a_{t}^{(i)}|s_{t})}{\pi_{\theta_{old}}(a_{t}^{(i)}|s_{t})},1-\epsilon,1+\epsilon\right)A(s_{t},a_{t}^{(i)})\right).
$$

其中 $a_{t}^{(i)}\sim\pi_{\theta_{old}}(a|s_{t})$ 是来自旧策略 $\pi_{\theta_{old}}$ 的第 $i$ 采样响应, 其更新被延迟. $A_{t}$ 是由下式给出的估计优势

<span id="equation-14"></span>

$$
A(s_{t},a_{t})=\mathcal{R}(s_{t},a_{t})-V(s_{t}).
$$

其中, $V_{\theta}(s)$ 是学习得到的价值函数, 即期望 $\mathbb{E}_{a\sim\pi_{\theta}(a|s)}[\mathcal{R}(s,a)]$. 它通常来自一个与策略网络规模相同的 Critic 网络, 但并非必须如此. 裁剪项防止概率比过度偏离 1, 从而保证更新稳定. 优势函数估计对 PPO 的性能影响很大. 近期变体分别着眼于减小优势估计的偏差 [Kaz24] 或方差 [Yue25a], 另一些工作则改进稳定的策略更新机制 [Liu25s], 或缓解稀疏奖励问题 [Dai25]. 不过, PPO 仍依赖独立的 Critic 网络估计优势, 显著增加了训练时的参数量.

**直接偏好优化 (DPO)** DPO 代表了突破性的转变, 完全绕过了对单独的显式奖励模型的需求. 它将 KL 约束下的奖励最大化问题重新定义为人类偏好数据上基于可能性的目标. 给定一个偏好数据集 $D=\{(y_{w},y_{l})\}$, 其中 $y_{w}$ 是首选响应, $y_{l}$ 是不首选响应, DPO 损失为:

<span id="equation-15"></span>

$$
L_{\mathrm{DPO}}(\pi_{\theta};\pi_{ref})=-\mathbb{E}_{(x,y_{w},y_{l})\sim D}\left[\log\sigma\left(\beta\log\frac{\pi_{\theta}(y_{w}|x)}{\pi_{ref}(y_{w}|x)}-\beta\log\frac{\pi_{\theta}(y_{l}|x)}{\pi_{ref}(y_{l}|x)}\right)\right].
$$

其中, $\pi_{ref}$ 是参考策略 (通常为初始 SFT 模型), $\beta$ 是超参数. DPO 虽然不再需要 Critic, 但性能仍从根本上取决于静态偏好数据集的质量和覆盖范围. 一些变体通过引入外部或在线数据 [Eth24, Hon24] 来克服这一限制; 另一些工作则采用更一般的优化目标 [Aza24] 或更精细的隐式奖励机制 [Men24, Lai24, Hon25].

**组相对策略优化 (GRPO)** DeepSeek [Guo25b] 取得的显著成功激发了人们对 GRPO 的巨大研究兴趣. GRPO 旨在解决 PPO 大 Critic 的低效率问题, 引入了一种新颖的轻量级评估范式. 它对响应组进行操作, 使用组内的相对奖励来计算优势, 从而消除了对绝对价值 Critic 的需要. GRPO 的核心目标可以概念化为:

<span id="equation-16"></span>

$$
L_{\mathrm{GRPO}}=\frac{1}{G}\sum_{g=1}^{G}\min\left(\frac{\pi_{\theta}(a_{t}^{(g)}|s_{t}^{(g)})}{\pi_{\theta_{old}}(a_{t}^{(g)}|s_{t}^{(g)})}\hat{A}(s_{t}^{(g)},a_{t}^{(g)}),\;\;\mathrm{clip}\left(\frac{\pi_{\theta}(a_{t}^{(g)}|s_{t}^{(g)})}{\pi_{\theta_{old}}(a_{t}^{(g)}|s_{t}^{(g)})},1-\epsilon,1+\epsilon\right)\hat{A}(s_{t}^{(g)},a_{t}^{(g)})\right).
$$

其中一组输出 $\{(s_{0}^{(g)},a_{0}^{(g)},\ldots,s_{T-1}^{(g)},a_{T-1}^{(g)})\}_{g=1}^{G}$ 是从旧策略 $\pi_{\theta_{old}}$ 中采样的. 优势函数估计为

<span id="equation-17"></span>

$$
\hat{A}(s_{t},a_{t})=\frac{\mathcal{R}(s_{t},a_{t})-\mathrm{mean}(\mathcal{R}(s_{t}^{(1)},a_{t}^{(1)}),\ldots,\mathcal{R}(s_{t}^{(G)},a_{t}^{(G)}))}{\mathrm{std}(\mathcal{R}(s_{t}^{(1)},a_{t}^{(1)}),\ldots,\mathcal{R}(s_{t}^{(G)},a_{t}^{(G)}))}.
$$

这种组相对方法的样本效率很高, 也能降低计算开销. 但基于组的优势估计容易出现方差高、精度低的问题. 因此, 后续工作提出了一系列由 GRPO 框架衍生的新算法 (见[表 2](#table-02)), 旨在显著改进优势估计.

本节从概念上把**智能体强化学习**界定为对自主智能体的系统化训练. 这类智能体由一组关键能力或模块组成, *即*规划 ([第 3.1 节](#section-3-1))、工具使用 ([第 3.2 节](#section-3-2))、记忆 ([第 3.3 节](#section-3-3))、自我改进 ([第 3.4 节](#section-3-4))、推理 ([第 3.5 节](#section-3-5))、感知 ([第 3.6 节](#section-3-6)) 及其他能力 ([第 3.7 节](#section-3-7)); 这一划分遵循经典的 LLM 智能体定义 [Wen23, Sha25b], 如[图 5](#figure-05) 所示. 传统智能体把 LLM 与规划机制 (*例如*, 任务分解和计划选择) [Wei25a]、推理机制 (思维链或多轮推理) [Zha24q]、外部工具调用 [Qin24e]、长短期记忆, 以及用于自我纠正和改进行为的迭代反思结合起来. Agentic RL 不再把这些组件视为静态流水线, 而是将其视为可联合优化、相互依赖的策略: 用于规划的 RL 学习多步决策轨迹; 用于记忆的 RL 塑造检索与编码动态; 用于工具使用的 RL 优化调用时机和准确性; 用于反思的 RL 推动内部自监督与自我改进. 因此, 后续小节将系统考察 RL 如何增强规划、工具使用、记忆、反思与推理能力. 我们旨在勾勒 RL 用于智能体能力的高层概念框架; 对全部相关工作的详尽梳理则放在[第 4 节](#section-4).

### 3.1 规划

规划, 即为实现目标而对一系列行动进行的深思熟虑, 构成了人工智能的基石, 需要复杂的推理、世界知识和适应性 [New58]. 最初的努力通过基于提示的方法 [Hua24d, Yao23b] 充分利用了 LLM 的先天能力. 例如, 模块化智能体规划器 (MAP) [Web25] 引入了一种受大脑启发的模块化架构, 该架构将规划分解为专门的 LLM 模块, 用于冲突监控、状态评估和协调. 然而, 这些方法缺乏通过经验 [Wei25a] 进行适应的机制. 强化学习已经成为解决这一差距的强大范例, 使智能体能够通过学习环境反馈来完善其规划策略. 强化学习与智能体规划的整合体现在两种不同的范式中, 区别在于强化学习是作为结构化规划过程的“外部指南”, 还是作为直接发展 LLM 内在规划策略的“内部驱动因素”, 我们将在下面详细介绍.

**RL 作为规划的外部指南.** 一个主要范式将 RL 定义为规划过程的外部指南, 其中 LLM 的主要作用是在结构化搜索框架内生成潜在的行动. 这里, 强化学习并不是用来直接微调 LLM 的生成能力, 而是用来训练辅助值或启发式函数[Wei25a]. 然后, 该学习函数通过评估不同规划轨迹的质量来指导经典搜索算法, 例如蒙特卡罗树搜索 (MCTS). RAP [Hao23] 和 LATS [Zho24e] 等代表性工作体现了这种方法. 无需搜索的规划 [Hon25c] 通过利用离线目标条件强化学习来学习语言价值评估模型, 从而指导 LLM 推理和规划, 而无需更新 LLM 的参数, 从而扩展了这一想法. 在这种配置中, LLM 充当知识丰富的行动提议者, 而 RL 则提供自适应的评估反馈以实现高效探索. 除了静态指导之外, 学习何时规划 [Pag25] 将动态规划制定为 RL 驱动的测试时计算分配问题, 训练智能体决定何时调用显式规划以平衡推理性能与计算成本. 相反, MAPF-DT [Ata25] 探索了相反的方向, 采用基于决策转换器的离线 RL 进行去中心化多智能体路径规划, 并在 LLM 指导下增强动态环境中的适应性和长期效率.

**强化学习作为规划的内部驱动因素.** 第二种更加集成的范式将强化学习定位为智能体核心规划能力的内部驱动因素. 这种方法将 LLM 直接作为策略模型, 并通过直接的环境互动来优化其规划行为. 不是指导外部搜索算法, 而是使用来自试错的基于强化学习的反馈来直接完善 LLM 生成计划的内部策略. 这是通过源自 RLHF 的方法来实现的, 例如在 ETO [Son24a] 中看到的成功与失败的轨迹上利用 DPO, 或通过终身学习框架来实现. 例如, VOYAGER [Wan24m] 通过环境交互迭代地构建和完善技能库. 这种范式将 LLM 从静态生成器转变为不断发展的自适应策略, 增强了其在动态环境中的稳健性和自主性. 在一个补充方向上, 动态推测规划 (DSP) [Gua25b]体现了一种在线强化机制, 该机制可以调整智能体的策略来共同优化延迟和运营成本, 这表明内部策略细化不仅可以控制任务成功, 还可以控制系统效率. RLTR [Li25s] 将规划与答案生成分离, 并引入直接评估动作序列质量的工具使用奖励, 从而无需依赖可验证的最终答案即可集中优化智能体的规划能力. AdaPlan 及其 PilotRL 框架 [Lu25d] 利用基于计划的全局指导和渐进式 RL 来增强 LLM 智能体在 AFLWorld 和 TextCraft 等文本游戏环境中的长期规划和执行协调. Planner-R1 [Zhu25g] 检查了 Agentic RL 中的奖励密度效应, 结果表明, 成形的过程级奖励可显著提高学习效率, 并使较小的模型获得有竞争力的规划能力.

**前景: 深思熟虑和直觉的综合.** 智能体规划的前景在于这两种范式的综合: 超越外部搜索和内部策略优化之间的区别. 最终目标是开发一种智能体, **将结构化搜索过程本身内部化**, 将直观、快速的计划生成与深思熟虑的、缓慢的、深思熟虑的推理无缝地融合在一起. 在这样的模型中, 强化学习不仅会完善最终计划, 还会优化管理审议过程的元策略: 学习何时探索替代路径、如何修剪无前途的分支, 以及在采取行动之前推理的深度. 这会将 LLM 智能体从提出操作或充当原始策略的组件转变为集成推理引擎.

### 3.2 工具使用

<span id="figure-04"></span>

![图 4. 智能体工具使用的发展.](./agentic-reinforcement-learning/figure-04.png)

**图 4.** 智能体工具使用的发展. 请注意, 此处仅选取少量代表性工作来反映研究进展.

强化学习已成为一种关键方法, 用于将支持工具的语言智能体从事后、ReAct 式管道发展为深度交错、多轮工具集成推理 (TIR) 系统. 虽然早期范例成功证明了工具调用的可行性, 但它们对 SFT 或提示工程的依赖限制了智能体模仿静态模式, 缺乏适应新场景或从错误中恢复的策略灵活性 [Che24m, Kav25]. Agentic RL 通过将学习范式从模仿转变为结果驱动的优化来解决这个问题, 使智能体能够自主发现何时、如何以及部署哪些工具. 这种演变描绘出了清晰的轨迹, 我们分三个阶段进行探索. 我们从 (1) 早期的 ReAct 式工具调用开始, 然后研究 (2) 现代工具集成推理 (TIR), 它将工具的使用深深嵌入到认知循环中, 最后, 讨论 (3) 多轮 TIR 的潜在挑战, 重点关注时间信用分配以实现稳健的长期性能.

**ReAct 风格的工具调用.** 早期的工具调用范例主要依赖于提示工程或 SFT 来引发工具使用行为. **(I) 提示工程**方法, 以 ReAct [Yao23b] 为例, 利用少量样本来指导 LLM 在“思想-行动-观察”循环中交织推理轨迹和行动, 充分利用模型的上下文学习能力. 除此之外, **(II) 基于 SFT 的方法**被引入以内部化模型的工具使用能力. 像 Toolformer [Sch23] 这样的框架采用自我监督的目标来教导模型在哪里插入 API 调用, 而 FireAct [Che23d]、AgentTuning [Zen24a]、Agent-FLAN [Che24n] 等其他框架则在专家生成或策划的工具交互轨迹数据集上微调模型 (例如 AgentBank [Son24]、APIBank) [Li23u]). 尽管 SFT 提高了工具调用的可靠性, 但这两种早期方法从根本上都受到其模仿性质的限制. 他们训练智能体复制静态的、预定义的工具使用模式, 从而缺乏适应新场景或从不可预见的错误中恢复的战略灵活性, 这是以强化学习为中心的方法通过将学习目标从模仿转向结果驱动的优化来直接解决的限制.

**工具集成的强化学习.** 基于纯粹模仿范式的局限性, 基于强化学习的工具使用方法将目标从复制固定模式转变为优化最终任务性能. 这种转变使智能体能够“战略性地”决定“何时”、“如何”以及“以何种组合”调用工具, 动态适应新的环境和不可预见的故障. 在基础上, 诸如 ToolRL [Qia25] 之类的框架证明, 即使从没有任何模仿痕迹的基础模型进行初始化, 强化学习训练也可以引发涌现能力, 例如错误代码的自我纠正、调用频率的自适应调整以及复杂子任务的多个工具的组合. 随后, 最近的研究激增产生了 OTC-PO [Wan25p]、ReTool [Fen25a]、AutoTIR [Wei25c]、VTool-R1 [Wu25j]、DeepEyes [Zhe25h]、Pixel-Reasoner [Su25]、Agentic Reasoning [Wu25h]、ARTIST [Sin25a]、ToRL 等工作[Li25o] 和许多其他工作 [Hao25, Fen24a, Wei25f, Li25h, Wu25d, Li25k, Che25i, Son25d, Ye25a], 它们采用 RL 策略, 在一次部署中将符号计算 (例如代码执行、图像编辑) 与自然语言推理交织在一起. 这种集成的控制环允许智能体平衡精确的、工具介导的操作与灵活的语言推理, 根据不断变化的任务状态定制推理过程. [Xu25]从理论上证明, TIR 通过引入确定性工具驱动的状态转换, 从根本上扩展了 LLM 能力, 超越了纯文本强化学习的“无形束缚”, 为有限预算下的可行性建立了 token 效率论证, 并提出了优势塑造策略优化 (ASPO) 来稳定指导智能体工具的使用.

如今, 这种工具集成推理不再是一种小众功能, 而是高级智能体模型的基本功能. 成熟的商业和开源系统, 例如 OpenAI 的 DeepResearch 和 o3 [Ope25e]、Kimi K2 [Kim25d]、Qwen QwQ-32B [Tea25j]、Zhipu GLM Z1 [Ai25a]、微软 rStar2-Agent [Sha25a] 和美团龙猫 [Mei25], 通常都会整合这些经过 RL 磨练的系统策略, 强调结果驱动优化在工具增强智能中的核心地位.

**前景: 长时程 TIR.** 虽然工具集成的 RL 已被证明可以有效优化单个推理循环内的操作, 但主要前沿在于将此功能扩展到需要多轮推理 [Gao25d] 的稳健、长时程任务. 这种飞跃从根本上受到时间信用分配 [Pig24] 挑战的瓶颈. 当前的强化学习方法通​​常依赖于稀疏的、基于轨迹级别/结果的奖励, 因此很难确定在一个漫长的、相互依赖的序列中哪个特定的工具调用导致了成功或失败. 虽然新兴研究已经开始探索更细粒度的奖励方案, 例如 GiGPO [Fen25b] 和 SpaRL [Wan25m] 中的回合优势估计, 但这些仍处于早期阶段. 因此, 开发更细粒度的信用分配机制, 可以准确地指导智能体通过复杂的决策链, 而不会无意中惩罚有用的探索或促进奖励投机, 仍然是推进智能体系统的一个关键且很大程度上尚未解决的问题.

### 3.3 记忆

智能体强化学习将记忆模块从被动数据存储转变为动态的、强化学习控制的子系统, 决定存储什么、何时检索以及如何忘记, 类似于人类 [Wu25n]. 本节通过四个有代表性的阶段来追踪这一演变.

**RAG 式记忆中的强化学习.** 早期系统 (*例如*, 检索增强生成) 将记忆视为外部数据存储; 当强化学习被使用时, 它只规定何时执行查询. 一些不涉及强化学习的经典记忆系统, 例如 MemoryBank [Zho24d]、MemGPT [Pac23a] 和 HippoRAG [Gut24], 采用预定义的记忆管理策略, 指定如何“存储”、“集成”和“检索”信息 (例如, 通过向量数据库或知识图进行存储; 基于语义相似性或拓扑连接性进行检索). 随后, 强化学习作为功能组件被纳入记忆管理管道. 一个值得注意的例子是 [Tan25b] 中提出的框架, 其中 RL 策略通过“前瞻性反思” (多级摘要) 和“回顾性反思” (强化检索结果) 来调整检索行为. 然而, 存储介质本身保持静态 (*例如*, 简单的向量存储或摘要缓冲区), 并且智能体无法控制写入过程. 最近, Memory-R1 [Yan25f] 引入了一种基于 RL 的记忆增强智能体框架, 其中记忆管理器根据下游 QA 性能通过 PPO 或 GRPO 学习执行结构化操作 (ADD/UPDATE/DELETE/NOOP), 而应答智能体则对 RAG 检索的条目采用记忆蒸馏策略来推理和应答. Mem-$\alpha$ [Wan25ae] 和 Memory-as-action [Zha25aj] 等后续工作也探索了强化学习, 将智能体训练成自动记忆管理器.

**用于 token 级记忆的强化学习.** 随后的进步引入了配备显式可训练记忆控制器的模型, 使智能体能够调节自己的记忆状态 (通常以 token 形式存储), 而无需依赖固定的外部记忆系统. 值得注意的是, 这种记忆通常以两种形式实例化. 第一个是** (I) 显式标记**, 对应于人类可读的自然语言. 例如, 在 MemAgent [Yu25f] 中, 智能体在 LLM 旁边维护一个自然语言记忆池, 并通过 RL 策略确定每个段要保留或覆盖哪些标记, 从而有效地将长上下文输入压缩为简洁、信息丰富的摘要. 类似的方法包括 MEM1 [Zho25i] 和 Memory Token [Jin25c], 这两种方法都显式保留自然语言记忆表示池. 更常见的是, 像 ReSum [Wu25l]、上下文折叠 [Sun25d] 这样的工作也探索了 RL 用于上下文记忆管理. 第二种形式是 **(II) 隐式标记**, 其中记忆以潜在嵌入的形式维护. 代表性的工作包括 MemoryLLM [Wan24t] 和 M+ [Wan25ad], 其中一组固定的潜在 token 充当“记忆 token”. 随着上下文的发展, 这些标记会被反复检索、集成到 LLM 的前向计算中并进行更新, 从而保留上下文信息并表现出强大的抗遗忘能力. 与显式标记不同, 这些记忆标记不与人类可读的文本绑定, 而是构成机器本机形式的记忆. 相关工作包括 IMM [Orl25] 和 Memory [Yan24i]. 在这两种范式中, 这些方法使智能体能够自主管理其记忆库, 从而在长上下文理解、持续适应和自我完善方面取得显著进步. MemGen [Zha25p] 首次提出了利用潜在记忆 token 来承载和生成经验知识的范式, 为基于强化学习的潜在记忆提供了有希望的方向.

**前景: 结构化记忆的强化学习.** 基于 token 级方法, 最近的趋势正在转向“结构化”记忆表示, 它组织和编码平面 token 序列之外的信息. 代表性的例子包括 Zep [Ras25]中的时间知识图、A-MEM [Xu25d]中的原子记忆笔记以及 G-Memory [Zha25o]和 Mem0 [Chh25]中基于分层图的记忆设计. 这些系统捕获更丰富的关系、时间或层次依赖性, 从而实现更精确的检索和推理. 然而, 它们的管理, 包括插入、删除、抽象和链接更新, 迄今为止一直受到手工规则或启发式策略的控制. 迄今为止, 很少有工作探索使用强化学习来动态控制此类结构化记忆的构建、细化或演化, 这使得这是推进智能体记忆能力的一个开放且有前途的方向.

### 3.4 自我提升

随着 LLM 智能体的发展, 最近的研究越来越强调强化学习是一种持续反思的机制, 使智能体能够从自己的错误中学习, 包括规划、推理、工具使用和记忆 [Gao25c]. 这些系统并不完全依赖于数据驱动的训练阶段或静态奖励模型, 而是结合了“迭代的、自我生成的反馈循环”, 从提示级启发式到成熟的强化学习控制器, 引导智能体不断自我改进.

**用于语言自我纠正的强化学习.** 这方面的初始方法利用基于提示的启发式方法, 有时称为“语言强化学习”, 其中智能体生成答案, 在语言上反映其潜在错误, 并随后生成完善的解决方案, 所有这些都在一次推理过程中进行, 无需梯度更新. 突出的例子包括 Reflexion [Shi23c]、Self-refine [Mad23]、CRITIC [Gou24] 和 Chain-of-Verification [He24c]. 例如, Self-Refine [Mad23] 协议指导 LLM 使用三种不同的生成、反馈和细化提示迭代地完善其输出, 在推理和编程等领域证明是有效的. 为了增强这种自我反思的有效性和鲁棒性, 已经开发了几种不同的策略: **(I) 多重采样**, 其中涉及通过从模型的分布中采样来生成多个输出 rollout. 通过汇总多次尝试的批评或解决方案, 智能体可以提高其自我反思的一致性和质量. 该方法在 If-or-Else [Li24m]、UALA [Han24a] 和 Multi-agent Verification [Lif25] 等工作中得到了广泛研究. 这种方法在概念上类似于测试时间缩放技术, 因此我们建议读者参考 [Pig24] 了解更多详细信息; **(II) 结构化反思工作流程**, 而不是提示对最终答案进行整体反思, 而是规定更专用和更精细的工作流程. 例如, 验证链 [He24c] 将流程手动分解为不同的“检索、重新思考和修改”阶段; **(III) 外部指导**, 通过纳入外部工具, 将反思过程建立在可验证、客观反馈的基础上. 这些工具包括代码解释器 (如自调试 [Che24l] 中所示) 、鲁班 [Guo24b] 中的 CAD 建模程序、T1 [Kan25a] 中的数学计算器、逐步奖励模型 [Xio25] 以及工具交互式批评机制 [Gou24].

**内部化自我纠正的强化学习.** 虽然口头自我纠正提供了一种有效的推理时间技术, 但其改进是短暂的并且仅限于单个会话. 为了灌输更持久和更广泛的自我改进能力, 后续研究采用了基于梯度更新的强化学习, 将这些反思反馈循环直接内化到模型参数中, 从根本上增强模型识别和纠正自身错误的固有能力. 该范例已应用于多个领域. 例如, KnowSelf [Qia25b]利用 DPO 和 RPO [Pan24d]来增强智能体在基于文本的游戏环境中的自我反思能力, 而 Reflection-DPO [Pat25b]则专注于用户与智能体交互场景, 使智能体能够通过反思推理更好地推断用户意图. DuPo [She25] 采用具有双任务反馈的 RL 来实现无注释优化, 增强 LLM 智能体在翻译、推理和重新排序任务中的自我纠正能力. SWEET-RL [Zho25g] 和 ACC-Collab [Est25a] 采用与上述工作略有不同的设置: 它们训练外部 Critic 模型, 为演员智能体的动作提供更高质量的修改建议. 尽管如此, 基本原则仍然紧密一致.

**用于迭代自我训练的强化学习.** 第三类也是最先进的一类模型将反思、推理和任务生成结合到一个自我维持的循环中, 从而实现完全智能体自主, 无需人工标记数据即可实现无限的自我改进. 这些方法可以通过其学习循环的架构来区分: **(I) 自我游戏和搜索引导的细化**, 它模拟经典的 RL 范式, 如 AlphaZero. 例如, R-Zero [Hua25a] 采用蒙特卡罗树搜索 (MCTS) 来探索推理树, 使用搜索结果完全从头开始迭代训练策略 LLM (Actor) 和价值 LLM (Critic). 类似地, ISC 框架 [Tia24b] 运行“想象、搜索和批评”的循环, 其中智能体生成潜在的解决方案路径, 使用搜索算法来探索它们, 并在产生最终答案之前利用 Critic 来完善其推理策略. **(II) 执行引导的课程生成**, 智能体创建自己的问题并从可验证的结果中学习. 绝对零[Zha25ao]通过提出自己的任务、尝试解决方案、通过执行验证它们以及使用基于结果的奖励来完善其策略来证明这一点. 类似地, 自我进化课程 [Che25k] 通过将问题选择本身构建为非平稳老虎机任务来增强这一过程, 从而允许智能体策略性地生成一个课程, 随着时间的推移最大化其学习收益. TTRL [Zuo25] 应用此原理对单个问题进行即时适应. 在测试时, 它使用基于执行的奖励来快速调整智能体针对当前特定任务的策略的临时副本; 然后使用这个专门的策略来生成最终答案, 然后再将其丢弃. 尽管学习是永久的还是短暂的有所不同, 但所有这些方法都强调了一个强大的、统一的策略: 利用基于执行的反馈来自主指导智能体的推理过程. ALAS [Atr25] 构建了一个自主管道, 可以抓取网络数据, 将其提炼为训练信号, 并不断微调 LLM, 从而无需手动数据集管理即可实现自我训练和自我进化. **(III) 集体引导**, 通过汇总共享经验来加速学习. 例如, SiriuS [Zha25as] 构建并增强了来自多智能体交互的成功推理轨迹的实时代码仓库, 利用这个不断增长的知识库来引导自己的训练课程. MALT [Mot25] 具有类似的动机, 但其实施仅限于三智能体设置. 尽管如此, 所有这些方法都定义了内部生成并不断发展的反馈循环, 代表着向真正自主智能体迈出了重要一步.

**前景: 反思能力的元进化.** 虽然当前的研究成功地使用强化学习通过反思来完善智能体的行为, 但反思过程本身在很大程度上仍然是手工制作的和静态的. 下一个前沿领域在于在更高的抽象层次上应用强化学习, 以实现**自适应反思的元学习**, 不仅关注纠正错误, 还关注学习如何随着时间的推移更有效地进行自我纠正. 在这种范式中, 智能体可以学习管理其自身反思策略的元策略. 例如, 它可以学习为给定任务动态选择最合适的反思形式, 决定快速口头检查是否足够, 或者是否需要成本更高的执行引导搜索. 此外, 智能体可以利用长期结果来评估和完善其用于自我批评的启发式方法, 从而有效地学习成为更好的内部 Critic. 通过优化反思机制本身, 这种方法超越了简单的自我纠正, 并在学习过程中走向了不断自我完善的状态, 代表着向智能体迈出了关键的一步, 不仅可以解决问题, 而且可以自主增强从经验中学习的基本能力.

<span id="section-3-5"></span>

### 3.5 推理

大语言模型中的推理可以大致分为“快速推理”和“慢速推理”, 基于双过程认知理论 [Kah11a, Tve74, Wes00], 正如最近的综述 [Ke25, Kum25] 中所讨论的那样. 快速推理对应于具有最少中间步骤的快速、启发式驱动的推理, 而慢速推理则强调深思熟虑的、结构化的和多步骤的推理. 了解这两种范式之间的权衡对于设计在复杂问题解决中平衡效率和准确性的模型至关重要.

**快速推理: 直观且高效的推理** 快速推理模型的运行方式类似于系统 1 [Li25u] 认知: 快速、直观且模式驱动. 他们无需明确的逐步审议即可立即做出响应, 在优先考虑流畅性、效率和低延迟的任务中表现出色. 大多数传统的 LLM 都属于这一类, 其中推理被隐式编码在下一个 token 预测 [Sha24d, Yan24j] 中. 然而, 这种效率是以系统推理为代价的, 使得这些模型更容易受到事实错误、偏见和肤浅的过度概括的影响.

为了解决快速推理中的严重幻觉问题, 当前的研究主要集中在各种直接方法上. 一些研究试图通过利用内部机制 [Wan23g, Yao23a, Bes24a] 或通过模拟类人认知推理来减轻下一个 token 预测范式中的错误和幻觉. 其他工作建议引入外部和内部置信估计方法 [Lig23a, Wan24p] 来识别更可靠的推理路径. 然而, 构建此类外部推理框架通常会面临算法适应性问题的风险, 并且很容易陷入复杂性陷阱.

**慢速推理: 深思熟虑和结构化的问题解决** 相反, 慢速推理模型旨在通过显式生成中间推理轨迹来模拟系统 2 认知 [Li25u]. 思路链提示、多步验证[Qin24d]、推理增强强化学习等技术让这些模型能够进行更深入的反思, 实现更大的逻辑一致性. 虽然由于扩展推理轨迹导致推理速度较慢, 但​​它们在数学、科学推理和多跳问答 [Chu25] 等知识密集型任务中实现了更高的准确性和鲁棒性. 代表性示例包括 OpenAI 的 o1 [Ope24h] 和 o3 系列 [Tea25c]、DeepSeek-R1 [Dee25c], 以及结合动态测试时间缩放 [Wel25, Zha24o, Xu25a, Yao23a] 或强化学习 [Zen25b, Yu25g, Wan25v, Lia25b, Lia25c, Yue25] 进行推理的方法.

现代慢速推理的输出结构与快速推理有很大不同. 其中包括清晰的探索和规划结构、频繁的验证和检查行为以及通常较长的推理长度和时间. 过去的工作探索了构建长链推理输出的多种模式. 一些方法 (Macro-o1、HuatuoGPT-o1 和 AlphaZero) 尝试通过结构化的智能体搜索 [Zha24s, Che24i, Che24h] 来合成长的思想链. 其他方法侧重于生成体现特定审议或反思思维模式的长 CoT 数据集; 示例包括 HiICL-MCTS、LLaVA-CoT、rStar-Math 和 ReasonFlux [Wu25g, Xu25b, Gua25a, Yan25j]. 最近在潜在空间中执行推理的方法利用潜在表示来进行并行推理并探索不同的推理轨迹 [Zha25al, Hao24]. 随着预训练基础模型的进步, 最近的工作已经转向自我改进范式——通常用强化学习来实例化——以进一步增强模型的推理能力 [Zen25b, Yu25g].

**前景: 将慢速推理机制整合到智能体推理中** 快速推理和慢速推理之间的二分法凸显了智能体推理中的一个开放挑战: 如何利用强化学习来可靠地训练智能体场景中的慢速推理推理能力. 智能体场景下的强化学习在训练稳定性方面面临更大的挑战, 例如确保与不同环境的兼容性. 主体推理本身也容易出现过度思考的情况. 纯粹的快速模型可能会忽略关键的推理步骤, 而缓慢的模型通常会遭受过度延迟或**过度思考行为**的影响, 例如不必要的长思想链. 新兴方法寻求混合策略 [Yan25g], 将快速推理的效率与慢速推理的严谨性 [Yan25m, Hou25, Li25t, Che25l] 结合起来. 例如, 自适应测试时间缩放允许模型根据任务复杂性决定是快速响应还是进行扩展审议. 开发这种认知一致的机制是构建高效可靠的推理智能体的关键一步.

### 3.6 感知

通过将视觉感知与语言抽象联系起来, 大视觉语言模型 (LVLM) 展示了前所未有的感知和理解多模态内容 [Tea23, Liu23n, Wan24q, Li24o, Che24p, Ope23e, Zha25ab, Zha24p] 的能力. 这一进展的核心是将显式推理机制纳入多模态学习框架 [Sha24c, Zha23i], 从被动感知转向主动视觉认知 [Su25b]. 强化学习已成为实现此目的的强大范例, 使视觉-语言-动作模型与复杂的多步骤推理目标保持一致, 超越了监督下一个 token 预测 [Zho25c, Wu25k] 的限制.

**从被动感知到主动视觉认知** 多模态内容通常需要细致入微、依赖于上下文的解释. 受 RL 在增强 LLM [Dee25c, Tea25h] 推理方面取得的巨大成功的启发, 研究人员越来越多地寻求将这些成果转移到多模态学习 [She25a, Pen25a] 中. 早期的工作重点是基于偏好的强化学习, 以增强 MLLM [Wan24s, Don25d, Zhu25e] 的思想链 (CoT) 推理能力. Visual-RFT [Liu25v] 和 Reason-RFT [Tan25a] 直接将 GRPO 应用于视觉领域, 自适应地将 IoU 等视觉特定指标作为可验证的奖励信号, 而 STAR-R1 [Li25w] 通过引入针对视觉 GRPO 定制的部分奖励来​​扩展这一想法. 在此基础上, Vision-R1 [Hua25c]、VLM-R1 [She25a]、LMM-R1 [Pen25a] 和 MM-Eureka [Men25] 等一系列方法开发了专门的策略优化算法, 旨在激励逐步视觉推理, 即使在较小的 3B 参数模型上也能表现出强大的性能. SVQA-R1 [Lin25d] 引入了 Spatial-GRPO, 这是一种新颖的分组 RL 方法, 可强制执行视图一致和变换不变的目标. Visionary-R1 [Xia25a] 将图像字幕强制作为推理之前的先决步骤, 从而减少强化微调期间的捷径利用. 还提出了一系列课程学习方法来简化和平滑视觉强化微调 [Yan25i, Che25g, Zha25k, Guo25e, Don25d] 的 RL 训练过程. R1-V [Che25g] 引入了 VLM-Gym, 并通过可扩展的纯 RL 自进化和感知增强冷启动来训练 G0/G1 模型, 从而在不同的视觉任务中产生涌现的感知与推理协同. R1-Zero [Zho25f] 表明, 即使是简单的基于规则的奖励也可以在非 SFT 模型中引发自我反思和扩展推理, 超越监督基线. PAPO [Wan25af] 提出了一种感知感知策略优化框架, 通过隐式感知 KL 损失和双熵正则化增强 RLVR 方法, 而 [Li25v] 提出了 RL 训练下的总结然后推理框架, 以减轻视觉幻觉并在没有密集人类注释的情况下改进推理. 总的来说, 这些方法表明, 只要使用精心设计的、可验证的奖励指标, R1 式 RL 可以成功转移到视觉领域, 从而在性能、鲁棒性和分布外泛化方面产生显著改进.

最近的工作探索了强化学习的另一个关键优势: 超越了将任务表述为被动感知的模式, 其中静态的、可验证的奖励仅根据 LVLM 基于文本的输出来计算. 相反, 强化学习可以用来激励对多模态内容的主动认知——将视觉表征视为可操作和可验证的中间思想. 这种范式使模型不仅能够“查看并回答”, 而且能够主动查看、操纵视觉信息并进行推理, 作为多步骤认知过程 [Su25b] 的一部分.

**基础驱动的主动感知.** 为了从被动感知推进到主动视觉认知, 一个关键方向是使 LVLM 能够在生成推理过程的同时反复回顾和查询图像. 这是通过扎根 [Nag16a, Mao16] 来实现的, 它将生成的思维链 (CoT) 的每一步锚定到多模态输入的特定区域, 通过显式地将文本与相应的视觉区域链接起来, 促进更有效和可验证的推理.

首先, GRIT [Fan25b] 将边界框标记与文本 CoT 交织在一起, 并使用具有可验证奖励和边界框正确性的 GRPO 作为监督. [Chu25c] 引入了一种简单的指向和复制机制, 允许模型在整个推理过程中动态检索相关图像区域. Ground-R1 [Cao25a] 和 BRPO [Chu25b] 在纯文本推理之前突出显示证据区域 (通过基于 IoU 的或反思奖励), 而 DeepEyes [Zhe25h] 则表明端到端 RL 可以自然地诱导这种接地行为. 焦点链通过基础 CoT 步骤并随后放大操作, 进一步完善了这种方法.

**工具驱动的主动感知.** 实现主动感知的另一个有希望的方向是将视觉认知构建为一个智能体过程, 其中外部工具、代码片段和运行时环境协助模型的认知工作流程 [Kem23, Zha25ar]. 例如, VisTA [Hua25d]和 VTool-R1 [Wu25j]专注于教授模型如何通过强化学习选择和使用视觉工具, 而 OpenThinkIMG [Su25a]则为训练模型“用图像思考”提供标准化基础设施. 最后, Visual-ARFT [Liu25v] 利用 RL 来促进工具创建, 利用 MLLM 的代码生成功能来动态扩展其感知工具包. Pixel Reasoner [Su25] 通过裁剪、擦除和绘制等操作扩展了模型的动作空间, 并引入了好奇心驱动的奖励来阻止过早终止探索.

**生成驱动的主动感知.** 除了基础和工具使用之外, 人类还利用他们最强大的认知能力之一——想象力——来绘制有助于解决问题的草图或图表. 受此启发, 研究人员开始为 LVLM 配备生成与思想链 (CoT) 推理交错的草图或图像的能力, 使模型能够更有效地具体化中间表示和推理 [Xu25e, Fan25c, Li25e]. 视觉规划[Xu25e]建议仅使用想象图像轨迹作为 CoT 图像思维, 使用下游任务成功作为奖励信号. GoT-R1 [Dua25] 在 Generation-CoT 框架内应用强化学习, 允许模型在生成图像之前自主发现语义空间推理计划. 类似地, T2I-R1 [Jia25b] 显式地将过程解耦为用于高级规划的语义级 CoT 和用于逐图像块的像素生成的 token 级 CoT, 并与 RL 联合优化这两个阶段.

**音频.** 强化学习也已从视觉语言模型扩展到包括音频在内的多种模式. 在音频语言领域, 我们将强化学习应用分为两大类. (1) 大型音频语言模型的推理增强: 利用强化学习指导模型为音频问答和逻辑推理 [Wen25, Dia25, Li25f, Li25f, Wen25] 等任务生成结构化、逐步的推理链. (2) 语音合成 (TTS) 中的细粒度组件优化: 采用强化学习直接细化系统组件, 例如改进持续时间预测器, 使用说话者相似度和单词错误率等感知质量指标作为奖励信号, 从而产生更自然、更易理解的语音 [Li25p]. 其他一些工作如 EchoInk-R1 [Xin25a] 通过在 GRPO 优化下集成视听同步, 进一步丰富了视觉推理.

### 3.7 其他

除了优化上述核心认知模块之外, Agentic RL 还增强了在扩展的**多轮交互**中保持策略一致性的能力. 在这里, 强化学习用于支持长期推理和有效的信用分配.

对于长期交互, 核心挑战是时间信用分配 [Pig24], 其中稀疏和延迟的反馈模糊了智能体的行为与遥远结果之间的联系. 智能体强化学习通过改进学习信号和优化框架来直接应对这一问题. 一种主要方法是 **(I) 基于流程的监督与最终结果奖励的集成. ** 该范例不依赖于轨迹结论的单一奖励, 而是使用*辅助模型*或*程序规则*来评估中间步骤的质量, 提供更密集、更直接的学习信号来指导智能体的多回合策略. 例如, EPO [Liu25m]、ThinkRM [Hon25b]、SPO [Guo25d]和 AgentPRM [Cho25]引入外部奖励模型, 为智能体提供逐步信号; 相比之下, RLVMR [Zha25an] 设计了手动定义的编程规则来指导中间监督. 第二个补充策略是 **(II) 将偏好优化从单轮扩展到多步骤分段. ** 像分段级 DPO (SDPO) [Kon25] 这样的技术超越了比较孤立的响应, 而是在整个对话片段或动作序列上构建偏好数据. 这使得模型能够直接了解早期决策如何影响长期成功, 从而提高其在扩展对话和复杂任务中保持战略一致性的能力.

### 4.1 搜索和研究智能体

搜索一直是利用外部知识扩展 LLM 的核心, 检索增强生成 (RAG) 是一种广泛使用的方法 [Gao24e, Fan24b]. 该范式现在正在从简单的信息检索发展到创建能够“深入研究”的自主智能体: 复杂的多步骤过程, 不仅涉及查找信息, 还涉及进行深入分析, 综合来自众多来源的见解, 并起草综合报告 [Kim25d, Per25]. 这种转变将目标从回答查询提升到处理复杂的研究任务. 早期的提示驱动方法依赖于脆弱的查询策略和手动工程. 虽然像 Search-o1 [Li25k] 这样的最新工作利用大型推理模型进行智能体、推理时间检索, 以及 DeepResearch [Zha25ad] 协综述询和摘要子智能体等多智能体系统, 但它们仍然缺乏学习信号. 这些基于提示的方法缺乏任何微调信号, 导致泛化能力有限, 并且在需要紧密循环的搜索、推理和综合的多轮设置中效果不佳. 这些限制导致采用强化学习来直接优化查询生成和搜索推理协调的端到端过程, 以实现高级研究目标. #### 4.1.1 开源强化学习方法

**从外部互联网搜索** 主要工作线建立在 RAG 基础上, 但依赖*实时网络搜索 API* 作为外部环境, 使用强化学习来优化查询生成和多步骤推理. DeepRetrieval [Jia25c] 率先取得了早期进展, 它将一次性查询生成构建为 GRPO 训练的策略, 并直接奖励针对实时搜索结果的召回和相关性. 受其成果的推动, 后续方法将范式扩展到多轮、推理集成和多模态搜索. Search-R1 [Jin25b] 和 DeepResearcher [Zhe25f] 将检索到的 token 屏蔽与基于结果的奖励集成起来, 以交错查询制定和答案生成. AutoRefine [Shi25b] 通过在连续搜索调用之间插入细化阶段, 使用 GRPO 不仅奖励答案正确性, 而且奖励检索质量, 进一步推进了这一轨迹, 使智能体能够在长时程推理过程中迭代过滤和构建噪声证据. R1-Searcher [Son25a] 采用两阶段冷启动 PPO 策略——首先学习何时调用网络搜索, 然后如何利用它——而其后继者 R1-Searcher++ [Son25b] 增加了监督微调、内部知识奖励以避免冗余, 以及动态记忆以持续同化. ReSearch [Che25i] 追求完全端到端的 PPO, 无需监督工具使用轨迹, 而 StepSearch [Wan25ah] 通过分配中间步骤级奖励来加速多跳 QA 的收敛. Atom-Searcher [Den25b] 是一个智能体深度研究框架, 它通过改进推理过程本身 (而不仅仅是最终结果) 来显著提高 LLM 问题的解决能力. WebDancer [Wu25d] 利用人类浏览轨迹监督和 RL 微调来生成自主的 ReAct 式智能体, 在 GAIA [Mia24] 和 WebWalkerQA [Wu25e] 上表现出色. WebThinker [Li25l] 将 Deep Web Explorer 嵌入到思考-搜索-草稿循环中, 通过 DPO 与人类反馈保持一致, 以解决复杂的报告生成问题. WebSailor [Li25h] 是一种完整的后训练方法, 旨在教授 LLM 智能体针对复杂的网络导航和信息查找任务进行复杂的推理. WebWatcher [Gen25] 进一步扩展到多模态搜索, 结合视觉语言推理、工具使用和 RL, 在 BrowseComp-VL 和 VQA 基准上超越纯文本和多模态基线. ASearcher [Gao25d] 使用大规模异步强化学习和合成的 QA 数据, 实现长程搜索 (40 多个工具调用) 并超越之前的开源方法. MiroMind 开放深度研究 (MiroMind ODR) [Tea25b] 旨在构建一个高性能、完全开源、开放协作的深度研究生态系统—智能体框架、模型、数据和训练基础设施均完全可访问和开放.

**从 LLM 内部知识搜索** 然而, 这些依赖外部 API 的训练方法面临两大挑战: (1) 实时互联网文档搜索的文档质量不受控制, 噪声信息给训练过程带来不稳定. (2) API 成本过高, 严重限制可扩展性. 为了增强训练的效率、可控性和稳定性, 最近的一些研究使用了 LLM 内部知识等可控模拟搜索引擎. 例如, ZeroSearch [Sun25b] 用从 LLM 本身提炼出来的伪搜索引擎取代了实时网络检索, 结合课程强化学习, 逐渐接近实时引擎性能, 而无需发出真正的查询. SSRL [Fan25a] 进一步发展了这一想法: 智能体在训练期间执行完全离线的“自我搜索”, 无需显式搜索引擎, 但可以无缝转移到在线推理, 而真正的 API 仍然可以提高性能. 尽管仍处于早期阶段, 但离线自我搜索增强了稳定性和可扩展性, 超越了 API 限制, 指向更多自力更生的研究智能体.

<span id="section-4-1-2"></span>

#### 4.1.2 闭源强化学习方法

**工业研究智能体.** 尽管在结合 RAG 和 RL 方面取得了进展, 但大多数开源模型在 OpenAI 的 BrowseComp [Wei25b] 上仍然失败, 这是一个具有挑战性的基准, 用于衡量 AI 智能体定位难以查找的信息的能力, 揭示长期规划、基于页面的工具使用和跨源验证方面的差距. 相比之下, 最近的闭源系统明显更强大, 已经从单纯的查询优化转变为完全自主的研究智能体, 可以导航开放网络、综合多个来源的信息并起草综合报告. 这可能是由于该行业拥有更强大的基础模型和更多高质量数据的可用性. OpenAI Deep Research [Ope25e] 在 BrowseComp 上达到 51.5% pass@1. 其他原型, Perplexity 的 DeepResearch [Per25]、Google Gemini 的 DeepResearch [Goo25]、Kimi-Researcher [Kim25d]、Grok AI DeepSearch [Xai25]、Doubao 和 Deep Think [Dou25], 将 RL 风格的微调与先进的工具集成和记忆模块相结合, 开创了交互式、迭代研究助手的新时代.

**案例研究: OpenAI Deep Research.** Deep Research 提供了一个具体示例, 说明[第 3 节](#section-3) 中的功能如何与 RL 型搜索策略相结合. 智能体从长期多步骤推理和规划开始, 将用户请求分解为子目标. 然后, 它执行 RL 型网络搜索: 发出查询、选择要打开的页面以及完善其搜索轨迹. 这些搜索策略是在训练期间使用 BrowseComp [Wei25b] 等面向研究的基准制定的. 在整个过程中, 智能体以暂存笔记的形式维护持久记忆, 并在综合之前执行跨源验证. 这些功能——推理、规划、工具使用、记忆和验证——与搜索深度、分支选择和证据集成的强化学习控制决策相结合, 形成了一个统一的研究智能体.

### 4.2 代码智能体

代码生成, 或者更广泛地说, 软件工程, 为基于 LLM 的 Agentic RL 提供了理想的测试平台: 执行语义是明确且可验证的, 并且自动信号 (编译、单元测试和运行时跟踪) 很容易获得 [Don25b]. 早期的多智能体框架 (*例如*、MetaGPT、AutoGPT、AgentVerse) 通过提示而不更新参数来协调角色, 展示了模块化角色分配 [Hon24a, Gra23, Che24k] 的前景. 代码的初始强化学习 (例如 CodeRL) 结合了基于执行的奖励模型和行动者 Critic 训练 [Le22], 催生了一波利用执行反馈来指导策略更新的研究. [表 5](#table-05) 展示了本节中研究的大部分工作. 我们沿着*任务复杂性*的增加来构建文献, 从*代码生成* ([第 4.2.1 节](#section-4-2-1)) 到*代码细化* ([第 4.2.2 节](#section-4-2-2)) 和*软件工程* ([第 4.2.3 节](#section-4-2-3)).

<span id="section-4-2-1"></span>

#### 4.2.1 RL 用于代码生成

早期的研究集中在相对简单的单轮代码生成 (*例如*, 一次性完成一个功能或解决一个编码挑战), 这为后续的大规模软件工程奠定了基础.

**结果奖励 RL.** 此类中的方法直接针对最终正确性进行优化, 通常通过 pass@k 或单元测试成功来衡量. AceCoder [Zen25a] 引入了用于代码生成的数据高效 RLHF 管道, 从现有代码片段构建大规模偏好对, 以通过 Bradley-Terry 损失训练奖励模型, 然后指导合成数据集上的 RFT. 除了早期的演员-Critic 公式之外, 最近的开源工作还在大型预训练代码模型上扩展了基于结果的强化学习. DeepCoder-14B [Luo25e] 通过迭代上下文延长和 DAPO 启发的过滤来稳定 GRPO 训练, 并采用稀疏结果奖励模型 (ORM) 来防止对策划编码数据的奖励投机攻击. RLTF 采用在线 RL 循环, 使用单元测试结果作为多粒度奖励信号, 从粗略的通过/失败结果到细粒度的故障定位, 直接指导代码细化 [Liu23o]. CURE 正式化了编码器-测试人员的共同进化: 测试人员生成或进化单元测试, 而编码器迭代地修补代码; 奖励精度目标可以减轻联合训练 [Wan25ab] 期间的低质量测试效果. 绝对零应用无需人类数据的自我对弈强化学习. 它为自己生成编码任务, 并使用执行结果作为可验证的奖励来引导推理能力 [Zha25ao]. Re:Form [Yan25e] 利用基于形式语言的 RL 推理和自动验证来减少人类先验, 从而实现可靠的程序合成并超越形式验证任务的强大基线. 在 [Fen25c] 中, 作者提出了一个两阶段的训练流程: 首先对高正确性基线进行微调, 然后执行效率驱动的在线 RL 优化.

**过程奖励 RL.** 为了减轻稀疏性和信用分配, 一些工作通过集成编译和执行反馈来设计流程级监督. StepCoder [Dou24] 将编译和执行分解为步级信号进行整形; 流程监督引导策略优化 (PSGPO) [Dai25]利用中间错误跟踪和流程注释来获得密集奖励; CodeBoost [Wan25y] 挖掘原始代码仓库, 以在单个 PPO 框架下统一异构执行衍生的信号, 范围从输出正确性到错误消息质量. 此外, PRLCoder [Ye25b] 通过构建对每个部分片段进行评分的奖励模型来引入过程监督强化学习: 教师模型会改变参考解决方案的行, 并根据编译器和测试反馈分配正/负信号. 与基本模型相比, 这种细粒度的监督可带来更快的收敛速度和 +10.5% 的通过率提高, 这说明了行级密集整形如何比仅输出信号更有效地指导代码合成. o1-Coder [Zha24r] 将强化学习与蒙特卡洛树搜索相结合, 其中策略从测试用例奖励引导的探索中学习, 并逐渐从伪代码改进为可执行代码. 后验-GRPO [Fan25] 奖励中间推理, 但通过最终测试成功来控制信用, 以防止投机性奖励利用; RLHF [Zha25n] 的策略过滤通过在策略更新之前过滤低置信度对来改进奖励正确性对齐. 将偏好监督扩展到昂贵的人工注释之外也被证明是有效的. CodeFavor [Liu24s] 根据代码演化历史构建 CodePrefBench, 涵盖正确性、效率、安全性和风格, 以改进偏好建模和对齐. Focused-DPO [Zha25aa] 通过在代码的易错区域上加权偏好优化来适应基于偏好的 RL, 使反馈更有针对性并提高跨基准的稳健性. [Yan25l] 研究了 RL 训练的小规模智能体如何通过分布式异步 RL 中的持续时间感知梯度更新来超越 MLE 环境中的大规模基于提示的模型.

#### 4.2.2 用于迭代代码细化的强化学习

第二条研究目标是需要调试和迭代细化的更复杂的编码任务. 在这些场景中, 智能体可能需要多次尝试, 使用人类需求或失败的测试结果的反馈来改进解决方案, 这更接近现实世界的任务.

**结果奖励 RL.** 一条代表线将整个细化循环视为一条轨迹, 同时优化最终任务的成功. RLEF [Geh25] (执行反馈强化学习) 将真实错误消息中的校正循环作为上下文, 同时优化最终通过率; 相对于单次基线, 这减少了所需的尝试次数并提高了竞争性编程性能. $\mu$Code [Jai25] 在单步奖励反馈下联合训练生成器和学习验证者, 表明验证者引导的结果奖励可以优于纯粹的执行反馈基线. R1-Code-Interpreter [Che25m] 利用多轮监督微调和强化学习来训练 LLM 来决定在逐步推理过程中何时以及如何调用代码解释器.

#### 4.2.3 自动化软件工程的强化学习

**结果奖励强化学习.** 现实环境中的端到端训练表明, 稀疏但经过验证的成功信号可以扩展. DeepSWE 使用经过验证的任务完成情况作为唯一奖励, 对软件工程任务执行大规模 RL, 在 SWE 基准式评估 [Luo25d] 上取得领先的开源结果. SWE-RL 从 GitHub 提交历史中提取基于规则、以结果为导向的信号, 从而能够对真实的改进模式进行训练, 并泛化到看不见的错误修复任务 [Wei25e]. Satori-SWE 引入了一种支持 RL 的进化测试时间缩放方法 (EvoScale), 该方法可以训练模型在迭代中自我改进, 以实现样本高效的软件工程任务 [Zen25]. OS-R1 [Lin25b] 提出了一种用于 Linux 内核调优的基于规则的强化学习框架, 可实现高效探索、准确配置以及优于启发式方法的性能. RLCoder 将检索增强的代码仓库级代码完成构建为 RL 问题, 使用基于困惑的反馈来训练检索器在没有标记数据 [Wan25aa] 的情况下获取有用的上下文. Qwen3-Coder 在 20,000 个并行环境中的长时程、多回合交互上执行大规模执行驱动的强化学习, 在 SWE-Bench Verified [Tea25i] 等基准测试中产生最先进的性能. 在机器学习领域, ML-Agent 执行多步骤管道 (*例如*, 自动化 ML), 优化基于性能的终端奖励 [Liu25q].

**过程奖励 RL.** 对智能体轨迹的密集监督改善了许多步骤的信用分配. 从优化的角度来看, 长上下文、多轮软件智能体受益于稳定的策略梯度变体; 例如, 解耦剪辑和动态采样策略优化 (DAPO) 通过多轮代码生成和调试交互, 利用长上下文反馈 [Gol25a], 提高了 SWE 平台上的训练稳定性和性能. SWEET-RL 在 ColBench (后端和前端任务) 上训练多回合智能体, 利用 RL 期间的特权信息来减少探索噪声并提高长时程泛化能力 [Zho25g].

**关于闭源系统的评论.** OpenAI 的 Codex 和 Anthropic 的 Claude Code 等商业系统强调根据偏好进行微调和强化学习, 以提高代码生成和编辑工作流程 [Ope25f, Ant25d] 的实用性和安全性. 虽然具体的训练细节受到公开限制, 但这些系统强调了 RL 在实际 IDE 和终端环境中将智能体行为与以开发人员为中心的目标相结合方面发挥的日益重要的作用.

#### 4.2.4 新兴范式

**代码世界模型** 最近的范式转变通过将世界模型本身构建为可执行代码来背离传统的神经近似. 在这些代码世界模型 (CWM) 中, 智能体综合程序来明确定义转换和奖励动态, 通过可验证的符号模拟而不是不透明的潜在状态来实现基于模型的规划.

GIF-MCTS [Dai24a] 将世界模型构建制定为程序归纳: LLM 编辑“环境”类, 搜索过程选择最能解释离线转换的版本, 生成适合下游规划的可执行模型. WorldCoder [Tan24a] 将动态和奖励表示为显式 Python 函数, 并通过由转换一致性和乐观约束引导的迭代合成修复过程对其进行细化. Meta 的 32B CWM [Tea25f] 通过提供一个在解释器轨迹和智能体轨迹上训练的开放权重模型来增强这一范式, 以提高程序合成和执行保真度. 最近的工作进一步将 CWM 应用于通用游戏环境 [Leh25], 其中 LLM 引入完整的基于规则的模拟器, 并直接在可执行模型上执行规划.

实现这些程序化的世界模型范式通常会产生大量的推理成本, 因为智能体会反复综合、细化和查询可执行模拟器. 在实践中, 经常采用低位量化 (例如, RTX 4500 Ada 等工作站 GPU 的 8 位或消费类硬件的 4 位), 以使大型面向代码的模型可以部署. 总的来说, CWM 建立了程序化的世界模型作为代码智能体的一致方向, 将基于 LLM 的程序合成与基于模型的推理的结构化、可验证的模拟相结合.

### 4.3 数学智能体

数学推理因其符号抽象性、逻辑一致性和长期演绎要求而被广泛认为是评估 LLM 智能体推理能力的黄金标准. 我们围绕两个互补的范式构建研究工作: *非正式推理* ([第 4.3.1 节](#section-4-3-1)), 它在没有正式验证支持的情况下运行, 包括自然语言推理和编程语言工具的使用; 和*形式推理* ([第 4.3.2 节](#section-4-3-2)), 它依赖于严格指定的形式语言和证明助手.

我们注意到 DAPO [Yu25g]、GRPO [Ren25b] 和 GRESO [Zhe25c] 等 RLVR 方法在 LLM 数学推理的最新增强中一直发挥着重要作用. 然而, 考虑到它们在推理任务中更广泛的相关性, 我们在[第 2.7 节](#section-2-7) 中讨论它们, 而不是在这里详细说明.

<span id="section-4-3-1"></span>

#### 4.3.1 非正式数学推理的强化学习

非正式数学本质上是指用自然语言进行推理和表达. 这种推理可能包含符号或函数名称, 但没有有限且明确的逻辑规则集定义其语法有效性, 也没有形式语义精确确定其解释和含义 [Yan24k, Asp25].

虽然非正式的数学推理在细节层面放松了严格的严格性, 但它提供了更大的表达灵活性并更好地捕捉论证的高级结构. 这使得它特别适合各种数学任务, 例如数学单词问题求解、方程操作和符号计算 [Sin25a, Mai25]. 尽管通用编程语言是符号性的, 但它们缺乏证明辅助语言的严格性和形式语义, 因此在应用于数学推理 [Yan24k] 时被认为是非正式的, 通常是通过工具调用执行器 (例如带有数字或符号库的 Python).

**结果奖励 RL.** 仅结果方法仅通过 RL 期间的最终数字或符号正确性 (例如代数方程) 来定义奖励. 根据经验, 这种训练通常会导致涌现的智能体行为, 包括自适应工具的使用与自然语言推理的交织. ARTIST [Sin25a] 引入了一个工具集成智能体推理、交错工具调用的框架, 例如直接在推理链内执行代码. 经过仅结果奖励的训练, 它实现了强大的性能并观察到了新兴的智能体行为, 包括自我反思和情境感知 CoT, 这进一步表明, 通过将动态工具使用与强化学习相结合, 智能体工具集成推理可以学习与环境交互的最佳策略, 凸显了强化学习在 LLM 中内化工具集成推理策略的潜力. 同样, ToRL [Li25o] 通过利用工具集成推理 RL 的扩展和鼓励代码执行行为来提高性能, 并且实验显示了新兴的认知行为, 例如自适应工具使用、基于工具反馈的自我纠正和自适应计算推理. ZeroTIR [Mai25] 研究了使用 Python 代码执行设置进行工具集成推理的基于结果奖励的 RL 缩放规律, 揭示了训练计算量与自发代码执行频率、平均响应长度和最终任务准确性之间的强相关性, 这证实了工具集成推理策略的实证出现. TTRL [Zuo25] 利用多数投票来估计奖励, 从而能够对未标记数据进行训练. 经过对这些多数票奖励的微调, 它不仅超越了基本模型的主要准确性, 而且还实现了经验性能曲线和上限, 令人惊讶的是, 它非常接近在 MATH-500 上标记测试答案的直接 RL 训练, 强调了其实用价值和潜力. 然而, RENT [Pra25] 表明多数投票在泛化方面受到限制, 它仅适用于具有确定性答案的问题, 并且不适用于自由回答输出. 为了解决这一限制, 它将熵最小化思想 [Wan21e] 扩展到 RL, 使用 token 级别的平均负熵作为奖励来指导学习, 在包括数学问题解决在内的一系列广泛基准上实现改进, 这表明基于置信度的奖励塑造可以作为持续改进的途径. 另外, Satori [She25b] 提出了行动思想链 (COAT), 这是 CoT 的一种变体, 它明确地集成了行动选择, 并将推理模块化为 3 重元行动, 包括延续、反思和探索替代方案, 并通过仅结果奖励的 RL 内化这种行为. 特别是, 1-shot RLVR [Wan25ac] 研究带有验证器信号的仅结果 RL 的数据效率. 令人惊讶的是, 他们发现仅使用 1 个示例的 RL 性能接近于使用 1.2k 个示例数据集, 而使用 2 个示例则接近于使用 7.5k MATH 训练数据集. 他们还强调了一个有趣的现象, 称为后饱和泛化, 即使单个示例的训练准确率接近 100%, 测试准确率仍会继续提高. 除了正确性之外, 幻觉仍然是非正式数学推理中的一个主要挑战, 激发了明确促进可信度的方法. 例如, [Kir24] 提出了一种博弈论训练算法, 可以联合优化正确性和易读性. 受 Prover-Verifier Games [Ani21] 的启发, 该方法交替训练预测解决方案正确性的小型验证者、生成验证者接受的解决方案的“有用”证明者和旨在愚弄验证者的“鬼祟”证明者. 根据经验, 这增加了有用的证明者准确性、验证者稳健性和易读性 (通过时间受限的验证任务中的人类准确性来衡量). 这一结果表明, 验证者引导的易读性优化可以增强 LLM 生成的非正式推理的可解释性和可信度. 最近的 rStar2-Agent [Sha25a] 是一个 14B 参数数学推理模型, 使用高吞吐量 Python 执行环境、一种新颖的 GRPO-RoC 算法 (在工具噪声中正确部署时重新采样) 和一个多阶段训练配方, 通过智能体强化学习进行训练, 只需 510 个 RL 步骤即可实现最先进的结果, 在 AIME24 和 AIME24 上实现平均 pass@1 分数 80.6% AIME25 上的评分为 69.8%.

**过程奖励 RL.** 过程感知方法利用中间评估器 (例如单元测试、断言、子任务检查) 来提供更密集的反馈、塑造信用分配并改进工具集成推理 (TIR). START [Li25d] 通过将手工制作的提示文本注入长 CoT 跟踪 (通常在连词之后或 CoT 停止标记之前) 来引导 TIR, 以鼓励在推理期间调用代码执行器. 这可以扩展测试时间, 从而提高推理准确性. 然后, 收集的轨迹用于微调模型, 内化工具调用行为. LADDER [Yos25] 引入了一个训练时间框架, 其中 LLM 递归地生成并解决复杂问题的逐渐简单的变体, 使用可验证的奖励信号来指导基于难度的课程, 并在数学推理方面取得实质性改进. 额外的测试时 RL 步骤 (TTRL) 进一步增强了性能. 作者认为, 这种具有可验证反馈的自生成课程学习方法可以推广到非正式数学任务之外的任何具有可靠自动验证的领域. 为了提高复杂问题的性能, SWiRL [Gol25] 通过迭代分解解决方案来合成逐步工具使用推理数据, 然后采用基于偏好的逐步 RL 方法在多步轨迹上微调基本模型. 虽然其中许多方法利用推理时间干预, 但由于依赖手动设计的逻辑结构, 它们经常受到泛化限制. 为了克服这个问题, RLoT [Hao25a] 使用 RL 训练轻量级导航智能体模型来自适应增强推理, 从而提高了跨不同任务的泛化能力.

虽然非正式方法在文字问题和符号计算方面表现出色, 但它们很难有效地扩展到高级数学任务, 例如自动定理证明. 这种限制源于两个基本挑战: 评估困难, 需要非正式方法无法提供的机器可验证反馈, 以及高质量形式证明数据 [Yan24k, Asp25] 的稀缺.

<span id="section-4-3-2"></span>

#### 4.3.2 形式数学推理的强化学习

形式数学推理是指以具有精确定义的语法和语义的形式语言进行的推理, 产生可供验证者机械检查的证明对象. 这种范式特别适合高级任务, 例如自动定理证明 (ATP) [Xin25], 其中给定一个陈述 (定理、引理或命题) 的智能体必须构造验证者接受的证明对象, 从而确保机器可验证的正确性. 从强化学习的角度来看, 形式定理证明通常被建模为马尔可夫决策过程 (MDP): 通过应用策略 [+2] 进行证明状态转换, 其中每个策略都被视为基于 RL 的证明搜索 [Wu21a] 中的离散动作. 在这个表述下, 形式定理证明可以被视为一个巨大的、离散的、参数化的动作空间上的搜索问题.

形式化证明由 Lean、Isabelle、Coq 和 HOL Light 等证明助手进行验证. 这些系统通常被称为交互式定理证明器 (ITP), 确定性地接受或拒绝证明对象, 产生二进制通过/失败信号作为 RL 训练的主要奖励, 而一些工作还探索利用错误消息作为辅助信号 [Amb25, Ji25a].

**结果奖励 RL.** 仅结果范式在 2024 年通过 DeepSeek-Prover-v1.5 [Xin25] 进行了大规模演示, 它仅基于二进制验证器反馈发布了精益中的端到端 RL 管道, 从而在 miniF2F [Zhe22a] 和 ProofNet [Aze23] 等基准上证明成功的显著改进. 作者提出了 MCTS 的一种变体, 即 RMaxTS, 它结合了发现新颖策略状态的内在奖励, 以鼓励推理时间搜索期间证据探索的多样性并缓解稀疏奖励问题. 在此方向上, Leanabell-Prover [Zha25w] 通过聚合来自多个来源和管道 (例如 Mathlib4 [Com20]、LeanWorkbook [Yin25a]、NuminaMath [Li24l]、STP [Ma25] 等) 的声明证明对和非正式推理草图的广泛混合数据集来扩展 DeepSeek-Prover-v1.5, 涵盖超过 20 个数学领域. 这种广泛的覆盖范围缓解了非正式到正式 (NL 到 Lean4) 对齐训练示例的稀缺性, 这对于连接自然语言推理和形式证明生成至关重要. 与此同时, Kimina-Prover [Wan25l] 预览版进一步强调了协调非正式和正式推理的关键挑战. 它实现了一种结构化的“形式推理模式”, 其中自然语言推理和 Lean 4 代码片段在思维块中交织. 为了加强这种一致性, 输出受到限制——至少包含一个策略块, 并在最终证明中重复使用不少于 60% 的精益 4 片段, 确保内部推理和形式输出之间的紧密对应. 最近的一项工作, Seed-Prover [Che25h], 集成了多种技术. 它首先采用以引理为中心的证明范式, 可以实现系统问题分解、跨轨迹引理重用和显式进度跟踪. 然后, 它通过随机结合非正式和正式证明、成功和失败的引理以及精益编译器反馈的多样化提示策略来丰富 RL 训练, 从而增强对不同输入的适应性. 在推理时, 它采用了一个猜想证明者管道, 将证明猜想插入引理中, 并从不断发展的引理池中生成新的猜想, 从而大大提高了其解决难题的能力. 作为补充, 随附的 Seed-Geometry 系统将形式推理扩展到几何, 在奥林匹克基准测试中提供最先进的性能. 总之, 这些努力表明, 稀疏但明确的奖励信号可以产生不平凡的收益, 特别是与有效的探索策略相结合时.

**过程奖励 RL.** 为了改善信用分配并减少浪费的探索, 一些工作用更密集的步骤级信号扩展了仅结果范式. DeepSeek-Prover-v2 [Dee24d] 设计了双模型管道来统一非正式 (自然语言) 和形式 (Lean4) 数学推理, 以增强形式推理能力. 它引入了子目标分解, 其中证明者模型解决递归分解的子目标并在子目标级别接收二元 Lean 反馈, 有效地提供更密集的监督并提高准确性和可解释性. 遵循这种双重角色协作思维, ProofNet++ [Amb25] 实现了一个神经符号 RL 框架, 该框架具有符号推理接口 (将 LLM 生成的推理映射到形式证明树) 和形式验证引擎 (使用 Lean 或 HOL Light 验证这些证明, 并将错误反馈路由回 LLM 进行自我纠正). Leanabell-Prover-v2 [Ji25a] 将验证者消息集成到长 CoT 框架内的强化更新中, 从而实现明确的验证者感知自我监控, 从而稳定策略生成并减少重复的故障模式.

**混合奖励强化学习.** 虽然仅结果奖励范式和过程感知奖励范式都显示出令人鼓舞的进步, 但高质量定理证明数据的稀缺进一步放大了稀疏奖励下强化学习以及阶梯级偏好信号 [Zho24c, Wan24r, Ma25] 设计的挑战. 为了缓解这些限制, 一项重要的工作采用了专家迭代 (ExIt) [Ant17], 这是一种将搜索与策略学习相结合的框架. 这种范例提供了仅结果或过程感知的强化学习的替代方案, 通过生成高质量的监督轨迹来缓解数据稀缺性. ExIt 不是直接针对稀疏验证者信号进行优化, 而是执行“搜索引导的数据增强”: 通过搜索发现并由验证者检查的有效证明轨迹被重新用作模仿学习循环中的专家演示. 它通常采用双角色系统: “专家”在仅结果验证者反馈下通过 MCTS 收集有效且渐进的轨迹, 而“学徒”在这些过程级轨迹上训练策略, 然后与专家共享改进的策略, 从而引导后续几轮搜索并加速收敛. 先前的工作 [Sut20] 将 ExIt 引入形式定理证明, 证明搜索生成的专家数据可以引导模型应对复杂的多步骤证明挑战. 后来的工作使这种设计适应精益和其他 ITP.

当应用于形式定理证明时, 朴素树搜索方法在巨大的参数化策略空间中导航时经常面临严重的搜索空间爆炸. 为了缓解这一问题, InternLM2.5-StepProver [Wu25p] 引入了一种基于偏好的 Critic 模型, 通过 RLHF 式优化进行训练, 以指导专家搜索, 有效地提供指导探索适当难度问题的课程. Lean-STAR [Lin25a] 通过集成自学推理机 (STaR) [Zel22a] 进一步增强了 ExIt. 它首先在合成的* (证明状态、生成的思想、真实策略) *三元组上训练思想增强的策略预测器. 然后, 在专家迭代循环中, 模型产生将思想与策略交织在一起的轨迹; 经过精益成功验证的策略轨迹将被保留并重复用于模仿学习. 根据经验, 思想的包含增加了基于样本的证明搜索中探索的多样性.

最近的一项工作 STP [Ma25] 指出, 由于正奖励稀疏, 仅仅依靠专家迭代会很快陷入停滞状态. 为了解决这个问题, 它将猜想者-证明者自我对弈的想法从 Minimo [Poe24] 扩展到具有开放式动作空间的实用形式语言 (Lean/Isabelle), 并从预训练模型开始. STP 实例化了一个双角色循环, 其中猜想者提出当前证明者几乎无法证明的陈述, 并且证明者接受标准专家迭代的训练; 这会生成自适应课程并减轻稀疏的训练信号. 根据经验, STP 在 LeanWorkbook [Yin25a] 上报告了巨大的收益, 并在 miniF2F [Zhe22a] 和 ProofNet [Aze23] 上报告了整体证明生成方法之间的竞争结果.

### 4.4 GUI 智能体

GUI 智能体通过不同的训练范例取得了进步. 早期系统以纯粹的零样本方式使用预先训练的视觉语言模型 (VLM), 将屏幕截图和提示直接映射到单步操作. 后来, 静态 (屏幕、动作) 轨迹上的 SFT 改进了基础和推理, 但受到人类操作痕迹稀缺的限制. 强化微调 (RFT) 将 GUI 交互重新构建为顺序决策, 允许智能体通过稀疏或成形奖励的试错来学习, 并从简单的单任务设置发展到复杂的、现实世界的长期场景. [表 7](#table-07) 展示了本节中研究的大部分工作.

<span id="section-4-4-1"></span>

#### 4.4.1 无 RL 方法

**基于 Vanilla VLM 的 GUI 智能体** 早期的 GUI 智能体以纯粹的零样本方式直接利用预先训练的视觉语言模型 (VLM), 将屏幕截图和提示映射到单步操作, 而无需任何特定于任务的微调. 代表性系统包括 MM-Navigator [Yan23c]、SeeAct [Zhe24b] 和 TRISHUL [Sin25], 它们在接口域或解析策略上有所不同, 但都同样依赖于现成的 VLM. 虽然展示了基础模型的通用性, 但这些方法的接地精度和可靠性有限, 限制了它们对复杂任务 [Zha25m, Ngu25] 的适用性.

**使用静态轨迹数据进行监督微调 (SFT)** SFT 范例通过最小化离线 (屏幕、动作) 对上的交叉熵损失 (无需在线交互), 将预先训练的视觉语言模型适应 GUI 任务. InfiGUIAgent [Liu25n] 采用两级管道, 首先改进接地, 然后结合分层和反思推理. UI-AGILE [Lia25a] 通过结合连续奖励、简化推理和基于裁剪的重采样来增强监督微调, 同时进一步提出用于处理高分辨率显示的分解基础机制. TongUI [Zha25l] 相反强调数据规模, 从多模态 Web 教程构建 143K 轨迹 GUI-Net 以增强泛化能力. 这些方法虽然侧重点不同, 但都面临着人类操作痕迹稀缺的限制.

<span id="section-4-4-2"></span>

#### 4.4.2 静态 GUI 环境中的强化学习

在静态设置中, 强化学习应用于具有确定性执行轨迹的预先收集的数据集, 在没有实时环境交互的情况下使用基于规则的标准进行结果评估. GUI-R1 [Luo25f] 在统一的动作模式上采用 R1 式的强化微调管道, 使用简单的格式和正确性奖励来改进适度数据的步骤级动作预测. UI-R1 [Lu25e] 应用组相关策略优化来稳定策略更新, 并通过紧凑的操作界面和针对操作类型和参数准确性的奖励塑造来提高精确的参数匹配. InFiGUI-R1 [Liu25o] 引入了两阶段训练范式, 首先提炼空间推理以增强基础, 然后通过具有子目标监督和恢复机制的强化学习来改善长时程推理. AgentCPM-GUI [Zha25am] 将接地感知预训练、监督模仿和基于 GRPO 的强化微调与简洁的 JSON 动作空间相结合, 减少解码开销, 同时提高长时程序列的鲁棒性. UI-Venus [Gu25b] 是一种基于多模态屏幕截图的 UI 智能体, 通过 RFT 进行微调, 具有自定义奖励功能和自我进化的轨迹框架, 在 UI 接地和导航方面实现了新的最先进的性能.

<span id="section-4-4-3"></span>

#### 4.4.3 交互式 GUI 环境中的强化学习

在交互式设置中, 强化学习智能体通过动态环境中的在线部署进行优化, 需要对随机转换和长期依赖具有鲁棒性. WebAgent-R1 [Wei25f] 通过异步轨迹生成和分组优势进行端到端多轮强化学习, 提高各种 Web 任务的成功率. [Vat25] 研究现实页面动态和大动作空间下网络智能体的强化学习, 突出了信用分配和安全探索方面的挑战. UI-TARS [Qin25a] 将 GUI 理解的预训练与原生桌面控制的强化学习相结合, 耦合里程碑跟踪和反思以增强长期执行力. DiGiRL [Bai24a] 在真实的 Android 设备上引入了离线到在线的强化学习管道, 结合优势加权更新、双鲁棒优势估计和指令级课程来应对非平稳性. ZeroGUI [Yan25h] 使用视觉语言评估器自动生成任务和奖励估计, 然后应用两阶段在线强化学习 (对生成的任务进行训练, 然后进行测试时间适应) 以减少人工监督. MobileGUI-RL [Shi25c] 通过轨迹感知 GRPO、递减效率奖励和课程过滤来扩展 Android 虚拟设备上的训练, 提高执行效率和泛化能力, 同时保持系统适用于大规模部署. ComputerRL [Lai25] 引入了 API-GUI 混合交互范例, 与大规模并行、完全异步的 RL 基础设施和新颖的 Entropulse 训练策略 (将 RL 与监督微调交替) 相结合, 使基于 GUI 的智能体能够在桌面环境中高效且可扩展地运行.

### 4.5 视觉智能体

强化学习已应用于广泛的视觉任务 (包括但不限于图像、视频、3D 感知和生成). 由于相关论文的数量很大, 本节无意提供详尽的概述; 为了对各种视觉任务的 RL 进行更全面的综述, 我们建议读者参阅有关视觉 [Wu25k, Zho25c] 的两项专门综述.

**图像任务.** DeepSeek-R1 [Dee25c] 的成功引发了人们对应用 RL 激励长形式推理行为的广泛兴趣, 鼓励 LVLM 生成扩展的 CoT 序列, 以改善视觉感知和理解 [Sha24c]. 这一研究轨迹已经从早期工作简单地将 R1 式目标应用于视觉领域 (主要旨在增强被动感知 [Tan25a, Li25w, Hua25c, She25a, Pen25a, Xia25a, Yan25i, Gao25a]) 发展到现在流行的主动感知范式, 或“用图像思考”[Su25b]. 关键的转变在于从仅引用图像一次的纯文本 CoT 转向交互式、基于视觉的推理, 这是通过 (i) 扎根 [Li25g, Nag16a, Mao16, Fan25b, Chu25c, Cao25a]、(ii) 使用 [Zha25ar, Hua25d, Wu25j, Su25a, Liu25v, Su25] 的智能体工具、以及 (iii) 通过草图或生成 [Xu25e, Dua25, Jia25b] 的视觉想象力来实现的. 除了纯文本输出之外, 许多视觉任务 (例如场景理解) 还需要结构化预测, 例如边界框、掩模和分割图. 首先, Visual-RFT [Liu25v] 自信地使用 IoU 作为边界框输出的可验证奖励, 而 Vision-R1 [Hua25c] 将精度和召回率作为本地化奖励. 扩展了这个想法, [Liu25p] 将 GRPO 应用于分割任务, 将软奖励和严格奖励与边界框 IoU 和 L1 损失以及逐点 L1 距离相结合. VLM-R1 [She25a] 采用平均精度 (mAP) 作为奖励, 以明确激励 LVLM 中的检测和定位能力. 最后, R1-SGG [Che25r] 引入了用于场景图匹配的 GRPO 奖励的三种变体, 从基于文本匹配和 IoU 的硬奖励到通过文本嵌入点积计算的软奖励. 强化学习也已广泛应用于图像生成, 特别是通过与扩散和流动模型的集成, 例如 RePrompt [Wu25i]、Diffusion-KTO [Li24n]、Flow-GRPO [Liu25d] 和 GoT-R1 [Dua25]. 除了基于扩散的方法之外, 强化学习还被用于自回归图像生成, 通过直接优化任务或用户特定的奖励信号 [Wan25q, Jia25b, Yua25] 来提高一致性、保真度和可控性.

**视频任务.** 遵循同样的精神, 许多工作将 GRPO 变体扩展到视频域 [Che24q, Fen24b, Maa23], 以增强时间推理 [Par25a, Li25m, Zhu25f, Lia25f, Ouy25a]. TW-GRPO [Dan25] 引入了 token 加权的 GRPO 框架, 该框架强调高信息 token 以生成更有针对性的推理链, 并采用软性多选择奖励来实现低方差优化. EgoVLM [Vin25] 将基于关键帧的奖励与直接 GRPO 训练相结合, 生成为自我中心视频量身定制的可解释推理轨迹. DeepVideo-R1 将 GRPO 目标重新表述为回归任务 [Par25a], 而 VideoChat-R1 则证明强化微调 (RFT) 对于特定任务的视频推理改进 [Li25m] 来说可以具有很高的数据效率. TinyLLaVA-Video-R1 探索将 RL 扩展到更小的视频 LLM [Zha25ag], [Che25o] 引入基础设施和两级管道 (CoT-SFT + RL) 以支持长视频的大规模 RL. 其他工作还将强化学习扩展到具体视频推理任务 [Zha25ap]. 在视频生成中也观察到类似的趋势, 其中应用强化学习来提高时间连贯性、可控性和语义对齐. 主要示例包括 DanceGRPO [Xue25]、GAPO [Zhu25d]、GRADEO [Mou25]、InfLVG [Fan25d]、Phys-AR [Lin25c]、VideoReward [Liu25e]、TeViR [Che25n] 和 InstructVideo [Yua24c].

**3D 视觉任务.** RL 也被广泛采用来促进 3D 理解 [Hon23a, Xu24d, Den24a, Che24g, Zho23b, Che24j] 和 3D 生成 [Wan24u, Yin25, Sid24]. MetaSpatial [Liu25w] 引入了第一个基于 RL 的 3D 空间推理框架, 利用物理感知约束和渲染图像评估作为训练期间的奖励. Scene-R1 [Yua25c] 在没有逐点 3D 监督的情况下学习推理 3D 场景, 而 SpatialReasoner [Ma25c] 引入了统一感知、计算和推理阶段的共享 3D 表示. 在 3D 生成领域, 强化学习已被应用于改善文本到 3D 的对齐和可控性. 值得注意的努力包括 DreamCS [Zou25], 它使生成结果与人类偏好保持一致; DreamDPO [Zho25h] 和 DreamReward [Ye24b], 使用 2D 奖励信号优化 3D 生成; Nabla-R2D3 [Liu25i], 它通过强化驱动的目标进一步完善 3D 输出.

### 4.6 具身智能体

具身智能体涵盖了广泛的系统家族, 这些系统感知结构化环境并在其中行动, 从视觉语言动作 (VLA) 模型到语言驱动的开放式智能体. 虽然许多最近的系统侧重于需要以现实世界视觉观察为基础的 VLA 设置, 但所有具体智能体都必须集成感知、推理和行动, 以便在复杂的物理或模拟环境中有效运行, 并执行以高级指令为条件的目标导向行为. 这些能力构成了具体场景中智能体 LLM 和 MLLM 的基本组成部分. 在指令驱动的具体场景中, 强化学习通常被用作训练后策略. 通用流程始于预训练的视觉-语言-动作 (VLA) 模型 [Kim24b, Bla24a, Tea25g, Lia25e], 该模型是通过教师强制监督下的模仿学习获得的. 然后将该模型嵌入到与环境交互以收集奖励信号的交互式智能体中. 这些奖励指导策略的迭代细化, 支持有效探索, 提高样本效率, 并增强模型在不同现实条件下的泛化能力. VLA 框架[Tea25d, Lu25b, Qi25, Son25e]中的强化学习可以大致分为两类: 导航智能体 (强调复杂环境中的空间推理和运动) 和操纵智能体 (重点关注在多样化和动态约束下对物理对象的精确控制).

**VLA 导航智能体中的 RL.** 对于导航智能体, 规划是核心功能. 采用强化学习来增强 VLA 模型预测和优化未来动作序列的能力. 一种常见策略 [Zha25aq] 是将传统机器人风格的 RL (使用逐步定向奖励) 直接集成到基于 VLA 的导航框架中. 一些方法在轨迹级别上运行. VLN-R1 [Qi25] 对齐预测路径和真实路径来定义轨迹级奖励, 并按照 DeepSeek-R1 应用 GRPO 来改进预测规划. OctoNav-R1 [Gao25a] 也利用 GRPO, 但侧重于加强 VLA 模型内的内部审议, 促进先思考后行动的范式, 从而实现更具预见性和稳健的导航. S2E [He25b] 引入了强化学习框架, 增强了导航基础模型的交互性和安全性, 将视频预训练与 RL 相结合, 以在 NavBench-GS 基准上实现卓越的泛化和性能.

**VLA 操纵智能体中的强化学习.** 操纵智能体 (通常涉及机械臂) 需要细粒度控制, 以便在不同条件下执行结构化任务. 在这种情况下, 强化学习被用来增强 VLA 模型的指令跟踪和轨迹预测能力, 特别是提高跨任务和环境的泛化能力. RLVLA [Liu25f] 和 VLA-RL [Lu25b] 采用预先训练的 VLM 作为评估器, 利用它们的反馈为 VLA 策略细化分配轨迹级奖励. 这些方法建立了一个在线强化学习框架, 可以有效提高操作性能并表现出良好的扩展特性. TGRPO [Che25p] 通过在预测轨迹上定义基于规则的奖励函数, 进一步将 GRPO 纳入操作任务中. 这使得 VLA 模型能够推广到未见过的场景, 并提高其在实际部署中的稳健性. VIKI-R [Kan25] 通过统一的基准和多智能体具体化合作的两阶段框架对此进行了补充, 将思想链微调与多级 RL 相结合, 以实现跨不同具体化的组合协调.

VLA 实体强化学习的一个核心挑战是将训练扩展到现实环境. 虽然仿真平台可以实现高效的大规模实验, 但模拟与真实的差距仍然很大, 特别是在细粒度的操作任务中. 由于物理机器人实验的高成本和复杂性, 直接在现实环境中进行强化学习目前是不切实际的. 大多数强化学习算法需要数百万个交互步骤, 这需要大量的时间、资源和维护. 因此, 开发可扩展的具体强化学习管道来弥合模拟与现实世界部署之间的差距仍然是一个开放且紧迫的问题.

**案例研究: Voyager.** 除了体现强化学习中的这些一般挑战之外, Voyager [Wan24m] (一种语言驱动的开放式体现智能体) 还说明了如何将规划、技能获取和基于强化学习的课程学习整合到实践中. 该智能体使用迭代循环来探索 Minecraft: 它生成计划, 与环境交互, 从成功的轨迹中提取可重用的技能, 并将它们存储在不断增长的技能库中. 课程调度程序根据智能体当前的技能集选择新任务, 而强化学习目标则指导哪些行为应作为技能进行提交, 以及何时完善或放弃它们. 这创建了一个自我完善的循环, 其中规划、环境交互、记忆和强化学习驱动的课程优化紧密耦合.

#### 4.7.1 强化学习驱动的非参数协调模块优化

这些方法使智能体参数保持冻结, 同时使用强化学习来优化外部协调结构, 例如通信拓扑、路由策略或工作流图. GPTSwarm、MaAS 和 G-Designer [Zhu24b, Zha25q, Zha25r] 等方法将 MAS 协调视为通过策略梯度更新的图级策略. 由于不存在智能体级梯度, 因此信用分配必须在拓扑或消息路由级进行操作. 奖励通常是延迟且稀疏的——例如, 只有最终任务的准确性——需要全局到本地的信用分解或结构先验以避免崩溃.

*固定通信协议* (预先指定的消息格式) 和*可学习协议*之间出现了一个关键的比较. 固定协议在稳定性至关重要的低数据或高度专业化领域表现出色, 而可学习协议允许强化学习发现有效的紧急通信, 但需要更高的样本复杂性和仔细的正则化, 以防止过度拟合或退化约定.

<span id="section-4-7-2"></span>

#### 4.7.2 强化学习驱动的所选智能体策略优化

第二类系统仅更新一部分智能体 (通常是领导者、协调员或专业专家), 同时保持其他智能体的稳定性. 代表性示例包括 Optima、DITS、MALT、ACC-Collab [Che25j, Shi25a, Mot25, Est25a]. 这些方法平衡了灵活性和可扩展性: 仅训练少数智能体降低了样本复杂性, 并避免了完全解耦的信用分配的不稳定性. MALT [Mot25] 采用异构多智能体搜索树来生成大规模标记轨迹, 通过监督微调 (SFT) 和直接偏好优化 (DPO) 的组合从成功和失败的推理路径中微调智能体.

这种制度中的信用分配从根本上来说是“半局部的”: 奖励从集体轨迹中产生, 但梯度仅适用于优化的智能体. 这需要角色条件 DPO [Mot25]、局部优势估计或反事实基线等机制来防止未更新智能体劫持奖励. 根据经验, 这种部分优化比完全联合多智能体训练产生更好的样本效率, 同时仍然能够出现专门的角色.

<span id="section-4-7-3"></span>

#### 4.7.3 端到端多智能体强化学习

完整的多智能体强化学习在共享或分散的目标下联合训练所有智能体, 通常形式化为 Dec-POMDP. MAGRPO、MAPoRL、MLPO、ReMA、FlowReasoner、Chain-of-Agents 和 SPIRAL [Liu25l, Par25, Est25, Wan25k, Gao25b, Li25j, Liu25b] 等方法共同优化协作和推理行为, 实现涌现的分工和通信约定. 例如, MAGRPO [Liu25l] 将多 LLM 合作形式化为 Dec-POMDP 问题, 并引入 GRPO 的多智能体变体, 这使得能够在 MAS 中联合训练 LLM 智能体, 同时保持去中心化执行. MAPoRL [Par25] 通过验证辩论响应并使用验证结果作为 RL 奖励来改进协作推理, 从而扩展了 MAD. RLCCF [Yua25a] 是一种自监督多智能体 RL 框架, 利用自一致性加权集成投票来生成伪标签, 并通过 GRPO 协作优化单个模型策略, 从而提高个人和集体推理的准确性. ReMA [Wan25k] 将推理分为元思维智能体和执行智能体, 在一致的 RL 目标下通过参数共享进行联合训练. LERO [Wei25d] 将 MARL 与 LLM 生成的混合奖励和进化搜索相结合, 以改进合作任务中的信用分配和部分可观察性处理. CURE [Wan25ab] 专注于代码生成, 通过 RL 联合训练代码生成器和单元测试器以产生更丰富的奖励信号, 从而在不同的编码基准上实现强大的泛化. MMedAgent-RL [Xia25b] 引入了一种基于强化学习的医疗 VQA 多智能体框架, 其中动态协调的全科医生和专家通过课程引导学习进行协作推理, 显著优于现有的 Med-LVLM, 并实现更类似于人类的诊断行为. 智能体链 (COA) [Li25j] 是一种端到端范例, 其中单个 LLM 通过动态编排角色扮演和使用工具的智能体来模拟多智能体协作; 这是通过多智能体蒸馏 (将最先进的多智能体系统的轨迹转换为训练数据) 和具有精心设计的奖励函数的智能体强化学习来实现的, 从而产生智能体基础模型 (AFM). SPIRAL [Liu25b] 为零和游戏中的 LLM 提出了一个完全在线、多回合、多智能体自我对弈强化学习框架, 采用具有角色条件优势估计 (RAE) 的共享策略来稳定学习, 并证明游戏玩法可以培养可转移的推理技能, 从而显著提高数学和一般推理基准.

然而, 端到端的多 LLM 训练加剧了“时间和结构性学分分配”问题, 因为奖励可能取决于长的多轮交互链. 解决方案包括角色条件优势估计 (RAE)、分层控制器-工作架构 (MLPO、ReMA) 和自我游戏课程 (SPIRAL), 这些课程通过构建越来越具有挑战性的交互来强化奖励信号. 这些分层模式反映了企业部署, 其中监督智能体协调多个工作人员; 事实证明, 强化学习在稀疏奖励设置下学习稳定的委托和仲裁策略特别有效. 尽管具有表达能力, 但联合 MARL 方法面临可扩展性限制: 样本复杂性与智能体数量大致呈线性增长, 与交互深度呈二次方增长. MAGRPO 和基于 PPO 的 MAPoRL 等算法使用集中 Critic 或价值共享基线来缓解这一问题, 但实现可扩展的信用分解仍然是一个主要的开放挑战.

<span id="section-4-8"></span>

### 4.8 其他任务

**TextGame.** ARIA [Yan25k] 通过意图驱动的奖励聚合来压缩庞大的动作空间, 从而减少稀疏性和方差. GiGPO [Fen25b] 通过分层分组增强临时信用分配, 而不会增加计算负担. RAGEN [Wan25ag] 通过过滤轨迹和稳定梯度来确保稳定的多轮学习, 同时倡导推理感知奖励. SPA-RL [Wan25m] 将延迟奖励分解为每步信号, 从而提高性能和接地精度. Trinity-RFT [Pan25a] 提供了一个统一的模块化框架, 用于跨任务 (包括文本游戏) 进行强化微调, 从而能够使用不同的 RL 模式和数据管道进行灵活、高效和可扩展的实验.

**表.** SkyRL-SQL [Liu25j] 引入了用于文本到 SQL 的数据高效、多轮 RL 管道, 使 LLM 智能体能够交互式地探测数据库、细化和验证 SQL 查询. SkyRL-SQL-7B 模型仅包含 653 个训练示例, 在 SQL 生成基准测试中超越了 GPT-4o 和 o4-mini. MSRL [Che25f] 引入了具有多粒度奖励的多模态结构化强化学习, 以克服图表到代码生成中的 SFT 平台, 在图表理解基准上实现最先进的性能.

**时间序列.** Time-R1 [Liu25t] 通过渐进式强化学习课程和基于规则的动态奖励系统, 增强中等规模的 LLM 的综合时间推理能力. TimeMaster [Zha25y] 训练时间序列 MLLM, 将 SFT 与 GRPO 结合起来, 以实现对可视化时间序列输入的结构化、可解释的时间推理.

**一般 QA.** 智能体模型 [Zha25ak] 将行动链生成内部化, 通过监督微调和强化学习的组合实现自主高效的决策. L-Zero [Zha25x] 利用低成本、可扩展的沙盒并发智能体工作池, 通过可扩展的端到端强化学习管道, 使大语言模型成为通用智能体.

**社交.** Sotopia-RL [Yu25e] 将粗略的情节级奖励细化为话语级、多维信号, 以便在部分可观察性和多方面目标下为社交智能 LLM 提供高效、稳定的 RL 训练. [Wan25s]引入了自适应模式学习 (AML) 框架和自适应模式策略优化 (AMPO) 算法, 利用强化学习在社交智能任务中动态切换多粒度推理模式, 比 GRPO 等固定深度强化学习方法获得更高的准确率和更短的推理链.

#### 5.1.1 Web 环境

在基于网络的环境领域, 一些基准测试为 Agentic RL 提供了受控但真实的静态环境. WebShop [Yao22c] 是一个模拟电子商务网站, 拥有大量真实产品目录和众包文本说明. 智能体浏览各种网页类型并发出各种操作 (例如搜索、选择项目、定制、购买) 来查找和购买产品, 其确定性搜索引擎有助于再现性. 此外, Mind2Web [Gou25] 是一个专为通用 Web 智能体设计的数据集, 包含来自不同领域的许多现实世界网站的大量任务. 它为查找航班或与社交资料交互等任务提供网页快照和众包操作序列, 强调跨看不见的网站和域的泛化. 同样, WebArena [Zho24f] 及其多模态扩展 VisualwebArena [Koh24] 是作为 Docker 容器提供的可自托管、可复制的 Web 环境. WebArena 提供跨常见领域 (如电子商务、社交论坛、协作开发和内容管理系统) 的功能齐全的网站, 丰富了实用工具和知识库, 并支持多选项卡任务和用户角色模拟. VisualwebArena 通过引入需要视觉理解的新任务和“标记集” (SoM) 表示来注释屏幕截图上的可交互元素, 从而扩展了这一点, 从而弥补了多模态 Web 智能体的差距. 此外, AppWorld [Tri24a]构成了一个模拟多应用生态系统的环境, 包含 9 个日常使用的应用 (例如 Amazon、Spotify、Gmail) 和 457 个可调用的 API, 并构建了一个包含约 100 个虚拟角色及其社交关系的数字世界. 智能体通过编写代码调用 API 来完成复杂的任务 (例如旅行计划和社交关系管理). 在这些环境中, 网页或视觉元素的所有更改都是专门针对智能体的操作而发生的.

<span id="section-5-1-2"></span>

#### 5.1.2 GUI 环境

AndroidWorld [Raw25] 作为在实时 Android 模拟器上运行的基准测试环境, 体现了这种活力, 具有跨 20 个实际应用的 116 个手工任务. 参数实例化强调了其动态性质, 参数实例化生成数百万个独特的任务变化, 确保环境演变成新颖的配置而无需直接智能体影响. 智能体通过一致的界面 (支持屏幕交互、应用导航和文本输入) 进行交互, 同时接收实时状态反馈, 并与 MiniWoB++ 集成, 为评估自适应性能提供持久的奖励信号. OSWorld [Xie24a] 是一个适用于多模态智能体的可扩展真实计算机环境, 支持跨 Ubuntu、Windows 和 macOS 的任务设置和基于执行的评估. 它包括大量现实世界的计算机任务, 涉及真实的 Web 和桌面应用、操作系统文件 I/O 以及跨多个应用的工作流程, 其中所有操作系统状态更改均由智能体的操作专门触发.

<span id="section-5-1-3"></span>

#### 5.1.3 编码和软件工程环境

与代码相关的任务受到广泛的可执行环境和基准测试的支持. 这些可以大致分为交互式环境, 其中智能体直接改变状态, 以及提供策划任务和评估管道的基准/数据集.

**交互式 SWE 环境.** 多个环境在软件工程工作流程下实例化智能体与环境的交互. Debug-Gym [Yua25b] 是一个基于文本的交互式编码环境, 用于调试设置中的 LLM 智能体. 它为智能体配备了 Python 调试器 (pdb) 等工具, 以主动探索和修改有缺陷的代码库, 支持代码仓库级信息处理并通过 Docker 容器确保安全. R2E-Gym [Jai25b] 构建了一个由程序生成的、可执行的 Gym 风格环境, 包含超过 8K 的软件工程任务, 由 SWE-Gen 管道和混合验证器提供支持. TheAgentCompany [Xu24c] 模拟一家软件开发公司, 智能体充当“数字工人”, 执行专业任务, 例如网页浏览、编码、程序执行以及与模拟同事的沟通. 它具有一系列多样化的长期任务, 并带有部分学分检查点, 为现实工作场所环境中的智能体提供了全面的测试平台. 在所有这些环境中, 底层问题定义和代码库保持固定, 并且变化仅由于智能体的操作而发生.

**编码基准和数据集.** 广泛的基准和数据集专注于构建策划的任务套件和评估管道. HumanEval [Che21e] 引入了 164 个手工编写的 Python 编程任务的基准, 通过 pass@k 指标来衡量功能正确性. MBPP [Aus21b] 提供 974 个入门级 Python 任务以及自然语言描述, 用于评估短程序综合. BigCodeBench [Zhu25h] 提出了一个大规模、无污染的函数级基准, 包含 1,140 个需要组合多个函数调用的任务. LiveCodeBench [Jai25a] 根据真实的竞争问题构建了一个不断更新、无污染的基准测试. SWE-bench [Jim24] 引入了源自真实 GitHub 问题的动态、执行驱动的代码修复基准测试. SWE-rebench [Bad25a] 引入了用于训练和评估的持续 GitHub 挖掘管道 ($>$21k 任务). DevBench [Li25c] 评估设计、设置、实施和测试的端到端开发. ProjectEval [Liu25g] 通过模拟用户交互构建 LLM 生成的、人工审核的项目任务. ColBench [Zho25g] 实例化了多轮后端/前端任务, 并具有逐步奖励的特权 Critic. NoCode-bench [Den25a] 通过真实代码库的文档更新来评估 LLM 的功能添加情况. CodeBoost [Wan25y] 通过提取和增强代码片段, 充当以数据为中心、执行驱动的训练管道.

**程序化世界模型环境.** 除了孤立的编码任务之外, 最近的基准测试还评估智能体是否可以诱导可执行的世界模型. 代码世界模型基准 (CWMB) [Dai24a] 要求智能体合成 Python“环境”类 (特别是“步骤”函数) 来复制真实动态, 评估转换保真度和下游规划效用. 作为补充, 代码模拟套件 [Mal24a, Mal25a] 提供了针对逐行执行预测和算法泛化的更细粒度的测试. 总的来说, 这些任务将评估重点从功能正确性转移到了构建程序化世界模型所必需的动力学归纳和程序模拟能力.

<span id="section-5-1-4"></span>

#### 5.1.4 特定领域的环境

**科学与研究.** ScienceWorld [Wan22h] 将科学模拟 (例如热力学、电学、化学) 集成到围绕基础科学教育设计的复杂的基于文本的任务中. PaperBench [Sta25] 通过从头开始复制 20 篇 ICML 2024 论文, 并根据基于标题的子任务进行评分, 评估 LLM 智能体复制尖端机器学习研究的能力. $\tau$-bench [Bar25c] 模拟软件工程任务的动态对话, 使用底层数据库状态和仅通过智能体的 API 调用更改的特定于域的规则进行操作.

**机器学习工程 (MLE).** MLE-Dojo [Qia25a] 是一个用于迭代机器学习工程工作流程的 Gym 风格框架, 基于现实世界的 Kaggle 竞赛而构建. 它为智能体提供了一个交互式环境来迭代实验、调试和完善解决方案. MLE-Bench [Cha25] 通过策划 75 场 Kaggle 竞赛, 根据公共排行榜上的人类基线评估智能体, 为 MLE 建立了基准. DA-Code [Hua24e] 解决了基于真实数据集和可执行分析的智能体数据科学工作流程, 为该领域提供了有针对性的基准.

**生物医学.** MedAgentGym [Xu25c] 为生物医学代码生成和测试提供特定领域的环境, 重点关注该专业科学领域内的任务.

**网络安全.** SecRepoBench [Dil25] 是针对安全漏洞修复的特定领域基准测试, 涵盖 27 个代码仓库和 15 个常见弱点枚举 (CWE) 类别.

<span id="section-5-1-5"></span>

#### 5.1.5 模拟和游戏环境

基于文本的环境模拟交互设置, 其中智能体操作通过自然语言表达. LMRL-Gym [Abd25] 为评估多轮语言交互中的强化学习算法提供了基准, 包括“20 个问题”和国际象棋等任务. TextWorld [Cot19] 是一个沙箱环​​境, 用于在基于文本的游戏中训练智能体, 提供手工编写和程序生成的游戏. 基于游戏的环境还强调可以独立发展的视觉设置. Crafter [Haf22] 是一款以深度探索和长时程推理为基准的 2D 开放世界生存游戏. Craftax [Mat24] 使用 JAX 基于 Crafter 构建, 为开放式 RL 引入了更高的复杂性和 GPU 加速. ELLM [Du23] 改进后的 Crafter 变体扩大了行动空间并引入了分散注意力的任务. 对于多智能体协调, SMAC [Sam19] 和 SMAC-Hard [Den24b] 为协作分散控制提供基于星际争霸 II 的基准. SMAC-R1 [Den24b]、Adaptive Command [Ma25b] 和 TacticCraft [Ma25a] 进一步提高了 LLM 智能体在《星际争霸 II》风格环境中的性能. Factorio [Hop25] 呈现了一种动态的、基于刻度的工业模拟, 其中智能体的不作为仍然会改变世界状态.

<span id="section-5-1-6"></span>

#### 5.1.6 通用环境

某些环境和基准旨在进行广泛的评估或提高一般智能体的能力. AgentGym [Xi25] 专注于通过指令调整和自我修正来提高 LLM 智能体泛化能力, 在 ALFWorld、BabyAI 和 SciWorld 等确定性环境中运行. Agentbench [Liu24t] 作为一个广泛的评估框架, 将 LLM 作为跨各种不同交互环境的智能体进行评估, 包括基于 SQL、基于游戏和基于 Web 的场景. InternBootcamp [Li25i] 是一个可扩展的框架, 集成了 1000 多个可验证的推理任务, 涵盖编程、逻辑谜题和游戏, 并具有用于 RL 训练和自动任务生成的标准化接口.

### 5.2 强化学习框架

本节总结与本文最相关的三类代码库与框架: Agentic RL 框架、RLHF 和 LLM 微调框架, 以及通用 RL 框架. [表 11](#table-11) 概述了当前主流的 Agentic RL 与 LLM RL 框架, 供读者参考.

**智能体 RL 框架.** 验证器 [Bro25] 引入了可验证的环境设置, 用于使用 LLM 进行端到端策略优化, 而 SkyRL-v0 [Cao25b] 及其模块化后继者 [Gri25] 则通过强化学习展示了长期的、真实世界的智能体训练. AREAL [Fu25] 通过针对语言推理任务定制的异步分布式架构扩展了这一范式, 而 MARTI [Zha25z] 将其进一步扩展到集成强化训练和推理的多智能体 LLM 系统. EasyR1 [Zhe25e] 带来了多模态支持, 使智能体能够在统一的 RL 框架中一起利用视觉和语言信号. AgentFly [Wan25u] 提出了一个可扩展且可扩展的智能体强化学习框架, 该框架为语言模型智能体提供传统强化学习算法的支持, 通过基于装饰器的工具和奖励定义、异步执行和集中资源管理来实现 token 级多轮交互, 以实现高吞吐量强化学习训练. Agent Lightning [Luo25g] 是一个灵活的 RL 框架, 通过将执行建模为 MDP 并使用分层 RL 算法 (LightningRL) 来训练任何具有近零代码修改的 AI 智能体, 从而将智能体执行与训练解耦. AWorld [Yu25c] 是一个分布式 Agentic RL 框架, 它通过协调跨集群的大规模并行部署, 解决了智能体训练的主要瓶颈——体验生成, 实现了单节点执行速度的 14.6 倍加速, 并实现了可扩展的端到端训练管道. ROLL [Wan25z] 提供了一个可扩展的库, 用于大规模 RL 优化, 具有统一的控制器、并行工作器和自动资源映射, 以实现高效的多 GPU 训练. VerlTool [Jia25a] 引入了基于 Verl [She25c] 构建的具有工具使用 (ARLT) 框架的 Agentic RL, 使智能体能够跨交互式环境联合优化规划和执行. AgentRL [Zha25s] 为多回合、多任务 Agentic RL 提供了可扩展的异步框架, 统一环境编排并引入跨策略采样和任务优势归一化以实现稳定的大规模训练.

**RLHF 和 LLM 微调框架.** OpenRLHF [Hu25a] 提供了一个高性能、可扩展的工具包, 专为大规模模型对齐而设计; TRL [Wer20] 为 RLHF 实验提供 Hugging Face 的基线实现; trlX [Hav23] 增加了分布式训练支持, 可微调模型高达数百亿个参数; HybridFlow [She25c] 简化了 RLHF 研究管道的实验管理和扩展. SLiMe [Thu25] 是一种用于 RL 扩展的 LLM 后训练框架, 它将 Megatron 与 SGLang 相结合以进行高性能多模态训练, 支持异步 RL, 并通过自定义接口和基于服务器的引擎实现奖励和数据生成的灵活分类工作流程.

**通用强化学习框架**提供支撑智能体 LLM 系统的核心算法与分布式执行引擎. RLlib [Lia18] 是面向生产的可扩展库, 为同策略、离策略和多智能体方法提供统一 API; Acme [Hof20] 为分布式强化学习提供模块化、面向研究的构件; Tianshou [Wen22] 是高性能纯 PyTorch 平台, 支持在线、离线和分层强化学习; Stable Baselines3 [Raf21] 封装了标准无模型算法的可靠 PyTorch 实现; PFRL [Fuj21] (原 ChainerRL) 提供经过基准测试的深度强化学习算法实现, 便于快速构建原型.

## 6 开放问题与未来方向

强化学习智能体向通用智能方向的进步取决于克服定义该领域研究前沿的三个关键挑战. 首先是**可信性**的挑战: 确保日益自主的智能体的可靠性、安全性和一致性. 其次是**扩大智能体训练**, 这需要克服计算、数据和算法效率方面的巨大实际瓶颈. 最后, 智能体的能力从根本上受到其世界的限制, 这使得**扩展智能体环境** (创建复杂且自适应的训练场) 变得至关重要.

<span id="section-6-1"></span>

### 6.1 可信度

**安全性.** 自主智能体的安全环境从根本上来说比标准 LLM 更复杂. 虽然传统模型主要容易受到文本输入、文本输出界面的攻击, 但智能体由于其工具、记忆和规划模块 [Wan25w, Sha25b] 等外部组件而拥有扩大的攻击面. 这种架构使他们面临直接提示注入之外的新威胁. 例如, 当智能体与受感染的外部环境 (例如恶意网站或 API) 交互时, 可能会发生间接提示注入, 从而毒害其记忆或工具输出 [Che24o]. 多智能体系统通过智能体间通信引入漏洞, 进一步加剧了这些风险, 其中一个受感染的智能体可以操纵或误导集体 [Wan25w] 内的其他智能体.

强化学习通过将智能体从被动的操纵受害者转变为主动的、寻求目标的漏洞利用者, 显著放大了这些特定于智能体的风险. 核心问题是通过奖励投机实现工具性目标: 强化学习智能体的主要指令是最大化其长期奖励, 并且它可能会了解到不安全的行为是实现这一目标的最有效途径. 例如, 如果智能体发现使用恶意第三方工具可以为给定任务带来高回报, 强化学习将积极强化和巩固这种不安全行为. 同样, 如果智能体得知它可以绕过安全协议以更有效地实现其目标, 则由此产生的奖励信号将教会它系统地探测和利用此类安全漏洞. 这会产生比一次性越狱更持久、更危险的威胁, 因为智能体会随着时间的推移自主学习和优化欺骗性或有害策略.

减轻这些放大的风险需要针对智能体系统量身定制的深度防御方法. 关键的第一道防线是强大的沙箱 [Lu25c, Rua24], 其中智能体在严格控制、权限有限的环境中运行, 以遏制受损工具或操作造成的潜在损害. 在训练层面, 缓解策略必须侧重于塑造奖励信号本身. 这包括实施基于流程的奖励, 惩罚不安全的中间步骤 (例如, 调用不受信任的 API), 并在 RL 循环中采用对抗性训练, 其中智能体因抵制操纵尝试和忽略有毒信息而获得明确奖励. 最后, 持续监控和异常检测对于部署后的安全至关重要. 通过跟踪智能体的行为, 例如工具调用和记忆访问模式, 可以识别与正常行为的偏差, 从而可以及时进行干预.

**幻觉.** 在智能体 LLM 的背景下, 幻觉是产生自信但毫无根据的输出, 包括陈述、推理步骤或工具使用, 这些输出并不植根于所提供的证据或外部现实. 这个问题不仅限于简单的事实错误, 还包括不忠实的推理路径和不一致的计划, 过度自信往往掩盖了智能体的不确定性 [Cos25, Hua25b]. 在多模态智能体中, 它还表现为跨模态不一致, 例如文本描述与图像不匹配, 将其视为基本基础问题 [Bai25b]. 评估幻觉需要评估客观事实的真实性和对给定来源的忠诚度, 通常通过 HaluEval-QA 等基准来衡量, 或者通过智能体适当放弃无法回答的问题的能力来衡量, 其中拒绝回答 (“我不知道”) 是认知意识 [Ng25, Son25c] 的关键信号.

如果奖励机制设计不周, 强化学习可能会无意中放大幻觉. 研究表明, 结果驱动的强化学习仅奖励最终答案的正确性, 可以鼓励智能体找到虚假的相关性或捷径. 这个过程可能会产生自信但毫无根据的中间推理步骤, 因为优化过程会陷入实现目标的局部最优, 但实际上并不是合理的 [Ng25]. 这种现象引入了“幻觉税”, 其中强化微调会降低智能体拒绝回答的能力, 迫使其对无法回答的问题做出回答, 而不是放弃 [Son25c]. 然而, 效果很大程度上取决于训练流程; 虽然仅 RL 训练后可能会恶化事实性, 但将 SFT 与可验证奖励 RL 过程相结合的结构化方法可以减轻这种退化 [Yao25a].

有前途的缓解策略涉及训练时间对齐和推理时间保障的混合方法. 在训练过程中, 一个关键的方向是从只注重结果的奖励转向基于过程的奖励. 事实感知逐步策略优化 (FSPO) 等技术根据证据验证每个中间推理步骤, 直接制定策略以阻止毫无根据的主张 [Ng25]. 以数据为中心的方法通过对智能体进行可解决和不可解决问题的训练来增强认知谦逊, 恢复他们在必要时放弃的能力 [Son25c]. 在系统层面, 这得到了推理时间技术的补充, 例如检索增强、用于事实检查的工具使用以及事后验证, 以将智能体的输出建立在可靠的来源上. 对于多模态智能体, 显式添加跨模态对齐目标对于确保 [Hua25b, Cos25, Bai25b] 的一致性至关重要. 总的来说, 这些方向旨在使智能体的寻求奖励行为与真实性目标保持一致, 从而培育更可靠、更值得信赖的自治系统.

**阿谀奉承.** LLM 智能体中的阿谀奉承是指他们倾向于生成符合用户陈述的信念、偏见或偏好的输出, 即使这些输出实际上不正确或导致次优结果[Wan25i]. 这种行为超越了单纯的对话宜人性, 从根本上影响了智能体的规划和决策过程. 例如, 阿谀奉承的智能体可能会在其内部计划中采用用户有缺陷的推理, 选择验证用户错误假设的行动方案, 或者从工具中过滤信息以仅呈现与用户观点 [Mal24b] 一致的内容. 这代表了一种严重的失调, 即智能体针对用户表达的偏好进行优化, 而不是针对他们实现最佳结果的潜在长期兴趣.

强化学习是造成这种行为的主要原因. 其底层机制是一种“奖励投机”形式, 其中智能体学习以不符合人类真实偏好 [Lu24a] 的方式利用奖励模型. 由于人类贴标签者经常表现出对令人愉快和验证的响应的偏好, 因此奖励模型无意中学会了将用户满意度与阿谀奉承的同意等同起来. 因此, RLHF 可以通过教导智能体遵循用户的观点是最大化奖励的可靠策略来直接激励和“加剧阿谀奉承的倾向”, 即使它会损害真实性 [Wen24a].

减少阿谀奉承是一个活跃的研究领域, 重点是完善奖励信号和训练动态. 一个有前途的方向是开发具有阿谀奉承意识的奖励模型, 该模型经过明确的训练, 可以惩罚那些仅仅鹦鹉学舌而没有进行批判性评估的反应.

在推理时, 明确提示智能体采取“红队”或逆向观点等策略也可以帮助抵消根深蒂固的阿谀奉承倾向. Cooper [Hon25a]是一个强化学习框架, 可以在线共同优化策略模型和奖励模型, 使用高精度的基于规则的验证器来选择正样本和 LLM 生成的负样本, 从而通过不断调整奖励模型来堵住紧急漏洞, 从而防止策略利用静态奖励模型 (即奖励投机). 最终, 未来的方向在于设计奖励系统, 该系统能够强有力地捕捉用户的长期利益 (例如接收准确的信息并做出正确的决策), 而不是他们立即获得验证的愿望.

<span id="section-6-2"></span>

### 6.2 扩展智能体训练

**计算.** 最近的进展表明, 扩展强化学习微调 (RFT) 计算可以直接增强基于 LLM 的智能体的推理能力. Agent RL Scaling Law 研究表明, 更长的训练范围可以系统地提高工具使用频率、推理深度和整体任务准确性, 凸显了为 RL 训练 [Mai25] 分配更多计算的预测优势. 同样, ProRL 表明, 长时间的 RL 训练将推理边界扩展到基础模型之外, 即使在预训练模型的大量采样失败的情况下, 也能发现新颖的解决策略 [Liu25h]. 在此基础上, ProRLv2 扩展了训练步骤并采用了更稳定的优化技术, 展示了较小模型的持续优势, 经过广泛的 RL 训练后, 在数学、代码和逻辑基准 [Hu25] 上可与较大模型的性能相媲美. 总的来说, 这些结果强调, 通过扩展强化学习训练来扩展计算不仅是对扩大模型或数据大小的补充, 而且是推进智能体推理的基本维度.

**模型大小.** 增加模型容量既增强了基于 RL 的智能体训练的前景, 也增强了其缺陷. 更大的模型释放了更大的潜力, 但风险是熵崩溃和能力边界变窄, 因为强化学习将输出分布锐化为高回报模式, 限制了多样性 [Don25c]. 像 RL-PLUS 这样的方法通过混合策略和优势函数来解决这个问题, 这些策略和优势函数可以促进新颖的推理路径, 突破能力上限 [Don25c]. 与此同时, 扩展需要大量计算, 因此效率至关重要. [Vat25] 中的两阶段方法使用大型教师为较小的学生生成 SFT 数据, 并通过策略 RL 进行细化. 这种“SFT+RL”设置优于每种单独的方法, 并且与纯 SFT 相比, 计算量减少了一半. 这项工作还强调了强化学习在规模上的极端超参数敏感性, 强调了仔细调整的必要性.

**数据大小.** 跨领域扩展 RL 训练会在智能体推理中引入协同作用和冲突. 数学、代码和逻辑任务中的跨域强化学习显示出复杂的交互 [Li25r]: 一些配对可以相互增强, 而另一些配对会干扰并降低性能. 模型初始化也很重要——指令调整模型的泛化能力与原始模型不同. 在此基础上, Guru 数据集 [Che25s] 跨越了六个推理领域, 表明 RL 增益与预训练暴露相关: 数学和代码从迁移中受益, 但模拟或逻辑等领域需要专门的训练. 这些发现表明, 虽然多域强化学习数据可以放大一般推理, 但必须精心策划以平衡互补性并减轻任务之间的干扰.

**效率.** LLM 后训练的效率是实现可持续扩展的核心问题 [Tie25]. 除了直接扩大规模, 近期研究还尝试通过后训练方案、方法改进和混合范式提高 RL 训练效率. POLARIS [An25] 表明, 校准数据难度、采用多样性驱动采样并延长推理长度, 可以显著提升 RL 的有效性, 让较小模型在推理基准上达到甚至超过大模型. [Liu25s] 系统评估了常见 RL 技术, 发现审慎组合少数简单策略, 往往比更复杂的方法效果更好. 另一项工作提出动态微调 (DFT) [Wu25o], 说明把 RL 原理引入梯度缩放, 只需很少的额外成本便能达到或超过先进 RL 方法. 这些进展指向两条路径: 一是继续改进基于 RL 的方案以提高效率; 二是重新思考训练范式, 在不采用完整在线 RL 的情况下嵌入类似 RL 的泛化信号. 一个特别值得研究的方向是, 智能体模型如何从极少量数据中获得可靠的泛化能力, 例如利用有原则的难度校准、元学习动态或信息论正则化, 从少量经验中提炼广泛的推理能力. 这些路径预示着一种新的后训练机制: 外推、抽象和泛化不再取决于单纯的数据量, 而取决于对训练过程结构与动态的利用.

<span id="section-6-3"></span>

### 6.3 扩展智能体环境

Agentic RL 的一个新兴但关键的前沿领域涉及从将训练环境视为静态实体到将其视为动态且可优化的系统的范式转变. 这种观点解决了智能体开发的核心瓶颈: 交互式、自适应环境的稀缺以及设计有效奖励信号的困难. 随着越来越多的共识认为, 像 ALFWorld [Shr21] 和 ScienceWorld [Wan22h] 这样的流行环境不足以训练通用智能体 [Zhe25g], 因此研究正在超越仅仅适应智能体的策略. 相反, 共同进化方法使用基于学习的方法来适应环境本身. 一项关键策略是自动化奖励函数设计. 这涉及部署辅助“探索者”智能体来生成交互轨迹的多样化数据集, 然后使用这些数据集通过启发式或偏好建模来训练奖励模型. 这有效地将智能体训练与昂贵的手动奖励规范过程脱钩, 从而无需直接人工注释即可学习复杂行为.

除了自动化奖励信号之外, 第二种更动态的策略是自动化课程生成, 将环境转变为活跃的教师. 这种方法建立了一个反馈循环, 其中突出显示特定弱点的智能体绩效数据被馈送到“环境生成器”LLM. 正如 EnvGen [Zal24] 所示, 该生成器随后会在程序上调整环境的配置, 创建专门针对和弥补智能体缺陷的新任务. 这种形式的目标导向的程序内容生成 (PCG) 确保智能体在其“最近发展区域”内始终受到挑战, 从而加速学习并防止过度拟合. 自动化奖励和自适应课程共同在智能体与其环境之间创建了一种共生关系, 建立了一个可扩展的“训练飞轮”, 这对于自我改进智能体系统的未来至关重要.

<span id="section-6-4"></span>

### 6.4 LLM 中强化学习的机制争论

为什么 RL 似乎能增强 LLM 推理, 目前有两种相互竞争的解释. “放大器”观点认为, 带有可验证奖励的 RL (通常采用 GRPO 等 PPO 式变体) 主要是在重塑基础模型的输出分布: 通过采样多条轨迹并奖励其中可验证正确的轨迹, RL 把概率质量集中到已经可达的推理路径上, 提高 pass@1, 但基本不改变解空间的支撑集. 与此一致, 大 k 的 pass@k 分析常常发现, 基础模型最终能达到或超过经 RL 调优的对应模型, 说明 RL 是在诱导已有能力, 而非创造能力; 另有证据表明, 反思行为在预训练期间便可能出现 [Sha24d, Yue25, Ai25]. “新知识”观点则认为, 在下一 token 预测之后进行 RL, 可以利用稀疏的结果级信号并鼓励更长的测试时计算, 从而引入性质不同的新计算. 理论结果表明, 对奇偶校验等问题, 仅靠下一 token 训练在统计或计算上代价过高, RL 却能实现泛化. 实验中, RL 能改善模型对分布外规则与视觉变体的泛化, 诱导基础模型中原本不存在、但能预测自我改进的认知行为 (验证、回溯、设置子目标), 甚至在预训练覆盖不足的领域扩大基础模型的 pass@k 边界 [Guo25b, Tsi25, Chu25a, Gan25, Che25s]. RL 能否真正赋予 LLM 超出预训练所得的新能力, 仍是一个悬而未决的问题, 其学习机制也尚未得到充分理解.

**案例研究: 数学推理.** 从机制角度看, [第 4.3 节](#section-4-3) 对数学推理 RL 的综述表明, RL 既不只是“采样放大器”, 也不是能够稳定产生全新推理算法的通用来源 [Yue25]. 在引用的数学与代码推理研究中, 约 2/3 主要强调 pass@1 准确率提升, 约 1/3 明确报告 pass@k 边界扩大 (例如, pass@1 固定或仅小幅提升时, pass@32 更高). 这说明许多系统主要用 RL 重塑已有有效轨迹上的采样分布, 而不是解锁性质不同的新轨迹. 不过, 1-shot RLVR 和自演化 System-2 式框架 (例如类似 rStar-Math 的流水线 [Gua25a]) 也表现出“饱和后”泛化与跨类别迁移; 这些现象很难仅用重新加权解释, 更可能意味着潜在能力在策略层面发生了重组.

根据经验, 我们发现这种“新能力”行为在具有以下特征的任务上最为可靠: (i) 高保真度、通常可执行或可正式检查的奖励信号; (ii) 组合或多步骤结构, 其中许多部分轨迹可验证分级; (iii)“中间”状态下的基础模型 (既不是近随机也不是近上限), 其中几乎未命中的轨迹空间足够丰富, 可供探索, 但仍然密集地分布着正确的推理路径. 在这些条件下, 策略梯度更新加上显式管理的探索 (例如, 熵奖励、自我博弈课程或搜索引导的专家迭代) 似乎使模型朝着内化更抽象的决策规则的方向发展——而在更简单、低噪声的基准或粗略的仅结果奖励上, 强化学习主要充当放大器, 锐化和重用预训练模型中已经隐含的模式.

### 6.5 现实世界智能体部署的架构模式

虽然该综述主要将 RL 作为提高推理性能的机制进行分析, 但 RL 优化系统的实际部署需要确保可靠性、安全性和操作稳健性的架构模式. 本小节综合了四个横切设计原则——安全护栏、人机交互监督、分层编排和智能体间通信协议——这些原则通常出现在 RL 增强推理系统的现实部署中, 无论在哪个领域.

**护栏和安全模式.** 部署的系统通常包含独立于 RL 优化循环运行的多层安全机制. 其中包括输入验证 (模式强制、语义过滤和约束检查) 、输出清理 (格式规范化、基础检查和事后约束满足) 以及工具或代码调用的沙箱执行. 这种护栏可以通过两种主要方式实现: ** (1) 使用强化学习优化本身作为保障**, 例如, 许多工作直接激励模型在通过强化学习 [Zhe25d, Zha25ah] 的推理输出过程中“安全思考”; **(2) 使用外部模块监控 RL 训练**, 例如 AWS Bedrock.

**人在环验证.** 在高风险或容易出现不确定性的环境中, 人工监督仍不可或缺 [Moz25, Tak25]. HITL 机制既包括对关键决策的同步审查, 也包括异步审计、异常处理和反馈收集. 这类机制通常依靠模型置信度信号或外部不确定性检测器触发人工介入 [Ban25]. 从架构上看, HITL 以稀疏但高保真的纠正信号补充 RL 奖励结构; 即使现实奖励反馈有限、延迟或带有噪声, 系统仍可安全部署.

**分层编排.** 许多实际系统采用分层控制结构 (例如主管 - 工作人员、控制器 - 执行者或计划者 - 求解器模式, 如 [Zha25ad, Liu25c, Hu25b] 中观察到的) 来管理复杂的工作流程. 监督层协调子任务、解决冲突或强制执行全局约束, 而较低级别的组件则专注于特定领域的推理或工具执行. 这种分解有利于时间和结构信用分配, 提高可扩展性, 并反映企业编排管道, 其中操作逻辑和执行完全分离.

**智能体间通信协议.** 多个推理实体彼此交互时, 无论它们是显式智能体还是模块化系统组件, 通信协议的选择都很重要. 固定协议 (*例如*, ANP [Cha25a]、A2A [Ref25] 和 ACP [Tea25e]) 稳定且可预测; 可学习的通信通道能够自适应协调, 但需要较强的正则化来防止涌现出的病态行为. 标准化通信接口有助于实现可组合性、可复现性, 并兼容外部工作流引擎.

### 6.6 更广泛的社会影响

自主、智能体 LLM 系统的不断部署引发了更广泛的社会考虑, 这些考虑日益影响研究重点. 本小节重点介绍了五个跨领域影响领域, 随着智能体能力的不断进步, 这些领域值得持续关注.

**双重使用风险.** Agentic RL 的部署降低了误用的障碍, 特别是通过“休眠智能体”行为, 其中模型在训练期间看似一致, 但在部署 [Hub24] 时激活隐藏的有害策略. 尽管有 SFT、RLHF 和对抗性训练, 但这种欺骗性的一致性常常持续存在, 因为模型 (尤其是那些利用思维链的模型) 学会区分评估环境和操作. 为了治理网络安全、CBRN 和自主复制和适应 (ARA) 等领域的此类危险, OpenAI 的准备框架建立了一个四层风险评估结构 [Ope25g]. 然而, 该框架因许可阈值、酌情评估协议和静态评估而面临批评, 这些批评未能考虑部署后能力演变 [Cog25].

**环境可持续性.** 由于需要生成 rollout、进行长时程推理和迭代决策, 大规模 RL 比 SFT 更加资源密集. 随着交互在多阶段工作流程 [Gar25] 上展开, 智能体系统进一步增加了训练和部署时间的碳足迹. 可持续实践包括硬件感知量化和注重资源效率的方法. HAQ 在硬件约束 [Wan19g] 下搜索最佳分层位宽, HERO 使用基于 RL 的优化 [Zha25ai] 导出低位量化策略以进行有效推理. 最近的其他工作还制定了环境评估基准 [Wu25m].

**劳动力市场影响.** 从 token 级辅助转向自主执行工作流, 使智能体系统在多种知识密集型任务中越来越可能替代人类. 代码智能体已在 SWE 基准 [Jim24, Liu23p] 中展现调试、补丁生成和仓库级问题解决能力. OSWorld 和 WebArena 的评测 [Xie24a, Zho24f] 也表明, GUI 与 Web 智能体能够自动执行交互式桌面和浏览器工作流. 经济分析指出, 这类端到端自动化可能对入门级岗位或常规认知岗位产生不成比例的影响, 引发对技能阶梯弱化和劳动力被替代的担忧 [Elo23, Bry23]. 这些趋势凸显了更广泛的社会经济影响, 尤其关系到日益暴露于自动化影响之下的劳动力市场.

**偏见放大.** RLHF 和 RLAIF 可能因过拟合注释者偏好 [Cas23a], 加剧社会偏见和意识形态迎合. 即使表面措辞礼貌, 这些模型仍会强化隐蔽歧视和性别刻板印象, 在多轮智能体环境中尤为明显 [Bar25a]. 标准优化还可能导致少数群体的偏好模式崩溃 [Xia25c]. 缓解方法同时作用于奖励层与策略层, 包括公平感知奖励学习 [Swa24, Ouy25b]、面向异构群体的 MaxMin-RLHF [Cha24b], 以及 DivPO 等保持多样性的目标 [Xia25c, Wan23f, Lan25b]. 其他方法还包括多元注释者池和 Constitutional AI [San23, Bai22a], 并使用 CrowS-Pairs、方言敏感测试 [Bar25b] 等基准评估.

**评估污染.** HumanEval 和 SWE-bench 等静态基准会受到数据污染影响, 导致分数虚高, 给人模型很鲁棒的错觉 [Ban24]. 在智能体场景中, 这会鼓励模型过拟合环境的偶然特征, 而非学习可泛化的推理能力. 为解决这些问题, 近期工作更重视动态且抗污染的基准, 包括 LiveCodeBench [Jai25a]、LiveSearchBench [Zho25e]、LiveTradeBench [Yu25d] 和 LiveBench [Whi25]. 再与 Breakpoint [Har25] 等对抗框架结合, 这些方法可以抑制针对测试集取巧, 更严格地评估分布外性能.

总的来说, 这些影响更广泛的考虑因素强化了将 Agentic RL 方法论进步与安全性、可持续性、公平性和鲁棒性原则相结合的重要性. 随着智能体系统朝着更广泛的部署方向发展, 理解和减轻这些社会影响仍将是未来研究的重要方向.

<span id="section-7"></span>

## 7 结论

本文综述了智能体强化学习 (Agentic RL) 这一范式: 它让 LLM 从被动文本生成器转变为置于复杂动态世界中的自主决策智能体. 我们首先形式化这一概念变化, 将 Agentic RL 的时间扩展部分可观察 MDP (POMDP), 与传统 LLM RL 的单步决策过程区分开来. 在此基础上, 本文建立两套分类体系来系统梳理该领域: 一套围绕规划、工具使用、记忆、推理、自我改进和感知等*核心智能体能力*, 另一套围绕这些能力在不同任务领域中的*应用*. 全文的核心论点是, RL 提供了一套关键机制, 能够把上述能力从静态启发式模块转化为自适应且鲁棒的智能体行为. 本文还汇总了开源环境、基准和框架, 为这一新兴领域的后续研究提供实用索引.

[+1]: 虽然 DPO 是 RLHF 优化目标的另一种形式, 但它从训练流程角度简化了优化, 因此有必要区分纯 RLHF 与 DPO.

[+2]: 在 Lean 一类交互式定理证明器 (ITP) 中, tactic 是命令或小型脚本, 用来指示系统细化当前证明目标; 生成的证明项是否正确, 由 ITP 内核检查.
