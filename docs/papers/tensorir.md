### 摘要

在各类设备上部署深度学习模型已经成为一个重要课题. 硬件专用化的浪潮带来了多种面向多维张量计算的加速原语. 这些新的加速原语与不断涌现的机器学习模型一起, 带来了巨大的工程挑战. 本文提出 TensorIR, 一种用于优化含有此类张量计算原语之程序的编译器抽象. TensorIR 推广了现有机器学习编译器使用的循环嵌套表示, 使张量计算成为一等公民. 最后, 我们在这一抽象之上构建了端到端框架, 可针对给定的张量计算原语自动优化深度学习模型. 实验结果表明, TensorIR 编译能够自动使用指定硬件后端的张量计算原语, 并在多个平台上达到可与先进手工优化系统相比的性能.

## 1 引言

<span id="figure-01"></span>

![见图注](./tensorir/figure-01.png)

**图 1.** 硬件专用化的发展趋势. 经典加速技术使用向量单元同时处理多个标量计算, 如今仍广泛用于 CPU 平台. 然而, 为了满足日益增长的计算吞吐需求, 现代加速器通常包含专用的高维张量计算指令, 因而需要张量化程序优化.

在图像识别 [He16, Sim15, How17]、自然语言处理 [Vas17, Dev18, Rad19] 和游戏 [Mni13, Lil15, Sch17] 等领域, 部署高性能机器学习模型已经成为一项新挑战. 机器学习的进步要求系统支持广泛的模型. 与此同时, 从服务器到嵌入式环境, 越来越多的设备需要部署智能应用.

硬件专用化进一步增加了问题的复杂性 ([图 1](#figure-01)). 为加速机器学习, 现代硬件后端引入专用原语来加快张量计算, 例如 Nvidia Tensor Core [Nvi17] 和 Google TPU [Jou17a]. 领域专家也开始开发微内核原语: 它们精心组织一系列高度优化的指令来完成一项子计算, 从而加速特定领域的张量算子库. 这些硬件指令与微内核原语通常作用于多维张量区域, 有效执行多维加载、点积和矩阵乘法等张量操作 ([图 1](#figure-01)). 我们把这些不透明的张量计算加速构件称为*张量化内在函数*, 把使用此类内在函数的变换过程称为*张量化*. 为了充分发挥这些硬件后端的能力, 现代机器学习系统需要优化包含分层循环嵌套、多维加载和张量内在函数的程序. 我们把这一问题称为*张量化程序优化*.

目前, 大多数张量化程序由领域专家优化. 他们把张量化原语与多维循环、线程模式和数据缓存组合起来, 构造 Intel MKL-DNN [Int17]、ARM Compute Library [Arm17] 和 NVIDIA cuDNN [Che14] 等专用内核库. 随后, TensorFlow [Aba16]、PyTorch [Pas19] 和 MXNet [Che15] 等机器学习框架会使用这些库. 然而, 要支持不断增加的模型和后端, 需要投入大量工程工作. 这些库还必须经过多个迭代周期, 才能适应快速变化和增长的机器学习应用, 这阻碍了新模型的演进.

<span id="figure-02"></span>

![见图注](./tensorir/figure-02.png)

**图 2.** 专家开发者可以把问题划分为 $4\times4$ 矩阵乘法及使用该乘法的循环, 再分别优化二者. 这样便能有效利用目标硬件中的专用张量指令.

本文提出以自动编译方法解决张量化程序优化问题. 以往大多数机器学习编译研究 [Che18, Vas18] 在循环嵌套变换构成的程序空间中搜索, 并不能自动处理张量化程序. 把自动程序优化扩展到张量化程序, 可以释放现代硬件后端中特定领域加速能力的价值. 要实现这一目标, 我们认为有以下关键挑战:

**张量化程序的抽象** 为张量化程序构建自动编译器, 需要一种抽象, 能够以实用方式捕获给定机器学习算子可能对应的等价张量化计算. 特别是, 该抽象需要表示多维内存访问、线程层次结构, 以及来自不同硬件后端的张量化计算原语. 它还必须有足够的表达能力, 能覆盖机器学习中大多数感兴趣的算子.

**张量化程序优化的巨大设计空间** 另一个挑战是为给定算子自动生成优化后的张量化程序. 编译器需要运用领域专家可能采用的多种技术, 包括有效使用循环分块、线程和数据布局变换. 更重要的是, 这些变换现在必须与张量化计算一同完成, 给分析和自动化带来额外复杂性. 各类变换的组合形成了庞大的搜索空间. 我们需要一种有效方法, 在给定搜索空间中找到优化后的张量化程序.

为应对这些挑战, 我们提出 *TensorIR*, 一种用于自动张量程序优化的抽象. 首先, 我们引入名为 *block* 的新构件, 将张量化计算区域与外层循环嵌套划分并隔离开来. 这一抽象既能有效表示张量化计算, 又能把它与循环嵌套、线程和内存层次结构组合起来. 我们还引入程序变换原语, 用来表达丰富的潜在优化空间, 并在抽象和变换原语之上构建新的自动调度算法. 此外, TensorIR 抽象还能表示并优化混合了不规则计算与张量计算的程序, 将支持范围扩展到普通张量表达式 [Che18] 之外. 本文的贡献如下:

- 我们提出一种新的张量化程序抽象, 将张量化计算与循环变换分离. 同一个抽象还可以统一表示张量内在函数和硬件约束.

- 我们构建了带正确性验证的变换原语, 用于生成丰富的张量化程序优化搜索空间.

- 我们设计并实现了新的张量化感知自动调度器.

我们把 TensorIR 集成到端到端编译框架中. 结果表明, 它的性能最高可超过现有机器学习编译方案 $7\times$, 并能自动达到可与高度优化的平台专用方案相比的性能.

## 2 概述

<span id="figure-03"></span>

![见图注](./tensorir/figure-03.png)

**图 3.** 本文方法概览. 我们使用名为 block 的关键抽象来划分并隔离张量化计算, 同时允许围绕张量化操作继续进行循环变换.

本节说明方法的核心见解, 并概述全文. 为说明出发点, 我们先看 [图 2](#figure-02) 所示的领域专家优化张量化程序的示例流程. 张量化计算原语通常对应原始张量算子计算的一个子问题. 因此, 领域专家自然会采用*分而治之*的方法: 把原程序分成张量化计算子问题和使用该计算的循环嵌套, 再分别优化. 分而治之让开发者能够专注于一个子问题, 不必同时顾及其他部分. 它也使系统可以面向多种张量化计算实现.

现有机器学习编译器大致采用两类方法 ([图 3](#figure-03)). Halide [Rag13]、TVM [Che18]、Tiramisu [Bag19]、AKG [Zha21k]、MLIR/Affine [Lat21] 和 AMOS [Zhe22d] 采用自底向上的方法, 用围绕标量操作体的循环嵌套迭代器描述搜索空间, 再通过搜索或多面体优化找到最佳循环嵌套变换. HTA [Fra04]、Fireiron [Hag20] 和 Stripe [Zer19] 则采用自顶向下的方法, 通过嵌套多面体结构逐步把问题分解成子问题. 既然分而治之对手工张量化程序优化如此重要, 一个自然的问题是: 能否把同样的见解用于机器学习编译器设计?

本文给出了肯定的答案. 具体来说, 我们在循环嵌套中引入名为 *block* 的新抽象. Block 包含恰到好处的签名信息, 能够*隔离*内部问题空间与外部问题. 以 block 签名为接口, 我们可以继续独立变换内、外两个问题. 与手工分而治之类似, block 的常见用途是表示硬件后端中的张量化计算原语; 在适合分治时, 它也能隔离更大的目标子问题. 重要的是, 张量计算在 TensorIR 中是一等公民. 带有 block 的循环嵌套可以看作迭代空间抽象的推广. [第 3 节](#section-3) 介绍 TensorIR 抽象的详细设计.

为实现张量化程序的自动优化, 我们在硬件张量计算原语的引导下构造问题划分方式的搜索空间, 再利用程序变换进一步搜索子问题的求解方式. [第 4 节](#section-4) 介绍张量化程序的自动调度算法.

我们的分而治之方法覆盖了既有编译器方法, 包括自底向上与自顶向下的搜索空间, 并把 HPC 和机器学习工程中的典型优化技术推广为支持自动张量化的抽象. 我们把库与编译流水线中的常见决策自动化, 从而自动生成可与供应商专用库竞争的方案. [第 5 节](#section-5) 给出实验结果.

<span id="figure-04"></span>

![见图注](./tensorir/figure-04.png)

**图 4.** TensorIR 程序示例, 包含三个主要元素: 多维缓冲区、循环嵌套和计算 block. 为简化起见, 图中省略了 block 的细节.

本节介绍 TensorIR 抽象. [图 4](#figure-04) 给出一个 TensorIR 程序示例. 我们为 TensorIR 引入 Python-AST (抽象语法树) 方言, 让开发者能直接在 Python 中构造和变换程序. TensorIR 程序包含三个主要元素: 多维缓冲区、循环嵌套 (在 GPU 环境中可能带线程绑定) 和 block. Block 可以包含一层或多层以子 block 为叶节点的嵌套循环, 也可以包含与计算内容对应的一系列命令式语句. 这种表示让我们能够把计算划分到相应的子 block 区域中, 再利用 block 签名保存的依赖信息有效执行程序变换. [第 3.1 节](#section-3-1) 讨论设计细节.

### 3.1 Block

TensorIR 中的 block 表示多维缓冲区某个子区域上的张量化计算. [图 5](#figure-05) 展示了矩阵乘法计算的示例 block. Block 体由一组 block 迭代变量 $v_y, v_x, v_k$ 参数化, 这些变量表示一种抽象的张量化计算. 以不同的 block 迭代变量取值组合实例化后, block 会映射到不同的具体运行实例. 这些迭代变量可以绑定到包含外层循环迭代器的表达式, 从而隐含 block 实例的执行顺序.

**设计理由** Block 的主要设计目标是隔离张量化计算, 让系统不必查看 block 体便能变换其外部循环嵌套. 但与标量计算不同, 我们未必能从不透明的张量计算体中提取变换所需的依赖信息. 因此, 我们引入含有充分依赖信息的 block 签名. [第 3.2 节](#section-3-2) 讨论这些变换. 此外, 签名还能独立验证变换期间迭代器绑定的正确性, 详见 [第 3.3 节](#section-3-3).

**Block 迭代器域** 虽然可以把 block 迭代器绑定到任意循环嵌套来实例化 block 体, 但大多数实例并不对应同一计算. 为保证各次变换之间的计算一致性, 我们把迭代器域信息和迭代器约束存入 block 签名. 在 [图 5](#figure-05) 的例子中, $vx$、$vy$ 和 $vk$ 必须绑定到域 $[0, 16)$ 中的迭代器. 此外, 因为 $vk$ 是归约轴, 除非归约是原子的, 否则不能把它绑定到并行循环. 域约束仍为外层循环变换留下了很大空间, 因为满足约束的循环构造方式有很多种. 我们的域签名可以看作表示迭代器整数域集合与关系的一种具体方法. 选择这种表示是因为它实现高效且易于推理, 但同样的设计思想也适用于其他整数集合与关系的形式化域表示 [Vas06].

**访问区域与依赖** 为提供充分的依赖信息, block 签名包含该 block 相对于多维缓冲区的访问区域及读写依赖. 在 [图 5](#figure-05) 中, block 读取 $A[vy*4: vy*4 + 4, vk*4: vk*4 + 4], B[vk*4: vk*4 + 4, vx*4: vx*4 + 4]$, 并写入区域 $C[vy*4: vy*4 + 4, vx*4: vx*4 + 4]$. 变换会使用这些依赖信息. 我们只标记每个 block 相对于多维缓冲区的依赖, 而不直接标记它与其他语句 (block) 的依赖. 这种间接表示支持更广泛的变换, 例如张量化程序优化中不可或缺的数据布局变换和重新计算.

**归约 Block 与初始化** 归约计算通常包含初始化与更新两个步骤. 我们可以自然地把归约计算映射为两个 block, 但一般又需要共同决定两个步骤的调度方式, 例如分块和计算位置. 因此, 我们为执行归约的 block 引入可选的初始化语句. 初始化语句在归约的第一次迭代中执行. 这种归约 block 表示主要用于变换阶段. 我们提供变换原语, 在双 block 表示和含初始化语句的单 block 表示之间转换, 以便为低层代码生成选择最佳表示.

### 3.2 调度变换

<span id="figure-08"></span>

![见图注](./tensorir/figure-08.png)

**图 8.** 使用硬件内在函数自动优化张量化程序. 输入工作负载是 $64\times64\times64$ 矩阵乘法后接 RELU 算子, 合成张量内在函数是由点积指令实现的 $4\times4\times4$ 矩阵乘法. 张量化候选生成步骤把 $64\times64\times64$ GEMM 划分为 $4\times4\times4$ 子块并隔离子计算. 随后, 张量化程序草图生成步骤调度计算并插入产生的数据移动 (AutoCopy) block, 各个 block 独立调度. 最后, 我们使用进化搜索填充草图中的随机决策, 并以验证机制过滤错误程序.

对于给定输入程序, 我们需要生成语义等价且足够丰富的程序搜索空间. 为此, 我们引入把 TensorIR 程序变换为等价优化程序的原语. 按照现有张量程序优化的惯例 [Rag13, Che18, Bag19], 我们把这一过程称为调度.

如果一个 block 只包含以子 block 为叶节点的循环嵌套, 它就是可调度的. 通过分析子 block 签名及其依赖信息, 我们可以变换可调度 block 中的循环嵌套和子 block 计算位置. 值得注意的是, 可调度 block 可以包含不可调度的子 block, 例如不透明的 Tensor Core 计算; 不透明 block 也可以包含可调度的子 block. 借助 block 隔离, 我们仍能在保持同一个不透明 block 的同时, 独立且有效地探索可调度部分的搜索空间. 本小节余下部分介绍各类调度原语.

**循环变换** 循环分块 (split、reorder) 和计算位置修改等循环变换, 是改善内存局部性的重要优化手段. 我们也提供这些循环变换原语, 示例见 [图 6](#figure-06). 现有张量编译器会直接提取每个叶级标量计算语句的依赖, 而我们只需检查 block 签名即可计算依赖. 除循环变换外, 系统还支持把循环绑定到 GPU 线程的原语, 并提供向量化和展开等注解提示. Block 隔离并不会妨碍许多重要的跨 block 协同优化, 例如内联和协同取数. 我们的循环变换覆盖以往工作提供的循环变换, 因而 TensorIR 可以复现 [第 2 节](#section-2) 提到的搜索空间.

**Blockization** 循环变换原语会保留 block 的整体层次结构. 如 [第 2 节](#section-2) 所述, 有时把子区域计算隔离为新的子 block 有助于划分问题. 我们称这一变换为 *blockization* ([图 7](#figure-07)). 经过 blockization 的程序不再以标量为基础, 因为新的子 block 对应张量化计算. 我们可以用 blockization 隔离可能的张量化候选. 除了 blockization, 我们还引入能够改变 block 层次结构的原语. 例如, 缓存原语会引入子 block, 把输入数据缓存到共享内存. 系统还支持在单个归约 block 与对应的初始化、更新 block 之间双向转换.

**调度与 TensorIR 分离** 许多既有张量编译器 [Rag13, Che18] 依靠声明式调度语言构造调度树. 为这些编译器添加调度原语时, 既要修改调度树数据结构, 也要修改相应的 lowering 规则. 我们采用不同做法: 每个调度原语都是从一个 TensorIR 程序到另一个程序的独立变换. 这一设计更容易扩展, 不同开发者可以基于稳定的 TensorIR 抽象并行开发新原语. 开发者也可以在任意变换阶段输出程序来调试, 并混合使用自动重写和调度变换.

### 3.3 验证

Block 及其缓冲区读写关系完整刻画了原始计算, 可用于验证循环嵌套和线程分配的正确性.

**循环嵌套验证** 循环嵌套验证检查循环嵌套给出的迭代器绑定是否满足迭代器域约束, 包括域大小和迭代器独立性. 例如, 若两个数据并行 block 迭代器绑定为 $v_1 = i; v_2 = i * 2$, 因为 $v_1$ 与 $v_2$ 并不独立, 对应程序无效. 而 $v_1 = i / 4; v_2 = i \% 4$ 可以是合法绑定. 我们构建模式匹配器, 从循环迭代器到 block 迭代变量中寻找准仿射映射, 再用该模式验证绑定的独立性和域. 除了迭代器域验证, 还必须检查生产者-消费者关系, 确保写入缓冲区区域的生产者 block 始终覆盖下游消费者读取的区域.

**线程验证** 为 GPU 和其他支持线程的加速器构建程序时, 还需要针对线程与内存层次结构做额外验证. 我们进行三类验证:

- **线程绑定**: 确保绑定到同一线程的不同迭代器彼此一致, 并满足后端的启动约束.

- **协同内存访问**: 对于由多个线程协同生成并存入共享内存的缓冲区 block, 需要确保该 block 覆盖同组全部线程的下游需求. 同时, 为该 block 提供输入的上游 block 必须覆盖同组全部线程对该 block 的读取需求.

- **执行作用域**: 验证张量内在函数在正确的执行作用域运行, 例如 Tensor Core 需要在 warp 级运行.

**调度原语的正确性** 我们为每个调度原语加入检查, 确保变换正确. 如果调度原语只修改循环嵌套, 也可以直接使用验证过程来保证正确性, 因为此时 block 的迭代域和依赖不变. 对于会改变 block 的调度原语, 例如 blockization, 我们则寻找该原语特有的必要条件.

循环嵌套验证和线程验证用于过滤无效 TensorIR 程序, 调度原语检查则用于保证变换前后 TensorIR 程序等价. 用户手工构造、导入或调度 TensorIR 程序出错时, 会收到警告或错误信息. 当用户让编译器自动生成程序时, 即 [第 4 节](#section-4) 将讨论的情形, 验证可以在搜索空间探索期间过滤误报候选. 因此, 用户编写的程序与编译生成的程序都能从验证中受益.

<span id="section-3-4"></span>

### 3.4 编程工作量

如 [图 4](#figure-04) 所示, 我们提供了 TensorIR 的 Python-AST 方言, 让开发者能直接在 Python 中构造、转储、检查、修改和变换 TensorIR 程序. 如果用户必须手工指定全部计算和优化, 编程工作量会很大. 我们的框架允许用户从 TensorFlow/PyTorch 导入模型, 并根据高层算子自动生成 TensorIR 程序. 此外, 系统通过自动调度 ([第 4 节](#section-4)), 针对给定硬件平台自动提供分块与缓存等优化. 用户需要定制算子时, 仍可用 Python 方言编写 TensorIR; 即使如此, 系统也会自动提供优化变换. 因而通常可以把编程工作量降到最低.

<span id="figure-09"></span>

![见图注](./tensorir/figure-09.png)

**图 9.** 张量化候选生成流程示例. 输入工作负载是标准 NHWC 二维卷积, 硬件后端内在函数是 $16\times16\times16$ 矩阵乘法. 系统先把缓冲区访问表达式转换为中间迭代器, 再根据缓冲区访问模式计算每个迭代器的特征函数, 并在具有相同特征向量的迭代器之间建立映射. 该映射进一步指导 block 实例空间和 *ReIndex* 缓冲区的变换. B 和 C 的 *ReIndex* 阶段虽然多余, 但会在草图生成阶段内联到消费者中, 因而不会影响性能.

## 4 张量化程序的自动调度

上一节介绍了 TensorIR 抽象和一组变换原语. 要充分利用这些改进, 还需要自动优化一组变换, 并把计算映射到原生张量内在函数. 本节介绍解决这一问题的张量化感知自动调度器.

[图 8](#figure-08) 给出方法概览. 系统以用户提供的工作负载描述和硬件平台的张量内在函数描述为输入. 自动调度器先检查计算模式, 生成张量化候选. 接着, 它生成使用张量化计算的程序草图候选, 并根据计算模式决定数据移动. 对张量化程序草图诱导出的搜索空间, 我们使用基于学习的代价模型来引导进化搜索. 整个过程以张量化为中心, 并利用新的 block 抽象隔离张量化计算. 下文逐步讨论各阶段细节.

<span id="section-4-1"></span>

### 4.1 张量内在函数的抽象

为了在优化中使用张量内在函数, 需要向系统提供其语义和后端实现. 我们用*同一个* TensorIR 抽象描述给定硬件后端的张量内在函数. 对每条张量化指令, 我们引入由两个 block 组成的 TensorIntrin 构件: 一个 block 描述计算*语义*, 另一个提供张量化计算的底层*实现*.

在 [图 8](#figure-08) 的例子中, 我们用标量计算体为 $C[i, j] \mathrel{+}= A[i, k] * B[k, j]$ 的普通循环嵌套表示计算语义, 并使用内部点积指令 $\texttt{accel.dot}$ 实现内在函数. TensorIntrin 还通过多维缓冲区规范纳入数据类型、存储作用域、内存布局和连续性约束. 验证步骤会使用这些约束.

值得注意的是, 在常见平台上, 张量内在函数通常要与特殊内存作用域、数据布局以及相应的加载/存储指令配合使用. 例如在 NVIDIA GPU 上, 如果使用 `nvcuda::wmma::mma_sync` API 执行稠密计算, 就需要分别用 `nvcuda::wmma::load_matrix_sync` 和 `nvcuda::wmma::store_matrix_sync` 准备输入操作数并取回输出结果. 在 ARM CPU 上, *a64_gemm_u8_8* $\times$ *12* 等微内核要求操作数按交错布局存储. 开发者可以为张量计算的每个输入、输出操作数指定特殊存储作用域, 将这些约束告知系统.

<span id="section-4-2"></span>

### 4.2 张量化候选生成

给定后端目标和输入程序后, 我们先把程序体与可能的 TensorIntrin 匹配, 生成张量化候选. 匹配逐步进行: 先在不考虑索引的情况下匹配表达式模式 $C[.] \mathrel{+}= A[.] \times B[.]$, 再通过提出可能的索引映射来细化匹配. [图 9](#figure-09) 逐步展示了匹配过程. 在该例中, 我们以矩阵乘法内在函数作为后端描述. 这个张量内在函数的计算可写为

$$
    C[x,y] \mathrel{+}= A[x,k] \times B[k,y]
$$

对于批量矩阵乘法等工作负载, 匹配很直接. 其计算可写为 $$C[b,i,j] \mathrel{+}= A[b,i,r] \times B[b,r,j],$$ 只需把 $x, y, k$ 映射到 $i, j, r$. 但对于索引表达式模式更复杂的二维卷积 (Conv2D),

$$
\begin{aligned}
    C[n, h, w, co] \mathrel{+}= &A[n, h * s_h + r_h * d_h, w*s_w+r_w*d_w, r_c] \\ \times &B[r_c, r_h, r_w, co],
\end{aligned}
$$

$x, y, k$ 与 $n, h, w, c, r_h, r_w, r_c$ 之间的映射并不直观.

在这类更一般的情形下, 我们把计算表达式改写成等价形式:

$$
\begin{aligned}
    C[n, h, w, co] \mathrel{+}= A_r[n, h, w, r_h, r_w, r_c] \times B[r_c, r_h, r_w, co],\\
    A_r[n, h, w, r_h, r_w, r_c] = A[n, h * s_h + r_h * d_h, w*s_w+r_w*d_w, r_c].
\end{aligned}
$$

我们把这一变换称为 *ReIndex*. 它利用缓冲区访问索引中出现的中间迭代器改写缓冲区访问表达式. 为了把新计算与张量内在函数匹配, 我们检查每个迭代器出现在哪些缓冲区访问中. 例如, $n, h, w$ 和 $x$ 出现在 $A(Ar), C$ 的索引中, $co$ 和 $y$ 出现在 $B, C$ 的索引中, 而 $r_h, r_w, r_c$ 和 $k$ 出现在 $A, C$ 的索引中. 检查这些出现模式后, 便可把计算迭代器映射到张量内在函数的迭代器. 具体来说, 我们把 $\operatorname{fuse}(n, h, y)$ 映射到 $x$, 把 $co$ 映射到 $y$, 把 $\operatorname{fuse}(r_h, r_w, r_c)$ 映射到 $k$. 这里, $\operatorname{fuse}()$ 会融合多个迭代器, 可递归定义为

$$
\begin{aligned}
    \operatorname{fuse}(i_1) &= i_1 \\
    \operatorname{fuse}(i_1, i_2, \dots, i_{r}) &= \operatorname{fuse}(i_1, i_2, \dots, i_{r-1}) * \operatorname{extent}(i_{r}) + i_{r},
\end{aligned}
$$

其中 $\operatorname{extent}$ 是迭代器 $i_r$ 的范围. 随后可把计算变换为

$$
\begin{aligned}
    C_t[\operatorname{fuse}(n, h, w), co] \mathrel{+}= &A_t[\operatorname{fuse}(n, h, w), \operatorname{fuse}(r_h, r_w, r_c)] \\ \times &B_t[\operatorname{fuse}(r_h, r_w, r_c), co],
\end{aligned}
$$

其中

$$
\begin{aligned}
    C_t[\operatorname{fuse}(n, h, w), co] = &C[n, h, w, co], \\
    A_t[\operatorname{fuse}(n, h, w), \operatorname{fuse}(r_h, r_w, r_c)] = &A_r[n, h, w, r_h, r_w, r_c] \\
    B_t[\operatorname{fuse}(r_h, r_w, r_c), co] = &B[r_h, r_w, r_c, co].
\end{aligned}
$$

我们使用该映射重塑 block 实例空间和外层循环, 并变换 *ReIndex* 缓冲区的布局. 系统插入布局改写 block, 分别把 $A, B, C$ 改写为 $A_t, B_t, C_t$, 再用 $A_t, B_t, C_t$ 改写计算体. 完成这些步骤后, 计算体便与张量内在函数兼容.

**循环重组与提前 Blockize** 除了计算体, 还必须保证张量计算区域与 TensorIntrin 提供的描述相符. 重组后的 block 实例空间形状未必能被张量内在函数的子问题大小整除. 对上一步得到的每个计算体, 我们把计算 block 和输入/输出操作数按需填充到最接近的可整除形状. 随后进行分块, 创建与张量内在函数循环嵌套匹配的内层循环, 再对内层循环执行 blockize, 隔离相应的张量计算. 本步骤生成的候选并非总能成功张量化, 因为内存布局、线程等约束取决于后续变换. 这些约束会嵌入张量化候选中, 并在验证阶段检查.

**过程的形式化描述** 至此, 我们从高层概述了张量化候选生成过程. 本小节余下部分给出该过程的形式化描述. 假设内在函数的标量表达式可形式化为

<span id="equation-02"></span>

$$
    O[\mathbf{v}_{0}] = f(O[\mathbf{v}_{0}], I_1[\mathbf{v}_1], I_2[\mathbf{v}_2], \dots, I_k[\mathbf{v}_k]).
$$

其中 $O$ 是输出操作数, $I_{[1: k]}$ 是输入操作数, $\mathbf{v}$ 是参数化该计算的迭代器集合, $\mathbf{v}_{[0:k]}$ 是所有由 $\mathbf{v}$ 中迭代器组成的列表, $f$ 是检测到的表达式模式. 这一形式可以容纳常见的点积和矩阵乘法内在函数. 再假设工作负载的标量表达式可形式化为

$$
\begin{aligned}
    \tilde{O}[g_{0}(\tilde{\mathbf{v}}_{0})] = f(\tilde{O}[g_{0}(\tilde{\mathbf{v}}_{0})], \tilde{I}_1[g_1(\tilde{\mathbf{v}}_1)], \dots, \tilde{I}_k[g_k(\tilde{\mathbf{v}}_k)]),
\end{aligned}
$$

其中 $\tilde{O}$、$\tilde{I}_{[1: k]}$、$\tilde{\mathbf{v}}_{[0:k]}$ 分别对应前式中的同类项, $f$ 完全相同. $g_{[0:k]}$ 是把迭代器列表映射到实际缓冲区访问位置的映射. 例如, 在 Conv2D 中有 $g_{A}(n, h, w, r_h, r_w, r_c)=(n, h * s_h + r_h * d_h, w*s_w+r_w*d_w, r_c).$

为了把问题化为更简单的规范形式, 我们应用 *ReIndex* 调度变换. 该变换为操作数创建中间缓存缓冲区, 并根据迭代器修改其布局. 形式化地说, 若对 $\tilde{I}_1[g_1(\tilde{\mathbf{v}}_1)]$ 执行 *ReIndex*, 就会在计算前创建如下改写 block:

$$
\begin{aligned}
    \hat{I}_{1}[\tilde{\mathbf{v}}_1] = \tilde{I}_1[g_1(\tilde{\mathbf{v}}_1)].
\end{aligned}
$$

对所有操作数应用 *ReIndex* 后, 工作负载的标量表达式可化为

<span id="equation-03"></span>

$$
    \hat{O}[\tilde{\mathbf{v}}_{0}] = f(\hat{O}[\tilde{\mathbf{v}}_{0}], \hat{I}_1[\tilde{\mathbf{v}}_1], \dots, \hat{I}_k[\tilde{\mathbf{v}}_k]),
$$

此时 [公式 2](#equation-02) 与 [公式 3](#equation-03) 中的缓冲区访问索引都直接对应迭代器.

为了匹配 [公式 2](#equation-02) 和 [公式 3](#equation-03), 我们检查 $\mathbf{v}_0, \mathbf{v}_1, \mathbf{v}_2, \dots \mathbf{v}_k$ 中的每一项是否包含迭代器 $v \in \mathbf{v}$, 据此定义其特征向量 $\chi(v) \in \{0,1\}^{k+1}$. 形式化地说,

$$
\begin{aligned}
    \chi(v)_i &= [v \in \mathbf{v}_i] \quad i \in [0, k],
\end{aligned}
$$

其中 $[]$ 是 Iverson 括号: 条件为真时返回 1, 否则返回 0 ([图 9](#figure-09)). 只要 $\forall v \in \mathbf{v}, \exists \tilde{v} \in \tilde{\mathbf{v}}, \chi(v) = \tilde{\chi}(\tilde{v})$, 就能成功提出映射. 在当前实现中, 还可以安全地假设 $\mathbf{v}$ 中所有迭代器的特征向量各不相同. 于是, 对每个 $v \in \mathbf{v}$, 我们融合所有满足 $\chi(v) = \tilde{\chi}(\tilde{v})$ 的 $\tilde{v}$, 再把融合后的迭代器映射到 $v$.

需要注意, $\mathbf{v}_{[0:k]}$ 或 $\tilde{\mathbf{v}}_{[0:k]}$ 各列表内部的迭代器顺序, 不会影响特征函数 $\chi$ 或 $\tilde{\chi}$ 的值. 但在融合所有满足 $\chi(v) = \tilde{\chi}(\tilde{v})$ 的 $\tilde{v}$ 时, 融合顺序会影响操作数在内存中的重组方式, 进而影响它与张量内在函数的兼容性. 当前实现对所有工作负载采用默认顺序, 将来可以推广到不同的融合顺序.

<span id="section-4-3"></span>

### 4.3 张量化程序草图生成

给定一组张量化候选后, 我们需要构造包含张量化的庞大程序搜索空间. 我们把现有的分层搜索空间生成方法 [Zhe20] 推广到张量计算. 系统先生成包含张量化计算的程序草图来构造搜索空间, 再枚举这些草图诱导出的选择. 如 [图 8](#figure-08) 右侧所示, 程序草图固定一部分程序结构, 同时为循环分块大小、计算缓存决策等剩余参数选择留出空间. 我们通过迭代应用预定义的草图生成规则来生成草图. 关键在于, 这些规则必须能处理张量化计算: 分析时既要查看 block 签名, 也要利用访问区域信息.

**让数据移动成为一等公民** 现有张量程序自动调度器把设计重点放在计算调度上, 对不同内存作用域之间的数据移动只给予次要关注. 但张量内在函数大幅提升计算吞吐后, 数据移动就成了张量程序的瓶颈. 此外, 数据移动决策通常依赖分块、线程绑定、执行作用域和生产者-消费者数据流粒度等计算调度决策. 基于这些观察, 我们让数据移动成为自动调度器中的一等公民, 并将其与计算调度解耦. 具体来说, 在草图生成规则决定执行数据移动的位置插入 *AutoCopy* block ([图 8](#figure-08)). 复制 block 隐藏内存调度细节, 只在 block 签名层暴露必要的缓冲区访问信息. 独立的复制 block 让草图生成过程无需考虑数据移动方式, 就能独立决定计算调度. *AutoCopy* block 体描述数据移动任务的细节, 包括缓冲区位置映射、线程和存储作用域要求. 数据移动调度器以这些信息为输入, 执行与内存有关的调度变换, 例如插入中间缓存阶段、利用数据移动张量内在函数、向量化、协同取数, 或用步长填充避免 bank conflict.

<span id="section-4-4"></span>

### 4.4 进化搜索

完成张量化程序草图生成后, 可以得到数十亿个可能诱导出的程序. 我们用进化搜索探索该空间并找到优化后的张量化程序. 搜索从随机初始化给定程序草图的各项选择开始, 随后对当前程序集合执行变异. 我们从变异候选中选出有希望的程序, 在目标硬件后端上进行基准测试, 再收集评估阶段的数据来更新学习得到的代价模型.

**张量化计算的代价模型** 我们构建了基于提升树集成 [Che16b] 的代价模型, 使用从程序中提取的特征. 特征向量包含内存访问模式、复用和循环注解等信息. 特别是, 我们既以隔离方式从 block 签名中提取特征, 也从 block 体中提取特征, 例如标记是否使用 Tensor Core. 我们的代价模型可以看作既有方法向张量化程序的推广. 我们认为, 面向张量化程序的有效代价模型是很有前景的未来研究方向.

**验证** 搜索期间的随机程序变异可能因为不满足张量内在函数约束或循环嵌套候选无效而产生错误程序. 潜在误报使搜索过程必须包含验证步骤. 我们使用 [第 3.3 节](#section-3-3) 的技术验证进化搜索中的程序候选, 识别并拒绝无效程序. 验证步骤减轻了进化搜索算法的负担, 也允许搜索过程中生成少量误报候选.

## 5 评估

我们在 Apache TVM [Che18] 之上实现 TensorIR. 本文的见解也能惠及其他机器学习编译框架. 本节通过评估回答以下问题:

- TensorIR 能否优化常见的机器学习算子集合 ([第 5.1 节](#section-5-1))?

- TensorIR 能否提升端到端网络执行性能 ([第 5.2 节](#section-5-2))?

- TensorIR 能否支持不同硬件平台上的张量内在函数 ([第 5.3 节](#section-5-3))?

为沿这些维度评估 TensorIR, 我们在 GPU 和 CPU 平台上将其与现有机器学习编译方案比较. 各小节会说明具体设置.

所有评估还贯穿另一个问题: TensorIR 与供应商专用库以及依赖这些库的框架相比如何? 这些库大多由专门的工程团队深度优化. 在所有实验设置中, TensorIR 都执行端到端自动优化, 无需调用外部库.

<span id="section-5-1"></span>

### 5.1 单算子评估

本节评估 TensorIR 处理深度学习模型算子的表现. 我们选取一组常见工作负载: 一维卷积 (C1D)、二维卷积 (C2D)、三维卷积 (C3D)、深度卷积 (DEP)、空洞卷积 (DIL)、通用矩阵乘法 (GMM)、分组卷积 (GRP) 和二维转置卷积 (T2D). 评估在带 Tensor Core 的 NVIDIA RTX 3080 平台上进行. 选择该平台是因为它有多种机器学习编译方案和库可作为比较基准. 所有算子的输入与累加器数据类型均为 float16. 我们以 TVM (commit: 27b0aad5, 带自动调度器 [Zhe20]) 和 AMOS (commit: 6aee6fe2) 作为两个机器学习编译器基线. 最后, 还与两个供应商专用方案比较: CUTLASS 2.9 和 TensorRT (PyTorch-TensorRT container Release 22.06).

**与机器学习编译器比较.**

<span id="figure-10"></span>

![见图注](./tensorir/figure-10.png)

**图 10.** 在 Nvidia GPU 上与现有机器学习编译器进行单算子比较. TensorIR 在不同工作负载上最多带来 $7.5\times$ 加速.

[图 10](#figure-10) 展示了与 AMOS 和 TVM 的比较. TVM [Che18] 在计算量较小的工作负载上表现良好, 例如 DEP; 但由于 Tensor Core 支持有限, 在 C2D、C3D、GMM 等重负载上表现较差. AMOS [Zhe22d] 可在每种工作负载上使用 Tensor Core, 但表现仍不及 TensorIR. 总体而言, TensorIR 相比现有机器学习编译方案最多提升 $7.5\times$. 这些提升来自更合适的抽象与自动调度, 后者能利用张量计算内在函数及相应的数据移动.

**与平台专用库比较.**

<span id="figure-11"></span>

![见图注](./tensorir/figure-11.png)

**图 11.** 与平台专用库进行单算子比较. CUTLASS 不支持 DEP、GRP 和 T2D, 因而图中没有这些算子的 CUTLASS 数据. 在 C1D、C2D、DEP、T2D 和 DIL 上, TensorIR 最多领先基线 $13.9\times$; 在 C3D、GMM 和 GRP 上, 其吞吐率达到基线的 $75\%$ 以上.

[图 11](#figure-11) 把 TensorIR 与 CUTLASS [Ker22] 和 TensorRT [Ten17a] 两种平台专用方案进行比较. 在 C1D、C2D、DEP、T2D 和 DIL 上, TensorIR 最多领先基线 $13.9\times$. 结果体现了 TensorIR 自动优化的优势. 在 C3D、GRP 和 GMM 上, TensorIR 也达到基线 $75\%$ 以上的吞吐率. 即使工作负载已经由专门工程团队深度优化, TensorIR 仍能接近或追平现有供应商专用方案. 随着更多库中积累的经验被引入 TensorIR, 我们预计剩余差距会继续缩小. 各基线方案都由专门工程团队优化, 而 TensorIR 只需给出张量内在函数声明, 即可完成自动编译.

### 5.2 端到端模型评估

本节评估 TensorIR 对端到端模型执行的影响. 我们在 NVIDIA RTX 3080 上测试四个广泛使用的模型 [He16, How17, Dev18, Dos20]. TVM 和 AMOS 是机器学习编译器基线, PyTorch 1.13.0.dev20220612 是框架参照, 最后还有由 Nvidia 工程团队深度优化的平台专用方案 TensorRT.

<span id="figure-12"></span>

![见图注](./tensorir/figure-12.png)

**图 12.** NVIDIA GPU 上的端到端模型评估. TensorIR 显著优于现有机器学习编译方案, 在流行网络上达到与 GPU 推理库相近或更高的吞吐率. 对 TensorRT 尚不支持的新兴模型 ViT, TensorIR 表现更好.

结果见 [图 12](#figure-12). TensorIR 比 PyTorch、TVM 和 AMOS 快 $1.2 - 8.8\times$. 与 TensorRT 相比, TensorIR 在 MobileNet V2 上性能高出 $30\%$, 在 ResNet50 和 BERT_large 上达到其 $88\% - 100\%$ 的吞吐率. TensorIR 还能自动支持 Vision Transformer 等 TensorRT 尚未支持的新兴模型. 结果表明, 我们的抽象与自动调度器在常见机器学习模型上可以接近, 甚至超过最佳工程库的性能. 自动化方案还让系统能更快支持新兴模型.

<span id="table-01"></span>

![见图注](./tensorir/table-01.png)

**表 1.** NVIDIA GPU 上端到端模型的调优时间比较. TensorIR 的调优速度最高为 TVM 的 $2\times$.

调优时间是基于搜索的自动深度学习编译器能否实用的重要因素. [表 1](#table-01) 比较了 TVM 与 TensorIR 的端到端调优时间. 我们的框架调优速度最高可达 TVM 的 $2\times$, 原因有两方面. 第一, 硬件性能分析占用了大部分调优时间; TensorIR 的自动张量化利用 Tensor Core 生成了比 TVM 更快的程序, 因而性能分析耗时也相应减少. 第二, 分而治之方法把问题空间划分并隔离为外层循环嵌套与内部计算体. 内部计算体由硬件内在函数张量化, 系统只需搜索外层循环的循环变换, 因而搜索空间更小. 当这些模型在许多设备上投入长达数月的生产部署时, 搜索时间是可以接受的. TensorIR 还可缓存历史代价模型与搜索记录, 进一步消除搜索时间. 对已经调优过的算子, 构建模型便不再需要搜索.

### 5.3 ARM CPU 评估

前两个小节在 Nvidia GPU 上评估 TensorIR. 本节研究 TensorIR 推广到不同平台的难易程度. 我们提供 8 位整数点积 (*sdot*) 的描述, 在 ARM 平台上评估. 该指令不同于前两节使用的 Tensor Core. 重要的是, 我们只向同一个 TensorIR 框架提供新的张量内在函数描述. 评估在 AWS Graviton2 CPU 上进行.

**图 13.** ARM CPU 上的单算子评估. 得益于原生张量内在函数加速, TensorIR 最多比 TVM 快 $12.6\times$. 它的性能也达到高度优化的平台专用库 ArmComputeLib 的同一水平.

**单算子结果.** 我们评估 C2D 和 GMM 两种常用算子. TVM 是机器学习编译器基线, ARMComputeLib [Arm17] 是平台专用库基线. 结果见 [图 13](#figure-13). 得益于利用原生硬件加速的能力, TensorIR 最多比 TVM 快 $12.5\times$. 同时, TensorIR 的吞吐率达到 ARMComputeLib [Arm17] 的 $85\% - 105\%$, 表明它在该平台上能达到供应商专用方案的性能水平.

## 6 相关工作

深度学习框架 [Aba16, Pas19, Che15] 通过调用供应商优化库来优化深度神经网络, 例如 cuDNN [Che14]、MKL-DNN [Int17]、TensorRT [Ten17a] 和 ArmComputeLibrary [Arm17]. 这些库有工程开发成本, 且只适用于特定硬件. TensorIR 是库开发的补充: 它自动提供可与供应商库相比的性能, 从而扩大覆盖范围并降低开发成本. 这些框架可以利用 TensorIR, 为各种硬件后端生成优化后的张量化程序.

矩阵乘法、点积等计算密集型线性代数算子在科学计算中十分重要, 因而长期以来都是 HPC 社区的优化目标, CUTLASS [Ker22] 即是一例. 分而治之是 HPC 和机器学习工程中的典型优化技术. TensorIR 吸收这些思想, 将其推广为支持自动张量化的抽象.

机器学习编译器和张量编译器为张量程序引入了不同抽象. Halide [Rag13] 与 TVM [Che18] 使用调度语言描述标量计算体循环嵌套的优化原语. Tensor Comprehensions [Vas18]、Tiramisu [Bag19] 和 MLIR/Affine [Lat21] 使用多面体模型 [Vas06] 分析循环嵌套依赖. 这些工作以自底向上的方式优化带有标量计算的循环嵌套. Fireiron [Hag20] 和 Stripe [Zer19] 则使用嵌套多面体结构, 以自顶向下方式描述张量程序. TensorIR 结合两类方法的见解, 并把表示推广到张量化程序. IREE [Ire19] 是利用平台专用优化流水线的端到端编译器链. TensorIR 着重自动完成张量化过程, 无需人工干预即可为多个平台生成优化代码. TACO [Kjo17, Cho20, Sen20a] 是稀疏张量代数编译器. Cortex [Feg21] 把张量编译推广到递归计算. 我们的工作与这些研究正交. 未来可以把 TensorIR 抽象与其中的见解结合, 支持范围更广的计算.

自动化是机器学习编译与张量程序优化中的核心课题. AutoTVM [Che18a] 引入基于学习的方法, 通过学习得到的代价模型和模板引导搜索来优化张量程序. Triton [Til19] 引入基于分块的模板表示, 以有效优化程序. FlexTensor [Zhe20a] 自动生成模板. Halide 使用蒙特卡洛树搜索构建自动调度器 [Ada19]. Ansor [Zhe20] 使用分层搜索空间改进自动调度. 我们的自动调度算法借鉴这些方法, 并将其推广到最适合领域专用硬件加速的张量化计算.

自动向量化 [Ros07, Kon13] 是编译器研究中的长期课题. 张量化可以看作向量化问题的推广, 让现代加速器使用张量内在函数 [Nvi17, Int19, Arm17a, Mor18a]. 已有一些工作 [Bha20a, Zha21k, Wen21, Zhe22d] 研究这一课题. AKG [Zha21k] 使用多面体方法探索张量化搜索空间; UNIT [Wen21] 引入通用张量化流程; AMOS [Zhe22d] 则通过张量表达式自动映射到张量化内在函数. 我们提出新的张量化计算抽象, 并把张量化与其他优化联合执行, 从而推广了以往方法. TensorIR 为进一步开发张量化感知自动调度方法奠定了基础.

<span id="section-7"></span>

## 7 结论

本文提出 TensorIR, 一种用于自动张量化程序优化的抽象. 我们设计了名为 block 的关键抽象, 它能隔离张量化计算, 并为程序优化提供有效的变换原语. 我们还构建了自动调度算法, 将张量化与其他优化联合执行, 生成高性能程序. 我们希望这项工作推动更多张量化程序优化研究, 并为硬件与软件专用化带来新的机会.
