## 摘要

许多体系结构研究者认为, 成本-能耗-性能要取得重大改进, 现在必须依靠领域专用硬件. 本文评估了一款名为张量处理单元 (Tensor Processing Unit, TPU) 的定制 ASIC, 它自 2015 年起部署在数据中心, 用于加速神经网络 (NN) 的推理阶段. TPU 的核心是一个包含 65,536 个 8 位 MAC 的矩阵乘法单元, 峰值吞吐量为每秒 92 TeraOps (TOPS), 并配有一块由软件管理的大容量 (28 MiB) 片上存储器. 相比 CPU 和 GPU 中那些随时间变化的优化手段 (缓存, 乱序执行, 多线程, 多处理, 预取, ...), TPU 的确定性执行模型更适合我们的 NN 应用对第 99 百分位响应时间的要求; 前述优化更有利于平均吞吐量, 而不是有保证的延迟. TPU 没有这些特性, 这有助于解释为什么它虽然拥有大量 MAC 和大容量存储器, 尺寸却相对较小, 功耗也较低. 我们将 TPU 与服务器级 Intel Haswell CPU 和 Nvidia K80 GPU 对比, 后两者与 TPU 同时期部署在相同的数据中心. 我们的工作负载使用高级 TensorFlow 框架编写, 包含生产环境中的 NN 应用 (MLP, CNN 和 LSTM), 代表了数据中心 95% 的 NN 推理需求. 尽管某些应用的利用率较低, TPU 的平均速度仍约为同期 GPU 或 CPU 的 15X - 30X, TOPS/Watt 则高出约 30X - 80X. 如果在 TPU 中使用 GPU 的 GDDR5 存储器, 实际达到的 TOPS 还会增至三倍, TOPS/Watt 将接近 GPU 的 70X 和 CPU 的 200X.

**索引词 -** DNN, MLP, CNN, RNN, LSTM, 神经网络, 领域专用体系结构, 加速器.

## 1 神经网络概论

云端的大规模数据集与支撑云计算的大量计算机相互结合, 推动了机器学习的复兴. 深度神经网络 (DNN) 尤其带来了一系列突破: 与传统方法相比, 语音识别的词错误率降低了 30%, 这是 20 年来最大的进步 [Dea16]; 自 2011 年以来, 图像识别竞赛的错误率从 26% 降至 3.5% [Kri12, Sze15, He16a]; 还击败了人类围棋冠军 [Sil16]. 与某些硬件目标不同, DNN 可用于广泛的问题, 因而一款面向 DNN 的 ASIC 可以复用于语音, 视觉, 语言, 翻译, 搜索排序等许多解决方案.

神经网络 (NN) 以实现类似大脑的功能为目标, 建立在一种简单的人工神经元之上: 对输入加权和应用非线性函数 (如 max(0, value)). 这些人工神经元被组织成层, 前一层的输出依次成为下一层的输入. DNN 中的"深度"来自层数超过少数几层: 云端的大规模数据集允许模型使用更多, 更大的层来捕捉更高层次的模式或概念, 从而获得更高精度; GPU 则提供了开发这些模型所需的算力.

NN 的两个阶段称为*训练* (或*学习*) 和*推理* (或*预测*), 分别对应开发和生产. 开发者选择层数和 NN 类型, 训练则确定权重. 如今几乎所有训练都使用浮点数, 这是 GPU 广受欢迎的原因之一. 一个称为*量化*的步骤会把浮点数转换成窄整数, 通常只有 8 位, 对推理而言一般已经足够. 8 位整数乘法的能耗和面积都可比 IEEE 754 16 位浮点乘法低 6X; 对整数加法而言, 能耗优势为 13X, 面积优势为 38X [Dal16].

目前流行三类 NN:

1. *多层感知机* (MLP): 每一新层由若干非线性函数组成, 其输入是前一层全部输出 (*全连接*) 的加权和, 因而会复用权重.
2. *卷积神经网络* (CNN): 后续每一层由若干非线性函数组成, 其输入是前一层空间邻近输出子集的加权和, 同样会复用权重.
3. *循环神经网络* (RNN): 后续每一层由若干非线性函数组成, 其输入是输出和先前状态的加权和. 最流行的 RNN 是*长短期记忆* (LSTM). LSTM 的精妙之处在于决定遗忘什么, 以及把什么作为状态传给下一层. 权重会跨时间步复用.

[表 1](#table-01) 给出三类 NN 各两个示例, 它们代表了我们数据中心 95% 的 NN 推理工作负载, 并用作基准测试. 这些程序通常以 TensorFlow [Aba16a] 编写, 短得出人意料: 只有 100 到 1500 行代码. 我们的基准程序只是运行在主机服务器上的大型应用的一小部分, 后者可能包含数千到数百万行 C++ 代码. 这些应用通常直接面向用户, 因而响应时间限制很严格.

每个模型需要 5M 到 100M 个权重 ([表 1](#table-01) 的第 9 列), 访问它们可能耗费大量时间和能量. 为摊薄访问成本, 推理或训练时会在一*批*相互独立的样本间复用相同的权重, 从而提高性能.

本文描述并测量*张量处理单元 (TPU)*, 并将其推理性能和功耗与同期 CPU, GPU 对比. 主要结论如下:

- 推理应用通常更重视响应时间而非吞吐量, 因为它们往往直接面向用户.
- 受延迟限制, K80 GPU 在推理中的利用率不足, 速度只略高于 Haswell CPU.
- 虽然芯片小得多, 功耗也低得多, TPU 的 MAC 数量仍是 K80 GPU 的 25 倍, 片上存储容量是其 3.5 倍.
- TPU 的推理速度约为 K80 GPU 和 Haswell CPU 的 15X - 30X.
- 六个 NN 应用中有四个在 TPU 上受存储器带宽限制; 如果 TPU 改用与 K80 GPU 相同的存储系统, 速度将约为 GPU 和 CPU 的 30X - 50X.
- TPU 的每瓦性能是同期产品的 30X - 80X; 使用 K80 存储器的改进版 TPU 将高出 70X - 200X.
- 大多数体系结构研究者都在加速 CNN, 但 CNN 只占我们数据中心工作负载的 5%.

## 2 TPU 的起源, 架构与实现

早在 2006 年, 我们就开始讨论在数据中心部署 GPU, FPGA 或定制 ASIC. 当时的结论是, 能在专用硬件上运行的少数应用, 几乎可以免费利用大型数据中心的剩余容量来完成, 而免费很难被超越. 2013 年, 情况发生了变化: 一项预测指出, 如果人们每天使用 3 分钟由语音识别 DNN 支撑的语音搜索, 数据中心的规模必须翻倍才能满足计算需求; 用传统 CPU 满足这一需求将极其昂贵. 因此, 我们启动了一个高优先级项目, 迅速打造用于推理的定制 ASIC (同时购买现成 GPU 用于训练). 目标是让成本性能比 GPU 提高 10X. 在这一任务推动下, TPU 只用 15 个月就完成了设计, 验证 [Ste15], 制造和数据中心部署. (受篇幅限制, 本文无法详述 TPU 的全部内容; 更多信息见 [Ros15, Ros15a, Ros15b, Ros15c, Tho15, You15].)

为降低部署延期的风险, TPU 没有与 CPU 紧密集成, 而是设计成 PCIe I/O 总线上的协处理器, 可以像 GPU 一样插入现有服务器. 为简化硬件设计和调试, 指令由主机服务器发送给 TPU 执行, 而不是由 TPU 自行取指. 因此, TPU 在理念上更接近 FPU (浮点单元) 协处理器, 而不是 GPU.

<span id="figure-02"></span>

![TPU 裸片布局图](./tpu-performance-analysis/figure-02.png)

**图 2.** TPU 裸片布局图. 着色方式与 [图 1](#figure-01) 相同. 浅色 (蓝色) 数据缓冲区占裸片的 37%, 浅色 (黄色) 计算部分占 30%, 中等深度 (绿色) I/O 占 10%, 深色 (红色) 控制部分仅占 2%. CPU 或 GPU 的控制部分要大得多 (设计也困难得多).

我们的目标是在 TPU 中运行完整的推理模型, 减少与主机 CPU 的交互, 并让其足够灵活, 不只满足 2013 年 NN 的需求, 也能适应 2015 年及以后的 NN. [图 1](#figure-01) 给出了 TPU 的框图.

TPU 指令由主机通过 PCIe Gen3 x16 总线发送到指令缓冲区. 内部模块通常通过 256 字节宽的路径互连. 从右上角看起, 矩阵乘法单元是 TPU 的核心. 它包含 256x256 个 MAC, 可对有符号或无符号整数执行 8 位乘加运算. 16 位乘积被累加到矩阵单元下方 4 MiB 的 32 位累加器中. 这 4 MiB 对应 4096 个各含 256 个元素的 32 位累加器. 矩阵单元每个时钟周期产生一个 256 元素的部分和. 我们选择 4096 的过程是: 先注意到达到峰值性能所需的每字节运算数 (即 [第 4 节](#section-4) 中 Roofline 的拐点) 约为 1350, 于是向上取整到 2048, 再将其加倍, 使编译器能在峰值性能下使用双缓冲.

当混用 8 位权重和 16 位激活值 (或反过来) 时, 矩阵单元以半速计算; 两者都是 16 位时则以四分之一速度计算. 它每个时钟周期读写 256 个值, 可以执行矩阵乘法或卷积. 矩阵单元保存一个 64 KiB 的权重块, 另有一个用于双缓冲 (用来隐藏载入一个块所需的 256 个周期). 该单元面向稠密矩阵设计. 为尽快部署, 体系结构中没有加入稀疏支持. 未来设计会优先支持稀疏性.

矩阵单元的权重先进入片上权重 FIFO; 该 FIFO 从称为*权重存储器*的片外 8 GiB DRAM 读取数据 (推理时权重只读; 8 GiB 可支持多个同时活跃的模型). 权重 FIFO 深度为四个块. 中间结果保存在片上 24 MiB 的*统一缓冲区*中, 也可作为矩阵单元的输入. 可编程 DMA 控制器在 CPU 主机内存与统一缓冲区之间传输数据.

[图 2](#figure-02) 给出了 TPU 裸片布局图. 24 MiB 统一缓冲区占裸片近三分之一, 矩阵乘法单元占四分之一, 因而数据通路接近裸片的三分之二. 将容量定为 24 MiB, 一部分是为了匹配裸片上矩阵单元的间距, 另一部分则是考虑到开发周期短, 以简化编译器 (见 [第 7 节](#section-7)). 控制部分仅占 2%. [图 3](#figure-03) 展示了安装在印刷电路板上的 TPU, 它像 SATA 磁盘一样插入现有服务器.

指令通过相对较慢的 PCIe 总线发送, 因此 TPU 指令沿用了 CISC 传统, 包含重复字段. 这些 CISC 指令的平均每指令时钟周期数 (CPI) 通常为 10 到 20. TPU 总共约有十几条指令, 其中以下五条最重要:

1. `Read_Host_Memory` 将数据从 CPU 主机内存读入统一缓冲区 (UB).
2. `Read_Weights` 从权重存储器读取权重到权重 FIFO, 作为矩阵单元的输入.
3. `MatrixMultiply/Convolve` 使矩阵单元执行矩阵乘法或卷积, 从统一缓冲区读取数据并把结果写入累加器. 一次矩阵运算接收大小可变的 B*256 输入, 与 256x256 的常量权重输入相乘, 产生 B*256 输出, 通过流水线在 B 个周期内完成.
4. `Activate` 执行人工神经元的非线性函数, 可选择 ReLU, Sigmoid 等. 输入来自累加器, 输出写入统一缓冲区. 由于它连接到非线性函数逻辑, 还可使用裸片上的专用硬件执行卷积所需的池化操作.
5. `Write_Host_Memory` 将数据从统一缓冲区写入 CPU 主机内存.

其余指令包括备用的主机内存读写, 设置配置, 两种同步, 中断主机, 调试标签, nop 和 halt. CISC `MatrixMultiply` 指令长 12 字节, 其中 3 字节是统一缓冲区地址; 2 字节是累加器地址; 4 字节是长度 (卷积时有时是两个维度); 其余是操作码和标志.

TPU 微体系结构的理念是让矩阵单元保持忙碌. 这些 CISC 指令采用 4 级流水线, 每条指令在独立的阶段执行. 设计意图是把其他指令与 `MatrixMultiply` 指令重叠执行, 从而隐藏前者的执行时间. 为此, `Read_Weights` 指令遵循解耦访问/执行理念 [Smi82]: 它发送地址后即可完成, 不必等待从权重存储器取回权重. 如果输入激活值或权重数据尚未就绪, 矩阵单元将停顿.

我们没有清晰的流水线重叠图, 因为 CISC 指令可占据一个流水站数千个时钟周期, 不像传统 RISC 流水线那样每级一个周期. 当某个网络层的激活必须完成, 下一层的矩阵乘法才能开始时, 会出现值得注意的情况: 矩阵单元进入一个"延迟槽", 等待显式同步后才能安全地从统一缓冲区读取数据.

读取大型 SRAM 比算术运算耗电得多, 因此矩阵单元采用脉动执行, 减少对统一缓冲区的读写以节省能量 [Kun80, Ram91, Ovt15a]. 来自不同方向的数据按固定间隔到达阵列中的单元, 并在其中组合. [图 4](#figure-04) 显示数据从左侧流入, 权重从顶部载入. 一次给定的 256 元素乘加运算以对角波前形式穿过矩阵. 权重会预先载入, 并随推进的波前与新数据块的第一批数据同时生效. 控制和数据都经过流水线处理, 让软件看到的效果如同同时读入 256 个输入, 并立即更新 256 个累加器中各自的一个位置. 从正确性看, 软件不需要知道矩阵单元的脉动特性; 从性能看, 软件则必须考虑该单元的延迟.

TPU 软件栈必须与 CPU 和 GPU 的软件栈兼容, 才能迅速把应用移植到 TPU. 应用中在 TPU 上运行的部分通常以 TensorFlow 编写, 再编译成可在 GPU 或 TPU 上运行的 API [Lar16]. 与 GPU 类似, TPU 软件栈分为用户空间驱动和内核驱动. 内核驱动很轻量, 只负责内存管理和中断, 设计目标是长期稳定. 用户空间驱动则经常变化. 它负责设置和控制 TPU 执行, 把数据重排成 TPU 所需的顺序, 将 API 调用转换成 TPU 指令, 并生成应用二进制文件. 用户空间驱动在模型首次求值时进行编译, 缓存程序映像, 并把权重映像写入 TPU 的权重存储器; 第二次及之后的求值会以全速运行. TPU 从输入到输出完整运行大多数模型, 尽量提高 TPU 计算时间与 I/O 时间的比例. 计算通常逐层进行, 重叠执行使矩阵乘法单元能够隐藏大多数不在关键路径上的操作.

## 3 CPU, GPU 与 TPU 平台

[表 1](#table-01) 中的六个生产应用构成了本文的工作负载. 如前所述, 它们代表数据中心 TPU 用量的 95%. 颇为反常的是, 在生产机器上部署和测量 AlexNet 或 VGG 这类流行的小型 DNN 很困难. 不过, 我们的一个 CNN 源于广泛使用的 Inception V2.

基准平台是在 2015 年部署 TPU 时已有的服务器级计算机. 这一限制意味着, 它们必须像 TPU 一样, 至少为内部 SRAM 和外部 DRAM 提供 SECDED 保护, 因而排除了 Nvidia Maxwell GPU 等选择. 要由公司采购和部署, 它们还必须是配置合理的机器, 而不是为赢得基准测试而拼装出的别扭产物.

[表 2](#table-02) 列出了我们的选择. 传统 CPU 服务器采用 Intel 的 18 核双插槽 Haswell 处理器. 该平台同时也是 GPU 或 TPU 的主机服务器. Haswell 使用 Intel 22nm 工艺制造. CPU 和 GPU 的裸片都非常大: 约 600 mm²!

2.3 GHz 的 CPU 时钟频率不包括 Turbo 模式, 因为在数据中心的 NN 应用上很少会触发该模式. Haswell 的时钟频率会随程序是否使用 AVX 指令而变化, 而我们的 NN 应用经常使用 AVX. Turbo 模式的更高时钟频率 (面向不使用 AVX 的程序) 会在程序没有用满全部核心时出现. 因此, Turbo 模式在数据中心很少出现的另一个原因是, 我们的应用通常会用满所有核心, 还可运行其他数据中心作业来填补任何空闲核心.

GPU 加速器为 Nvidia K80. 每张 K80 卡包含两个裸片, 并为内部存储器和 DRAM 提供 SECDED. Nvidia 称,"K80 加速器以更少, 更强大的服务器提供应用性能, 可大幅降低数据中心成本" [Nvi16]. 2015 年, NN 研究者经常使用 K80; 到 2016 年 9 月, 新的云端 GPU 服务仍在选择它 [Bar16].

这台服务器可安装四张 K80 卡, 共八个 K80 裸片, 我们测试的正是这种配置. K80 提供 Boost 模式, 可把时钟频率提高到 875 MHz. Haswell 的 Turbo 模式由硬件控制, 因而在芯片温度显著上升前可短时突发运行. Boost 模式则由软件驱动控制 [Nvi15], 因此至少持续数百毫秒. 这意味着供电和散热必须按 K80 基本始终运行在 Boost 模式来配置, 否则芯片可能过热. 对这一平台而言, 启用 Boost 模式会迫使我们减少 K80 卡的数量, 损害总体拥有成本. 因此, Boost 模式被禁用. 这一限制会降低峰值带宽和 TOPS (见 [表 2](#table-02) 的说明); [第 8 节](#section-8) 将分析启用它的情况.

参与基准测试的每台服务器含有 2 到 8 个裸片, 因此下文通常给出按单裸片归一化的结果 ([图 5](#figure-05)-[图 8](#figure-08), [图 10](#figure-10)-[图 11](#figure-11), 以及 [表 3](#table-03), [表 4](#table-04) 和 [表 6](#table-06)), 但有时也给出整机结果 ([图 9](#figure-09)). 希望两者的区别足够清楚.

## 4 性能: Roofline, 响应时间与吞吐量

为展示六个应用在三种处理器上的性能, 我们改用高性能计算 (HPC) 中的 Roofline 性能模型 [Wil09]. 这个简单的可视化模型并不完美, 但能帮助理解性能瓶颈的成因. 该模型假定应用无法装入片上缓存, 因此要么受计算能力限制, 要么受存储器带宽限制. 对 HPC 而言, Y 轴表示每秒浮点运算性能, 所以峰值计算速率构成 Roofline 的"水平"部分. X 轴表示运算强度, 以每访问一个 DRAM 字节执行的浮点运算数衡量. 存储器带宽的单位是字节/秒; 因为 (FLOPS/秒)/(FLOPS/字节) = 字节/秒, 它会转化成 Roofline 的"倾斜"部分. 运算强度不足时, 程序受存储器带宽限制, 位于 Roofline 倾斜部分的下方.

<span id="figure-05"></span>

![TPU 单裸片 Roofline](./tpu-performance-analysis/figure-05.png)

**图 5.** TPU (单裸片) Roofline. 它的拐点位于很靠右的位置, 即每读取一个权重存储器字节执行 1350 次运算.

应用的实际每秒运算数与其正上方性能上限之间的差距, 表示在运算强度不变时进一步调优性能可能带来的收益; 当然, 提高运算强度的优化 (如缓存分块) 可能获得更大收益.

把 Roofline 模型用于 TPU 时, NN 应用经过量化, 因此首先要把浮点运算替换成整数运算. 其次, NN 应用的权重通常无法装入片上存储器, 所以我们把运算强度重新定义为每读取一个权重字节执行的整数运算数 (见 [表 1](#table-01) 第 10 列).

[图 5](#figure-05) 以双对数坐标展示单个 TPU 裸片的 Roofline 模型. TPU 的 Roofline 有很长的"倾斜"部分, 此处运算强度意味着性能受存储器带宽而非峰值计算能力限制. 六个应用中有五个正好顶到性能上限: MLP 和 LSTM 受存储器限制, CNN 受计算限制. CNN1 的运算强度虽然很高, 却只达到 14.1 TOPS, 而 CNN0 达到 86 TOPS.

[表 3](#table-03) 根据可让我们部分观察 TPU 运行情况的性能计数器解释了 CNN1 的表现. TPU 在 CNN1 上执行矩阵运算的周期不足一半 (第 1 行第 7 列). 在这些活跃周期中, 65,536 个 MAC 只有约一半装有有效权重, 因为 CNN1 的某些层特征深度较浅. 约 35% 的周期用于等待权重从存储器载入矩阵单元, 这发生在 4 个全连接层执行期间, 它们的运算强度仅为 32 (见 [第 8 节](#section-8) 最后一条"谬误"). 因此, 还有约 19% 的周期无法由矩阵相关计数器解释. TPU 采用重叠执行, 所以我们无法精确核算这些周期, 但可以看到, 23% 的周期因流水线中的 RAW 依赖而停顿, 1% 的周期因等待 PCIe 总线输入而停顿.

## 5 成本性能, TCO 与每瓦性能

成千上万台采购计算机时, 成本性能比比性能更重要. 数据中心最合适的成本指标是总体拥有成本 (TCO). 我们为数千颗芯片实际支付的价格取决于相关公司之间的谈判. 出于商业原因, 我们无法公布这类价格信息, 也不能公布可能让人推导出价格的数据. 不过, 功耗与 TCO 相关, 而我们可以公布每台服务器的功率, 所以本文用每瓦性能作为性能/TCO 的替代指标. 本节比较整台服务器而非单个裸片, [表 2](#table-02) 的"基准服务器"列列出了这些配置.

[图 9](#figure-09) 给出了 K80 GPU 和 TPU 相对 Haswell CPU 的每瓦性能几何平均值与加权平均值. 我们给出两种每瓦性能计算方法. 第一种 ("总计") 在计算 GPU 和 TPU 的每瓦性能时包含主机 CPU 服务器的功耗. 第二种 ("增量") 则先从 GPU 和 TPU 的功耗中减去主机 CPU 服务器功耗.

按总计每瓦性能计算, K80 服务器是 Haswell 的 1.2 - 2.1X. 按增量每瓦性能计算, 省略 Haswell 服务器功耗后, K80 服务器为 1.7- 2.9X.

TPU 服务器的总计每瓦性能比 Haswell 高 17 到 34 倍, 这使它达到 K80 服务器的 14 到 16 倍. TPU 的相对增量每瓦性能为 41 到 83, 这是公司采用定制 ASIC 的理由; 相比 GPU, TPU 的每瓦性能提高到 25 到 29 倍.

## 6 能耗比例性

热设计功耗 (TDP) 会影响供电配置成本, 因为必须在硬件满功率运行时提供充足的电力和散热. 但电费取决于工作负载在一天中变化时的平均功耗. [Bar07] 发现, 服务器处于 100% 忙碌状态的时间不足 10%, 因而提出*能耗比例性*: 服务器的功耗应与完成的工作量成正比. 上一节的功耗估算基于我们在数据中心观测到的 TDP 比例.

我们测量了所提供的工作负载利用率从 0% 变到 100% 时的性能和功耗, 数据按工作负载每变化 10% 分桶收集 [Lan09]. [图 10](#figure-10) 给出 CNN0 工作负载变化时三种芯片的服务器功耗除以每台服务器裸片数量后的结果. 对 GPU 和 TPU, 图中同时绘制增量功耗 (K80 和 TPU) 与总功耗 (K80+Haswell/4 和 TPU+Haswell/2). 注意, 三者使用的批大小相同.

可以看到, TPU 功耗最低, 每个裸片的总功耗为 118W (TPU+Haswell/2), 增量功耗为 40W ([图 10](#figure-10) 中的 TPU), 但它的能耗比例性较差: 在 10% 负载下, TPU 的功耗是 100% 负载时的 88%. (开发周期很短, 未能加入许多节能特性.) 不出所料, Haswell 的能耗比例性是三者中最好的: 10% 负载下的功耗为 100% 负载时的 56%. K80 比 TPU 更接近 CPU, 10% 工作负载下的功耗为满载时的 66%. 不受计算限制的 LSTM1 表现相近: 在 10% 负载下, CPU 使用满载功耗的 47%, GPU 使用 78%, TPU 使用 94%.

如果服务器在运行 CNN0 时还充当加速器主机, 它的功耗会怎样? GPU 和 TPU 满载时, CPU 服务器分别使用满功率的 52% 和 69%. (CPU 为 TPU 完成更多工作, 因为 TPU 的运行速度远高于 GPU.) 因此, Haswell 服务器加四个 TPU 的功耗增加不到 20%, 运行 CNN0 的速度却是单独 Haswell 服务器的 80 倍 (4 个 TPU 对 2 个 CPU).

首先, 提高存储器带宽 (*memory*) 的影响最大: 存储器带宽提高 4X 时, 平均性能提高 3X. 其次, 无论是否增加累加器, 提高时钟频率对平均性能的帮助都很小. 原因是 MLP 和 LSTM 受存储器限制, 只有 CNN 受计算限制. [图 11](#figure-11) 只显示六个 DNN 的加权平均值, 因而不易看出这一点: 时钟频率提高 4X 对 MLP 和 LSTM 几乎没有影响, 但能让 CNN 性能提高约 2X. 第三, 对所有应用而言, 矩阵单元从 256x256 扩大到 512x512 后, [图 11](#figure-11) 中的平均性能反而略有下降, 无论累加器是否增加. 这个问题类似于大页面的内部碎片, 只不过因涉及两个维度而更严重. 以 LSTM1 中的 600x600 矩阵为例. 使用 256x256 矩阵单元时, 平铺 600x600 需要 9 步, 总时间为 18 us. 更大的 512x512 单元只需四步, 但每步耗时是原来的四倍, 总时间为 32 us. CISC 指令很长, 因而解码开销可以忽略, 也无法隐藏从 DRAM 载入数据的开销.

[表 8](#table-08) 给出了 24 MiB 统一缓冲区的利用情况, 它最初按 MLP 以最多 2048 的批大小运行来确定容量. 我们最近改进了统一缓冲区的存储分配器, 将六个应用中最大应用所需的存储器降至 14 MiB. 在部署后的前 18 个月, 新分配器仍在开发, TPU 使用了全部容量. 现在, 多出的容量为采用更大模型留下余量.

接着, 我们用性能模型评估了一款假想的 TPU 裸片 (TPU'), 如果开发时间不只 15 个月, 它或许可以用相同工艺设计出来. 更激进的逻辑综合和模块设计可能把时钟频率提高 50%. 设计类似 K80 的 GDDR5 存储器接口电路, 可把权重存储器带宽提高到五倍以上, 使 Roofline 拐点从 1350 移到 250. 如 [图 11](#figure-11) 所示, 只把时钟频率提高到 1050 MHz 而不改善存储器, 几乎不会带来变化. 如果时钟保持 700 MHz, 但为权重存储器采用 GDDR5, 几何平均值会显著提高到 2.6, 加权平均值提高到 3.9. 两者同时改变时, 几何平均值提高到 2.9, 但加权平均值不变, 因而 TPU' 只是采用了更快的存储器.

[图 11](#figure-11) 不包含主机服务器时间. 我们用 [表 5](#table-05) 计算 TPU 与主机服务器交互的开销时间. 加上同样的额外时间后, TPU' 的两个平均值分别从 2.6 降至 1.9, 从 3.9 降至 3.2. 这一变化既偏乐观, 因为它没有包含 CPU 运行应用中主机负责部分的时间; 又偏悲观, 因为有了速度快 3X 的 TPU', 我们很可能会积极调优主机代码.

仅把 DDR3 权重存储器替换成相当的 GDDR5 存储器, 就需要把存储器通道数量增加到四个. 这一改动会让裸片面积增加约 10%. 不过, 更高的存储器带宽减轻了统一缓冲区的压力, 因而把统一缓冲区缩小到 14 MiB 可收回 10% 的面积. 由于每台服务器有 4 个 TPU, GDDR5 还会把 TPU 系统的功耗预算从 861W 提高到约 900W.

## 8 讨论

本节沿用 [Hen18] 以反驳回应谬误和陷阱的写法.

- **谬误: 数据中心的 NN 推理应用同等重视吞吐量和响应时间.**

  开发者对响应时间有很高要求, 这让我们感到意外, 因为 2014 年有人认为批大小会足够大, 可让 TPU 达到峰值性能, 或者延迟要求不会那么严格. 一个主要应用是离线图像处理, 当时的直觉是, 如果交互式服务也需要 TPU, 大多数服务只需积累更大的批. 2014 年, 甚至一个重视响应时间的应用 (LSTM1) 的开发者也称限制为 10 ms, 但实际将其移植到 TPU 时, 限制缩短到 7 ms. 众多这类服务对 TPU 的意外需求, 加上低响应时间的影响和偏好, 改变了局面; 应用开发者经常选择降低延迟, 而不是等待更大批量的积累. 好在 TPU 拥有简单, 可重复的执行模型, 有助于满足交互式服务的响应时间目标; 它的峰值吞吐量也很高, 即使批大小较小, 性能仍高于同期 CPU 和 GPU.

- **谬误: K80 GPU 体系结构很适合 NN 推理.**

  GPU 一直被视为高吞吐量体系结构, 依靠高带宽 DRAM 和数千个线程实现目标. 这一视角有助于解释为何 K80 的推理速度只略高于 Haswell, 却远低于 TPU. K80 的后续产品肯定会加入优化以提高峰值推理性能, 但考虑到它们面向吞吐量的体系结构方案, GPU 可能更难满足严格的延迟限制. 而且, [第 7 节](#section-7) 表明 TPU 还有很大的改进空间, 因而并非容易追赶的目标.

- **陷阱: 体系结构研究者忽视了重要的 NN 任务.**

  体系结构社区对 NN 的关注令我们欣慰: ISCA 2016 有 15% 的论文研究 NN 硬件加速器 [Alb16, Che16c, Chi16, Han16a, Kim16a, Lik16, Liu16, Rea16, Sha16b]! 遗憾的是, 这九篇论文全部研究 CNN, 只有两篇提到其他 NN. CNN 比 MLP 更复杂, 在 NN 竞赛中也很突出 [Rus15], 这或许解释了它的吸引力, 但 CNN 只占我们数据中心 NN 工作负载的约 5%. CNN 在边缘设备中或许很常见, 数据中心的卷积模型数量却尚未赶上 MLP 和 LSTM. 我们希望体系结构研究者至少以同样的热情尝试加速 MLP 和 LSTM.

- **陷阱: 对 NN 硬件而言, 每秒推理数 (IPS) 不是准确的综合性能指标.**

  我们的结果表明, IPS 不适合概括 NN 硬件的整体性能, 因为它只是应用中典型推理复杂度的倒数 (例如 NN 层的数量, 大小和类型). 例如, TPU 运行 4 层 MLP1 时达到 360,000 IPS, 运行 89 层 CNN1 时却只有 4,700 IPS, 因而 TPU 的 IPS 相差 75X! 所以, 用 IPS 作为单一速度指标来概括 NN 加速器, 比用 MIPS 或 FLOPS 概括常规处理器更加误导 [Hen18], 更应受到批评. 为更好地比较 NN 机器, 我们需要用高级语言编写的基准套件, 以便移植到各式各样的 NN 体系结构. Fathom 是这类基准套件中一个很有希望的新尝试 [Ado16].

- **谬误: 如果启用 Boost 模式, K80 GPU 的结果会好得多.**

  暂且不谈 K80 Boost 模式对 TCO 的负面影响 ([第 3 节](#section-3)), 我们在 LSTM1 上测量了该模式. Boost 模式最多把时钟频率提高 1.6 倍, 从 560 MHz 增至 875 MHz, 性能提高 1.4X, 但功耗也提高 1.3X. 每瓦性能净增 1.1X, 所以对 LSTM1 而言, Boost 模式只会轻微影响我们的能耗-速度分析.

- **谬误: 如果更高效地使用 CPU 和 GPU, 或拿更新的版本比较, 其结果会与 TPU 相当.**

  由于高效使用 AVX2 整数支持需要投入大量工作, 我们最初只有一个 DNN 的 CPU 8 位结果, 收益约为 3.5X. 与其把这一个例外连同单独的 Roofline 放进结果, 用浮点数展示全部 CPU 结果更不容易让人混淆, 也更节省篇幅. 如果所有 DNN 都有类似的加速, 每瓦性能比将从 41-83X 降到 12-24X. 新款 16nm, 1.5GHz, 250W 的 P40 数据中心 GPU 每秒可执行 47 Tera 次 8 位运算, 但它在 2015 年初尚不可用, 因而与我们的三个平台并非同期产品. 我们也无法知道 P40 在严格时间界限内能实现多大比例的峰值性能. 如果比较更新的芯片, [第 7 节](#section-7) 表明, 只需使用 K80 的 GDDR5 存储器, 就能让采用 28nm 工艺, 0.7GHz, 40W 的 TPU 性能提高到三倍 (代价是额外增加 10W).

- **陷阱: 事后才为 NN 硬件添加性能计数器.**

  TPU 有 106 个性能计数器, 真要说的话, 我们还希望再多几个 (见 [表 3](#table-03)). NN 加速器的存在理由就是性能, 而它们还处在演进的早期, 远未形成判断运行情况的可靠直觉.

- **谬误: 经过两年软件调优后, 提高 TPU 性能只剩硬件升级这一条路.**

  如果开发者和编译器作者投入更多工作, 让 CNN1 更贴合 TPU 硬件, CNN1 在 TPU 上的性能还可以提高. 例如, 开发者可以重组应用, 将卷积层产生的多个短批聚合成一个更深的批 (从 32 增至 128), 供四个全连接层使用. 这样的单层会提高矩阵单元的利用率 ([表 3](#table-03)). CNN1 目前在 TPU 上的运行速度已经超过 CPU 的 70 倍, CNN1 的开发者对此非常满意, 因而并不清楚这类优化会不会进行, 又会在何时进行.

## 9 相关工作

两篇综述记录表明, 定制 NN ASIC 至少可以追溯到 25 年前 [Ien96, Asa02]. 例如, CNAPS 芯片包含一个由 64 个 16 位乘 8 位乘法器组成的 SIMD 阵列, 多个 CNAPS 芯片可通过一个定序器连接 [Ham90]. Synapse-1 系统基于一款名为 MA-16 的定制脉动乘加芯片, 每次可执行十六个 16 位乘法 [Ram91]. 系统串接多个 MA-16 芯片, 并用定制硬件执行激活函数.

从 1995 年起, 共有 25 台由 T0 定制 ASIC 加速的 SPERT-II 工作站投入部署, 同时用于语音识别的 NN 训练和推理 [Asa98]. 40 MHz 的 T0 为 MIPS 指令集体系结构增加了向量指令. 这个八通道向量单元基于 8 位和 16 位输入, 每个时钟周期最多可产生十六个 32 位算术结果, 推理速度比 SPARC-20 工作站快 25 倍, 训练速度快 20 倍. 他们发现 16 位不足以用于训练, 因而改用两个 16 位字, 这让训练时间增加了一倍. 为克服这一缺点, 他们引入由 32 到 1000 个数据集组成的"组" (批), 减少更新权重所花的时间; 这种方法比使用一个字但不分批的训练更快.

较新的 DianNao 系列 NN 体系结构针对 NN 应用中的存储器访问模式提供高效的体系结构支持, 尽量减少片上和外部 DRAM 访问 [Keu16, Che16j]. 它们都使用 16 位整数运算, 所有设计都完成了版图, 但没有制造芯片. 最初的 DianNao 使用包含 64 个 16 位整数乘加单元的阵列和 44 KB 片上存储器, 估计面积为 3 mm² (65 nm), 运行频率为 1 GHz, 功耗为 0.5W [Che14b]. 大部分能量消耗在从 DRAM 访问权重上, 因而后续设计 DaDianNao ("大电脑") 加入 eDRAM, 在片上保存 36 MiB 权重 [Che14a]. 目标是在多芯片系统中提供足够的存储器, 避免访问外部 DRAM. 后续的 PuDianNao ("普通电脑") 面向 DNN 之外更传统的机器学习算法, 如支持向量机 [Liu15]. 另一个分支 ShiDianNao ("视觉电脑") 面向 CNN, 通过把加速器直接连接到传感器来避免 DRAM 访问 [Du15].

Convolution Engine 同样面向图像处理中的 CNN [Qad13]. 该设计部署 64 个 10 位乘加单元, 并定制一个估计采用 45 nm 工艺, 运行于 800 MHz 的 Tensilica 处理器. 预计它的能量-面积效率是 SIMD 处理器的 8X 到 15X, 与仅针对特定内核设计的定制硬件相差 2X 到 3X 以内.

Fathom 基准论文的结果似乎与我们矛盾, 其中 GPU 的推理速度远高于 CPU [Ado16]. 但它们的 CPU 和 GPU 不是服务器级产品, CPU 只有四个核心, 应用未使用 CPU 的 AVX 指令, 也没有响应时间截止限制 (见 [表 4](#table-04)) [Bro16a].

Catapult 是利用可重构性支持 DNN 的部署最广泛的实例, 许多研究都提出过这种方法 [Far09, Cha10, Far11, Pee13, Cav15, Zha15]. 他们选择 FPGA 而非 GPU, 既为了降低功耗, 也为了降低延迟敏感应用无法良好映射到 GPU 的风险. FPGA 还可以改作其他用途, 如搜索, 压缩和网络接口卡 [Put15]. TPU 项目实际始于 FPGA, 但我们发现当时的 FPGA 在性能上无法与同期 GPU 竞争, 而 TPU 可以在达到或超过 GPU 速度的同时大幅降低功耗, 因而有望同时显著优于 FPGA 和 GPU, 于是放弃了 FPGA.

Catapult 虽然最早发表于 2014 年 [Put14], 但它与 TPU 属于同期产品, 因为 28nm Stratix V FPGA 和 TPU 都在 2015 年部署到数据中心. Catapult 的时钟频率为 200 MHz, 有 3,926 个 18 位 MAC, 5 MiB 片上存储器, 11 GB/s 存储器带宽, 功耗为 25W. TPU 的时钟频率为 700 MHz, 有 65,536 个 8 位 MAC, 28 MiB 片上存储器, 34 GB/s 存储器带宽, 通常功耗为 40W. Catapult 的修订版使用更新的 FPGA, 并于 2016 年实现更大规模部署 [Cau16].

Catapult V1 使用脉动矩阵乘法器, 运行 CNN 的速度是 2.1 GHz, 16 核双插槽服务器的 2.3X [Ovt15]. 如果使用 Catapult V2 的下一代 FPGA (14nm Arria 10), 性能可能提高到 7X, 更仔细地做平面布局后甚至可能达到 17X [Ovt15a]. 尽管这种比较并不对等, 当前 TPU 裸片运行 CNN 的速度是稍快服务器的 40X 到 70X ([表 2](#table-02) 和 [表 6](#table-06)). 最大的差异或许在于, 用户要获得最佳性能, 必须用低级硬件设计语言 Verilog 编写长程序 [Met16, Put16], 而 TensorFlow 高级框架只需编写短程序. 换句话说, TPU 的可重编程性来自软件, FPGA 的可重编程性则来自固件.

TPU 部署后出现的近期研究通过优化权重和数据很小或为零的情况来加速 DNN. TPU 的紧张工期不允许加入这类优化, 但我们在研究中也看到了同样的机会. Efficient Inference Engine 先通过滤除极小值, 在一个独立步骤中把权重数量减少约 10 倍 [Han15a], 再用 Huffman 编码进一步压缩数据, 从而提高推理性能 [Han16a]. Cnvlutin [Alb16] 会在激活输入为零时避免乘法; 激活输入有 44% 的时间为零, 推测部分原因是 ReLU 非线性函数会把负值变成零; 这使平均性能提高 1.4 倍.

Eyeriss 是一种新型低功耗数据流体系结构, 它利用零值, 通过对数据进行游程编码来缩小内存占用, 并在输入为零时避免计算以节省功耗 [Che16c]. 按 Eyeriss 的术语, TPU 卷积层把 C 和 M 分别映射到矩阵单元的行和列, 执行一遍需要 HWN 个周期. C/M 较高时, 处理该层需要执行 RS 遍; C/M 较低时, 可用多种技术减少执行遍数并提高利用率. (更多信息见在线文献 [Ros15, Ros15a, Ros15b, Ros15c, Tho15, You15].)

Minerva 是一个跨算法, 体系结构和电路领域的协同设计系统, 一方面剪除较小的激活数据, 另一方面量化数据, 从而将功耗降低 8X [Rea16]. [Gup15] 研究用于训练而非推理的 16 位定点算术. 其他研究利用 DNN 计算的低精度, 在计算中采用模拟电路来改善能效和性能 [Lik16, Sha16b]. Cambricon 通过为 DNN 定制指令集来缩短代码 [Liu16]. 近期工作还研究了 NN 的存内处理体系结构 [Chi16, Kim16a].

下面将 TPU 与其中一些体系结构比较:

- [Che14b] 使用 DMA 把数据从 DRAM 传到输入缓冲区和权重缓冲区. 三级流水 NFU 读取这些数据, 执行乘法, 加法和非线性函数; 结果进入输出缓冲区, 再写回 DRAM. NFU 没有存储空间, 也不是脉动结构.
- [Gup15] 似乎在脉动阵列中保存部分和, 同时流式传输矩阵的两个输入; TPU 保存权重矩阵块, 同时流式传输另一个输入和激活前的部分和. TPU 不支持随机舍入.
- [Zha15] 由若干计算单元构成, 每个单元相当于 TPU 矩阵单元的 4x2 版本. 在 ASIC 中, 连接输入输出缓冲区与这些计算引擎的交叉开关会带来显著布线成本. 令人意外的是, [Zha15] 中没有通过体系结构支持额外的归约操作, 以合并各计算引擎的结果.

[Gup15, Che14b, Zha15] 三者都在计算期间把激活值保存在 DRAM 中; TPU 统一缓冲区的容量足以保证正常运行时不需要向 DRAM 溢出或从中重新载入.

## 10 结论

TPU 挂在 I/O 总线上, 存储器带宽也相对有限, 因而其利用率受到限制, 六个 NN 应用中有四个受存储器限制; 但 Roofline 性能模型表明, 一个大数的一小部分仍可能相当大. 这一结果提示, Amdahl 定律还可以有一条"丰裕推论": 即使一个庞大, 廉价的资源利用率较低, 仍能提供高性能和高成本效益.

与 K80 GPU 的 32 位浮点数据通路相比, TPU 利用 8 位整数脉动矩阵乘法器在能耗和面积上低一个数量级的优势, 在相对较小的裸片上容纳了 25 倍的 MAC (65,536 个 8 位 MAC, 对比 2,496 个 32 位 MAC) 和 3.5 倍的片上存储器 (28 MiB, 对比 8 MiB), 功耗却不到 K80 的一半. 更大的存储器有助于提高应用的运算强度, 让它们更充分地利用大量 MAC.

我们发现, 体系结构社区最近虽然着重研究 CNN, 但 CNN 只占我们数据中心代表性 NN 工作负载的约 5%, 这表明 MLP 和 LSTM 应得到更多关注. 历史正在重演: 当年许多体系结构研究者专注于浮点性能, 后来却发现大多数主流工作负载主要执行整数运算.

我们观察到, 每秒推理数 (IPS) 更多取决于 NN 而非底层硬件, 因此用 IPS 作为 NN 处理器的单一性能指标, 甚至比用 MIPS 和 MFLOPS 衡量 CPU 与 GPU 更糟糕.

我们还了解到, 推理应用通常是面向用户应用的一部分, 因而响应时间限制很严, NN 体系结构必须在应对第 99 百分位延迟期限时保持良好性能. K80 或许擅长训练, 但在我们的工作负载上, 其平均推理速度只略高于 Haswell; 原因可能是它更重吞吐量而非延迟, 这与推理应用严格的响应时间期限冲突.

TPU 裸片利用 MAC 和片上存储器方面的优势, 运行由领域专用 TensorFlow 框架编写的短程序时, 速度是 K80 GPU 裸片的 15 倍, 每瓦性能优势达到 29 倍; 每瓦性能与性能/总体拥有成本相关. 相比 Haswell CPU 裸片, 对应比值分别为 29 和 83. 未来 CPU 和 GPU 的推理速度肯定会提高, 但重新设计的 TPU 若采用约 2015 年的 GPU 存储器, 速度可提高到两至三倍, 相对 K80 和 Haswell 的每瓦性能优势将分别提高到近 70 倍和 200 倍.

总之, TPU 成功的原因包括: 尺寸较大但没有过大的矩阵乘法单元; 容量可观且由软件控制的片上存储器; 能运行完整推理模型, 减少对主机 CPU 的依赖; 单线程, 确定性的执行模型, 实践证明它很适合第 99 百分位响应时间限制; 足够的灵活性, 既能适配 2013 年的 NN, 也能适配 2017 年的 NN; 去掉通用特性, 从而在数据通路和存储器更大的情况下, 裸片仍然小且功耗低; 量化应用使用 8 位整数; 应用以 TensorFlow 编写, 可轻松移植到差异很大的 TPU 硬件并实现高性能, 无需为了高效运行而重写.

商业产品之间出现数量级差异在计算机体系结构中很少见, TPU 因而可能成为领域专用体系结构的范型. 我们预计, 许多人会构建后续产品, 把标准进一步提高.
